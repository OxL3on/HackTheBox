## 1. Windows Operating System পরিচিতি

একজন Penetration Tester-এর Windows এবং Linux—দুটি Operating System সম্পর্কেই ভালো ধারণা থাকা প্রয়োজন। কারণ, বাস্তব Security Assessment-এ On-premises এবং Cloud—উভয় পরিবেশেই এই দুটি OS ব্যাপকভাবে ব্যবহৃত হয়।

একজন Pentester-এর জানতে হবে:

- Windows ও Linux কীভাবে কাজ করে।
- এই OS-গুলোতে কীভাবে Attack এবং Defense করা হয়।
- একটি সিস্টেমে প্রবেশ করার পর সেটিকে ব্যবহার করে কীভাবে আরও Pentesting করা যায়।
- বিভিন্ন OS version-এর মধ্যে কী পার্থক্য রয়েছে এবং কোন version-এ কী ধরনের vulnerability বা misconfiguration থাকতে পারে।

### 1.1 Windows-এর ইতিহাস

- November 20, 1985: Microsoft প্রথম Windows প্রকাশ করে। প্রথম Windows ছিল MS-DOS-এর ওপর তৈরি একটি Graphical Operating System Shell।
- পরবর্তী Desktop সংস্করণগুলোতে Windows File Manager, Program Manager এবং Print Manager যুক্ত হয়।
- Windows 95: Windows ও DOS-এর আরও পূর্ণাঙ্গ integration নিয়ে আসে। এতে প্রথমবার Built-in Internet Support এবং Internet Explorer browser যুক্ত হয়।
- পরবর্তীতে Windows XP, Vista, Windows 8 এবং অন্যান্য সংস্করণ প্রকাশিত হয়। মূল HTB কনটেন্টে Windows 11-কে সর্বশেষ Desktop version হিসেবে উল্লেখ করা হয়েছে।

Microsoft বিভিন্ন ব্যবহারকারীর জন্য Windows Desktop-এর বিভিন্ন Edition প্রকাশ করেছে—সাধারণ ব্যবহারকারী থেকে শুরু করে Enterprise পর্যায় পর্যন্ত।

### 1.2 Windows Server-এর ইতিহাস

## 1993

Windows NT 3.1 Advanced Server

Windows Server-এর প্রথম প্রকাশিত সংস্করণ। পরবর্তী NT সংস্করণগুলোতে IIS, Networking Protocols এবং Administrative Wizards-এর মতো সুবিধা যুক্ত হয়।

## 2000

Windows 2000 Server

- Active Directory (AD) চালু হয়।
- File Sharing, Data Encryption এবং VPN-এর মতো কাজ পরিচালনায় সহায়তা করে।
- Microsoft Management Console (MMC) যুক্ত হয়।
- Dynamic Disk Volumes সমর্থন করে।

## 2003

Windows Server 2003

Server Roles, Built-in Firewall এবং Volume Shadow Copy Service যুক্ত হয়।

## 2008

Windows Server 2008

Failover Clustering, Hyper-V Virtualization, Server Core, Event Viewer এবং Active Directory-তে বড় ধরনের উন্নতি আসে।

## 2012+

Server 2012, 2016 ও 2019

পরবর্তী সংস্করণগুলোতে আরও উন্নতি হয়। HTB-এর মূল কনটেন্ট অনুযায়ী, Server 2019-এ Kubernetes, Linux Containers এবং উন্নত Security Features-এর সমর্থন যুক্ত হয়েছে।

### 1.4 Legacy Windows এবং End of Life

Windows-এর নতুন সংস্করণ আসার সঙ্গে সঙ্গে পুরোনো সংস্করণগুলো অনেক সময় Deprecated হয়ে যায় এবং Microsoft-এর নিয়মিত Security Update পাওয়া বন্ধ করে দেয়। কিছু ক্ষেত্রে Long-Term Support Contract থাকলে ব্যতিক্রম হতে পারে।

HTB-এর মূল কনটেন্টে উল্লেখ রয়েছে:

- Windows Server 2008 এবং Server 2012-এর Security Update Support শেষ হয় January 14, 2020।
- সেখানে Server 2012 R2 এবং পরবর্তী সংস্করণগুলোকে Supported হিসেবে উল্লেখ করা হয়েছে।
- EternalBlue নামে পরিচিত Critical `SMBv1` Vulnerability আবিষ্কারের পর Microsoft পুরোনো Windows সংস্করণের জন্যও বিশেষ Out-of-Band Patch প্রকাশ করেছিল।

গুরুত্বপূর্ণ: এগুলো মূল HTB কনটেন্টের ঐতিহাসিক তথ্য। বর্তমান Support Status যাচাই করতে Microsoft-এর Lifecycle Documentation দেখতে হবে।

#### কেন Pentester-এর জন্য গুরুত্বপূর্ণ?

অনেক প্রতিষ্ঠান এখনও পুরোনো Windows ব্যবহার করে। এর কারণ হতে পারে:

- গুরুত্বপূর্ণ পুরোনো Application-এর ওপর নির্ভরশীলতা।
- Operating System পরিবর্তন করার খরচ।
- Operational সমস্যা বা Compatibility Issue।
- বাজেটের সীমাবদ্ধতা।

পুরোনো OS-এ Unsupported Software, পুরোনো Vulnerability এবং Misconfiguration থাকার ঝুঁকি থাকতে পারে। তাই Assessment-এর সময় OS Version এবং Build Number শনাক্ত করা গুরুত্বপূর্ণ।

## 3. `Get-WmiObject` দিয়ে Windows Information বের করা

`Get-WmiObject` হলো Windows PowerShell-এর একটি Cmdlet, যা WMI (Windows Management Instrumentation) ব্যবহার করে Windows System-এর তথ্য সংগ্রহ করতে পারে।

এটি দিয়ে আমরা জানতে পারি:

- Operating System-এর Version ও Build Number।
- চলমান Process-এর তালিকা।
- Windows Services-এর তালিকা।
- BIOS সম্পর্কিত তথ্য।
- Remote Computer-এর System Information।

### 3.1 OS Version ও Build Number বের করা

মূল HTB কমান্ড:

```
Get-WmiObject -Class win32_OperatingSystem | select Version,BuildNumber
```

উদাহরণ Output:

```
Version    BuildNumber
-------    -----------
10.0.19041 19041
```

কমান্ডটি কীভাবে কাজ করে?

\| অংশ | কাজ | |---|---| | `Get-WmiObject` | WMI থেকে তথ্য সংগ্রহ করে | | `-Class win32_OperatingSystem` | Operating System-সংক্রান্ত WMI Class নির্বাচন করে | | `|` | প্রথম কমান্ডের Output পরের কমান্ডে পাঠায় | | `select Version,BuildNumber` | শুধু Version এবং BuildNumber দেখায় |

এই Output অনুযায়ী, উদাহরণ সিস্টেমটি Windows 10 এবং এর Build Number হলো `19041`।

### 3.2 অন্যান্য গুরুত্বপূর্ণ WMI Class

| WMI Class               | কী তথ্য পাওয়া যায়          |
| ----------------------- | -------------------------- |
| `Win32_OperatingSystem` | Operating System-এর তথ্য   |
| `Win32_Process`         | System-এর Process List     |
| `Win32_Service`         | Windows Services-এর তালিকা |
| `Win32_Bios`            | BIOS সম্পর্কিত তথ্য        |

BIOS (Basic Input/Output System): এটি কম্পিউটারের Motherboard-এ থাকা Firmware, যা Power Management, Input/Output Interface এবং System Configuration-এর মতো মৌলিক কাজ নিয়ন্ত্রণে সাহায্য করে।

### 3.3 Remote Computer-এর তথ্য সংগ্রহ

`Get-WmiObject`-এর `-ComputerName` Parameter ব্যবহার করে Remote Computer-এর তথ্যও সংগ্রহ করা যায়। এটি উপযুক্ত Permission ও Network Access থাকা সাপেক্ষে Remote Service শুরু বা বন্ধ করার মতো কাজেও ব্যবহার করা যায়।

- Desktop Computer

- Smartphone

প্রতিষ্ঠানগুলো কর্মীদের জন্য নির্দিষ্ট Workstation এবং Computer ব্যবহারের Security Policy তৈরি করে। তবে বর্তমানে Remote Work বাড়ার কারণে কর্মীদের দূর থেকে Computer ব্যবহার ও পরিচালনা করার প্রয়োজনও বেড়েছে।

IT, Software Development এবং Information Security-তে কাজ করা ব্যক্তিদের প্রতিদিন একাধিক Computer Local ও Remote—দুইভাবেই ব্যবহার করতে হতে পারে।

### 4.2 Remote Access Concepts

Remote Access হলো Network-এর মাধ্যমে অন্য Computer-এ সংযোগ স্থাপন করা।

এটি দিয়ে দূর থেকে:

- Server পরিচালনা করা যায়।
- Application তৈরি ও পরীক্ষা করা যায়।
- Employee Workstation Administer করা যায়।
- Security Issue তদন্ত করা যায়।
- বিভিন্ন System-এর Management ও Automation করা যায়।

Remote Access-এর ওপর নির্ভরশীল দুটি গুরুত্বপূর্ণ Service Provider হলো:

- MSP (Managed Service Provider): অন্য প্রতিষ্ঠানের IT System পরিচালনা ও রক্ষণাবেক্ষণ করে।
- MSSP (Managed Security Service Provider): অন্য প্রতিষ্ঠানের Security Monitoring ও Security Management-সংক্রান্ত কাজ পরিচালনা করে।

Remote Access ব্যবহারের সুবিধা:

1. বিভিন্ন System-এর Management একটি জায়গা থেকে করা যায়।
2. প্রতিষ্ঠানের Technology Standardize করা যায়।
3. Repetitive Task Automation করা যায়।
4. Remote Work সহজ হয়।
5. সমস্যা বা সম্ভাব্য Security Threat দেখা দিলে দ্রুত Response দেওয়া যায়।

## 5. Remote Desktop Protocol (RDP)

RDP হলো একটি Network Protocol, যা দিয়ে দূর থেকে Windows Computer-এর Graphical Desktop ব্যবহার করা যায়।

RDP Client দিয়ে Target Computer-এর IP Address অথবা Hostname নির্দিষ্ট করে সংযোগ স্থাপন করা হয়।

### 5.1 RDP কীভাবে কাজ করে?

RDP Client/Server Architecture অনুসরণ করে।

- RDP Client: যে Computer থেকে সংযোগ করা হচ্ছে।
- RDP Server: যে Target Computer-এ Remote Access চালু রয়েছে।
- IP Address: Network-এ Computer শনাক্ত করতে ব্যবহৃত হয়।
- Port: Target Computer-এর নির্দিষ্ট Application বা Service-এ যোগাযোগ করতে ব্যবহৃত হয়।

RDP-এর Default Port হলো:

```
3389
```

RDP কাজ করার জন্য Target Windows System-এ Remote Access অনুমোদিত থাকতে হবে।

### 5.2 IP Address ও Port সহজ উদাহরণে

ধরো, একটি Corporate Network হলো একটি রাস্তা।

- Network-এর একটি Computer-এর IP Address হলো রাস্তার একটি বাড়ির ঠিকানা।
- সেই Computer-এর Port হলো বাড়ির নির্দিষ্ট দরজা বা জানালা।
- কোনো Application-এর Port-এ Request পাঠালে সেটি সংশ্লিষ্ট Application বা Service-এর কাছে পৌঁছায়।

একটি Network Packet Target Computer-এর IP Address-এ পৌঁছালে, Packet-এর Header-এ থাকা Port Number অনুযায়ী উপযুক্ত Service-এ Request পাঠানো হয়।

মূল HTB Resource:

[Connecting with xfreerdp — GIF](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/49/ConnectingwithXfreerdp.gif?utm_source=chatgpt.com)

### 6.1 RDP Connection Command

মূল HTB কমান্ড:

```
xfreerdp /v:<targetIp> /u:htb-student /p:Password
```

এখানে:

| Option           | অর্থ                                          |
| ---------------- | --------------------------------------------- |
| `xfreerdp`       | RDP Client চালু করে                           |
| `/v:<targetIp>`  | Target-এর IP Address বা Hostname নির্ধারণ করে |
| `/u:htb-student` | Username নির্ধারণ করে                         |
| `/p:Password`    | Password নির্ধারণ করে                         |

`<targetIp>`-এর জায়গায় HTB Lab-এর দেওয়া Target IP বসাতে হবে। Username ও Password-এর জায়গায় প্রদত্ত Credential ব্যবহার করতে হবে।

উদাহরণস্বরূপ, যদি Target IP হয় `10.10.10.10`, তাহলে কমান্ডটি হবে:

```
xfreerdp /v:10.10.10.10 /u:htb-student /p:Password
```

এখানে IP ও Credential শুধু উদাহরণ। বাস্তব Lab-এ নিজের Target Information ব্যবহার করবে।

### 6.2 `xfreerdp`-এর অতিরিক্ত সুবিধা

- Terminal-এ পুরো কমান্ড Copy-Paste করা যায়; প্রতিটি Option হাতে লিখতে হয় না।
- Drive Redirection ব্যবহার করে Local Machine ও Target Host-এর মধ্যে File Transfer করা সম্ভব হতে পারে।
- অতিরিক্ত Option ব্যবহার করে Connection-এর আচরণ নিয়ন্ত্রণ করা যায়।

Drive Redirection এবং অন্যান্য Advanced Option HTB Academy-এর পরবর্তী Module-গুলোতে আরও বিস্তারিতভাবে শেখানো হবে।

## 7. Windows Target-এ সংযোগ করা

HTB Lab-এর Target চালু করার পর প্রদত্ত Credential দিয়ে RDP Connection স্থাপন করতে হবে।

মূল কমান্ড:

```
xfreerdp /v:<targetIp> /u:htb-student /p:Password
```

এখানে:

1. `<targetIp>`-এর জায়গায় Target-এর IP Address বসাও।
2. `/u:`-এর পরে প্রদত্ত Username দাও।
3. `/p:`-এর পরে প্রদত্ত Password দাও।
4. কমান্ড চালিয়ে RDP Session স্থাপন করো।

নিরাপদ Credential ব্যবহারের পরামর্শ

Password কমান্ডের মধ্যে সরাসরি লিখলে তা Shell History বা Process Information-এ প্রকাশিত হওয়ার ঝুঁকি থাকতে পারে। বাস্তব Assessment-এ Tool-এর সমর্থিত নিরাপদ Credential Input পদ্ধতি ব্যবহার করো। HTB Lab-এর ক্ষেত্রে প্রদত্ত নির্দেশনা অনুসরণ করবে।
