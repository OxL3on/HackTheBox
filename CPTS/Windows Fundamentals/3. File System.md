## 1. Windows File Systems

Windows-এ প্রধানত ৫ ধরনের File System রয়েছে:

- FAT12
- FAT16
- FAT32
- NTFS
- exFAT

`FAT12` ও `FAT16` আধুনিক Windows System-এ সাধারণত আর ব্যবহার করা হয় না। এই Section-এ FAT32 ও exFAT সম্পর্কে সংক্ষেপে আলোচনা করা হয়েছে, তবে মূল ফোকাস হলো NTFS।

## 2. FAT32 (File Allocation Table)

FAT32 বিভিন্ন ধরনের Storage Device-এ ব্যবহৃত হয়। যেমন:

- USB Flash Drive
- SD Card
- Hard Drive

নামের `32` বোঝায়, FAT32 Storage Device-এর Data Cluster শনাক্ত করার জন্য 32-bit Data ব্যবহার করে।

### FAT32-এর সুবিধা (Pros)

- Device Compatibility: Computer, Digital Camera, Gaming Console, Smartphone, Tablet-সহ বিভিন্ন Device-এ ব্যবহার করা যায়।
- Cross-Platform Compatibility: Windows 95 থেকে শুরু করে বিভিন্ন Windows Version, macOS এবং Linux-এ Support রয়েছে।

### FAT32-এর অসুবিধা (Cons)

- একটি File-এর Size সর্বোচ্চ 4 GB-এর কম হতে পারে; 4 GB বা তার বেশি Size-এর File সংরক্ষণ করা যায় না।
- Built-in Data Protection ও File Compression Feature নেই।
- File Encryption-এর জন্য Third-party Tool প্রয়োজন।

## 3. NTFS (New Technology File System)

NTFS হলো Windows-এর Default File System, যা Windows NT 3.1 থেকে ব্যবহৃত হয়ে আসছে।

NTFS, FAT32-এর সীমাবদ্ধতাগুলো দূর করার পাশাপাশি Metadata পরিচালনা এবং Data Structure উন্নত করার মাধ্যমে ভালো Performance দেয়।

### NTFS-এর সুবিধা (Pros)

1. Reliability: System Failure বা Power Loss-এর পর File System-এর Consistency পুনরুদ্ধার করতে সাহায্য করে।
2. Granular Permissions: File ও Folder-এর জন্য আলাদা আলাদা Permission নির্ধারণ করা যায়।
3. Large Partitions: অনেক বড় আকারের Partition Support করে।
4. Journaling: File-এর পরিবর্তন—যেমন Add, Modify ও Delete—সম্পর্কিত তথ্য Log করে রাখে।

### NTFS-এর অসুবিধা (Cons)

- অধিকাংশ Mobile Device-এ NTFS Nativeভাবে Support করে না।
- পুরোনো Media Device, যেমন TV ও Digital Camera, অনেক সময় NTFS Storage Device Support করে না।

### FAT32 বনাম NTFS

| বিষয়                    | FAT32                                              | NTFS                                      |
| ----------------------- | -------------------------------------------------- | ----------------------------------------- |
| Compatibility           | বিভিন্ন OS ও Device-এ ব্যাপক Support               | কিছু পুরোনো Device-এ Support সীমিত        |
| Maximum File Size       | 4 GB-এর কম                                         | অনেক বড় File Support করে                  |
| File/Folder Permissions | NTFS-এর মতো Granular Permission নেই                | Granular Permission Support করে           |
| Journaling              | নেই                                                | আছে                                       |
| Built-in Compression    | নেই                                                | Support করে                               |
| Security                | Built-in File Permission ও Encryption সুবিধা সীমিত | উন্নত Permission ও Security Feature রয়েছে |

## 4. NTFS Permissions

NTFS File System-এ File ও Folder-এর ওপর Basic এবং Advanced Permission সেট করা যায়।

কোনো User একটি File বা Folder কী করতে পারবে, তা Permission দিয়ে নির্ধারণ করা হয়।

### 4.1 গুরুত্বপূর্ণ Permission Types

| Permission             | কাজ                                                                                                                          |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `Full Control`         | File/Folder Read, Write, Modify ও Delete করা যায়; Permission পরিবর্তনসহ পূর্ণ নিয়ন্ত্রণ পাওয়া যায়।                           |
| `Modify`               | File/Folder Read, Write ও Delete করা যায়।                                                                                    |
| `List Folder Contents` | Folder ও Subfolder-এর তালিকা দেখা যায় এবং File Execute করা যায়। এটি Folder-এ প্রযোজ্য এবং Folder থেকে Inherit হতে পারে।      |
| `Read and Execute`     | File ও Subfolder দেখা, তালিকা করা এবং File Execute করা যায়। File ও Folder উভয় ক্ষেত্রেই প্রযোজ্য।                            |
| `Write`                | Folder ও Subfolder-এ File যোগ করা এবং File-এর Content পরিবর্তন বা লেখা যায়।                                                  |
| `Read`                 | Folder-এর তালিকা দেখা এবং File-এর Content পড়া যায়।                                                                           |
| `Traverse Folder`      | কোনো Folder-এর Content List করার অনুমতি না থাকলেও তার মধ্য দিয়ে অন্য File বা Folder-এ পৌঁছানোর অনুমতি দেওয়া বা বন্ধ করা যায়। |

### 4.2 Traverse Folder Permission-এর উদাহরণ

ধরো, একটি User-এর নিচের Path-এর Directory Content List করার বা File দেখার Permission নেই:

```
C:\Users\bsmith\documents\webapps\backups\backup_02042020.zip
```

কিন্তু তার কাছে প্রয়োজনীয় `Traverse Folder` Permission রয়েছে।

তাহলে সে Parent Folder-এর Content List করতে না পারলেও উপযুক্ত অন্যান্য Permission থাকলে ওই Path ধরে Backup Archive-এ পৌঁছাতে পারে।

মনে রাখবে: Traverse Permission একা কোনো File পড়ার অনুমতি দেয় না। File Access করতে সংশ্লিষ্ট File-এর প্রয়োজনীয় Permission-ও থাকতে হবে।

### 4.3 Permission Inheritance

NTFS-এ সাধারণত File ও Folder তাদের Parent Folder থেকে Permission Inherit করে।

উদাহরণ:

```
C:\Company
└── Documents
    └── Report.txt
```

যদি `C:\Company` থেকে Permission Inherit করা হয়, তাহলে `Documents` এবং `Report.txt`-ও সেই Permission পেতে পারে, যদি Inheritance বন্ধ না করা থাকে এবং Permission-এর Scope প্রযোজ্য হয়।

এর সুবিধা:

- প্রতিটি File ও Folder-এর জন্য আলাদাভাবে Permission সেট করতে হয় না।
- Administrator-এর কাজ সহজ হয়।
- অনেক File ও Folder একসঙ্গে পরিচালনা করা যায়।

প্রয়োজনে Administrator কোনো File বা Folder-এর Inheritance বন্ধ করে সরাসরি সেই File বা Folder-এর জন্য Permission সেট করতে পারেন।

## 5. NTFS Permission পরীক্ষা: `icacls`

Windows-এ NTFS Permission পরিচালনা করার দুটি সাধারণ উপায়:

1. File Explorer-এর Security Tab ব্যবহার করা।
2. Command Line থেকে `icacls` ব্যবহার করা।

`icacls` দিয়ে File ও Folder-এর Permission দেখা, পরিবর্তন করা, Inheritance পরিচালনা করা এবং Access নিয়ন্ত্রণ করা যায়।

### 5.1 Directory-এর Permission দেখা

বর্তমান Directory-এর Permission দেখতে:

```
icacls
```

অথবা নির্দিষ্ট Directory-এর Permission দেখতে:

```
icacls C:\Windows
```

এখানে `icacls C:\Windows` দিয়ে বর্তমান Working Directory যেখানেই হোক, `C:\Windows`-এর Permission পরীক্ষা করা যায়।

### 5.2 Original HTB Output

```
C:\htb> icacls c:\windows
c:\windows NT SERVICE\TrustedInstaller:(F)
           NT SERVICE\TrustedInstaller:(CI)(IO)(F)
           NT AUTHORITY\SYSTEM:(M)
           NT AUTHORITY\SYSTEM:(OI)(CI)(IO)(F)
           BUILTIN\Administrators:(M)
           BUILTIN\Administrators:(OI)(CI)(IO)(F)
           BUILTIN\Users:(RX)
           BUILTIN\Users:(OI)(CI)(IO)(GR,GE)
           CREATOR OWNER:(OI)(CI)(IO)(F)
           APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(RX)
           APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(OI)(CI)(IO)(GR,GE)
           APPLICATION PACKAGE AUTHORITY\ALL RESTRICTED APPLICATION PACKAGES:(RX)
           APPLICATION PACKAGE AUTHORITY\ALL RESTRICTED APPLICATION PACKAGES:(OI)(CI)(IO)(GR,GE)

Successfully processed 1 files; Failed processing 0 files
```

প্রতিটি Account বা Group-এর পাশে Permission এবং Inheritance সংক্রান্ত তথ্য দেখানো হয়েছে।

### 5.3 গুরুত্বপূর্ণ Account ও Group

| Account / Group                       | অর্থ                                                                                          |
| ------------------------------------- | --------------------------------------------------------------------------------------------- |
| `NT SERVICE\TrustedInstaller`         | Windows-এর গুরুত্বপূর্ণ System Component ও Update পরিচালনার সঙ্গে সম্পর্কিত Service Identity। |
| `NT AUTHORITY\SYSTEM`                 | Windows-এর Local System Account, যার অনেক ক্ষেত্রে উচ্চ Privilege থাকে।                       |
| `BUILTIN\Administrators`              | Local Administrators Group।                                                                   |
| `BUILTIN\Users`                       | সাধারণ Local Users Group।                                                                     |
| `CREATOR OWNER`                       | কোনো File বা Folder-এর Creator/Owner-এর সঙ্গে সম্পর্কিত বিশেষ Security Principal।             |
| `ALL APPLICATION PACKAGES`            | Windows Application Package-গুলোর জন্য ব্যবহৃত Security Principal।                            |
| `ALL RESTRICTED APPLICATION PACKAGES` | Restricted Application Package-গুলোর জন্য ব্যবহৃত Security Principal।                         |

## 6. `icacls`-এর Inheritance Flags

`icacls` Output-এ Permission-এর পাশে কিছু বিশেষ Flag থাকে।

| Flag   | পূর্ণরূপ                 | কাজ                                                                                    |
| ------ | ------------------------ | -------------------------------------------------------------------------------------- |
| `(CI)` | Container Inherit        | Permission Subfolder-এর মতো Container-এ Inherit হতে পারে।                              |
| `(OI)` | Object Inherit           | Permission File-এর মতো Object-এ Inherit হতে পারে।                                      |
| `(IO)` | Inherit Only             | Permission শুধু Child Object-এ Inherit হওয়ার জন্য; বর্তমান Object-এ সরাসরি কার্যকর নয়। |
| `(NP)` | Do Not Propagate Inherit | Permission পরবর্তী Descendant-এ আর Propagate হবে না।                                   |
| `(I)`  | Inherited                | Permission Parent Container থেকে Inherit হয়েছে।                                        |

### 6.1 Output বোঝার উদাহরণ

```
NT AUTHORITY\SYSTEM:(OI)(CI)(IO)(F)
```

এর অর্থ:

- `NT AUTHORITY\SYSTEM` — যে Account-এর Permission দেখানো হচ্ছে।
- `(OI)` — Permission File-এ Inherit হতে পারে।
- `(CI)` — Permission Subfolder-এ Inherit হতে পারে।
- `(IO)` — Permission বর্তমান Folder-এ সরাসরি কার্যকর নয়; Child Object-এর জন্য Inheritance নির্দেশ করে।
- `(F)` — Full Access।

অর্থাৎ, এই Entry-তে SYSTEM Account-এর জন্য File ও Subfolder-এ Full Control Inherit হওয়ার ব্যবস্থা রয়েছে।

গুরুত্বপূর্ণ: `(IO)` থাকার কারণে এই নির্দিষ্ট Entry-কে বর্তমান Folder-এ সরাসরি Full Control হিসেবে ব্যাখ্যা করা যাবে না। Permission-এর কার্যকারিতা বুঝতে Entry-এর সব Flag একসঙ্গে দেখতে হবে।

## 7. `icacls`-এর Basic Permission Codes

`icacls` Output-এ Permission বোঝানোর জন্য সংক্ষিপ্ত Code ব্যবহার করা হয়।

| Code | অর্থ              |
| ---- | ----------------- |
| `F`  | Full Access       |
| `D`  | Delete Access     |
| `N`  | No Access         |
| `M`  | Modify Access     |
| `RX` | Read and Execute  |
| `R`  | Read-Only Access  |
| `W`  | Write-Only Access |
| `GR` | Generic Read      |
| `GE` | Generic Execute   |

উদাহরণ:

```
BUILTIN\Users:(RX)
```

অর্থাৎ, এই Entry অনুযায়ী `BUILTIN\Users` Group-এর Read এবং Execute Permission রয়েছে।

আরেকটি উদাহরণ:

```
NT AUTHORITY\SYSTEM:(M)
```

অর্থাৎ, SYSTEM Account-এর জন্য Modify Permission নির্ধারিত রয়েছে।

## 8. `icacls` দিয়ে Permission পরিবর্তন করা

এখন একটি উদাহরণের মাধ্যমে Permission Grant এবং Remove করা শিখি।

HTB-এর উদাহরণে Administrator Account থেকে `C:\Users` Directory-এর Permission দেখা হচ্ছে। এখানে `joe` User-এর জন্য আলাদা Write Permission দেখানো নেই।

### 8.1 বর্তমান Permission পরীক্ষা

```
C:\htb> icacls c:\Users
c:\Users NT AUTHORITY\SYSTEM:(OI)(CI)(F)
         BUILTIN\Administrators:(OI)(CI)(F)
         BUILTIN\Users:(RX)
         BUILTIN\Users:(OI)(CI)(IO)(GR,GE)
         Everyone:(RX)
         Everyone:(OI)(CI)(IO)(GR,GE)

Successfully processed 1 files; Failed processing 0 files
```

Output থেকে বোঝা যায়:

- `SYSTEM` — File ও Folder-এর জন্য Full Control Inherit করতে পারে।
- `Administrators` — File ও Folder-এর জন্য Full Control Inherit করতে পারে।
- `Users` — Root Folder-এ Read/Execute Permission রয়েছে।
- `Everyone` — Root Folder-এ Read/Execute Permission রয়েছে।

এখানে `joe`-এর জন্য আলাদা Write Permission নেই।

### 8.2 User-কে Full Control দেওয়া

`joe` User-কে `C:\Users` Directory-তে Full Control দিতে:

```
icacls C:\Users /grant joe:f
```

ব্যাখ্যা:

| অংশ        | কাজ                                               |
| ---------- | ------------------------------------------------- |
| `icacls`   | Permission পরিচালনার Tool।                        |
| `C:\Users` | যে Directory-এর Permission পরিবর্তন করা হবে।      |
| `/grant`   | নির্দিষ্ট User বা Group-কে Permission প্রদান করে। |
| `joe:f`    | `joe` User-কে Full Control (`F`) দেয়।             |

Command সফল হলে উদাহরণ Output:

```
C:\htb> icacls c:\users /grant joe:f
processed file: c:\users
Successfully processed 1 files; Failed processing 0 files
```

### 8.3 `(OI)` এবং `(CI)` না দিলে কী হয়?

উপরের Command-এ `(OI)` এবং `(CI)` উল্লেখ করা হয়নি।

তাই এখানে `joe`-কে `C:\Users` Folder-এর ওপর Full Control দেওয়া হয়েছে, কিন্তু সেই Permission স্বয়ংক্রিয়ভাবে সব Child File ও Subfolder-এ Inherit করার নির্দেশ দেওয়া হয়নি।

অর্থাৎ, Parent Folder-এর Permission Grant করলেই তার সব Child Object-এ একই Permission চলে যাবে—এমন নয়।

Permission যাচাই করতে:

```
icacls C:\Users
```

HTB-এর উদাহরণে Output-এর নতুন Entry:

```
C:\htb> icacls c:\users
c:\users WS01\joe:(F)
         NT AUTHORITY\SYSTEM:(OI)(CI)(F)
         BUILTIN\Administrators:(OI)(CI)(F)
         BUILTIN\Users:(RX)
         BUILTIN\Users:(OI)(CI)(IO)(GR,GE)
         Everyone:(RX)
         Everyone:(OI)(CI)(IO)(GR,GE)

Successfully processed 1 files; Failed processing 0 files
```

এখানে:

```
WS01\joe:(F)
```

এর অর্থ হলো `WS01` Computer/Domain Context-এর `joe` User-কে `C:\Users` Folder-এর ওপর Full Control দেওয়া হয়েছে।

### 8.4 Child File ও Folder-এ Permission Inherit করানো

Child File ও Folder-এ Permission Inherit করানোর জন্য Inheritance Flag ব্যবহার করা যায়।

উদাহরণ:

```
icacls C:\Users /grant joe:(OI)(CI)F
```

এখানে:

- `(OI)` — File-এ Permission Inherit হতে পারে।
- `(CI)` — Subfolder-এ Permission Inherit হতে পারে।
- `F` — Full Control।

এই Command-এর মাধ্যমে `joe`-কে Parent Directory এবং উপযুক্ত Child Object-এ Full Control দেওয়ার Inheritance Rule নির্ধারণ করা হয়।

সতর্কতা: Full Control খুব শক্তিশালী Permission। বাস্তব System-এ এটি Grant করার আগে নিশ্চিত হতে হবে যে User-এর সত্যিই এই Privilege প্রয়োজন।

### 8.5 Permission Remove করা

`joe` User-এর জন্য সরাসরি Grant করা Permission সরাতে:

```
icacls C:\Users /remove joe
```

ব্যাখ্যা:

- `/remove` — নির্দিষ্ট User বা Group-এর Access Control Entry (ACE) সরাতে ব্যবহৃত হয়।
- `joe` — যে User-এর Entry সরানো হবে।

এই Command `C:\Users`-এর Access Control List থেকে `joe`-এর সংশ্লিষ্ট Entry সরায়। এটি অন্য Directory-তে থাকা আলাদা Permission Entry-গুলোকে স্বয়ংক্রিয়ভাবে সরিয়ে দেয় না।

## 9. `icacls`-এর অন্যান্য ব্যবহার

`icacls` শুধু Permission দেখার জন্য নয়; আরও অনেক কাজের জন্য ব্যবহার করা যায়।

- নির্দিষ্ট User বা Group-কে File/Folder-এর Permission দেওয়া।
- কোনো User বা Group-এর Access স্পষ্টভাবে Deny করা।
- Permission Inheritance Enable বা Disable করা।
- File ও Folder-এর Ownership পরিবর্তন করা।
- Domain Environment-এ নির্দিষ্ট User বা Group-এর Permission পরিচালনা করা।
