## ১. Service Permissions কী?

Windows services দীর্ঘসময় background-এ চলে। ভুল permissions-এর কারণে DLL/executable replace, unauthorized execution, privilege escalation ও persistence সম্ভব হতে পারে।

Service Account: Critical service চালাতে আলাদা account ব্যবহার করা উচিত। যেমন, DHCP service যদি Bob-এর account-এ চলে এবং Bob-এর account disable হয়, DHCP বন্ধ হয়ে network downtime হতে পারে।

## ২. `services.msc` দিয়ে পরীক্ষা

`services.msc` → `Windows Update (wuauserv)` → Properties।

গুরুত্বপূর্ণ তথ্য:

- Service Name: Command-line-এ ব্যবহৃত নাম।
- Path to executable: Service চালুর executable path। Directory-তে দুর্বল NTFS permission থাকলে executable replace হতে পারে।
- Log On: Service কোন account-এ চলে।
- Recovery: Service fail করলে restart বা program চালানোর মতো action নির্ধারণ করা যায়।

Built-in accounts:

- `LocalService`
- `NetworkService`
- `LocalSystem` — Local Windows OS-এ সর্বোচ্চ privilege।

Principle of Least Privilege: Application-কে প্রয়োজনীয় সর্বনিম্ন privilege দাও।

## ৩. `sc.exe` দিয়ে Services পরীক্ষা

Service configuration দেখাও:

```
sc qc wuauserv
```

গুরুত্বপূর্ণ output:

```
SERVICE_NAME: wuauserv
TYPE               : 20  WIN32_SHARE_PROCESS
START_TYPE         : 3   DEMAND_START
ERROR_CONTROL      : 1   NORMAL
BINARY_PATH_NAME   : C:\WINDOWS\system32\svchost.exe -k netsvcs -p
DISPLAY_NAME       : Windows Update
DEPENDENCIES       : rpcss
SERVICE_START_NAME : LocalSystem
```

Remote service query:

```
sc \\hostname_or_ip query ServiceName
```

Service stop করতে:

```
sc stop wuauserv
```

Admin privilege ছাড়া ফলাফল:

```
[SC] OpenService FAILED 5:
Access is denied.
```

Elevated terminal-এ configuration পরিবর্তনের উদাহরণ:

```
sc config wuauserv binPath=C:\Winbows\Perfectlylegitprogram.exe
sc qc wuauserv
```

Output-এ `BINARY_PATH_NAME` পরিবর্তিত হয়ে নতুন path দেখাবে। এটি service executable path পরিবর্তনের উদাহরণ; অনুমোদিত lab ছাড়া এমন পরিবর্তন করো না।

## ৪. `sc sdshow` ও SDDL

Service-এর security descriptor দেখতে:

```
sc sdshow wuauserv
```

উদাহরণ:

```
D:(A;;CCLCSWRPLORC;;;AU)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;SY)S:(AU;FA;CCDCLCSWRPWPDTLOSDRCWDWO;;;WD)
```

Windows-এর securable object-এর Security Descriptor-এ owner, primary group, DACL ও SACL থাকতে পারে।

- DACL: কারা কী access পাবে।
- SACL: Access attempt auditing/logging।
- SDDL: Security descriptor প্রকাশের string format।
- ACE: Access Control Entry; নির্দিষ্ট user/group-এর permission।

প্রথম DACL entry:

```
D:(A;;CCLCSWRPLORC;;;AU)
```

| অংশ  | অর্থ                           |
| ---- | ------------------------------ |
| `D:` | DACL                           |
| `A`  | Allow                          |
| `AU` | Authenticated Users            |
| `CC` | `SERVICE_QUERY_CONFIG`         |
| `LC` | `SERVICE_QUERY_STATUS`         |
| `SW` | `SERVICE_ENUMERATE_DEPENDENTS` |
| `RP` | `SERVICE_START`                |
| `LO` | `SERVICE_INTERROGATE`          |
| `RC` | `READ_CONTROL`                 |

`;;CCLCSWRPLORC;;;AU`-তে permission code-গুলো নির্দিষ্ট principal `AU`-এর অনুমোদিত action বোঝায়। সম্পূর্ণ descriptor-এ তিনটি ACE আছে—`AU`, `BA` (Built-in Administrators) ও `SY` (SYSTEM)।

## ৫. PowerShell দিয়ে Service Permissions

Service-এর Registry key-এর ACL দেখতে:

```
Get-Acl -Path HKLM:\System\CurrentControlSet\Services\wuauserv | Format-List
```

Output-এর গুরুত্বপূর্ণ অংশ:

```
Owner : NT AUTHORITY\SYSTEM
Group : NT AUTHORITY\SYSTEM
Access:
 BUILTIN\Users Allow ReadKey
 BUILTIN\Administrators Allow FullControl
 NT AUTHORITY\SYSTEM Allow FullControl
```

`Get-Acl` readable permissions এবং SDDL দুটোই দেখায়। SDDL-এ security principal-এর SID-ও থাকতে পারে, যা `sc sdshow` output-এ একইভাবে দৃশ্যমান হয় না।

## মূল কথা

- Service permissions ও executable directory-এর NTFS permissions পরীক্ষা করো।
- Service কোন account-এ চলছে এবং কী privilege আছে দেখো।
- `sc qc` = configuration, `sc sdshow` = security descriptor।
- `Get-Acl` = Registry ACL ও SDDL।
- Command-line পদ্ধতি script ও বড় network/domain environment-এ GUI-এর চেয়ে সহজে scale করে।
