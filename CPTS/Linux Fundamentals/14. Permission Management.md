# Permission Management


## 1. Linux Permissions কী?

Linux-এ permissions নির্ধারণ করে কে কোনো file বা directory পড়তে, পরিবর্তন করতে বা execute করতে পারবে।

প্রতিটি file ও directory-এর থাকে:

- Owner: যে user-এর মালিকানায় file বা directory আছে।
- Group: যে group-এর সঙ্গে এটি যুক্ত।
- Others: owner ও group-এর বাইরে থাকা users।

একজন user একাধিক group-এর সদস্য হতে পারে। Group membership-এর মাধ্যমে অতিরিক্ত access পাওয়া সম্ভব।

নতুন file বা directory তৈরি করলে সাধারণত সেটি তৈরি করা user-এর owner হয় এবং তার সংশ্লিষ্ট group-এর সঙ্গে যুক্ত হয়।

## 2. তিন ধরনের Permission

| Permission | Symbol | কাজ                          |
| ---------- | ------ | ---------------------------- |
| Read       | `r`    | File-এর content পড়া          |
| Write      | `w`    | File-এর content পরিবর্তন করা |
| Execute    | `x`    | File execute করা             |

এই permission-গুলো আলাদাভাবে owner, group এবং others-এর জন্য নির্ধারণ করা যায়।

### Directory-এর ক্ষেত্রে `execute` permission

Directory-এর ক্ষেত্রে `x`-এর অর্থ file execute করা নয়; বরং directory-এর ভেতর দিয়ে navigate বা traverse করতে পারা।

- `r`: Directory-এর entry বা নামগুলো list করতে সাহায্য করে।
- `w`: Directory-তে file বা subdirectory তৈরি, delete ও rename করতে সাহায্য করে; সাধারণত traversal-এর জন্য `x`-ও প্রয়োজন।
- `x`: Directory-তে প্রবেশ বা traverse করতে দেয় এবং permission থাকলে ভেতরের entry access করতে সাহায্য করে।

`x` না থাকলে directory-এর ভেতর দিয়ে traverse করা যায় না, user-এর অন্য access থাকলেও।

উদাহরণ:

```
cry0l1t3@htb[/htb]$ ls -l

drw-rw-r-- 3 cry0l1t3 cry0l1t3   4096 Jan 12 12:30 scripts

cry0l1t3@htb[/htb]$ ls -al mydirectory/

ls: cannot access 'mydirectory/script.sh': Permission denied
ls: cannot access 'mydirectory/..': Permission denied
ls: cannot access 'mydirectory/subdirectory': Permission denied
ls: cannot access 'mydirectory/.': Permission denied
total 0
d????????? ? ? ? ?            ? .
d????????? ? ? ? ?            ? ..
-????????? ? ? ? ?            ? script.sh
d????????? ? ? ? ?            ? subdirectory
```

এখানে directory-তে প্রয়োজনীয় execute permission না থাকায় তার contents access করতে সমস্যা হচ্ছে।

মনে রাখবে: Directory-তে `x` থাকলেই ভেতরের file execute বা modify করা যায় না। File execute করতে সেই file-এ `x` দরকার। Directory-এর content তৈরি, delete বা rename করতে directory-তে `w` এবং সাধারণত `x` প্রয়োজন।

## 3. `ls -l` দিয়ে Permission বোঝা

উদাহরণ:

```
cry0l1t3@htb[/htb]$ ls -l /etc/passwd

- rwx rw- r--   1 root root 1641 May  4 23:42 /etc/passwd
- --- --- ---   |  |    |    |   |__________|
|  |   |   |    |  |    |    |        |_ Date
|  |   |   |    |  |    |    |__________ File Size
|  |   |   |    |  |    |_______________ Group
|  |   |   |    |  |____________________ User
|  |   |   |    |_______________________ Number of hard links
|  |   |   |_ Permission of others (read)
|  |   |_____ Permissions of the group (read, write)
|  |_________ Permissions of the owner (read, write, execute)
|____________ File type (- = File, d = Directory, l = Link, ... )
```

Permission string-এর গঠন:

`- | rwx | rw- | r--`

- প্রথম character `-`: Regular file। `d` হলে directory, `l` হলে link।
- `rwx`: Owner-এর permissions।
- `rw-`: Group-এর permissions।
- `r--`: Others-এর permissions।

## 4. `chmod` দিয়ে Permission পরিবর্তন

`chmod` command দিয়ে file বা directory-এর permissions পরিবর্তন করা হয়।

### Symbolic mode

| Symbol | অর্থ                         |
| ------ | ---------------------------- |
| `u`    | Owner বা user                |
| `g`    | Group                        |
| `o`    | Others                       |
| `a`    | All users                    |
| `+`    | Permission যোগ করা           |
| `-`    | Permission সরানো             |
| `=`    | নির্দিষ্ট permission সেট করা |

প্রথমে file-এর permission দেখি:

```
ls -l shell
```

Output:

```
-rwxr-x--x   1 cry0l1t3 htbteam 0 May  4 22:12 shell
```

সব user-এর জন্য read permission যোগ করা:

```
chmod a+r shell && ls -l shell
```

Output:

```
-rwxr-xr-x   1 cry0l1t3 htbteam 0 May  4 22:12 shell
```

এখানে `a+r` মানে owner, group ও others—সবার জন্য `r` যোগ করা।

### Octal mode

Octal number ব্যবহার করেও permissions সেট করা যায়।

```
chmod 754 shell && ls -l shell
```

Output:

```
-rwxr-xr--   1 cry0l1t3 htbteam 0 May  4 22:12 shell
```

### Permission-এর numeric value

| Permission     | Value |
| -------------- | ----- |
| `r`            | 4     |
| `w`            | 2     |
| `x`            | 1     |
| Permission নেই | 0     |

প্রতিটি group-এর value যোগ করে octal digit পাওয়া যায়।

```
Binary Notation:                4 2 1  |  4 2 1  |  4 2 1
----------------------------------------------------------
Binary Representation:          1 1 1  |  1 0 1  |  1 0 0
----------------------------------------------------------
Octal Value:                      7    |    5    |    4
----------------------------------------------------------
Permission Representation:      r w x  |  r - x  |  r - -
```

`754`-এর অর্থ:

- `7 = 4 + 2 + 1 = rwx` → Owner
- `5 = 4 + 1 = r-x` → Group
- `4 = r--` → Others

তাই `chmod 754 shell` দিলে permission হয় `rwxr-xr--`।

## 5. `chown` দিয়ে Owner ও Group পরিবর্তন

File বা directory-এর owner এবং group পরিবর্তন করতে `chown` ব্যবহার করা হয়।

Syntax:

```
chown <user>:<group> <file/directory>
```

উদাহরণ:

```
chown root:root shell && ls -l shell
```

Output:

```
-rwxr-xr--   1 root root 0 May  4 22:12 shell
```

এখানে `shell` file-এর owner ও group—দুটিই `root` করা হয়েছে।

## 6. SUID ও SGID

সাধারণ permission ছাড়াও Linux-এ special permission আছে:

- SUID (Set User ID)
- SGID (Set Group ID)

এগুলো নির্দিষ্ট program execute করার সময় file-এর owner বা group-এর privilege ব্যবহার করতে পারে।

- SUID সেট থাকলে program সাধারণত file-এর owner-এর effective user ID নিয়ে চলে।
- SGID সেট থাকলে executable program সাধারণত file-এর group-এর effective group ID নিয়ে চলে।

Permission display-তে সাধারণ `x`-এর জায়গায় `s` দেখা যেতে পারে।

### Security risk

SUID বা SGID ভুলভাবে সেট করা হলে privilege escalation-এর ঝুঁকি তৈরি হতে পারে।

উদাহরণ হিসেবে, `journalctl`-এ shell launch করার সুবিধা আছে। এটিকে অসতর্কভাবে SUID root permission দেওয়া হলে user সেটি চালিয়ে root privilege-সহ shell পেতে পারে।

GTFOBins reference: [https://gtfobins.github.io/gtfobins/journalctl/](https://gtfobins.github.io/gtfobins/journalctl/?utm_source=chatgpt.com)

মূল কথা: কোনো program-এ SUID/SGID আছে কি না এবং সেটি কীভাবে কাজ করে, তা security assessment-এর সময় পরীক্ষা করা গুরুত্বপূর্ণ।

## 7. Sticky Bit

Shared directory-তে অন্য user-এর file delete বা rename করা আটকাতে Sticky Bit ব্যবহার করা হয়।

Sticky bit থাকা directory-তে সাধারণত:

- File-এর owner নিজের file delete বা rename করতে পারে।
- Directory-এর owner file delete বা rename করতে পারে।
- `root` file delete বা rename করতে পারে।
- অন্য user directory access করতে পারলেও সাধারণত অন্যের file delete বা rename করতে পারে না।

উদাহরণ:

```
cry0l1t3@htb[/htb]$ ls -l

drw-rw-r-t 3 cry0l1t3 cry0l1t3   4096 Jan 12 12:30 scripts
drw-rw-r-T 3 cry0l1t3 cry0l1t3   4096 Jan 12 12:32 reports
```

এখানে দুইটি directory-তেই sticky bit আছে, কিন্তু `t` ও `T`-এর পার্থক্য হলো:

- Lowercase `t`: Sticky bit সেট এবং others-এর execute (`x`) permission আছে।
- Uppercase `T`: Sticky bit সেট, কিন্তু others-এর execute (`x`) permission নেই।

`T` থাকলে others directory traverse করতে পারে না। তাই তাদের directory-এর contents access করার ক্ষমতাও সীমিত হয়।

## 8. Quick Revision

| Command / Concept       | কাজ                                                     |
| ----------------------- | ------------------------------------------------------- |
| `r`                     | Read                                                    |
| `w`                     | Write                                                   |
| `x`                     | File execute; directory traverse                        |
| `chmod`                 | Permission পরিবর্তন                                     |
| `chmod a+r file`        | সবার জন্য read permission যোগ                           |
| `chmod 754 file`        | Owner `rwx`, group `r-x`, others `r--`                  |
| `chown user:group file` | Owner ও group পরিবর্তন                                  |
| SUID                    | Program owner-এর effective user privilege-এ চলতে পারে   |
| SGID                    | Program group-এর effective group privilege-এ চলতে পারে  |
| Sticky bit              | Shared directory-তে অন্যের file delete/rename সীমিত করে |
| `t`                     | Sticky bit + others-এর execute permission               |
| `T`                     | Sticky bit + others-এর execute permission নেই           |

সবচেয়ে গুরুত্বপূর্ণ: `chmod` permission পরিবর্তন করে, `chown` owner/group পরিবর্তন করে, আর SUID, SGID ও Sticky Bit বিশেষ access behavior নিয়ন্ত্রণ করে।
