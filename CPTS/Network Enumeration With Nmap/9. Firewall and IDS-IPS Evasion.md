# Firewall and IDS/IPS Evasion

## 1. Firewall

Firewall হলো unauthorized connection থেকে network-কে রক্ষা করার security measure।

Firewall software এবং/অথবা hardware দিয়ে তৈরি হতে পারে। এটি network traffic monitor করে এবং নির্ধারিত rules অনুযায়ী connection handle করে।

প্রতিটি packet পরীক্ষা করে সিদ্ধান্ত নেয়:

- `Passed` — Packet যেতে দেওয়া হবে।
- `Dropped` — Packet ignore করা হবে।
- `Blocked` — Packet আটকে দেওয়া হবে।

এর উদ্দেশ্য হলো সম্ভাব্য বিপজ্জনক unwanted connections প্রতিরোধ করা।

## 2. IDS/IPS

দুটিই software-based security components।

| System | কাজ                                                               |
| ------ | ----------------------------------------------------------------- |
| `IDS`  | Network scan করে potential attack শনাক্ত, analyze এবং report করে। |
| `IPS`  | Potential attack শনাক্ত হলে নির্ধারিত defensive action নেয়।       |

IDS/IPS attack শনাক্ত করতে Pattern Matching এবং Signatures ব্যবহার করে।

যেমন: Service detection scan-এর নির্দিষ্ট pattern শনাক্ত হলে IPS connection attempt prevent করতে পারে।

### Firewall Rules শনাক্ত করা

Port `filtered` দেখানোর বিভিন্ন কারণ থাকতে পারে। সাধারণত firewall-এর rules অনুযায়ী packet:

- `Dropped`: Packet ignore করা হয়, কোনো response ফেরত আসে না।
- `Rejected`: Explicit response ফেরত আসে।

Rejected packet-এর response:

- TCP: `RST` flag ফেরত দেয়।
- ICMP: বিভিন্ন error code ফেরত দিতে পারে।

ICMP error types:

- `Net Unreachable`
- `Net Prohibited`
- `Host Unreachable`
- `Host Prohibited`
- `Port Unreachable`
- `Proto Unreachable`

### TCP ACK Scan (`-sA`)

TCP ACK scan (`-sA`) সাধারণ SYN (`-sS`) বা Connect (`-sT`) scan-এর তুলনায় firewall ও IDS/IPS-এর জন্য filter করা কঠিন।

কারণ:

- ACK scan শুধু `ACK` flag-সহ TCP packet পাঠায়।
- Port open বা closed যাই হোক, host `RST` flag দিয়ে response দেয়।
- Firewall সাধারণত external network থেকে আসা নতুন `SYN` connection block করে।
- কিন্তু `ACK` packet অনেক সময় pass করে, কারণ firewall বুঝতে পারে না connection প্রথমে external network নাকি internal network থেকে establish হয়েছিল।

## 3. Detect IDS/IPS

Firewall rules-এর তুলনায় IDS/IPS শনাক্ত করা কঠিন, কারণ এগুলো passive traffic monitoring systems।

- IDS host-গুলোর মধ্যে connection পরীক্ষা করে। নির্দিষ্ট content বা pattern পাওয়া গেলে administrator-কে notify করে।
- IPS administrator-এর configured rules অনুযায়ী potential attack automatically prevent করে।
- IDS এবং IPS আলাদা application; IPS হলো IDS-এর complement।

### IDS/IPS শনাক্ত করার পদ্ধতি

Penetration test-এর সময় বিভিন্ন IP address-সহ কয়েকটি VPS ব্যবহার করার পরামর্শ দেওয়া হয়েছে।

যদি administrator potential attack শনাক্ত করে, তাহলে প্রথমে attack-এর source IP block করতে পারে। ফলে ওই IP দিয়ে target network access করা যাবে না। ISP-কেও contact করে Internet access block করা হতে পারে।

IDS:

- IDS সাধারণত administrator-কে potential attack শনাক্ত করতে সাহায্য করে।
- Administrator এরপর connection কীভাবে handle করবে তা ঠিক করে।
- একটি port ও তার service aggressively scan করে security measures trigger করা যায়।
- এরপর security measures নেওয়া হচ্ছে কি না দেখে network-এ monitoring application আছে কি না বোঝা যায়।

IPS:

- একটি VPS থেকে scan করা যায়।
- কোনো সময় VPS block হয়ে target network access হারালে বোঝা যায় administrator security measures নিয়েছে।
- এরপর অন্য VPS দিয়ে penetration test চালানো যেতে পারে।

মূল বিষয়: Scan যতটা সম্ভব quiet রাখতে হবে এবং target network ও services-এর সাথে interaction disguise করতে হবে। নাহলে IPS আমাদের block করতে পারে।

## 4. Decoys

কিছু ক্ষেত্রে administrator নির্দিষ্ট region বা subnet block করে রাখে। আবার IPS-ও আমাদের block করতে পারে।

এমন পরিস্থিতিতে Nmap-এর Decoy scan (`-D`) ব্যবহার করা যায়।

এটি IP header-এ একাধিক random IP address যোগ করে packet-এর প্রকৃত source লুকানোর চেষ্টা করে।

- `RND:5` দিলে ৫টি random IP address generate হয়।
- IP-গুলো colon (`:`) দিয়ে আলাদা করা যায়।
- আমাদের real IP address random IP-গুলোর মধ্যে randomly বসানো হয়।
- Example-এ real IP দ্বিতীয় position-এ রয়েছে।
- Decoy IP-গুলো alive হওয়া গুরুত্বপূর্ণ। না হলে SYN-flooding security mechanism-এর কারণে target service unreachable হতে পারে।

`-S` দিয়ে source IP address specify করা হয়।

- SYN scan

## 5. DNS Proxying

By default, Nmap target সম্পর্কে অতিরিক্ত information পাওয়ার জন্য reverse DNS resolution করে, যদি অন্যভাবে specify করা না হয়।

DNS query সাধারণত `UDP port 53` দিয়ে পাঠানো হয়।

আগে `TCP port 53` মূলত DNS server-এর মধ্যে `Zone transfers` অথবা `512 bytes`-এর বেশি data transfer-এর জন্য ব্যবহার হতো। IPv6 এবং DNSSEC-এর প্রসারের কারণে এখন TCP port 53 দিয়েও বেশি DNS request হচ্ছে।

### Custom DNS Server

Nmap দিয়ে নিজের DNS server specify করা যায়:

`--dns-server <ns>,<ns>`

DMZ-তে থাকলে এটি গুরুত্বপূর্ণ হতে পারে। কারণ কোম্পানির DNS server সাধারণত Internet-এর DNS server-এর তুলনায় বেশি trusted হয়। তাই internal network-এর host-এর সাথে interact করতে company DNS server ব্যবহার করা যেতে পারে।

আরেকটি উপায় হলো scan-এর source port হিসেবে `TCP port 53` ব্যবহার করা:

`--source-port`

Administrator যদি firewall দিয়ে এই port control করে, কিন্তু IDS/IPS সঠিকভাবে filter না করে, তাহলে TCP packet trusted হিসেবে pass হতে পারে।

এখন firewall TCP port `53` accept করছে। তাই IDS/IPS-এর filtering-ও অন্য port-এর তুলনায় দুর্বল কি না পরীক্ষা করা যায়।
