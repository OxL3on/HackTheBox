# Host and Port Scanning

## 1. Overview

Host alive শনাক্ত করার পর target system সম্পর্কে আরও বিস্তারিত information সংগ্রহ করতে হবে।

যে information প্রয়োজন:

- Open ports এবং তাদের services
- Service versions
- Services থেকে পাওয়া information
- Operating system

একটি scanned port-এর মোট ৬টি state হতে পারে।

| State               | Description                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------------- |
| `open`              | Port-এর সঙ্গে connection establish হয়েছে। এটি TCP connection, UDP datagram অথবা SCTP association হতে পারে।     |
| `closed`            | TCP response-এ `RST` flag পাওয়া যায়। এটি target alive কিনা জানতেও সাহায্য করতে পারে।                           |
| `filtered`          | Target থেকে response না পাওয়া গেলে অথবা error code এলে Nmap বুঝতে পারে না port open নাকি closed।               |
| `unfiltered`        | শুধু TCP-ACK scan-এ দেখা যায়। Port accessible, কিন্তু open নাকি closed তা নির্ধারণ করা যায় না।                 |
| `open\\|filtered`   | নির্দিষ্ট port থেকে response না পেলে Nmap এই state দেখায়। Firewall বা packet filter port-টি protect করতে পারে। |
| `closed\\|filtered` | শুধু IP ID idle scan-এ দেখা যায়। Port closed নাকি firewall দিয়ে filtered, তা নির্ধারণ করা যায় না।              |

## 2. Discovering Open TCP Ports

Defaultভাবে Nmap `-sS` SYN scan দিয়ে top 1000 TCP ports scan করে।

- `-sS` default হয় যখন Nmap root হিসেবে চালানো হয়। কারণ raw TCP packet তৈরির জন্য socket permission প্রয়োজন।
- Root না হলে defaultভাবে TCP Connect scan (`-sT`) চলে।
- Port ও scan method specify না করলে Nmap automatically এগুলো নির্ধারণ করে।

Port নির্ধারণের পদ্ধতি:

| Option                | Description                                                   |
| --------------------- | ------------------------------------------------------------- |
| `-p 22,25,80,139,445` | নির্দিষ্ট port-গুলো scan করে                                  |
| `-p 22-445`           | Port range scan করে                                           |
| `--top-ports=10`      | Nmap database-এর সবচেয়ে frequently used top 10 ports scan করে |
| `-p-`                 | সব port scan করে                                              |
| `-F`                  | Fast scan; top 100 ports scan করে                             |

### Nmap - Trace the Packets

Packet trace করলে দেখা যায় TCP port `21`-এ target আমাদের `RST` flag পাঠিয়েছে।

SYN scan আরও পরিষ্কারভাবে দেখতে ICMP Echo Request (`-Pn`), DNS resolution (`-n`) এবং ARP ping (`--disable-arp-ping`) বন্ধ করা হয়।

```
sudo nmap 10.129.2.28 -p 21 --packet-trace -Pn -n --disable-arp-ping
```

Output:

```

RCVD (0.0573s) TCP 10.129.2.28:21 > 10.10.14.2:63090 RA ttl=64 id=0 iplen=40  seq=0 win=0
Nmap scan report for 10.129.2.28
Host is up (0.014s latency).

PORT   STATE  SERVICE
21/tcp closed ftp
MAC Address: DE:AD:00:00:BE:EF (Intel Corporate)

Nmap done: 1 IP address (1 host up) scanned in 0.07 seconds
```

Scanning Options:

| Option               | Description                          |
| -------------------- | ------------------------------------ |
| `10.129.2.28`        | নির্দিষ্ট target scan করে            |
| `-p 21`              | শুধু নির্দিষ্ট port scan করে         |
| `--packet-trace`     | পাঠানো ও receive করা সব packet দেখায় |
| `-n`                 | DNS resolution বন্ধ করে              |
| `--disable-arp-ping` | ARP ping বন্ধ করে                    |

Packet বোঝা:

আমরা `10.10.14.2` থেকে target `10.129.2.28`-এর port `21`-এ `SYN` flag (`S`) পাঠিয়েছি।

Target থেকে `RST` এবং `ACK` flag (`RA`) এসেছে।

- `ACK`: TCP packet receive হওয়ার acknowledgement।
- `RST`: TCP session terminate করে।

### Request

| Message                                                      | Description                                  |
| ------------------------------------------------------------ | -------------------------------------------- |
| `SENT (0.0429s)`                                             | Nmap target-এ packet পাঠিয়েছে                |
| `TCP`                                                        | Target port-এর সঙ্গে interaction-এর protocol |
| `10.10.14.2:63090 >`                                         | আমাদের IPv4 address এবং source port          |
| `10.129.2.28:21`                                             | Target IPv4 address এবং target port          |
| `S`                                                          | পাঠানো TCP packet-এর SYN flag                |
| `ttl=56 id=57322 iplen=44  seq=1699105818 win=1024 mss 1460` | অতিরিক্ত TCP Header parameters               |

### Response

| Message                             | Description                                   |
| ----------------------------------- | --------------------------------------------- |
| `RCVD (0.0573s)`                    | Target থেকে packet receive হয়েছে              |
| `TCP`                               | ব্যবহৃত protocol                              |
| `10.129.2.28:21 >`                  | Target-এর IPv4 address এবং reply source port  |
| `10.10.14.2:63090`                  | আমাদের IPv4 address এবং যে port-এ reply এসেছে |
| `RA`                                | TCP packet-এর RST ও ACK flags                 |
| `ttl=64 id=0 iplen=40  seq=0 win=0` | অতিরিক্ত TCP Header parameters                |

## 3. Connect Scan

Nmap-এর [TCP Connect Scan](https://nmap.org/book/scan-methods-connect-scan.html?utm_source=chatgpt.com) (`-sT`) TCP three-way handshake ব্যবহার করে port open নাকি closed তা নির্ধারণ করে।

কাজের পদ্ধতি:

1. Target port-এ `SYN` packet পাঠায়।
2. `SYN-ACK` পেলে port `open`।
3. `RST` পেলে port `closed`।

Connect Scan-এর বৈশিষ্ট্য:

- Full TCP three-way handshake complete করে।
- Port state নির্ধারণে highly accurate।
- এটি stealthy নয়; বরং least stealthy technique-গুলোর একটি।
- Full connection establish হওয়ায় অধিকাংশ system-এ logs তৈরি হয়।
- Modern IDS/IPS সহজেই detect করতে পারে।
- Accuracy priority হলে এবং service-এ significant disruption না করে network map করতে হলে useful।
- Normal client connection-এর মতো আচরণ করায় service error বা instability হওয়ার সম্ভাবনা intrusive scan-এর তুলনায় কম।
- তাই একে কখনো কখনো more "polite" scan বলা হয়।

SYN Scan-এর সঙ্গে পার্থক্য:

- SYN Scan বা half-open scan full handshake complete করে না।
- Initial SYN পাঠানোর পর connection incomplete রাখে।
- ফলে connection logs trigger হওয়ার সম্ভাবনা কমে।
- তবে advanced IDS/IPS এই scan-ও detect করতে পারে।

### Connect Scan on TCP Port 443


## 4. Filtered Ports

কোনো port `filtered` দেখালে এর একাধিক কারণ থাকতে পারে।

সাধারণত Firewall নির্দিষ্ট connection handle করার জন্য rules ব্যবহার করে। Packet দুইভাবে handle হতে পারে:

- `dropped`
- `rejected`

Dropped হলে:

- Target থেকে কোনো response আসে না।
- Nmap-এর default retry rate (`--max-retries`) হলো `10`।
- Nmap request আবার পাঠায়, যাতে বোঝা যায় আগের packet ভুলভাবে handle হয়েছিল কিনা।

### Firewall Packet Drop করলে

আগের scan-এ TCP port `139` filtered ছিল। এবার packet কীভাবে handle হচ্ছে তা দেখতে ICMP Echo Request (`-Pn`), DNS resolution (`-n`) এবং ARP ping (`--disable-arp-ping`) বন্ধ করা হয়েছে।

## 5. Discovering Open UDP Ports

কিছু system administrator TCP port filter করলেও UDP port filter করতে ভুলে যান।

UDP একটি `stateless protocol`। TCP-এর মতো three-way handshake প্রয়োজন হয় না।

- UDP-তে acknowledgement পাওয়া যায় না।
- ফলে timeout অনেক বেশি হয়।
- তাই UDP scan (`-sU`) TCP SYN scan (`-sS`)-এর তুলনায় অনেক slow।

### UDP Response বোঝা

UDP scan-এর একটি অসুবিধা হলো অনেক সময় কোনো response পাওয়া যায় না।

- Nmap scanned UDP port-এ empty datagram পাঠায়।
- Response না এলে UDP packet আদৌ পৌঁছেছে কিনা বোঝা যায় না।
- UDP port `open` হলে application configured থাকলেই response পাওয়া যায়।

| `--reason`           | Port-এর নির্দিষ্ট state-এর কারণ দেখায় |

## 6. Version Scan

Open port থেকে আরও information পেতে `-sV` ব্যবহার করা হয়।

এটি identify করতে পারে:

- Service version
- Service name
- Target সম্পর্কে অতিরিক্ত details
