**Direct Object Reference Locations**

* **URL Parameters:** Look for explicit identifiers (e.g., `?uid=1`, `?filename=file_1.pdf`).
* **API Endpoints:** RESTful paths often contain IDs (e.g., `/api/users/1/profile`).
* **HTTP Headers:** Examine cookies and custom headers for user or session IDs.
* **Exploitation:** Manually increment values (`?uid=2`, `?uid=3`) or use a fuzzer (like wfuzz or Burp Intruder) to iterate through thousands of variations to find accessible, unauthorized data.

**Front-End Code Analysis (AJAX Calls)**
Modern frameworks frequently load all JavaScript functions to the client-side, relying on the UI to simply hide admin buttons from standard users. Review the front-end source code for unused AJAX calls that reveal hidden parameters or endpoints.

```javascript
function changeUserPassword() {
    $.ajax({
        url:"change_password.php",
        type: "post",
        dataType: "json",
        data: {uid: user.uid, password: user.password, is_admin: is_admin},
        success:function(result){
            //
        }
    });
}

```

*Exploitation:* If you find a hidden function like the one above, manually trigger it in the browser console or replicate the HTTP request using a proxy to see if the backend enforces access controls.

**Deobfuscating Hashed & Encoded References**
Developers often mistake obfuscation for security. If a reference looks randomized, test it for common encoding or hashing.

* **Encoding (e.g., Base64):** Identifiable by character sets (and often trailing `=` signs).
* *Example:* `?filename=ZmlsZV8xMjMucGRm` decodes to `file_123.pdf`.
* *Exploitation:* Base64-encode your target (`file_124.pdf` ➔ `ZmlsZV8xMjQucGRm`) and inject it into the request.


* **Hashing (e.g., MD5):** Check the front-end JavaScript to see if the hashing logic is exposed client-side.

```javascript
$.ajax({
    url:"download.php",
    type: "post",
    dataType: "json",
    data: {filename: CryptoJS.MD5('file_1.pdf').toString()},
    success:function(result){
        //
    }
});

```

*Exploitation:* Identify the hash algorithm (via source code review or hash identifier tools), calculate the hash for your target object, and send the request.

**Comparing User Roles (Cross-Session Testing)**
To map out complex access controls and parameter structures, register two separate accounts (User A and User B).

1. Capture a request containing sensitive data or privileged actions from User A:

```json
{
  "attributes" : 
    {
      "type" : "salary",
      "url" : "/services/data/salaries/users/1"
    },
  "Id" : "1",
  "Name" : "User1"
}

```

2. *Exploitation:* Inject User A's API parameters and object references into an HTTP request authenticated with User B's session cookies/tokens. If the application returns User A's data to User B, it is vulnerable to IDOR.
