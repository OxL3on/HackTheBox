# Intro to XXE - [LINK](https://academy.hackthebox.com/app/module/134/section/1203)


XML External Entity (XXE) Injection occurs when a web application processes user-supplied XML input without properly disabling external entity parsing. Because XML allows defining custom variables (entities) that can pull data from local files or remote URLs, an attacker can manipulate this feature to disclose sensitive local files, map internal networks, or execute Denial of Service (DoS) attacks.

## XML Structure Basics

Extensible Markup Language (XML) is a markup language designed for data transfer and storage, representing data in hierarchical element trees.

| Key | Definition | Example |
| --- | --- | --- |
| **Declaration** | The first line defining the XML version and encoding. | `<?xml version="1.0" encoding="UTF-8"?>` |
| **Tag** | The markers outlining an XML document, wrapped in `<` and `>`. | `<date>` |
| **Element** | The root or child data container, consisting of tags and the value inside. | `<date>01-01-2022</date>` |
| **Attribute** | Optional specifications stored inside the tag itself. | `version="1.0"` |
| **Entity** | XML variables, referenced in the document wrapped with `&` and `;`. | `&lt;` (for `<`) or `&company;` |

*Note: Special characters like `<`, `>`, `&`, and `"` must be replaced with their corresponding entity references (e.g., `&lt;`, `&gt;`, `&amp;`, `&quot;`) when used as raw data.*

## Document Type Definition (DTD)

A Document Type Definition (DTD) defines the accepted structure and elements of an XML document. DTDs can be defined directly within the XML file (inline) or referenced externally.

**Inline DTD Definition:**

```xml
<!DOCTYPE email [
  <!ELEMENT email (date, time, sender, recipients, body)>
  <!ELEMENT recipients (to, cc?)>
  <!ELEMENT date (#PCDATA)> <!-- #PCDATA means raw parsed character data -->
]>

```

**External DTD Referencing (The `SYSTEM` Keyword):**
External DTDs are loaded using the `SYSTEM` keyword, which instructs the XML parser to fetch the structure from a local path or URL.

```xml
<!-- Referencing a local file -->
<!DOCTYPE email SYSTEM "email.dtd">

<!-- Referencing a remote URL -->
<!DOCTYPE email SYSTEM "http://inlanefreight.com/email.dtd">

```

## XML Entities (The Core Vulnerability)

XML Entities act as custom variables defined within the DTD. Once defined, they can be referenced anywhere in the XML document using `&entityname;`.

**1. Internal Entities:**
Store static, hardcoded string values.

```xml
<!DOCTYPE email [
  <!ENTITY company "Inlane Freight">
]>
<!-- Usage: &company; becomes "Inlane Freight" -->

```

**2. External Entities (XXE Vector):**
By combining the `ENTITY` definition with the `SYSTEM` keyword, you can instruct the XML parser to fetch the variable's value from an external source (like a local server file or a remote HTTP request).

```xml
<!DOCTYPE email [
  <!-- Fetching via HTTP -->
  <!ENTITY company SYSTEM "http://localhost/company.txt">
  
  <!-- Fetching a local system file -->
  <!ENTITY signature SYSTEM "file:///var/www/html/signature.txt">
]>

```

*The Exploit:* When the application parses the XML and encounters `&signature;`, it will read the contents of `/var/www/html/signature.txt` from its own local filesystem and embed it directly into the XML structure. If the application reflects that XML back to the user, the local file is successfully disclosed.
