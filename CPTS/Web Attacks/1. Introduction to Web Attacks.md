Web applications represent the most frequent attack surface for modern businesses, often serving as the initial entry point for compromising internal networks. This module focuses on three highly prevalent web vulnerabilities that arise from poor configuration, flawed access controls, and insecure data parsing.

## Core Web Attacks Overview

While specific commands and payloads will be covered in their respective deep-dive sections, you must understand the foundational mechanisms and impacts of these three attacks:

| Attack Type | Core Mechanism | Primary Impact |
| --- | --- | --- |
| **HTTP Verb Tampering** | Sending HTTP requests using unexpected or non-standard methods (verbs) to a web server that fails to restrict them properly. | Bypassing web application authorization mechanisms and subverting security controls designed for standard `GET` or `POST` requests. |
| **Insecure Direct Object References (IDOR)** | Exploiting a lack of robust back-end access controls when an application exposes direct references to internal objects (like sequential user IDs, file names, or database keys). | Unauthorized viewing, editing, or deleting of other users' private data and files by manipulating the exposed reference ID in the request. |
| **XML External Entity (XXE) Injection** | Supplying maliciously crafted XML data to a web application that relies on outdated or insecurely configured XML parsing libraries. | Arbitrary local file disclosure (e.g., reading source code, config files, passwords), server credential theft, and potential Remote Code Execution (RCE). |

> **Strategic Value:** Exploiting vulnerabilities like XXE often allows you to retrieve the application's source code. This successfully transitions an engagement from a "Blackbox" assessment into a "Whitebox" assessment, drastically increasing your ability to find deeper vulnerabilities.
