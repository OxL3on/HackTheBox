# Bypassing Security Filters - [LINK](https://academy.hackthebox.com/app/module/134/section/1178)


Bypassing security filters via HTTP Verb Tampering occurs when a developer applies input sanitization to a specific HTTP method's variable array (like `$_GET`) but executes the backend function using a generic array (like `$_REQUEST`). This allows you to completely bypass the security filter by transmitting your payload through an alternate, unfiltered HTTP method.

**The Attack Workflow: Filter Evasion & Command Injection**

1. **Identify the Filter:** Trigger the security filter.
Attempt to inject a special character into an input field (e.g., submitting `test;` as a file name). If the application uses a targeted filter, it will return an error such as "Malicious Request Denied!" while blocking the request.


2. **Craft the Injection Payload:** Prepare the test payload.
Construct a payload to test for the underlying vulnerability the filter was trying to protect against. For Command Injection, use a payload that creates two files sequentially:
`file1; touch file2;`


3. **Intercept and Tamper the Verb:**
Capture the blocked request in a proxy tool like Burp Suite. If the original request was a `GET` request, right-click and select **Change Request Method** to switch it to a `POST` request (or vice versa).


4. **Execute and Verify:** Confirm the underlying exploit.
Forward the tampered request. Because the `POST` method lacks the sanitization applied to the `GET` method, the request passes through the filter. Verify success by checking the application—if both `file1` and `file2` were successfully created, you have achieved Command Injection.
