# XXE Prevention - [LINK](https://academy.hackthebox.com/app/module/134/section/1218)

Unlike other input validation vulnerabilities (like XSS or SQLi) that rely heavily on manual secure coding practices, XXE is primarily a configuration and dependency issue. It occurs when applications use outdated XML parsers that allow external entity resolution by default.

## 1. Avoid Outdated Components and Libraries

The most effective way to prevent XXE is to ensure the underlying XML parsing libraries are up to date and utilizing secure defaults.

* **Deprecated Functions:** Avoid using unsafe functions that allow developers to toggle external entities insecurely. For example, PHP's `libxml_disable_entity_loader` is deprecated as of PHP 8.0.0 because relying on it is inherently unsafe.
* **Secondary Processors:** Update all dependencies that might parse XML under the hood, including:
* API libraries (e.g., SOAP implementations)
* Image processors (e.g., SVG parsers)
* Document processors (e.g., PDF generation libraries)


* **Reference:** Always consult the **OWASP XXE Prevention Cheat Sheet** for language-specific guidance on identifying vulnerable libraries and implementing safe parsing functions.

## 2. Implement Secure XML Configurations

If you cannot immediately update a library, or as a defense-in-depth measure, you must manually harden the XML parser's configuration. Ensure the parser is explicitly configured to:

| Security Configuration | Purpose |
| --- | --- |
| **Disable Custom DTDs** | Prevents the parser from accepting inline `DOCTYPE` definitions entirely. |
| **Disable External Entities** | Stops the `SYSTEM` keyword from resolving local files or remote URLs. |
| **Disable Parameter Entities** | Prevents the use of `%entity;` inside DTDs (mitigating advanced CDATA/OOB exfiltration). |
| **Disable XInclude** | Disables an alternative XML feature used to build documents from external files. |
| **Prevent Entity Reference Loops** | Protects the server memory from Denial of Service (DoS / Billion Laughs) attacks. |

## 3. Architecture and Defense-in-Depth

* **Disable Verbose Errors:** Ensure proper exception handling is in place and disable the display of runtime errors (like PHP parser errors) in production. This completely neutralizes **Error-Based XXE** attacks.
* **Format Migration:** Whenever possible, avoid XML and XML-based APIs (like SOAP) entirely. Migrate to JSON and RESTful APIs, which are not susceptible to XXE.
* **Web Application Firewalls (WAFs):** Deploy a WAF to detect and block common XXE payloads in incoming HTTP requests. However, treat this only as a supplementary layer—WAFs can be bypassed, so the backend parser must still be secured.
