
# Other Upload Attacks 

Beyond standard arbitrary and limited file uploads, there are several advanced techniques that exploit how a web application processes, stores, or reflects file names and uploaded content.

## 1. Injections in File Name

If an uploaded file's name is reflected on a webpage or processed by the backend database/OS without proper sanitization, we can inject payloads directly into the filename.

* **Command Injection:** If the server handles the file using OS commands (e.g., `mv file /tmp`), we can achieve RCE.
* **Payloads:** `file$(whoami).jpg` OR `file`whoami`.jpg` OR `file.jpg||whoami`


* **Cross-Site Scripting (XSS):** If the filename is displayed back to the user, we can execute JavaScript.
* **Payload:** `<script>alert(window.origin);</script>`


* **SQL Injection (SQLi):** If the filename is insecurely inserted into a backend database query.
* **Payload:** `file';select+sleep(5);--.jpg`



## 2. Upload Directory Disclosure

When the web app does not provide a link to the uploaded file, we must find the uploads directory to trigger our payloads.

* **Source Code Disclosure:** Use LFI or XXE (as discussed in previous sections) to read the source code and find the directory or file naming scheme.
* **Forcing Error Messages:** Triggering backend errors often leaks the upload path in the stack trace or error response.
* Upload a file with a name that already exists.
* Send two identical upload requests simultaneously (race condition).
* Upload a file with an overly long name (e.g., 5,000 characters) to break the application's string handling.



## 3. Windows-specific Attacks

Windows environments have legacy features and reserved keywords that can be exploited to cause errors (for path disclosure), overwrite files, or cause DoS.

* **Reserved Characters:** Using characters reserved for wildcards/special uses can cause errors if not quoted or sanitized.
* **Payloads:** `|`, `<`, `>`, `*`, or `?`


* **Reserved Names:** Windows prevents creating files with specific reserved system names. Uploading these will cause a write error, often disclosing the directory.
* **Payloads:** `CON`, `COM1`, `LPT1`, or `NUL`


* **Windows 8.3 Filename Convention:** Legacy Windows systems truncated long filenames to 8 characters using a Tilde (`~`) and a digit. Modern Windows still supports this for backward compatibility.
* *Example:* `hackthebox.txt` becomes `HAC~1.TXT` (or `HAC~2.TXT` if `HAC~1` exists).
* **Exploitation:** We can use this convention to overwrite existing configuration files or bypass extension filters. For instance, uploading a file named `WEB~1.CON` could overwrite the application's `web.conf` file.



## 4. Advanced File Upload Attacks

If a web application automatically processes an uploaded file (e.g., encoding a video, compressing/decompressing, resizing, or renaming), vulnerabilities in those processing libraries can be exploited.

* **Example:** Utilizing a known vulnerability in the `ffmpeg` library where a crafted AVI file upload leads to an XXE attack.
* **Custom Code:** Discovering flaws in custom processing code requires advanced Whitebox techniques and fuzzing. Reviewing Bug Bounty reports is recommended to study these complex scenarios.
