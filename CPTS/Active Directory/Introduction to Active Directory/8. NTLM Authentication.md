## Introduction (ভূমিকা)

Kerberos এবং LDAP ছাড়াও, Active Directory (AD) বেশ কয়েকটি অথেনটিকেশন (authentication) মেথড ব্যবহার করে যা বিভিন্ন অ্যাপ্লিকেশন ও সার্ভিস ব্যবহার করে (এবং অ্যাটাকাররা অ্যাবিউজ করে)। এগুলোর মধ্যে উল্লেখযোগ্য হলো: **LM, NT, NTLMv1, এবং NTLMv2**।

* **LM এবং NT:** এগুলো হলো হ্যাশ অ্যালগরিদম (hash algorithms), যা মূলত পাসওয়ার্ড স্টোর করার জন্য ব্যবহৃত হয়।
* **NTLMv1 এবং NTLMv2:** এগুলো হলো অথেনটিকেশন প্রোটোকল, যা ওই হ্যাশগুলোর ওপর ভিত্তি করে তৈরি। NTLMv1 অথেনটিকেশনের জন্য LM বা NT যেকোনো হ্যাশ ব্যবহার করতে পারে, কিন্তু NTLMv2 শুধুমাত্র NT হ্যাশ ব্যবহার করে।

নিচে এই হ্যাশ এবং প্রোটোকলগুলোর একটি দ্রুত তুলনা দেওয়া হলো। এই টেবিলটি দেখলে বোঝা যায় যে, কেন সব জায়গায় সম্ভব হলে Kerberos-কে প্রধান অথেনটিকেশন প্রোটোকল হিসেবে বেছে নেওয়া হয়।

### Hash Protocol Comparison (হ্যাশ ও প্রোটোকল তুলনা)

| Hash/Protocol | Cryptographic technique | Mutual Authentication | Message Type | Trusted Third Party |
| --- | --- | --- | --- | --- |
| **NTLM** | Symmetric key cryptography | No | Random number | Domain Controller |
| **NTLMv1** | Symmetric key cryptography | No | MD4 hash, random number | Domain Controller |
| **NTLMv2** | Symmetric key cryptography | No | MD4 hash, random number | Domain Controller |
| **Kerberos** | Symmetric key cryptography & asymmetric cryptography | Yes | Encrypted ticket using DES, MD5 | Domain Controller/Key Distribution Center (KDC) |

## LM (LAN Manager)

LAN Manager বা LM হ্যাশ হলো Windows অপারেটিং সিস্টেমের সবচেয়ে পুরোনো পাসওয়ার্ড স্টোরেজ মেকানিজম। এটি ১৯৮৭ সালে OS/2 অপারেটিং সিস্টেমে প্রথম ব্যবহৃত হয়।

* **কোথায় স্টোর থাকে:** এগুলো Windows হোস্টের লোকাল `SAM` ডাটাবেসে এবং Domain Controller-এর `NTDS.DIT` ডাটাবেসে সেভ করা থাকে।
* **কেন এটি বাতিল করা হয়েছে:** LM হ্যাশের অ্যালগরিদমে মারাত্মক সিকিউরিটি দুর্বলতা থাকার কারণে Windows Vista / Server 2008 থেকে এটিকে ডিফল্টভাবে বন্ধ (turned off) করে দেওয়া হয়েছে। তবে অনেক বড় এবং পুরোনো সিস্টেমে এটি এখনও দেখা যায়।

### LM হ্যাশের দুর্বলতা ও এটি কীভাবে কাজ করে

1. **পাসওয়ার্ড লিমিট:** LM-এ পাসওয়ার্ড সর্বোচ্চ ১৪ ক্যারেক্টারের হতে পারে।
2. **Case Sensitivity নেই:** এটি case-sensitive নয়। হ্যাশ জেনারেট করার আগে এটি পাসওয়ার্ডের সব অক্ষরকে বড় হাতের (uppercase) করে নেয়। এর ফলে সম্ভাব্য ক্যারেক্টার বা keyspace কমে মাত্র ৬৯টি ক্যারেক্টারে নেমে আসে।
3. **অ্যালগরিদম (কীভাবে হ্যাশ হয়):**
* প্রথমে ১৪ ক্যারেক্টারের পাসওয়ার্ডটিকে ৭ ক্যারেক্টারের দুটি ভাগে ভাগ করা হয় (যদি পাসওয়ার্ড ১৪ ক্যারেক্টারের কম হয়, তবে বাকি অংশ NULL ক্যারেক্টার দিয়ে পূরণ করা হয়)।
* প্রতিটি ৭ ক্যারেক্টারের ভাগ থেকে দুটি DES-key তৈরি করা হয়।
* এরপর এই কী-গুলো দিয়ে `KGS!@#$%` নামক একটি ফিক্সড স্ট্রিংকে এনক্রিপ্ট করা হয়, যার ফলে দুটি 8-byte সাইফারটেক্সট (ciphertext) তৈরি হয়।
* অবশেষে, এই দুটি ভ্যালুকে একসাথে জোড়া লাগিয়ে (concatenate) একটি সম্পূর্ণ LM হ্যাশ তৈরি করা হয়।


4. **কেন ক্র্যাক করা সহজ:** এই পদ্ধতির কারণে একজন অ্যাটাকারকে একসাথে ১৪ ক্যারেক্টারের পাসওয়ার্ড ক্র্যাক করতে হয় না। তাকে শুধু ৭ ক্যারেক্টার করে দু'বার ব্রুট-ফোর্স (brute-force) করতে হয়। Hashcat এবং এক বা একাধিক GPU ব্যবহার করে এটি খুব দ্রুত ক্র্যাক করা যায়।
* যদি কোনো ইউজারের পাসওয়ার্ড ৭ ক্যারেক্টার বা তার কম হয়, তবে LM হ্যাশের দ্বিতীয় অর্ধেক সবসময় একই ভ্যালু দেখাবে। এটি দেখে অ্যাটাকার টুল ব্যবহার না করেই বুঝতে পারে যে পাসওয়ার্ডটি ছোট।



Group Policy ব্যবহার করে LM হ্যাশের ব্যবহার সম্পূর্ণ নিষিদ্ধ (disallow) করা যায়। একটি LM হ্যাশ দেখতে নিচের মতো হয়:

```text
299bd128c1101fd6

```

> **Note:** Windows Vista এবং Windows Server 2008 এর আগের অপারেটিং সিস্টেমগুলো (যেমন: Windows NT4, 2000, 2003, XP) ডিফল্টভাবে ইউজারের পাসওয়ার্ডের LM হ্যাশ এবং NTLM হ্যাশ—উভয়ই স্টোর করে রাখত।

## NTHash (NTLM)

আধুনিক Windows সিস্টেমগুলোতে NT LAN Manager (NTLM) হ্যাশ ব্যবহৃত হয়। এটি একটি challenge-response অথেনটিকেশন প্রোটোকল।

### Challenge-Response কীভাবে কাজ করে

অথেনটিকেট করার জন্য এটি তিনটি মেসেজ ব্যবহার করে:

1. ক্লায়েন্ট প্রথমে সার্ভারকে একটি `NEGOTIATE_MESSAGE` পাঠায়।
2. সার্ভার ক্লায়েন্টের পরিচয় যাচাই করার জন্য একটি `CHALLENGE_MESSAGE` পাঠায়।
3. সবশেষে, ক্লায়েন্ট একটি `AUTHENTICATE_MESSAGE` দিয়ে রেসপন্স করে।

### NTHash-এর বৈশিষ্ট্য

* এগুলো লোকালি `SAM` ডাটাবেসে অথবা Domain Controller-এর `NTDS.DIT` ফাইলে স্টোর করা থাকে।
* অথেনটিকেট করার জন্য প্রোটোকলটি দুটি হ্যাশ থেকে যেকোনো একটি বেছে নিতে পারে: LM হ্যাশ অথবা NT হ্যাশ।
* **NT হ্যাশের অ্যালগরিদম:** এটি ইউজারের পাসওয়ার্ডটিকে প্রথমে little-endian UTF-16 এ কনভার্ট করে, তারপর তার MD4 হ্যাশ তৈরি করে। অ্যালগরিদমটি দেখতে এমন: `MD4(UTF-16-LE(password))`

### দুর্বলতা (Vulnerabilities)

যদিও NT হ্যাশ LM হ্যাশের চেয়ে অনেক বেশি শক্তিশালী (কারণ এটি 65,536 ক্যারেক্টারের সম্পূর্ণ ইউনিকোড সেট সাপোর্ট করে), তারপরও Hashcat-এর মতো টুল ব্যবহার করে অফলাইনে এটি বেশ দ্রুত ব্রুট-ফোর্স করা যায়।

* GPU ব্যবহার করে ৮ ক্যারেক্টারের সম্পূর্ণ NTLM keyspace ৩ ঘণ্টারও কম সময়ে ক্র্যাক করা সম্ভব।
* বড় পাসওয়ার্ড (১৫+ ক্যারেক্টার) ক্র্যাক করা কঠিন হলেও ডিকশনারি অ্যাটাক (dictionary attack) এবং রুলস (rules) ব্যবহার করে সেটিও ক্র্যাক করা যেতে পারে।
* **Pass-the-hash (PtH):** NTLM হ্যাশের সবচেয়ে বড় দুর্বলতা হলো এটি pass-the-hash অ্যাটাকের শিকার হতে পারে। অ্যাটাকার যদি কোনোভাবে হ্যাশটি সংগ্রহ করতে পারে, তবে আসল প্লেইন-টেক্সট পাসওয়ার্ড না জেনেই সে ওই হ্যাশটি ব্যবহার করে টার্গেট সিস্টেমে (যেখানে ওই ইউজার লোকাল অ্যাডমিন) অথেনটিকেট করতে পারে।

### হ্যাশের গঠন (Hash Format)

একটি NT হ্যাশ দেখতে এমন হয়: `b4b9b02e6f09a9bd760f388b67351e2b` (যা সম্পূর্ণ NTLM হ্যাশের দ্বিতীয় অংশ)।
একটি সম্পূর্ণ NTLM হ্যাশের গঠন দেখতে নিচের মতো হয়:

```shellsession
Rachel:500:aad3c435b514a4eeaad3b935b51304fe:e46b9e548fa0d122de7f59fb6d48eaa2:::

```

এই হ্যাশটিকে আমরা আলাদা আলাদা অংশে ভাগ করে বুঝতে পারি:

* `Rachel` হলো ইউজারনেম (username)।
* `500` হলো Relative Identifier (RID)। 500 হলো অ্যাডমিনিস্ট্রেটর অ্যাকাউন্টের পরিচিত RID।
* `aad3c435b514a4eeaad3b935b51304fe` হলো LM হ্যাশ। যদি সিস্টেমে LM হ্যাশ ডিজেবল করা থাকে, তবে এটি কোনো কাজেই আসে না। (উপরের এই নির্দিষ্ট স্ট্রিংটি একটি ডামি বা ব্ল্যাঙ্ক LM হ্যাশ)।
* `e46b9e548fa0d122de7f59fb6d48eaa2` হলো NT হ্যাশ। পাসওয়ার্ডের শক্তির ওপর ভিত্তি করে এই অংশটি অফলাইনে ক্র্যাক করা যেতে পারে, অথবা pass-the-hash অ্যাটাকের জন্য সরাসরি ব্যবহার করা যেতে পারে।

**Pass-the-Hash Attack Example (CrackMapExec ব্যবহার করে):**

```shellsession
00Luffy00@htb[/htb]$ crackmapexec smb 10.129.41.19 -u rachel -H e46b9e548fa0d122de7f59fb6d48eaa2

SMB         10.129.43.9     445    DC01      [*] Windows 10.0 Build 17763 (name:DC01) (domain:INLANEFREIGHT.LOCAL) (signing:True) (SMBv1:False)
SMB         10.129.43.9     445    DC01      [+] INLANEFREIGHT.LOCAL\rachel:e46b9e548fa0d122de7f59fb6d48eaa2 (Pwn3d!)

```

*(এখানে `-u` দিয়ে ইউজারনেম এবং `-H` দিয়ে হ্যাশটি দেওয়া হয়েছে। `Pwn3d!` মানে অ্যাটাক সফল এবং ইউজারের লোকাল অ্যাডমিন রাইটস আছে।)*

> **Note:** LANMAN (LM) বা NTLM কোনোটিই হ্যাশ করার সময় **Salt** ব্যবহার করে না।

## NTLMv1 (Net-NTLMv1)

NTLM প্রোটোকল NT হ্যাশ ব্যবহার করে ক্লায়েন্ট এবং সার্ভারের মধ্যে challenge/response সম্পন্ন করে।

* **কীভাবে কাজ করে:** NTLMv1 অথেনটিকেশনের সময় NT এবং LM উভয় হ্যাশই ব্যবহার করে।
* **কেন দুর্বল:** নেটওয়ার্ক থেকে Responder-এর মতো টুল দিয়ে এই হ্যাশ (যাকে Net-NTLMv1 বলা হয়) ক্যাপচার করার পর অফলাইনে "ক্র্যাক" করা সহজ।
* **Pass-the-hash:** মনে রাখা জরুরি, এই নেটওয়ার্ক হ্যাশগুলো দিয়ে pass-the-hash অ্যাটাক করা যায় **না**। এগুলো শুধুমাত্র NTLM relay অ্যাটাক বা ক্র্যাক করার জন্য ব্যবহৃত হয়।
* **অ্যালগরিদম:** সার্ভার ক্লায়েন্টকে একটি 8-byte র্যান্ডম নম্বর (challenge) পাঠায় এবং ক্লায়েন্ট একটি 24-byte রেসপন্স রিটার্ন করে। অ্যালগরিদমটি দেখতে এমন:

**V1 Challenge & Response Algorithm:**

```shellsession
C = 8-byte server challenge, random
K1 | K2 | K3 = LM/NT-hash | 5-bytes-0
response = DES(K1,C) | DES(K2,C) | DES(K3,C)

```

**NTLMv1 Hash Example:**

```shellsession
u4-netntlm::kNS:338d08f8e26de93300000000000000000000000000000000:9526fb8c23a90751cdd619b6cea564742e1e4bf33006ba41:cb8086049ec4736c

```

## NTLMv2 (Net-NTLMv2)

NTLMv1 এর দুর্বলতাগুলো দূর করতে Windows NT 4.0 SP4-এ প্রথম NTLMv2 প্রোটোকল নিয়ে আসা হয় এবং Windows Server 2000 থেকে এটি ডিফল্ট হিসেবে ব্যবহৃত হচ্ছে।

* **কীভাবে কাজ করে:** এটি NTLMv1 এর চেয়ে অনেক বেশি শক্তিশালী এবং বিভিন্ন স্পুফিং (spoofing) অ্যাটাক থেকে সুরক্ষিত। সার্ভার থেকে আসা 8-byte চ্যালেঞ্জের বিপরীতে NTLMv2 দুটি রেসপন্স পাঠায়।
* এই রেসপন্সগুলোতে চ্যালেঞ্জের একটি 16-byte HMAC-MD5 হ্যাশ, ক্লায়েন্ট থেকে জেনারেট করা একটি র্যান্ডম চ্যালেঞ্জ, ইউজারের ক্রেডেনশিয়ালের একটি HMAC-MD5 হ্যাশ এবং বর্তমান সময় (timestamp) ও ডোমেইন নেম যুক্ত থাকে।
* টাইমস্ট্যাম্প এবং ডোমেইন নেম যুক্ত থাকার কারণে এটি অনেক বেশি নিরাপদ।

**V2 Challenge & Response Algorithm:**

```shellsession
SC = 8-byte server challenge, random
CC = 8-byte client challenge, random
CC* = (X, time, CC2, domain name)
v2-Hash = HMAC-MD5(NT-Hash, user name, domain name)
LMv2 = HMAC-MD5(v2-Hash, SC, CC)
NTv2 = HMAC-MD5(v2-Hash, SC, CC*)
response = LMv2 | CC | NTv2 | CC*

```

**NTLMv2 Hash Example:**

```shellsession
admin::N46iSNekpT:08ca45b7d7ea58ee:88dcbe4446168966a153a0064958dac6:5c7830315c7830310000000000000b45c67103d07d7b95acd12ffa11230e0000000052920b85f78d013c31cdb3b92f5d765c783030

```

## Domain Cached Credentials (MSCache2)

Active Directory এনভায়রনমেন্টে লগইন করার জন্য সাধারণত পিসিকে Domain Controller (DC)-এর সাথে যোগাযোগ করতে হয়। কিন্তু যদি কোনো কারণে নেটওয়ার্ক ডাউন থাকে বা ডিসি-র সাথে যোগাযোগ করা সম্ভব না হয়, তবে পিসিতে লগইন করার জন্য Microsoft **Domain Cached Credentials (DCC)** বা MS Cache v1 এবং v2 অ্যালগরিদম তৈরি করেছে।

* **কীভাবে কাজ করে:** ডোমেইন-জয়েন করা কোনো মেশিনে যে ইউজাররা সফলভাবে লগইন করে, তাদের শেষ ১০ জনের হ্যাশ পিসির লোকাল রেজিস্ট্রিতে (`HKEY_LOCAL_MACHINE\SECURITY\Cache`) সেভ করা থাকে।
* **বৈশিষ্ট্য ও দুর্বলতা:**
1. এই হ্যাশগুলো ব্যবহার করে pass-the-hash অ্যাটাক করা যায় **না**।
2. এগুলো ক্র্যাক করা অত্যন্ত ধীরগতির (slow)। অত্যন্ত শক্তিশালী GPU রিগ ব্যবহার করে Hashcat দিয়ে ক্র্যাক করতে গেলেও অনেক সময় লাগে।
3. তাই, যদি পাসওয়ার্ড খুব দুর্বল না হয়, তবে এই হ্যাশগুলো ক্র্যাক করার চেষ্টা করা সাধারণত সময়ের অপচয় (futile)।


* **অ্যাক্সেস:** একজন পেনিট্রেশন টেস্টার বা অ্যাটাকার তখনই এই হ্যাশগুলো সংগ্রহ করতে পারবে, যখন তার কাছে ওই হোস্টের লোকাল অ্যাডমিন (local admin) অ্যাক্সেস থাকবে।

**DCC Hash Example Format:**

```text
$DCC2$10240#bjones#e4e938d12fe5974dc42a90120bd9c90f

```
