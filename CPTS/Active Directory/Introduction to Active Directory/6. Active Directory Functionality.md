## FSMO Roles (Flexible Single Master Operation)

আগের সেকশনগুলোতে যেমনটি উল্লেখ করা হয়েছে, Active Directory-তে ৫টি Flexible Single Master Operation (FSMO) রোল রয়েছে। ডোমেইন কন্ট্রোলারগুলোর (DC) মাঝে কাজ ভাগ করে দেওয়ার জন্য এই রোলগুলো ব্যবহৃত হয়।

নিচে প্রতিটি রোলের সহজ ব্যাখ্যা দেওয়া হলো:

| Roles | Description (বিবরণ) |
| --- | --- |
| **Schema Master** | এটি AD স্কিমার (schema) read/write কপি ম্যানেজ করে। AD-তে কোনো অবজেক্টের কী কী বৈশিষ্ট্য (attributes) থাকতে পারবে, তা স্কিমা নির্ধারণ করে দেয়। |
| **Domain Naming Master** | এটি ডোমেইনের নামগুলো ম্যানেজ করে এবং নিশ্চিত করে যেন একই ফরেস্টের (forest) মাঝে একই নামের দুটি ডোমেইন তৈরি না হয়ে যায়। |
| **Relative ID (RID) Master** | ডোমেইনে নতুন কোনো অবজেক্ট তৈরি করার সময় এটি অন্যান্য ডোমেইন কন্ট্রোলারগুলোকে RID-এর ব্লক অ্যাসাইন করে দেয়। এটি নিশ্চিত করে যেন একাধিক অবজেক্ট একই SID না পায়। (মূলত Domain SID-এর সাথে এই RID যুক্ত করেই একটি ইউনিক SID তৈরি করা হয়)। |
| **PDC Emulator** | যে হোস্টে এই রোলটি থাকে, সেটি ডোমেইনের প্রধান (authoritative) DC হিসেবে কাজ করে। এটি ইউজারদের অথেনটিকেশন রিকোয়েস্টের রেসপন্স দেওয়া, পাসওয়ার্ড পরিবর্তন করা এবং Group Policy Objects (GPOs) ম্যানেজ করার কাজ করে। এছাড়া ডোমেইনের সময় (time) ঠিক রাখাও এর কাজ। |
| **Infrastructure Master** | এই রোলটি বিভিন্ন ডোমেইনের মাঝে GUID, SID এবং DN (Distinguished Name) ট্রান্সলেট করে। যেসব অর্গানাইজেশনে একটি ফরেস্টের ভেতর একাধিক ডোমেইন থাকে, তাদের মাঝে যোগাযোগ স্থাপনে এটি সাহায্য করে। এই রোলটি ঠিকমতো কাজ না করলে Access Control Lists (ACLs)-এ নামের পরিবর্তে শুধু SID দেখাবে। |

**গুরুত্বপূর্ণ বিষয়:** প্রতিষ্ঠান অনুযায়ী এই রোলগুলো নির্দিষ্ট কোনো DC-কে দেওয়া হতে পারে, অথবা নতুন DC অ্যাড করার সময় ডিফল্টভাবেও অ্যাসাইন হতে পারে। FSMO রোলে কোনো সমস্যা দেখা দিলে ডোমেইনে অথেনটিকেশন এবং অথোরাইজেশনে জটিলতা সৃষ্টি হয়।

## Domain and Forest Functional Levels (ডোমেইন এবং ফরেস্ট ফাংশনাল লেভেল)

Active Directory Domain Services (AD DS)-এ কী কী ফিচার এবং সক্ষমতা (capabilities) অ্যাভেইলেবল আছে, তা নির্ধারণ করার জন্য Microsoft ফাংশনাল লেভেলের কনসেপ্ট নিয়ে আসে। এগুলো ডোমেইন এবং ফরেস্ট—উভয় লেভেলেই কাজ করে। এর মাধ্যমে এও নির্ধারণ করা হয় যে, কোন Windows Server অপারেটিং সিস্টেম ডোমেইন বা ফরেস্টে Domain Controller হিসেবে রান করতে পারবে।

নিচে Windows 2000 native থেকে Windows Server 2016 পর্যন্ত ডোমেইন ফাংশনাল লেভেলের পার্থক্যগুলোর একটি ওভারভিউ দেওয়া হলো (প্রতিটি লেভেলে তার ঠিক আগের লেভেলের ডিফল্ট AD DS ফিচারগুলোও অন্তর্ভুক্ত থাকে):

| Domain Functional Level | Features Available (অ্যাভেইলেবল ফিচারসমূহ) | Supported Domain Controller Operating Systems |
| --- | --- | --- |
| **Windows 2000 native** | ডিস্ট্রিবিউশন এবং সিকিউরিটি গ্রুপের জন্য Universal groups, গ্রুপ নেস্টিং (group nesting), গ্রুপ কনভার্শন (সিকিউরিটি ও ডিস্ট্রিবিউশন গ্রুপের মধ্যে), এবং SID history। | Windows Server 2008 R2, Windows Server 2008, Windows Server 2003, Windows 2000 |
| **Windows Server 2003** | Netdom.exe ডোমেইন ম্যানেজমেন্ট টুল, lastLogonTimestamp অ্যাট্রিবিউটের অন্তর্ভুক্তি, well-known ইউজার ও কম্পিউটার কন্টেইনার, constrained delegation এবং selective authentication। | Windows Server 2012 R2, Windows Server 2012, Windows Server 2008 R2, Windows Server 2008, Windows Server 2003 |
| **Windows Server 2008** | Distributed File System (DFS) রেপ্লিকেশন সাপোর্ট, Kerberos প্রোটোকলের জন্য Advanced Encryption Standard (AES 128 এবং AES 256) সাপোর্ট, Fine-grained পাসওয়ার্ড পলিসি। | Windows Server 2012 R2, Windows Server 2012, Windows Server 2008 R2, Windows Server 2008 |
| **Windows Server 2008 R2** | Authentication mechanism assurance, Managed Service Accounts। | Windows Server 2012 R2, Windows Server 2012, Windows Server 2008 R2 |
| **Windows Server 2012** | Claims-এর জন্য KDC সাপোর্ট, compound authentication এবং Kerberos armoring। | Windows Server 2012 R2, Windows Server 2012 |
| **Windows Server 2012 R2** | Protected Users গ্রুপের মেম্বারদের জন্য অতিরিক্ত প্রোটেকশন, Authentication Policies এবং Authentication Policy Silos। | Windows Server 2012 R2 |
| **Windows Server 2016** | ইন্টারেক্টিভ লগইনের জন্য স্মার্ট কার্ড রিকোয়ারমেন্ট, নতুন Kerberos ফিচার এবং নতুন ক্রেডেনশিয়াল প্রোটেকশন ফিচার। | Windows Server 2019 এবং Windows Server 2016 |

> **নোট:** Windows Server 2019 রিলিজ হওয়ার পর নতুন কোনো ফাংশনাল লেভেল যুক্ত করা হয়নি। তবে, কোনো এনভায়রনমেন্টে Server 2019 Domain Controller অ্যাড করতে হলে সিস্টেমের মিনিমাম রিকোয়ারমেন্ট হিসেবে Windows Server 2008 ফাংশনাল লেভেল থাকতে হবে। এছাড়া টার্গেট ডোমেইনে SYSVOL রেপ্লিকেশনের জন্য অবশ্যই DFS-R ব্যবহার করতে হবে।

### Forest Functional Levels

বছরের পর বছর ধরে ফরেস্ট ফাংশনাল লেভেলগুলোতেও কিছু মূল সক্ষমতা যুক্ত হয়েছে:

| Version | Capabilities (সক্ষমতাসমূহ) |
| --- | --- |
| **Windows Server 2003** | এতে ফরেস্ট ট্রাস্ট, ডোমেইন রিনেমিং, read-only domain controllers (RODC) এবং আরও অনেক ফিচার যুক্ত করা হয়। |
| **Windows Server 2008** | ফরেস্টে যুক্ত হওয়া সব নতুন ডোমেইন ডিফল্টভাবে Server 2008 ডোমেইন ফাংশনাল লেভেলে থাকে। নতুন কোনো ফিচার যুক্ত হয়নি। |
| **Windows Server 2008 R2** | Active Directory Recycle Bin যুক্ত করা হয়, যার মাধ্যমে AD DS রান থাকা অবস্থায় ডিলিট হওয়া অবজেক্ট রিস্টোর (restore) করা যায়। |
| **Windows Server 2012** | ফরেস্টে যুক্ত হওয়া সব নতুন ডোমেইন ডিফল্টভাবে Server 2012 ডোমেইন ফাংশনাল লেভেলে থাকে। নতুন কোনো ফিচার নেই। |
| **Windows Server 2012 R2** | ফরেস্টে যুক্ত হওয়া সব নতুন ডোমেইন ডিফল্টভাবে Server 2012 R2 ডোমেইন ফাংশনাল লেভেলে থাকে। নতুন কোনো ফিচার নেই। |
| **Windows Server 2016** | Microsoft Identity Manager (MIM) ব্যবহার করে Privileged access management (PAM)-এর সক্ষমতা যুক্ত হয়। |

## Trusts (ট্রাস্ট)

দুটি আলাদা ডোমেইন বা ফরেস্টের মধ্যে অথেনটিকেশন স্থাপন করার জন্য ট্রাস্ট (Trust) ব্যবহার করা হয়। এর ফলে একজন ইউজার তার নিজের ডোমেইনের বাইরে গিয়ে অন্য ডোমেইনের রিসোর্স অ্যাক্সেস করতে পারে (বা অ্যাডমিনিস্টার করতে পারে)। সহজ কথায়, ট্রাস্ট হলো দুটি ডোমেইনের অথেনটিকেশন সিস্টেমের মাঝের একটি লিংক বা সেতু।

ট্রাস্টের কয়েকটি ধরন রয়েছে:

| Trust Type | Description (বিবরণ) |
| --- | --- |
| **Parent-child** | একই ফরেস্টের ভেতরের ডোমেইন। চাইল্ড ডোমেইন এবং প্যারেন্ট ডোমেইনের মাঝে একটি two-way transitive ট্রাস্ট থাকে। |
| **Cross-link** | অথেনটিকেশন প্রক্রিয়া দ্রুত করার জন্য চাইল্ড ডোমেইনগুলোর নিজেদের মাঝের একটি ট্রাস্ট। |
| **External** | দুটি আলাদা ফরেস্টের দুটি আলাদা ডোমেইনের মাঝে তৈরি হওয়া একটি non-transitive ট্রাস্ট (যদি তাদের মাঝে আগে থেকে কোনো forest trust না থাকে)। এই ধরনের ট্রাস্ট SID filtering ব্যবহার করে। |
| **Tree-root** | একটি ফরেস্টের রুট ডোমেইন এবং একটি নতুন ট্রি রুট ডোমেইনের মাঝে তৈরি হওয়া two-way transitive ট্রাস্ট। ফরেস্টে নতুন কোনো ট্রি রুট ডোমেইন বানালে বাই-ডিজাইন এটি তৈরি হয়ে যায়। |
| **Forest** | দুটি ফরেস্ট রুট ডোমেইনের মাঝে তৈরি হওয়া transitive ট্রাস্ট। |

### Transitive বনাম Non-transitive Trust

* **Transitive trust:** এর মানে হলো ট্রাস্টটি এক্সটেন্ড (extend) হতে পারে। অর্থাৎ, চাইল্ড ডোমেইন যাকে ট্রাস্ট করবে, মূল ডোমেইনও তাকে ট্রাস্ট করবে (ধরা যাক, A ট্রাস্ট করে B-কে, আবার B ট্রাস্ট করে C-কে; তাহলে A স্বয়ংক্রিয়ভাবে C-কে ট্রাস্ট করবে)।
* **Non-transitive trust:** এই ক্ষেত্রে শুধুমাত্র ওই নির্দিষ্ট ডোমেইনকেই ট্রাস্ট করা হয়। ট্রাস্টটি অন্য কোনো ডোমেইনে এক্সটেন্ড হয় না।

### One-way বনাম Two-way (Bidirectional) Trust

* **Two-way (Bidirectional):** এই ট্রাস্টে উভয় ডোমেইনের ইউজাররাই একে অপরের রিসোর্স অ্যাক্সেস করতে পারে।
* **One-way:** এখানে শুধু trusted ডোমেইনের ইউজাররা trusting ডোমেইনের রিসোর্স অ্যাক্সেস করতে পারে, উল্টোটা নয়। অর্থাৎ, **ট্রাস্টের ডিরেকশন এবং অ্যাক্সেসের ডিরেকশন একে অপরের বিপরীত হয়।** (যদি Domain A, Domain B-কে ট্রাস্ট করে, তবে Domain B-এর ইউজাররা Domain A-এর রিসোর্স অ্যাক্সেস করতে পারবে)।

### Security Risks (নিরাপত্তা ঝুঁকি)

অনেক সময় ডোমেইন ট্রাস্টগুলো ভুলভাবে সেটআপ করা থাকে, যা অ্যাটাকারদের জন্য অনাকাঙ্ক্ষিত অ্যাটাক পাথ (attack paths) তৈরি করে দেয়। অনেক সময় শুধু সহজে কাজ করার জন্য ট্রাস্ট তৈরি করা হয়, কিন্তু পরে এর সিকিউরিটি ঝুঁকি নিয়ে আর কোনো রিভিউ করা হয় না।

কোম্পানি অধিগ্রহণ বা মার্জার (Mergers and acquisitions)-এর ফলে নতুন কোম্পানির সাথে দ্বিমুখী (bidirectional) ট্রাস্ট তৈরি হতে পারে, যা অজান্তেই মূল কোম্পানির এনভায়রনমেন্টে ঝুঁকি ডেকে আনে। এটি খুবই সাধারণ একটি বিষয় যে, মূল ডোমেইনের বাইরের কোনো ডোমেইনে (যেমন অ্যাকুয়ার করা কোম্পানির ডোমেইনে) Kerberoasting-এর মতো অ্যাটাক চালিয়ে এমন কোনো ইউজারের অ্যাক্সেস পাওয়া যায়, যার মূল ডোমেইনে অ্যাডমিনিস্ট্রেটিভ অ্যাক্সেস রয়েছে।
