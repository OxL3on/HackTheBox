## Introduction to Active Directory (অ্যাকটিভ ডিরেক্টরি পরিচিতি)

Active Directory (AD) হলো Windows network environment-এর জন্য একটি directory service। এটি একটি distributed এবং hierarchical structure, যা কোনো অর্গানাইজেশনের resources-এর centralized management করার সুবিধা দেয়। এই resource-গুলোর মধ্যে users, computers, groups, network devices, file shares, group policies, devices এবং trusts অন্তর্ভুক্ত থাকে। AD একটি Windows domain environment-এ authentication এবং authorization ফাংশন প্রদান করে।

AD-এর মাধ্যমে administrator এবং user-দের জন্য প্রয়োজনীয় তথ্য খুঁজে পাওয়া এবং ব্যবহার করা সহজ হয়। এটি highly scalable, যা প্রতি domain-এ লক্ষাধিক (millions of) object সাপোর্ট করে এবং অর্গানাইজেশন বড় হওয়ার সাথে সাথে নতুন domain তৈরির সুযোগ দেয়।

## Security and Attack Surface (নিরাপত্তা এবং অ্যাটাক সারফেস)

সাম্প্রতিক বছরগুলোতে AD-এর ওপর অ্যাটাক উল্লেখযোগ্যভাবে বৃদ্ধি পেয়েছে। এর প্রধান কারণ এবং সিকিউরিটি কনসার্নগুলো নিচে তুলে ধরা হলো:

* **Backward Compatibility ও Misconfigurations:** AD মূলত backward-compatible হিসেবে ডিজাইন করা হয়েছে এবং এর অনেক ফিচার "secure by default" নয়। এর ফলে এটি খুব সহজেই misconfigured হতে পারে।


* **Lateral and Vertical Movement:** অ্যাটাকাররা AD-এর দুর্বলতাগুলোকে কাজে লাগিয়ে নেটওয়ার্কের ভেতরে lateral এবং vertical মুভমেন্ট করতে পারে এবং unauthorized access অর্জন করতে পারে।


* **Read-only Access:** AD মূলত একটি বিশাল read-only database, যা domain-এর সকল user-এর কাছে অ্যাক্সেসযোগ্য, তাদের privilege level যাই হোক না কেন। কোনো extra privilege ছাড়া একজন basic AD user account-ও AD-এর বেশিরভাগ object enumerate করতে পারে।


* **Standard User Risk:** যেকোনো user account ব্যবহার করে domain enumerate করা যায় এবং misconfiguration খুঁজে বের করা যায় বলে একটি AD implementation-কে সঠিকভাবে সুরক্ষিত করা অত্যন্ত গুরুত্বপূর্ণ। শুধুমাত্র একটি standard domain user account ব্যবহার করেই একাধিক অ্যাটাক করা সম্ভব।


* **Defense-in-depth:** এই ঝুঁকিগুলো defense-in-depth strategy এবং security, hardening AD, network segmentation ও least privilege-এর ওপর জোর দেওয়ার প্রয়োজনীয়তা প্রমাণ করে। এর একটি উল্লেখযোগ্য উদাহরণ হলো `noPac` attack, যা ২০২১ সালের ডিসেম্বরে প্রথম রিলিজ হয়।



ধারণা করা হয় যে, প্রায় 95% Fortune 500 কোম্পানি Active Directory ব্যবহার করে, যা এটিকে অ্যাটাকারদের প্রধান লক্ষে (key focus) পরিণত করেছে। একটি সফল phishing attack-এর মাধ্যমে কোনো অ্যাটাকার যদি standard domain user হিসেবে AD environment-এ প্রবেশ করতে পারে, তবে সেই অ্যাক্সেস ব্যবহার করেই সে সম্পূর্ণ domain ম্যাপ করা এবং অ্যাটাকের রাস্তা খোঁজা শুরু করতে পারে।

Ransomware অপারেটররা ক্রমশ Active Directory-কে তাদের অ্যাটাক পাথের প্রধান অংশ হিসেবে টার্গেট করছে। উদাহরণস্বরূপ, Conti Ransomware (যা বিশ্বজুড়ে ৪০০টিরও বেশি অ্যাটাকে ব্যবহৃত হয়েছে) PrintNightmare (CVE-2021-34527) এবং Zerologon (CVE-2020-1472)-এর মতো recent critical Active Directory flaws ব্যবহার করে privilege escalate এবং target network-এ lateral movement করেছে।

Security researchers নিয়মিতভাবে নতুন vulnerabilities আবিষ্কার করছেন যা Active Directory এবং এর সাথে ইন্টারফেস করা অন্যান্য প্রযুক্তি (যেমন Microsoft Exchange)-কে প্রভাবিত করে। অনেক সময় এই extremely high-risk attack-গুলোর মাধ্যমে সম্পূর্ণ domain-এর administrative control নেওয়ার জন্য একটি standard domain user account-ই যথেষ্ট হয়।

## History of Active Directory (অ্যাকটিভ ডিরেক্টরির ইতিহাস)

Active Directory-এর বিবর্তন এবং ইতিহাস নিচে পর্যায়ক্রমে আলোচনা করা হলো:

* **১৯৭১:** RFCs-এ প্রথম LDAP (যা Active Directory-এর ভিত্তি) পরিচিত হয়।


* **১৯৯৩:** Active Directory-এর পূর্বে X.500 organizational unit concept ছিল। এটি Novell এবং Lotus-এর তৈরি সকল directory system-এর earliest version ছিল, যা ১৯৯৩ সালে Novell Directory Services নামে রিলিজ হয়।


* **১৯৯০:** Microsoft সর্বপ্রথম directory services দেওয়ার চেষ্টা করে Windows NT 3.0 রিলিজের মাধ্যমে। এই অপারেটিং সিস্টেমটি LAN Manager protocol এবং OS/2 অপারেটিং সিস্টেমের ফিচারগুলোকে একত্রিত করেছিল। OS/2 মূলত Microsoft ও IBM মিলে তৈরি করেছিল এবং এর লিড ছিলেন Ed Iacobucci (যিনি IBM DOS-এর ডিজাইন লিড ছিলেন এবং পরবর্তীতে Citrix Systems co-found করেন)।


* **১৯৯৭:** পুরো নব্বইয়ের দশক জুড়ে NT operating system বিবর্তিত হয়েছে এবং Microsoft-এর নিজস্ব proprietary elements-এর সাথে LDAP এবং Kerberos-এর মতো প্রোটোকলগুলো অ্যাডাপ্ট (adapt) করেছে। ১৯৯৭ সালে Active Directory-এর প্রথম beta রিলিজ হয়।


* **২০০০:** নব্বইয়ের দশকের মাঝামাঝি সময়ে Active Directory প্রথম পরিচিতি পেলেও, Windows Server 2000 রিলিজের আগ পর্যন্ত এটি Windows operating system-এর অংশ ছিল না।


* **২০০৩:** Windows Server 2003 রিলিজের সাথে সাথে extended functionality এবং improved administration যুক্ত হয়। এতে `Forest` ফিচার যুক্ত করা হয়, যা sysadmin-দের আলাদা domains, users, computers এবং অন্যান্য object-কে একটি ছাতার নিচে (same umbrella) কন্টেইনার (containers) হিসেবে রাখার সুবিধা দেয়।


* **২০০৮:** Server 2008-এ Active Directory Federation Services (ADFS) নিয়ে আসা হয়, যার উদ্দেশ্য ছিল Windows Server অপারেটিং সিস্টেমের ইউজারদের জন্য বিভিন্ন সিস্টেম এবং অ্যাপ্লিকেশনে Single Sign-On (SSO) প্রদান করা। ADFS ইউজারদের জন্য একই LAN-এ না থাকা সত্ত্বেও বিভিন্ন অ্যাপ্লিকেশন এবং সিস্টেমে সাইন-ইন করা সহজ করে দেয়। এটি claims-based Access Control Authorization model ব্যবহার করে, যেখানে identity provider একটি security token-এর মাধ্যমে ইউজারের আইডেন্টিটি প্যাকেজ করে।


* **২০১৬:** Server 2016 রিলিজের ফলে AD environment-কে cloud-এ মাইগ্রেট করার সক্ষমতা যুক্ত হয়। একইসাথে user access monitoring এবং Group Managed Service Accounts (gMSA)-এর মতো additional security enhancements যুক্ত হয়। gMSA নির্দিষ্ট স্বয়ংক্রিয় টাস্ক, অ্যাপ্লিকেশন এবং সার্ভিসগুলোকে আরও সুরক্ষিত উপায়ে রান করার সুবিধা দেয় এবং এটি Kerberoasting অ্যাটাক প্রতিরোধের জন্য একটি রেকমেন্ডেড মিটিগেশন (mitigation) হিসেবে ব্যবহৃত হয়।


* **২০১৬ (Cloud Push):** Azure AD Connect রিলিজের মাধ্যমে ক্লাউডের দিকে একটি বড় পদক্ষেপ নেওয়া হয়। এটি Microsoft Office 365 environment-এ মাইগ্রেট করা ইউজারদের জন্য একটি single sign-on মেথড হিসেবে ডিজাইন করা হয়েছিল।


---

২০০০ সাল থেকে বর্তমান দিন পর্যন্ত Active Directory বিভিন্ন misconfiguration-এর শিকার হয়েছে। AD পরিচালনা করা কোনো সহজ কাজ নয়, কারণ একটি change বা fix অন্য জায়গায় নতুন সমস্যার সৃষ্টি করতে পারে। Directory services স্পেসে Microsoft-এর প্রায় একচেটিয়া আধিপত্য (monopoly) রয়েছে। কোম্পানিগুলো cloud এবং hybrid environment-এর দিকে ধাবিত হলেও, অনেক কোম্পানির জন্যই on-prem AD হারিয়ে যাচ্ছে না। Network penetration testing করার সময় প্রায় সব এনগেজমেন্টেই কোনো না কোনোভাবে AD-এর সম্মুখীন হতে হবে। একটি AD environment-এর structure, function এবং protocols সম্পর্কে গভীর ধারণা থাকলে ১০,০০০ হোস্টের একটি environment-কে ২০টি হোস্টের environment-এর মতোই আত্মবিশ্বাসের সাথে মোকাবিলা করা সম্ভব।
