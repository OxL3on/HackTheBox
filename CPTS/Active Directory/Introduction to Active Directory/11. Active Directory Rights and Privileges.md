# Active Directory Rights and Privileges - [LINK](https://academy.hackthebox.com/app/module/74/section/709)


## Introduction (ভূমিকা)

Active Directory (AD) ম্যানেজমেন্টের অন্যতম প্রধান ভিত্তি হলো **Rights (অধিকার)** এবং **Privileges (প্রিভিলেজ বা বিশেষ সুবিধা)**। এগুলো যদি সঠিকভাবে ম্যানেজ করা না হয়, তবে অ্যাটাকার বা পেনিট্রেশন টেস্টাররা খুব সহজেই এর অপব্যবহার (abuse) করতে পারে।

### Rights বনাম Privileges

AD এবং সাধারণ ইনফরমেশন সিকিউরিটিতে এই দুটির মধ্যে পার্থক্য বোঝা খুবই গুরুত্বপূর্ণ:

* **Rights (অধিকার):** সাধারণত কোনো ইউজার বা গ্রুপকে নির্দিষ্ট কোনো অবজেক্টের (যেমন: কোনো ফোল্ডার বা ফাইল) অ্যাক্সেস পারমিশন দেওয়াকে Right বলে।
* **Privileges (প্রিভিলেজ):** এটি ইউজারকে নির্দিষ্ট কোনো কাজ বা অ্যাকশন (যেমন: প্রোগ্রাম রান করা, সিস্টেম বন্ধ করা, পাসওয়ার্ড রিসেট করা ইত্যাদি) করার পারমিশন দেয়।

Privileges কোনো ইউজারকে আলাদাভাবে দেওয়া যেতে পারে, অথবা কোনো বিল্ট-ইন বা কাস্টম গ্রুপের মেম্বার হওয়ার কারণেও সে এগুলো পেতে পারে।
Windows কম্পিউটারে **User Rights Assignment** নামে একটি কনসেপ্ট আছে, যা নামে Rights হলেও বাস্তবে এটি ইউজারকে দেওয়া এক ধরনের Privileges।

## Built-in AD Groups (AD-এর বিল্ট-ইন গ্রুপসমূহ)

AD-তে ডিফল্টভাবে অনেক সিকিউরিটি গ্রুপ থাকে। এর মধ্যে কিছু গ্রুপ তাদের মেম্বারদের এতটাই শক্তিশালী প্রিভিলেজ দেয়, যা কাজে লাগিয়ে অ্যাটাকাররা ডোমেইনে নিজেদের প্রিভিলেজ বাড়িয়ে একেবারে Domain Admin বা Domain Controller (DC)-এর SYSTEM প্রিভিলেজ নিয়ে নিতে পারে।

অনেক AD নেটওয়ার্কেই ইউজারদের অতিরিক্ত গ্রুপের মেম্বার করে দেওয়া একটি সাধারণ ভুল, যার ফায়দা অ্যাটাকাররা নিয়ে থাকে। তাই এই গ্রুপগুলোর মেম্বারশিপ খুব কড়াকড়িভাবে ম্যানেজ করা উচিত।

নিচে কিছু সাধারণ বিল্ট-ইন গ্রুপের লিস্ট দেওয়া হলো:

| Group Name | Description (বিবরণ) |
| --- | --- |
| **Account Operators** | এরা ইউজার, লোকাল এবং গ্লোবাল গ্রুপের মতো বেশিরভাগ অ্যাকাউন্ট তৈরি ও মডিফাই করতে পারে এবং ডোমেইন কন্ট্রোলারে লোকালি লগইন করতে পারে। তবে এরা অ্যাডমিনিস্ট্রেটর অ্যাকাউন্ট বা অ্যাডমিন গ্রুপগুলোর (Administrators, Server Operators, Backup Operators ইত্যাদি) মেম্বারদের ম্যানেজ করতে পারে না। |
| **Administrators** | এই গ্রুপের মেম্বারদের কোনো নির্দিষ্ট কম্পিউটার বা (ডিসি-তে থাকলে) পুরো ডোমেইনের ওপর সম্পূর্ণ এবং বাধাহীন (unrestricted) অ্যাক্সেস থাকে। |
| **Backup Operators** | ফাইলের পারমিশন যাই হোক না কেন, এরা কম্পিউটারের যেকোনো ফাইল ব্যাকআপ এবং রিস্টোর করতে পারে। এরা ডিসি-তে লগইন করতে এবং তা বন্ধ (shutdown) করতে পারে। এদেরকে Domain Admins হিসেবেই বিবেচনা করা উচিত। এরা SAM/NTDS ডাটাবেসের শ্যাডো কপি বানাতে পারে, যা থেকে পাসওয়ার্ড এবং অন্যান্য গুরুত্বপূর্ণ তথ্য বের করা সম্ভব। |
| **DnsAdmins** | এদের নেটওয়ার্কের DNS ইনফরমেশনে অ্যাক্সেস থাকে। ডোমেইন কন্ট্রোলারে DNS সার্ভার রোল ইন্সটল করা থাকলেই কেবল এই গ্রুপটি তৈরি হয়। |
| **Domain Admins** | এরা পুরো ডোমেইন অ্যাডমিনিস্টার করার ফুল অ্যাক্সেস পায় এবং ডোমেইনে যুক্ত সব মেশিনের লোকাল অ্যাডমিনিস্ট্রেটর গ্রুপের মেম্বার হয়। |
| **Domain Computers** | ডোমেইনে তৈরি হওয়া সব কম্পিউটারকে (ডোমেইন কন্ট্রোলার ছাড়া) এই গ্রুপে অ্যাড করা হয়। |
| **Domain Controllers** | ডোমেইনের সব ডিসি এই গ্রুপে থাকে। নতুন ডিসি তৈরি হলে স্বয়ংক্রিয়ভাবে এখানে অ্যাড হয়ে যায়। |
| **Domain Guests** | ডোমেইনের বিল্ট-ইন Guest অ্যাকাউন্টটি এই গ্রুপে থাকে। |
| **Domain Users** | ডোমেইনের সব ইউজার অ্যাকাউন্ট এই গ্রুপে থাকে। নতুন ইউজার তৈরি হলেই এখানে অ্যাড হয়ে যায়। |
| **Enterprise Admins** | এরা ডোমেইনের কনফিগারেশনের সম্পূর্ণ অ্যাক্সেস পায়। এই গ্রুপটি শুধু AD ফরেস্টের রুট ডোমেইনে (root domain) থাকে। এরা চাইল্ড ডোমেইন তৈরি বা ট্রাস্ট তৈরি করার মতো ফরেস্ট-ওয়াইড (forest-wide) পরিবর্তন করতে পারে। ডিফল্টভাবে রুট ডোমেইনের অ্যাডমিনিস্ট্রেটর অ্যাকাউন্টই শুধু এই গ্রুপের মেম্বার থাকে। |
| **Event Log Readers** | এরা লোকাল কম্পিউটারের ইভেন্ট লগ পড়তে পারে। হোস্টকে ডিসি হিসেবে প্রমোট করলেই এই গ্রুপটি তৈরি হয়। |
| **Group Policy Creator Owners** | এরা ডোমেইনে Group Policy Objects (GPOs) তৈরি, এডিট বা ডিলিট করতে পারে। |
| **Hyper-V Administrators** | এদের Hyper-V-এর সব ফিচারে সম্পূর্ণ অ্যাক্সেস থাকে। ডোমেইনে ভার্চুয়াল ডিসি থাকলে, এই গ্রুপের মেম্বারদের Domain Admins হিসেবে বিবেচনা করা উচিত। |
| **IIS_IUSRS** | এটি Internet Information Services (IIS) দ্বারা ব্যবহৃত একটি বিল্ট-ইন গ্রুপ। |
| **Pre–Windows 2000 Compatible Access** | Windows NT 4.0 বা তার আগের ভার্সনের সাথে কম্প্যাটিবিলিটির জন্য এটি রাখা হয়েছে। এটি একটি লিগ্যাসি (legacy) কনফিগারেশন, যা অনেক সময় এমন দুর্বলতা তৈরি করে যেখানে নেটওয়ার্কের যে কেউ ভ্যালিড ক্রেডেনশিয়াল ছাড়াই AD থেকে তথ্য পড়তে পারে। |
| **Print Operators** | এরা প্রিন্টার ম্যানেজ, তৈরি, শেয়ার এবং ডিলিট করতে পারে। এরা ডিসি-তে লোকালি লগইন করতে পারে। অ্যাটাকাররা ক্ষতিকারক প্রিন্টার ড্রাইভার লোড করে প্রিভিলেজ এস্কেলেট করতে এই গ্রুপ ব্যবহার করতে পারে। |
| **Protected Users** | এই গ্রুপের মেম্বারদের ক্রেডেনশিয়াল চুরি বা Kerberos অ্যাবিউজ থেকে অতিরিক্ত নিরাপত্তা দেওয়া হয়। |
| **Read-only Domain Controllers** | ডোমেইনের সব RODC এই গ্রুপে থাকে। |
| **Remote Desktop Users** | রিমোট ডেস্কটপের (RDP) মাধ্যমে হোস্টে কানেক্ট করার পারমিশন দিতে এটি ব্যবহৃত হয়। এটিকে রিনেম, ডিলিট বা মুভ করা যায় না। |
| **Remote Management Users** | Windows Remote Management (WinRM)-এর মাধ্যমে কম্পিউটারে রিমোট অ্যাক্সেস দিতে এই গ্রুপ ব্যবহৃত হয়। |
| **Schema Admins** | এরা AD স্কিমা মডিফাই করতে পারে (যা দিয়ে AD-এর সব অবজেক্ট ডিফাইন করা হয়)। এটি শুধু রুট ডোমেইনে থাকে এবং ডিফল্টভাবে শুধু অ্যাডমিনিস্ট্রেটর অ্যাকাউন্ট এর মেম্বার থাকে। |
| **Server Operators** | এটি শুধু ডিসি-তেই থাকে। এরা ডিসি-তে সার্ভিস মডিফাই করা, SMB শেয়ার অ্যাক্সেস করা এবং ফাইল ব্যাকআপ করার কাজ করতে পারে। ডিফল্টভাবে এই গ্রুপে কেউ থাকে না। |

## User Rights Assignment (ইউজার রাইটস অ্যাসাইনমেন্ট)

Group Policy (GPO) বা বর্তমান গ্রুপ মেম্বারশিপের ওপর ভিত্তি করে ইউজারদের বিভিন্ন রাইটস অ্যাসাইন করা যায়। সিকিউরিটির দৃষ্টিকোণ থেকে সব রাইটস গুরুত্বপূর্ণ না হলেও, কিছু রাইটসের কারণে অনাকাঙ্ক্ষিতভাবে প্রিভিলেজ এস্কেলেশন হতে পারে।

উদাহরণস্বরূপ, আমরা যদি এমন কোনো GPO-র ওপর write access পাই, যা আমাদের নিয়ন্ত্রিত কোনো ইউজারের ওপর অ্যাপ্লাই করা আছে, তবে আমরা `SharpGPOAbuse` এর মতো টুল ব্যবহার করে ওই ইউজারকে টার্গেটেড রাইটস দিতে পারি।

নিচে কিছু বিপজ্জনক প্রিভিলেজের উদাহরণ দেওয়া হলো:

| Privilege | Description (বিবরণ) |
| --- | --- |
| **SeRemoteInteractiveLogonRight** | এটি টার্গেট ইউজারকে RDP-এর মাধ্যমে হোস্টে লগইন করার অধিকার দেয়, যা সেনসিটিভ ডেটা পেতে বা প্রিভিলেজ বাড়াতে ব্যবহৃত হতে পারে। |
| **SeBackupPrivilege** | এটি ইউজারকে সিস্টেম ব্যাকআপ তৈরির ক্ষমতা দেয়। এটি ব্যবহার করে SAM, SYSTEM Registry hives এবং NTDS.dit-এর মতো সেনসিটিভ ফাইলের কপি নিয়ে পাসওয়ার্ড বের করা যায়। |
| **SeDebugPrivilege** | এটি কোনো প্রসেসের মেমরি ডিবাগ এবং অ্যাডজাস্ট করার অনুমতি দেয়। এটি থাকলে অ্যাটাকার `Mimikatz` ব্যবহার করে LSASS প্রসেসের মেমরি থেকে পাসওয়ার্ড বের করতে পারে। |
| **SeImpersonatePrivilege** | এটি কোনো প্রিভিলেজড অ্যাকাউন্টের (যেমন NT AUTHORITY\SYSTEM) টোকেন ইমপার্সোনেট বা ভান ধরার অনুমতি দেয়। `JuicyPotato`, `PrintSpoofer` এর মতো টুল ব্যবহার করে এটি দিয়ে প্রিভিলেজ এস্কেলেট করা যায়। |
| **SeLoadDriverPrivilege** | এই প্রিভিলেজ থাকা ইউজার ডিভাইস ড্রাইভার লোড এবং আনলোড করতে পারে, যা সিস্টেম কম্প্রোমাইজ করতে ব্যবহার করা যেতে পারে। |
| **SeTakeOwnershipPrivilege** | এটি কোনো অবজেক্টের ওনারশিপ বা মালিকানা নেওয়ার অনুমতি দেয়। এর মাধ্যমে আমরা এমন কোনো ফাইল শেয়ারের অ্যাক্সেস নিতে পারি, যা আগে আমাদের অ্যাক্সেসযোগ্য ছিল না। |

## Viewing a User's Privileges (ইউজারের প্রিভিলেজগুলো দেখা)

হোস্টে লগইন করার পর `whoami /priv` কমান্ড টাইপ করলে বর্তমান ইউজারের সব রাইটসের লিস্ট দেখা যায়। কিছু রাইটস শুধু অ্যাডমিনদের জন্যই থাকে এবং সেগুলো কেবল elevated (অ্যাডমিনিস্ট্রেটর হিসেবে রান করা) CMD বা PowerShell সেশনেই দেখা যায় বা ব্যবহার করা যায়।

Windows Vista থেকে **User Account Control (UAC)** নামে একটি সিকিউরিটি ফিচার যুক্ত করা হয়, যা ডিফল্টভাবে অ্যাপ্লিকেশনগুলোকে সম্পূর্ণ পারমিশন নিয়ে রান করতে বাধা দেয়।

### Standard Domain User's Rights (সাধারণ ইউজারের অধিকার)

```powershell
PS C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                Description                    State
============================= ============================== ========
SeChangeNotifyPrivilege       Bypass traverse checking       Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set Disabled

```

**ব্যাখ্যা:** সাধারণ ইউজারের রাইটস খুবই সীমিত এবং এখানে কোনো বিপজ্জনক প্রিভিলেজ নেই।

### Domain Admin Rights (Non-Elevated - সাধারণ কনসোল)

PS C:\htb> whoami /priv

### Backup Operator Rights

নিচে Backup Operators গ্রুপের একজন মেম্বারের রাইটসের উদাহরণ দেওয়া হলো। UAC-এর কারণে এর অনেক পাওয়ারফুল রাইটস (যেমন `SeBackupPrivilege`) ডিফল্টভাবে এনাবল নেই। তবে আমরা দেখতে পাচ্ছি এর `SeShutdownPrivilege` আছে, যার মানে এই ইউজার একটি ডোমেইন কন্ট্রোলারকে শাটডাউন করতে পারে। এটি দিয়ে কোনো ডেটা চুরি করা না গেলেও, ডিসি বন্ধ করে দিয়ে নেটওয়ার্কে বড় ধরনের ব্যাঘাত ঘটানো সম্ভব।

```powershell
PS C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                Description                    State
============================= ============================== ========
SeShutdownPrivilege           Shut down the system           Disabled
SeChangeNotifyPrivilege       Bypass traverse checking       Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set Disabled

```

### সতর্কতা (Best Practices)

অ্যাটাকার এবং ডিফেন্ডার হিসেবে আমাদের বুঝতে হবে যে, বিল্ট-ইন সিকিউরিটি গ্রুপের মাধ্যমে ইউজাররা কী কী অধিকার পায়। প্রায়ই দেখা যায়, একদম সাধারণ ইউজারদের এই গ্রুপগুলোতে অ্যাড করে দেওয়া হয়েছে, যা দিয়ে সহজেই ডোমেইন কম্প্রোমাইজ করা যায়।

* এই গ্রুপগুলোর অ্যাক্সেস খুব কড়াকড়িভাবে কন্ট্রোল করা উচিত।
* সবচেয়ে ভালো প্র্যাকটিস হলো এই গ্রুপগুলোকে ফাঁকা রাখা এবং শুধু দরকার হলেই কাউকে অ্যাড করা।
* এই গ্রুপগুলোতে অ্যাড করা অ্যাকাউন্টগুলোর পাসওয়ার্ড খুব স্ট্রং হওয়া উচিত এবং অ্যাডমিনের রেগুলার কাজের অ্যাকাউন্টের চেয়ে এগুলো আলাদা হওয়া উচিত।
