# Kerberos, DNS, LDAP, MSRPC - [LINK](https://academy.hackthebox.com/app/module/74/section/701)



## Introduction (ভূমিকা)

Windows অপারেটিং সিস্টেম যোগাযোগের জন্য বিভিন্ন ধরনের প্রোটোকল ব্যবহার করে। তবে Active Directory-র জন্য সুনির্দিষ্টভাবে চারটি প্রোটোকল অপরিহার্য:

1. **LDAP:** Lightweight Directory Access Protocol
2. **Kerberos:** Microsoft's version of Kerberos (অথেনটিকেশনের জন্য)
3. **DNS:** Domain Name System (অথেনটিকেশন এবং যোগাযোগের জন্য)
4. **MSRPC:** Microsoft's Remote Procedure Call (এটি ক্লায়েন্ট-সার্ভার মডেল-ভিত্তিক অ্যাপ্লিকেশনগুলোর জন্য একটি interprocess communication টেকনিক)

---

## 1. Kerberos (কার্বেরোস)

Windows 2000 এর পর থেকে ডোমেইন অ্যাকাউন্টগুলোর জন্য **Kerberos** হলো ডিফল্ট অথেনটিকেশন প্রোটোকল। এটি একটি ওপেন স্ট্যান্ডার্ড (open standard), যার মানে এটি অন্যান্য সিস্টেমের সাথেও কাজ করতে পারে যারা এই একই স্ট্যান্ডার্ড ব্যবহার করে।

### Kerberos কীভাবে কাজ করে?

যখন একজন ইউজার তার পিসিতে লগইন করে, তখন Kerberos **mutual authentication** (পারস্পরিক প্রমাণীকরণ) ব্যবহার করে ইউজারের পরিচয় নিশ্চিত করে। এর মানে হলো ইউজার এবং সার্ভার উভয়েই একে অপরের পরিচয় যাচাই করে।

Kerberos হলো একটি **stateless authentication protocol** যা পাসওয়ার্ড নেটওয়ার্কের মাধ্যমে পাঠানোর পরিবর্তে **টিকিট (tickets)** এর ওপর ভিত্তি করে কাজ করে।
Active Directory Domain Services (AD DS)-এর অংশ হিসেবে Domain Controller-এ একটি **Key Distribution Center (KDC)** থাকে, যার কাজ হলো এই টিকিটগুলো ইস্যু করা।

### Kerberos Authentication Process (কার্বেরোস অথেনটিকেশন প্রক্রিয়া)

Kerberos-এর মাধ্যমে ইউজার ক্রেডেনশিয়াল (পাসওয়ার্ড) নেটওয়ার্কের মাধ্যমে ট্রান্সমিট না করেই কীভাবে অথেনটিকেশন সম্পন্ন হয়, তার ধাপগুলো নিচে দেওয়া হলো:

| ধাপ | প্রক্রিয়া |
| --- | --- |
| **১. AS-REQ (Authentication Service Request)** | যখন একজন ইউজার লগইন করে, তখন তার পাসওয়ার্ড ব্যবহার করে একটি টাইমস্ট্যাম্প (timestamp) এনক্রিপ্ট করা হয় এবং KDC-তে পাঠানো হয়। KDC এটি ডিক্রিপ্ট করে অথেনটিকেশনের ইন্টিগ্রিটি (integrity) যাচাই করে। |
| **২. TGT Issue (Ticket-Granting Ticket)** | KDC সার্ভিসে থাকা AS-REQ চেক করে ইউজারের ইনফরমেশন ভেরিফাই করে এবং একটি **TGT (Ticket-Granting Ticket)** তৈরি করে যা `krbtgt` অ্যাকাউন্টের গোপন কী (secret key) দিয়ে এনক্রিপ্ট করা থাকে। এরপর এটি ইউজারের কাছে পাঠিয়ে দেয়। এই TGT বারবার ক্রেডেনশিয়াল প্রদান না করেই নেটওয়ার্ক রিসোর্স অ্যাক্সেসের জন্য সার্ভিস টিকিট রিকোয়েস্ট করতে ব্যবহৃত হয়। |
| **৩. TGS-REQ (Ticket-Granting Service Request)** | ইউজার কোনো নির্দিষ্ট সার্ভিসে অ্যাক্সেস করার জন্য (যেমন: MSSQL ডেটাবেস) তার TGT টি DC-কে প্রদান করে একটি **TGS (Ticket Granting Service)** টিকিটের রিকোয়েস্ট করে। TGT সফলভাবে ভ্যালিডেট হলে এর ডেটা কপি করে একটি TGS টিকিট তৈরি করা হয়। |
| **৪. TGS_REP (Ticket-Granting Service Reply)** | তৈরি করা TGS টিকিটটি সার্ভিস বা কম্পিউটার অ্যাকাউন্টের NTLM পাসওয়ার্ড হ্যাশ দিয়ে এনক্রিপ্ট করা হয় এবং TGS_REP-এর মাধ্যমে ইউজারের কাছে পাঠানো হয়। |
| **৫. AP_REQ (Application Request)** | সবশেষে, ইউজার সেই TGS-টি সার্ভিসের কাছে প্রেজেন্ট করে। টিকিটটি ভ্যালিড হলে ইউজার সেই রিসোর্সে বা অ্যাপ্লিকেশনে কানেক্ট করার অনুমতি পায়। |

**গুরুত্বপূর্ণ বিষয়:** Kerberos প্রোটোকল **Port 88 (TCP এবং UDP উভয়ই)** ব্যবহার করে। Nmap-এর মতো টুল দিয়ে পোর্ট 88 স্ক্যান করে আমরা সহজেই কোনো এনভায়রনমেন্টে Domain Controller খুঁজে বের করতে পারি।

## 2. DNS (Domain Name System)

Active Directory Domain Services (AD DS) ক্লায়েন্টদের (যেমন: ওয়ার্কস্টেশন, সার্ভার ইত্যাদি) ডোমেইন কন্ট্রোলার খুঁজে বের করতে এবং ডোমেইন কন্ট্রোলারদের নিজেদের মধ্যে যোগাযোগ স্থাপন করতে **DNS** ব্যবহার করে।

### DNS-এর কাজ

DNS হোস্টনেমকে IP অ্যাড্রেসে রূপান্তর করে (resolve) এবং এটি অভ্যন্তরীণ নেটওয়ার্ক ও ইন্টারনেট উভয় জায়গায় ব্যাপকভাবে ব্যবহৃত হয়।
প্রাইভেট ইন্টারনাল নেটওয়ার্কগুলো সার্ভার ও ক্লায়েন্টদের মধ্যে যোগাযোগ সহজ করার জন্য Active Directory DNS নেমস্পেস ব্যবহার করে।
AD নেটওয়ার্কের চলমান সার্ভিসগুলোর একটি ডাটাবেস **Service Records (SRV)** এর মাধ্যমে বজায় রাখে। এই SRV রেকর্ডগুলো ক্লায়েন্টদের প্রয়োজনীয় সার্ভিস (যেমন: ফাইল সার্ভার, প্রিন্টার বা ডোমেইন কন্ট্রোলার) খুঁজে পেতে সাহায্য করে।

কোনো সিস্টেমের IP অ্যাড্রেস পরিবর্তন হলে DNS ডাটাবেসে স্বয়ংক্রিয়ভাবে পরিবর্তন আনার জন্য **Dynamic DNS** ব্যবহৃত হয়। ম্যানুয়ালি এই এন্ট্রিগুলো করা অত্যন্ত সময়সাপেক্ষ এবং এতে ভুলের সম্ভাবনা থাকে।

### DNS Query Process

যখন একটি ক্লায়েন্ট নেটওয়ার্কে যোগ দেয়, তখন এটি DNS সার্ভিসের কাছে একটি কোয়েরি (query) পাঠায়। এরপর DNS ডাটাবেস থেকে একটি SRV রেকর্ড রিট্রিভ করে ডোমেইন কন্ট্রোলারের হোস্টনেম ক্লায়েন্টের কাছে পাঠায়। ক্লায়েন্ট এই হোস্টনেম ব্যবহার করে ডোমেইন কন্ট্রোলারের IP অ্যাড্রেস সংগ্রহ করে।

DNS **TCP এবং UDP Port 53** ব্যবহার করে। সাধারণত UDP পোর্ট 53 ডিফল্ট হিসেবে কাজ করে, কিন্তু যদি যোগাযোগ করতে না পারে এবং DNS মেসেজের সাইজ ৫১২ বাইটের বেশি হয়, তখন এটি TCP ব্যবহার করে।

### DNS Commands Example (PowerShell)

**Forward DNS Lookup (ডোমেইন নাম থেকে আইপি):**

```powershell
PS C:\htb> nslookup INLANEFREIGHT.LOCAL

Server:  172.16.6.5
Address:  172.16.6.5

Name:    INLANEFREIGHT.LOCAL
Address:  172.16.6.5

```

**Reverse DNS Lookup (আইপি থেকে ডোমেইন নাম):**

```powershell
PS C:\htb> nslookup 172.16.6.5

Server:  172.16.6.5
Address:  172.16.6.5

Name:    ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL
Address:  172.16.6.5

```

**Finding IP Address of a Host (হোস্টনেম থেকে আইপি):**

```powershell
PS C:\htb> nslookup ACADEMY-EA-DC01

Server:   172.16.6.5
Address:  172.16.6.5

Name:    ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL
Address:  172.16.6.5

```

## 3. LDAP (Lightweight Directory Access Protocol)

Active Directory ডিরেক্টরি লুকআপের (directory lookups) জন্য **LDAP** সাপোর্ট করে। LDAP হলো একটি ওপেন-সোর্স এবং ক্রস-প্ল্যাটফর্ম প্রোটোকল, যা বিভিন্ন ডিরেক্টরি সার্ভিসের (যেমন: AD) বিপরীতে অথেনটিকেশনের জন্য ব্যবহৃত হয়।

### LDAP কীভাবে কাজ করে?

AD ইউজারের অ্যাকাউন্ট ইনফরমেশন এবং সিকিউরিটি ইনফরমেশন (যেমন পাসওয়ার্ড) স্টোর করে এবং নেটওয়ার্কের অন্যান্য ডিভাইসের সাথে এগুলো শেয়ার করতে সাহায্য করে। **LDAP হলো সেই ভাষা যা অ্যাপ্লিকেশনগুলো ডিরেক্টরি সার্ভিস প্রদানকারী সার্ভারগুলোর সাথে যোগাযোগ করতে ব্যবহার করে।** সহজ কথায়, নেটওয়ার্ক এনভায়রনমেন্টের সিস্টেমগুলো LDAP-এর মাধ্যমেই AD-এর সাথে "কথা বলে"।

LDAP সেশন শুরু হয় একটি LDAP সার্ভারের (যাকে Directory System Agent-ও বলা হয়) সাথে কানেক্ট করার মাধ্যমে। AD-এর ডোমেইন কন্ট্রোলার সব সময় LDAP রিকোয়েস্ট (যেমন সিকিউরিটি অথেনটিকেশন রিকোয়েস্ট) শোনার জন্য প্রস্তুত থাকে।

> **তুলনা:** Apache যেমন একটি ওয়েব সার্ভার যা HTTP প্রোটোকল ব্যবহার করে, ঠিক তেমনি Active Directory হলো একটি ডিরেক্টরি সার্ভার যা LDAP প্রোটোকল ব্যবহার করে।

LDAP **Port 389** ব্যবহার করে এবং LDAP over SSL (LDAPS) **Port 636** এর মাধ্যমে যোগাযোগ করে।

### LDAP Authentication (LDAP অথেনটিকেশন)

LDAP সেশনের অথেনটিকেশন স্টেট সেট করার জন্য একটি "BIND" অপারেশন ব্যবহার করা হয়। এর দুটি ধরন রয়েছে:

1. **Simple Authentication:** এর মধ্যে অ্যানোনিমাস অথেনটিকেশন, আনঅথেনটিকেটেড অথেনটিকেশন এবং ইউজারনেম/পাসওয়ার্ড অথেনটিকেশন অন্তর্ভুক্ত। অর্থাৎ, ইউজারনেম এবং পাসওয়ার্ড ব্যবহার করে একটি BIND রিকোয়েস্ট তৈরি করে LDAP সার্ভারে অথেনটিকেট করা হয়।
2. **SASL Authentication:** Simple Authentication and Security Layer (SASL) ফ্রেমওয়ার্ক অন্যান্য অথেনটিকেশন সার্ভিস (যেমন: Kerberos) ব্যবহার করে LDAP সার্ভারের সাথে বাইন্ড (bind) করে এবং এরপর LDAP-এ অথেনটিকেট করে। এটি অতিরিক্ত নিরাপত্তা প্রদান করে।

**সতর্কতা:** ডিফল্টভাবে LDAP অথেনটিকেশন মেসেজগুলো **cleartext**-এ পাঠানো হয়, তাই ইন্টারনাল নেটওয়ার্কে যে কেউ এটি স্নিফ (sniff) করতে পারে। এ কারণে ট্রানজিটে থাকা ডেটা সুরক্ষিত রাখতে TLS এনক্রিপশন বা অনুরূপ কিছু ব্যবহার করার পরামর্শ দেওয়া হয়।

## 4. MSRPC (Microsoft Remote Procedure Call)

MSRPC হলো Remote Procedure Call (RPC)-এর একটি মাইক্রোসফট ইমপ্লিমেন্টেশন। এটি ক্লায়েন্ট-সার্ভার মডেল-ভিত্তিক অ্যাপ্লিকেশনগুলোর জন্য একটি interprocess communication টেকনিক। Windows সিস্টেমগুলো Active Directory-তে অ্যাক্সেস করতে MSRPC-এর চারটি মূল RPC ইন্টারফেস ব্যবহার করে:

| Interface Name | Description (বিবরণ) |
| --- | --- |
| **lsarpc** | এটি Local Security Authority (LSA) সিস্টেমের জন্য RPC কলের একটি সেট। এটি কম্পিউটারের লোকাল সিকিউরিটি পলিসি ম্যানেজ করে, অডিট পলিসি নিয়ন্ত্রণ করে এবং ইন্টারেক্টিভ অথেনটিকেশন সার্ভিস প্রদান করে। ডোমেইন সিকিউরিটি পলিসির ব্যবস্থাপনায় LSARPC ব্যবহৃত হয়। |
| **netlogon** | Netlogon হলো একটি Windows প্রসেস যা ডোমেইন এনভায়রনমেন্টে ইউজার এবং অন্যান্য সার্ভিসগুলোকে অথেনটিকেট করে। এটি সব সময় ব্যাকগ্রাউন্ডে চলতে থাকে। |
| **samr** | Remote SAM (samr) ডোমেইন অ্যাকাউন্ট ডাটাবেসের ম্যানেজমেন্ট ফাংশনালিটি প্রদান করে, যেখানে ইউজার এবং গ্রুপের তথ্য সংরক্ষিত থাকে। আইটি অ্যাডমিনরা সিকিউরিটি প্রিন্সিপাল তৈরি (create), পড়া (read), আপডেট করা (update) এবং ডিলিট (delete) করতে এই প্রোটোকল ব্যবহার করেন।<br>

<br>

<br>**অ্যাটাকার দৃষ্টিকোণ:** অ্যাটাকাররা (বা পেনটেস্টাররা) `BloodHound`-এর মতো টুল ব্যবহার করে samr প্রোটোকলের সাহায্যে ইন্টারনাল ডোমেইনের রিকনেসেন্স (reconnaissance) করতে পারে এবং "attack paths" তৈরি করতে পারে। প্রতিষ্ঠানগুলো একটি Windows registry key পরিবর্তন করে শুধুমাত্র অ্যাডমিনিস্ট্রেটরদের রিমোট SAM কোয়েরি করার পারমিশন দিয়ে এর থেকে রক্ষা পেতে পারে (কারণ ডিফল্টভাবে সব অথেনটিকেটেড ডোমেইন ইউজারই এই কোয়েরি করতে পারে)। |
| **drsuapi** | এটি মাইক্রোসফটের এমন একটি API যা Directory Replication Service (DRS) Remote Protocol ইমপ্লিমেন্ট করে। এটি মাল্টি-ডিসি এনভায়রনমেন্টে ডোমেইন কন্ট্রোলারগুলোর মধ্যে রেপ্লিকেশন-সম্পর্কিত কাজগুলো পরিচালনা করে।<br>

<br>

<br>**অ্যাটাকার দৃষ্টিকোণ:** অ্যাটাকাররা drsuapi ব্যবহার করে Active Directory ডোমেইন ডাটাবেসের (`NTDS.dit`) একটি কপি তৈরি করতে পারে। এর মাধ্যমে তারা ডোমেইনের সব অ্যাকাউন্টের পাসওয়ার্ড হ্যাশ সংগ্রহ করে **Pass-the-Hash** অ্যাটাক করতে পারে অথবা `Hashcat`-এর মতো টুল দিয়ে অফলাইনে ক্র্যাক করে cleartext পাসওয়ার্ড বের করতে পারে। এরপর তারা RDP বা WinRM ব্যবহার করে সিস্টেমগুলোতে লগইন করতে পারে। |
