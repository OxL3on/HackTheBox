# **Authentication Methods**

### **1. Authentication Protocols**

Windows Domain-এ মূলত দুই ধরনের network authentication protocol আছে:

| Protocol | কাজ                                               |
| -------- | ------------------------------------------------- |
| Kerberos | Modern Windows-এর default authentication          |
| NetNTLM  | পুরোনো protocol, compatibility-এর জন্য রাখা হয়েছে |

Domain credentials দিয়ে কোনো service-এ login করলে Domain Controller credentials verify করে।


### **2. Kerberos Authentication**

**Kerberos:** Ticket ব্যবহার করে প্রমাণ করে যে User আগে থেকেই authenticate করেছে।

Important Terms

- **KDC (Key Distribution Center):** Kerberos tickets তৈরি করে। সাধারণত DC-তে থাকে।
- **TGT (Ticket Granting Ticket):** অন্য service-এর ticket চাওয়ার permission।
- **TGS (Ticket Granting Service):** নির্দিষ্ট service access করার ticket।
- **SPN (Service Principal Name):** কোন service ও server access করতে চাই তা identify করে।
- **Session Key:** Ticket request ও authentication-এর জন্য ব্যবহৃত key।
- **krbtgt:** যে account-এর password hash দিয়ে TGT encrypt করা হয়।

**Authentication Process:**

[learnsecuritymanagement.com](https://www.learnsecuritymanagement.com/cissp-kerberos-authentication?utm_source=chatgpt.com)

**Step 1 – Get TGT**

1. User username ও password থেকে তৈরি key দিয়ে encrypted timestamp KDC-তে পাঠায়।
2. KDC TGT ও Session Key দেয়।
3. TGT `krbtgt` account-এর password hash দিয়ে encrypted থাকে।
4. User TGT-এর ভিতরের information পড়তে পারে না।

**Step 2 – Get TGS**

1. User কোনো service (Website, Database, Share) access করতে চায়।
2. TGT, encrypted timestamp ও SPN দিয়ে KDC-এর কাছে TGS চায়।
3. KDC TGS ও Service Session Key দেয়।
4. TGS Service Owner-এর password hash দিয়ে encrypted থাকে।

**Step 3 – Access Service**

1. User TGS service-কে পাঠায়।
2. Service নিজের account-এর password hash দিয়ে TGS decrypt করে।
3. Service Session Key verify করে।
4. Authentication successful হলে access দেয়।

### **3. NetNTLM Authentication**

**NetNTLM:** Challenge-Response authentication। এখানে password বা password hash সরাসরি network দিয়ে পাঠানো হয় না।

<img width="1051" height="605" alt="image" src="https://github.com/user-attachments/assets/4459b806-01fe-4dfa-8adc-fe5a84b62f07" />


[medium.com](https://medium.com/%40isiahjohnstone/active-directory-basics-9587c430dc56?utm_source=chatgpt.com)

**Process:**

1. Client → Server: Authentication request।
2. Server → Client: Random number (Challenge)।
3. Client: NTLM hash ও Challenge ব্যবহার করে Response তৈরি করে পাঠায়।
4. Server → DC: Challenge ও Response পাঠায়।
5. DC: নিজে Response calculate করে মিলিয়ে দেখে।
6. Match হলে authentication success, না হলে denied। Result Server-এর মাধ্যমে Client-কে জানানো হয়।

**Local Account হলে:** Server নিজেই তার local SAM-এ থাকা password hash দিয়ে response verify করতে পারে। DC লাগে না।

### **4. Pentesting-এর জন্য গুরুত্বপূর্ণ**

| Concept      | কেন গুরুত্বপূর্ণ                                                     |
| ------------ | -------------------------------------------------------------------- |
| Kerberos TGT | TGT ও krbtgt account security গুরুত্বপূর্ণ                           |
| TGS          | Service account-এর hash দিয়ে TGS encrypted থাকে                      |
| SPN          | Kerberos service identification ও Kerberoasting-এর জন্য গুরুত্বপূর্ণ |
| NetNTLM      | NTLM authentication relay ও hash capture attacks-এর সঙ্গে সম্পর্কিত  |
| SAM          | Local account password hashes সংরক্ষণ করে                            |


### **Quick Revision**

| Term     | সহজ অর্থ                           |
| -------- | ---------------------------------- |
| Kerberos | Ticket-based authentication        |
| NetNTLM  | Challenge-Response authentication  |
| KDC      | Ticket তৈরি করে                    |
| TGT      | Service ticket চাওয়ার ticket       |
| TGS      | নির্দিষ্ট service access-এর ticket |
| SPN      | Service ও server identify করে      |
| krbtgt   | TGT encrypt করার account           |
| SAM      | Local account hashes রাখে          |

**মনে রাখবে:**

- Kerberos: `TGT → TGS → Service`
- NetNTLM: `Request → Challenge → Response → DC Verification`
