# osTicket

## 1. osTicket পরিচিতি

[osTicket](https://osticket.com?utm_source=chatgpt.com) একটি open-source support ticketing system। Jira, OTRS, Request Tracker ও Spiceworks-এর মতো।

- Email, phone এবং web form-এর user inquiry একটি web interface-এ manage করে।
- PHP দিয়ে তৈরি এবং MySQL database ব্যবহার করে।
- Windows ও Linux-এ install করা যায়।
- `Helpdesk software - powered by osTicket` search করলে প্রায় 44,000 results পাওয়া যায়। বিভিন্ন company, school, university ও local government এটি ব্যবহার করে।
- [Mr. Robot](https://forum.osticket.com/d/86225-osticket-on-usas-mr-robot-s01e08?utm_source=chatgpt.com) সিরিজেও osTicket দেখানো হয়েছিল।

এই section-এর উদ্দেশ্য হলো osTicket enumeration ও attack শেখার পাশাপাশি support ticketing system কেন penetration test-এ গুরুত্বপূর্ণ তা বোঝা।

osTicket নিয়মিত maintain করা হয়। বহু বছরের CVE দেখলেও খুব বেশি vulnerability বা exploit পাওয়া যায় না।

[CVE Details](https://www.cvedetails.com/vendor/2292/Osticket.html?utm_source=chatgpt.com)

Application vulnerable না হলেও সেটিকে attack-এর কাজে ব্যবহার করা সম্ভব। এর কাজকে তিনটি layer-এ ভাগ করা যায়:

| Layer         | কাজ                        |
| ------------- | -------------------------- |
| 1. User input | User সমস্যা জানায়          |
| 2. Processing | Staff সমস্যাটি পরীক্ষা করে |
| 3. Solution   | সমস্যার সমাধান দেওয়া হয়    |

### User Input

osTicket-এর মূল কাজ হলো company employees-দের কাছে user-এর সমস্যা পৌঁছে দেওয়া, যাতে তারা সমাধান করতে পারে।

- এটি open-source, তাই documentation ও tutorial পাওয়া যায়।
- [osTicket documentation](https://docs.osticket.com/en/latest/Getting%20Started/Post-Installation.html?utm_source=chatgpt.com) অনুযায়ী admin panel শুধু staff এবং administrator privilege থাকা user-রা access করতে পারে।

Social Engineering:

Target company osTicket ব্যবহার করলে একটি technical problem তৈরি করে support team-এর সঙ্গে যোগাযোগ করা যায়।

Service সম্পর্কে কিছু না জানার ভান করে সমস্যা জানালে staff-এর কাছ থেকে অতিরিক্ত তথ্য পাওয়া যেতে পারে।

### Processing

Staff বা administrator সমস্যাটি reproduce করে মূল কারণ খুঁজে বের করার চেষ্টা করে।

- Internal isolated environment-এ পরীক্ষা করা হয়।
- Environment production system-এর মতো configuration-এ রাখা হয়।
- Internal bug সন্দেহ হলে code error ও বড় সমস্যা খুঁজে দেখা হয়।

### Solution

সমস্যার গভীরতার ওপর নির্ভর করে technical department-এর অন্য staff-রাও email conversation-এ যুক্ত হতে পারে।

এখান থেকে পাওয়া যেতে পারে:

- নতুন email address, যা osTicket admin panel-এ ব্যবহার করা যেতে পারে।
- Username, যা OSINT বা অন্য company service-এ চেষ্টা করা যেতে পারে।

## 3. Attacking osTicket

Exploit-DB-তে osTicket-এর বিভিন্ন issue পাওয়া যায়:

- Remote File Inclusion
- SQL Injection
- Arbitrary File Upload
- XSS

osTicket version `1.14.1`-এ SSRF vulnerability ছিল।

[CVE-2020-24881](https://nvd.nist.gov/vuln/detail/CVE-2020-24881?utm_source=chatgpt.com)

- Internal resources access করার চেষ্টা করা যায়।
- Internal port scanning করা যায়।

### Ticket Enumeration

`kevin` একজন support agent বলে মনে হয়, কিন্তু তার কোনো open ticket নেই।

আরও খুঁজে একটি closed ticket পাওয়া যায়। সেখানে remote employee এবং support agent-এর conversation ছিল।

<img width="1487" height="1205" alt="image" src="https://github.com/user-attachments/assets/74736f1c-8dd2-496d-8edb-e976ce0227fd" />


Conversation-এর ঘটনা:

1. Employee VPN account lock হয়ে যাওয়ার কথা জানায়।
2. Support agent password reset করে।
3. Agent জানায় password standard new joiner password-এ reset করা হয়েছে।
4. Employee password জানে না এবং ফোনে password দিতে বলে।
5. Agent ভুল করে support portal-এর মাধ্যমেই password পাঠিয়ে দেয়।

এখান থেকে পাওয়া password exposed VPN portal-এ employee-এর account দিয়ে চেষ্টা করা যেতে পারে। Employee password পরিবর্তন না করলে সেটি কাজ করতে পারে।

### Standard Password Reuse

Support agent জানায়, নতুন employee-দের জন্য এটিই standard password।

অনেক organization-এ helpdesk নতুন user এবং password reset-এর জন্য একই standard password ব্যবহার করে।

যদি:

- Domain password policy দুর্বল হয়।
- Login-এর পর password change বাধ্যতামূলক না হয়।

তাহলে একই password অন্য user-এর account-এও কাজ করতে পারে।

এই scenario-তে company employee-দের username list তৈরি করতে [linkedin2username](https://github.com/initstring/linkedin2username?utm_source=chatgpt.com) ব্যবহার করা যেতে পারে। এরপর VPN endpoint-এ standard password দিয়ে password spraying করা সম্ভব হতে পারে।

### Address Book Enumeration

osTicket-এর মতো application-এ address book-ও থাকতে পারে।

Enumeration-এর সময় সেখান থেকে সব email ও username export করা উচিত। এগুলো password spraying-এর মতো attack-এ কাজে লাগতে পারে।

## 5. Closing Thoughts

এই section-এর scenario-গুলো fictional হলেও বাস্তব assessment-এ এমন ঘটনা ঘটতে পারে।

External support portal পেলে:

- Portal-এর functionality পরীক্ষা করতে হবে।
- নতুন ticket তৈরি করা যায় কি না দেখতে হবে।
- Ticket-এর মাধ্যমে legitimate company email পাওয়া যায় কি না দেখতে হবে।
- সেই email দিয়ে অন্য company service-এ registration চেষ্টা করা যেতে পারে।
- এর মাধ্যমে sensitive data access-এর সুযোগ তৈরি হতে পারে।

এখানে আরও দুটি গুরুত্বপূর্ণ বিষয় দেখা যায়:

- Password reuse-এর ঝুঁকি।
- Helpdesk agent-এর ticket queue access পেলে sensitive information leakage-এর সম্ভাবনা।

### Organization কীভাবে প্রতিরোধ করবে?

1. External-এ কোন কোন application exposed থাকবে তা সীমিত করা।
2. সব external portal-এ MFA enforce করা।
3. Employees-দের security awareness training দেওয়া এবং third-party service-এ corporate email ব্যবহার না করতে বলা।
4. Active Directory ও সব application-এ strong password policy enforce করা।
   - `welcome`-এর variation
   - `password`
   - Company name
   - Seasons ও months-এর নাম — এসব common password নিষিদ্ধ করা।
5. প্রথম login-এর পর user-কে password পরিবর্তন করতে বাধ্য করা এবং নিয়মিত password expire করা।
