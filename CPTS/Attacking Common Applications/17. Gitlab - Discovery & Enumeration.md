# GitLab – Discovery & Enumeration

## 1. GitLab পরিচিতি

[GitLab](https://about.gitlab.com/?utm_source=chatgpt.com) হলো web-based Git repository hosting tool।

এতে রয়েছে:

- Git repository hosting
- Wiki
- Issue tracking
- CI/CD pipeline (Continuous Integration and Deployment)

Technology:

- Open-source।
- শুরুতে Ruby দিয়ে তৈরি।
- বর্তমানে Go, Ruby on Rails এবং Vue.js ব্যবহার করে।
- প্রথম প্রকাশ: 2014।
- Free ও paid Enterprise version রয়েছে।

GitLab-এর কিছু তথ্য (source লেখার সময়):

- 1,466 employees।
- 66টি দেশে 30 million-এর বেশি registered users।
- নিজেদের internal procedures ও OKRs-এর বেশিরভাগ publicly প্রকাশ করে।
- ব্যবহারকারী company: Drupal, Goldman Sachs, HackerOne, Ticketmaster, Nvidia, Siemens ইত্যাদি।

আরও তথ্য: [GitLab Company](https://about.gitlab.com/company/?utm_source=chatgpt.com)

GitLab-এর মতো আরও Git hosting tool:

- GitHub
- Bitbucket

[Comparison](https://stackshare.io/stackups/bitbucket-vs-github-vs-gitlab?utm_source=chatgpt.com)

### কেন GitLab গুরুত্বপূর্ণ?

Company-এর Git repository-তে অনেক গুরুত্বপূর্ণ তথ্য থাকতে পারে:

- API interaction scripts।
- Hardcoded password বা credentials।
- Configuration files।
- SSH private keys।
- API keys।

কখনো developer ভুল করে এসব sensitive information repository-তে commit করে ফেলে।

GitLab repository তিন ধরনের:

| Type     | Access                              |
| -------- | ----------------------------------- |
| Public   | Login ছাড়াই access করা যায়          |
| Internal | Authenticated user access করতে পারে |
| Private  | নির্দিষ্ট user-রাই access করতে পারে |

আমাদের করণীয়:

- Public repository পরীক্ষা করা।
- Account registration সম্ভব হলে account তৈরি করা।
- Internal repository access করা যায় কি না দেখা।
- Repository-তে credentials ও secrets খোঁজা।

সাধারণত company email প্রয়োজন হয় এবং administrator approval লাগে। তবে কিছু GitLab instance-এ যে কেউ registration করতে পারে।

GitLab signup settings:

`http://gitlab.inlanefreight.local:8081/admin/application_settings/general`


আরেকটি গুরুত্বপূর্ণ বিষয়: OSINT থেকে user credentials পেলে GitLab-এ login চেষ্টা করা যায়। GitLab-এ Two-Factor Authentication (2FA) default অবস্থায় disabled থাকে।

2FA settings:

`http://gitlab.inlanefreight.local:8081/admin/application_settings/general`


## 2. Footprinting & Discovery

GitLab ব্যবহার হচ্ছে কি না বুঝতে GitLab URL browse করলেই login page দেখা যেতে পারে।

উদাহরণ:

`http://gitlab.inlanefreight.local:8081/users/sign_in`


### GitLab Version বের করা

Version number জানার উপায়:

1. Login করতে হবে।
2. `/help` page-এ যেতে হবে।
3. সেখানে version দেখা যাবে।

Registration enabled থাকলে account তৈরি করে version check করা যায়।

Account তৈরি সম্ভব না হলে low-risk exploit দিয়ে version বের করার চেষ্টা করা যেতে পারে:

[Exploit-DB 49821](https://www.exploit-db.com/exploits/49821?utm_source=chatgpt.com)

তবে বিভিন্ন exploit অন্ধভাবে চালানো উচিত নয়।

Version জানার অন্য উপায়:

- Page-এর date দেখা।
- First public commit দেখা।
- User registration সম্ভব হলে account তৈরি করা।

Version বের করা সম্ভব না হলে একের পর এক exploit চালানোর পরিবর্তে secrets খোঁজার দিকে মনোযোগ দিতে হবে।

## 3. Enumeration

Version জানা বা login করা ছাড়া GitLab-এ খুব বেশি কিছু করা যায় না।

প্রথমে `/explore` browse করতে হবে।

URL:

`http://gitlab.inlanefreight.local:8081/explore`


এখানে `Inlanefreight dev` নামে একটি public project পাওয়া গেছে।

### Public Repository কেন গুরুত্বপূর্ণ?

Repository থেকে পাওয়া যেতে পারে:

- Company infrastructure সম্পর্কে তথ্য।
- Production source code।
- Code review করে vulnerability।
- Hardcoded credentials।
- Credential-সহ script বা configuration file।
- SSH private key।
- API key।

Project browse:

`http://gitlab.inlanefreight.local:8081/root/inlanefreight-dev`


এখানে আরও পরীক্ষা করতে হবে:

- `groups`
- `snippets`
- `help`
- Search functionality
- অন্যান্য public projects

Public data পরীক্ষা শেষ হলে account registration সম্ভব কি না দেখতে হবে।

Company email restriction বা admin approval না থাকলে registration করে additional internal project পাওয়া যেতে পারে।

### Account Registration

URL:

`http://gitlab.inlanefreight.local:8081/users/sign_up`


Registration form দিয়েও valid username enumerate করা যায়।

উদাহরণ: `root` username আগে থেকেই নেওয়া থাকলে সেটি valid username হওয়ার ইঙ্গিত দেয়।

Password dump থেকে credentials পাওয়া গেলে সেগুলোও login বা password reuse যাচাইয়ে কাজে লাগতে পারে।

### Email Enumeration

GitLab-এ email address-ও enumerate করা সম্ভব।

আগে থেকে ব্যবহৃত email দিয়ে registration করলে error দেখায়:

```
1 error prohibited this user from being saved:  Email has already been taken
```

Source লেখার সময় এই technique GitLab-এর latest version-এও কাজ করত।

মনে রাখবে: `Sign-up enabled` checkbox বন্ধ থাকলেও `/users/sign_up` page-এ গিয়ে username enumerate করা সম্ভব হতে পারে। তবে নতুন account register করা যাবে না।

### প্রতিরোধের উপায়

- সব user account-এ 2FA enforce করা।
- Failed login attempt block করতে `Fail2Ban` ব্যবহার করা।
- Internal corporate network-এর বাইরে থেকে GitLab access সীমিত করা।

### Internal Repository Access

Example credentials:

```
Username: hacker
Password: Welcome
```

Registration সম্পন্ন হলে automatically login হয়ে projects dashboard-এ নিয়ে যাবে।

আবার `/explore` page-এ গেলে নতুন একটি internal project পাওয়া যায়:

`Inlanefreight website`


এটি company-এর static website বলে মনে হচ্ছে।

যদি অন্য ধরনের application হতো (যেমন PHP application), তাহলে source code download করে পরীক্ষা করা যেত:

- Vulnerability
- Hidden functionality
- Credentials
- Sensitive data

বাস্তব assessment-এ account register করে internal repository access করতে পারলে অনেক sensitive information পাওয়া সম্ভব।

## 4. Onwards

এই section-এর মূল শিক্ষা হলো Enumeration-এর গুরুত্ব।

প্রতিটি application সরাসরি exploitable হতে হবে এমন নয়। Vulnerability না থাকলেও application থেকে গুরুত্বপূর্ণ তথ্য পাওয়া যেতে পারে।

বিশেষ করে external penetration test-এ attack surface ছোট থাকে। তাই সফল attack-এর জন্য দুই বা তার বেশি source থেকে তথ্য সংগ্রহ করে একসঙ্গে ব্যবহার করতে হতে পারে।
