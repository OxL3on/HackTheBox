## 1. Tomcat Manager কেন গুরুত্বপূর্ণ?

Tomcat-এর `/manager` বা `/host-manager` endpoint-এ access পেলে Remote Code Execution (RCE) পাওয়া সম্ভব হতে পারে।

এই section-এ target:

- URL: `http://web01.inlanefreight.local:8180`
- IP: `10.129.201.58`
- Port: `8180`

মূল ধাপগুলো হলো:

1. Tomcat Manager-এর weak/default credentials খোঁজা।
2. Login করতে পারলে WAR file upload করা।
3. WAR-এর মধ্যে JSP web shell ব্যবহার করে command execute করা।
4. Ghostcat vulnerability (`CVE-2020-1938`) পরীক্ষা করা।

## 2. Tomcat Manager — Login Brute Force

Metasploit-এর `auxiliary/scanner/http/tomcat_mgr_login` module ব্যবহার করে login credentials পরীক্ষা করা যায়। বিকল্প হিসেবে Burp Suite Intruder বা custom script ব্যবহার করা যায়।

Module link: [https://www.rapid7.com/db/modules/auxiliary/scanner/http/tomcat_mgr_login/](https://www.rapid7.com/db/modules/auxiliary/scanner/http/tomcat_mgr_login/?utm_source=chatgpt.com)

### Metasploit configuration

```
msf6 auxiliary(scanner/http/tomcat_mgr_login) > set VHOST web01.inlanefreight.local
msf6 auxiliary(scanner/http/tomcat_mgr_login) > set RPORT 8180
msf6 auxiliary(scanner/http/tomcat_mgr_login) > set stop_on_success true
msf6 auxiliary(scanner/http/tomcat_mgr_login) > set rhosts 10.129.201.58
```

- `VHOST`: target-এর virtual host।
- `RPORT`: target port।
- `STOP_ON_SUCCESS true`: সঠিক credential পাওয়া গেলে আর চেষ্টা করবে না।
- `RHOSTS`: target IP বা host।

Configuration যাচাই:

```

```

## 3. Burp Suite দিয়ে Metasploit-এর traffic পরীক্ষা

Metasploit module কাজ না করলে বা প্রত্যাশামতো আচরণ না করলে Burp Suite অথবা ZAP দিয়ে traffic proxy করে troubleshooting করা যায়।

প্রথমে Burp Suite চালু করে:

```
msf6 auxiliary(scanner/http/tomcat_mgr_login) > set PROXIES HTTP:127.0.0.1:8080

PROXIES => HTTP:127.0.0.1:8080

msf6 auxiliary(scanner/http/tomcat_mgr_login) > run
```

এরপর Burp-এ request ও response দেখা যাবে।

Tomcat এখানে HTTP Basic Authentication ব্যবহার করে। Request-এর `Authorization` header-এ credentials Base64-encoded থাকে।

উদাহরণ:

```
echo YWRtaW46dmFncmFudA== |base64 -d
```

Output:

```
admin:vagrant
```

এখানে `YWRtaW46dmFncmFudA==` হলো `admin:vagrant`-এর Base64 encoding। এটি encryption নয়; শুধু encoding।

## 5. Tomcat Manager — WAR File Upload

Tomcat-এর GUI application manager সাধারণত এই endpoint-এ থাকে:

`/manager/html`

এটি access করার জন্য `manager-gui` role থাকা user প্রয়োজন।

সঠিক credentials দিয়ে login করতে পারলে একটি packaged Tomcat application অর্থাৎ `.WAR` file upload করে application compromise করা সম্ভব হতে পারে।

WAR (Web Application Archive): Java web application দ্রুত deploy এবং backup storage-এর জন্য ব্যবহৃত archive file।

Target Manager URL:

`http://web01.inlanefreight.local:8180/manager/html`

Login করার পর Manager interface থেকে নতুন application deploy করা যায়।

### Cleanup

কাজ শেষ হলে Tomcat Manager-এ ফিরে application-এর পাশে `Undeploy` ব্যবহার করে upload করা application সরাতে হবে।

Report-এর জন্য file ও upload location note করতে হবে। এই উদাহরণে location:

`/opt/tomcat/apache-tomcat-10.0.10/webapps`

Web shell দিয়ে ওই directory-তে `ls` করলে দেখা যাবে:

- `backup.war`
- `backup` directory
- `backup`-এর মধ্যে `cmd.jsp` এবং deploy-এর সময় তৈরি `META-INF`

`Undeploy` সাধারণত uploaded WAR archive এবং application directory সরিয়ে দেয়।

## 6. Web shell ব্যবহারে সতর্কতা

বিশেষ করে external system-এ web shell upload করলে অননুমোদিত access আটকাতে হবে।

পাঠ্যাংশে দেওয়া ব্যবস্থা:

- Randomized filename ব্যবহার করা, যেমন MD5 hash।
- Access শুধু নিজের source IP address-এ সীমিত রাখা।
- Password protection যোগ করা।

কারণ অন্য attacker web shell খুঁজে পেলে সেটি ব্যবহার করে নিজের access বা foothold তৈরি করতে পারে।

## 7. CVE-2020-1938 — Ghostcat

Ghostcat হলো Tomcat-এর একটি vulnerability, যার মাধ্যমে authentication ছাড়াই Local File Inclusion (LFI) হতে পারে।

Reference: [https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2020-1938](https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2020-1938\&utm_source=chatgpt.com)

পাঠ্যাংশ অনুযায়ী, নিচের version-গুলোর আগের Tomcat release vulnerable ছিল:

- `9.0.31`
- `8.5.51`
- `7.0.100`

### Vulnerability-এর কারণ

Tomcat-এর AJP protocol-এর misconfiguration-এর কারণে এই vulnerability তৈরি হয়েছিল।

AJP (Apache JServ Protocol): একটি binary protocol, যা request proxy করার জন্য ব্যবহৃত হয়। সাধারণত front-end web server থেকে পেছনের application server-এ request পাঠাতে এটি ব্যবহার করা হয়।

Tomcat server-এ AJP service সাধারণত port `8009`-এ চলে।

## 8. Final Notes — কী মনে রাখবে?

- Tomcat দেখলে `/manager` এবং `/host-manager` endpoint পরীক্ষা করতে হবে।
- Weak/default credentials থাকলে Manager-এ access পাওয়া সম্ভব হতে পারে।
- `manager-gui` role-যুক্ত user `/manager/html` access করতে পারে।
- Valid Manager credentials দিয়ে WAR file deploy করা সম্ভব হতে পারে।
- JSP web shell দিয়ে Tomcat server-এ command execute করা সম্ভব হতে পারে।
- Shell যে user হিসেবে চলছে, তার permission-ই command execution-এর ক্ষমতা নির্ধারণ করে। উদাহরণে user ছিল `tomcat`।
- কাজ শেষে uploaded application undeploy করে cleanup করতে হবে এবং report-এর জন্য path note করতে হবে।
- Ghostcat (`CVE-2020-1938`) পরীক্ষা করতে AJP port `8009` এবং Tomcat version শনাক্ত করা গুরুত্বপূর্ণ।
- Tomcat অনেক সময় Linux-এ `root` বা Windows-এ `SYSTEM`-এর মতো উচ্চ privilege-যুক্ত user হিসেবে চলতে পারে। তাই এটি privileged foothold পাওয়ার সম্ভাব্য পথ হতে পারে, Linux server কিংবা Active Directory-তে joined Windows server—দুই ক্ষেত্রেই।

মনে রাখার সহজ flow:

`Tomcat Discovery → Manager Credentials → Manager Access → WAR Deployment → Command Execution`

আর Ghostcat-এর flow:

`AJP Port 8009 → Vulnerable Tomcat Version → WEB-INF File Read`
