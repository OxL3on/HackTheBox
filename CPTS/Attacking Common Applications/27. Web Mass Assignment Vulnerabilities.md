# Web Mass Assignment Vulnerabilities

## 1. Mass Assignment কী?

অনেক framework-এ Mass Assignment feature থাকে, যার মাধ্যমে form থেকে পাওয়া একসঙ্গে অনেকগুলো user input সরাসরি object বা database-এ insert করা যায়।

- অনেক সময় user input-এর জন্য whitelist ব্যবহার করা হয় না।
- ফলে attacker অতিরিক্ত parameter পাঠিয়ে application-এর গুরুত্বপূর্ণ attribute পরিবর্তন করতে পারে।
- এর মাধ্যমে sensitive information চুরি, database data পরিবর্তন বা delete করা সম্ভব।

Web Mass Assignment Vulnerability: HTTP request-এর parameter পরিবর্তন করে application-এর model attributes modify করার vulnerability।

Attacker code বিশ্লেষণ করে parameter খুঁজে বের করে এবং unprotected critical parameter-এ value পাঠিয়ে database ও application-এর functionality পরিবর্তন করতে পারে।

### Ruby on Rails Example

ধরি, `User` model:

```
class User < ActiveRecord::Base
  attr_accessible :username, :email
end
```

এখানে শুধু `username` ও `email` mass assignment-এর জন্য allowed।

কিন্তু attacker request-এ অতিরিক্ত `admin` parameter পাঠাতে পারে:

```
{ "user" => { "username" => "hacker", "email" => "hacker@example.com", "admin" => true } }
```

এর ফলে `admin` attribute পরিবর্তন করে attacker admin privilege পাওয়ার চেষ্টা করতে পারে।

## 2. Exploiting Mass Assignment Vulnerability

ধরি, একটি Asset Manager web application-এর source code আমাদের দেওয়া হয়েছে।

Registration সম্পন্ন করার পর `Success!!` message আসে। কিন্তু login করলে দেখায়:

`Account is pending approval`

অর্থাৎ administrator registration approve না করা পর্যন্ত login করা যাবে না।

### Step 1: Login Code Analysis

File: `/opt/asset-manager/app.py`

```
for i,j,k in cur.execute('select * from users where username=? and password=?',(username,password)):  if k:    session['user']=i    return redirect("/home",code=302)  else:    return render_template('login.html',value='Account is pending for approval')
```

- এখানে `k` value check করা হচ্ছে।
- `k` set থাকলে login সফল।
- না থাকলে `Account is pending for approval` দেখায়।

### Step 2: Registration Code Analysis

```
try:  if request.form['confirmed']:    cond=Trueexcept:      cond=Falsewith sqlite3.connect("database.db") as con:  cur = con.cursor()  cur.execute('select * from users where username=?',(username,))  if cur.fetchone():    return render_template('index.html',value='User exists!!')  else:    cur.execute('insert into users values(?,?,?)',(username,password,cond))    con.commit()    return render_template('index.html',value='Success!!')
```

এখানে:

- Registration request-এ `confirmed` parameter থাকলে `cond=True` হয়।
- না থাকলে `cond=False` হয়।
- Database-এ `username`, `password`, `cond` insert হয়।

অর্থাৎ `confirmed` parameter set করলেই registration approval bypass করা সম্ভব।

### Step 3: Burp Suite দিয়ে Exploit

1. নতুন user register করার চেষ্টা করো।
2. Burp Suite দিয়ে `/register`-এর HTTP POST request capture করো।
3. Request-এ `confirmed` parameter যোগ করো।

POST parameters:

```
username=new&password=test&confirmed=test
```

### Step 4: Login

এখন নিচের credentials দিয়ে login করো:

```
Username: new
Password: test
```

Exploit successful

Mass Assignment vulnerability ব্যবহার করে administrator-এর approval ছাড়াই application-এ login করা সম্ভব হয়েছে।

## 3. Prevention

Mass Assignment vulnerability প্রতিরোধ করতে:

- Allowed fields-এর attributes explicitly assign করতে হবে।
- Framework-এর whitelist ব্যবহার করতে হবে।
- শুধু অনুমোদিত attributes পরিবর্তন করার সুযোগ দিতে হবে।

### Ruby on Rails – Strong Parameters

```
class UsersController < ApplicationController
  def create
    @user = User.new(user_params)
    if @user.save
      redirect_to @user
    else
      render 'new'
    end
  end

  private

  def user_params
    params.require(:user).permit(:username, :email)
  end
end
```

এখানে `user_params` শুধু `username` ও `email` গ্রহণ করবে।

Client অতিরিক্ত কোনো parameter পাঠালেও তা ignore হবে। ফলে শুধু explicitly permitted attributes-ই Mass Assignment দিয়ে পরিবর্তন করা যাবে।
