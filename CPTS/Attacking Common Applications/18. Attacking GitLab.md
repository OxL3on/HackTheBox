# Attacking GitLab

## 1. GitLab পরিচিতি

আগের section-এ দেখেছি, login ছাড়াই GitLab access করে sensitive data পাওয়া সম্ভব।

যদি valid company user অথবা admin হিসেবে access পাওয়া যায়, তাহলে organization পুরোপুরি compromise করার মতো তথ্যও পাওয়া যেতে পারে।

- September 2021 পর্যন্ত GitLab-এর 553টি CVE রিপোর্ট করা হয়েছিল।
- সব vulnerability exploitable নয়।
- তবে কিছু গুরুতর vulnerability দিয়ে Remote Code Execution (RCE) সম্ভব।

[CVE Details](https://www.cvedetails.com/vulnerability-list/vendor_id-13074/Gitlab.html?utm_source=chatgpt.com)

## 2. Username Enumeration

Username Enumeration মানে কোনো application-এ কোন username সত্যিই আছে তা বের করা।

GitLab এটিকে সাধারণত vulnerability মনে করে না। তবে এটি গুরুত্বপূর্ণ, কারণ user দুর্বল password ব্যবহার করলে account access পাওয়া সম্ভব হতে পারে।

[GitLab HackerOne Policy](https://hackerone.com/gitlab?type=team\&utm_source=chatgpt.com)

GitLab-এর বক্তব্য: User ও project enumeration/path disclosure-কে vulnerability হিসেবে বিবেচনা করা হয় না, যদি অতিরিক্ত impact দেখানো না যায়।

### Username বের করার উপায়

### Account Lockout

Username enumeration-এর পর password spraying করার সময় account lockout সম্পর্কে সতর্ক থাকতে হবে।

GitLab version `16.6`-এর আগের default settings:

- 10 বার ভুল login attempt হলে account lock হবে।
- 10 মিনিট পর automatically unlock হবে।

আগে এই settings পরিবর্তন করতে GitLab source থেকে compile করতে হতো। Version `16.6` থেকে Admin UI দিয়েই পরিবর্তন করা যায়।

দুটি গুরুত্বপূর্ণ setting:

| Setting                                          | কাজ                                   |
| ------------------------------------------------ | ------------------------------------- |
| `max_login_attempts`                             | কতবার ভুল login করলে account lock হবে |
| `failed_login_attempts_unlock_period_in_minutes` | কত মিনিট পর account unlock হবে        |

Configuration: [GitLab Devise Configuration](https://gitlab.com/gitlab-org/gitlab-foss/-/blob/master/config/initializers/8_devise.rb?utm_source=chatgpt.com)

Default configuration:

```
# Number of authentication tries before locking an account if lock_strategy
# is failed attempts.
config.maximum_attempts = 10

# Time interval to unlock the account if :time is enabled as unlock_strategy.
config.unlock_in = 10.minutes
```

Admin চাইলে minimum password length বাড়াতে পারে। কিন্তু শুধু password length বাড়ালে password attack-এর ঝুঁকি পুরোপুরি দূর হয় না।

### এরপর কী করা যায়?

Valid username list পেলে authorized assessment-এ controlled password spraying করা যায়।

Common weak password-এর উদাহরণ:

```
Welcome1
Password123
```

অথবা অন্য password dump থেকে পাওয়া credentials reuse করা যায়।

তবে account lockout-এর বিষয়টি মাথায় রাখতে হবে।

## 3. Authenticated Remote Code Execution (RCE)

RCE হলো দূর থেকে target server-এ নিজের পছন্দমতো command execute করতে পারা।

এটি অত্যন্ত গুরুতর vulnerability, কারণ:

- Server-এর data access করা সম্ভব হতে পারে।
- প্রয়োজনে privilege escalation করে আরও বেশি access পাওয়া যায়।
- Network-এর অন্য system attack করার foothold তৈরি হতে পারে।
- শেষ পর্যন্ত পুরো network compromise হতে পারে।

### GitLab CVE-2021-22205

GitLab Community Edition version `13.10.2` এবং তার আগের version-গুলোতে authenticated RCE vulnerability ছিল।

কারণ: Uploaded image file-এর metadata handle করার সময় ExifTool-এ সমস্যা ছিল।

- GitLab দ্রুত vulnerability fix করেছিল।
- কিন্তু কিছু organization এখনও vulnerable version ব্যবহার করতে পারে।

References:

- [HackerOne Report](https://hackerone.com/reports/1154542?utm_source=chatgpt.com)
- [Exploit-DB 49951](https://www.exploit-db.com/exploits/49951?utm_source=chatgpt.com)

### কী প্রয়োজন?

এটি Authenticated RCE, তাই প্রথমে valid username ও password প্রয়োজন।

Credentials পাওয়া যেতে পারে:

- OSINT থেকে।
- Credential guessing attack থেকে।
- GitLab self-registration enabled থাকলে নিজে account তৈরি করে।
