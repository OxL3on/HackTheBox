## 1. Application Discovery কী?

প্রতিষ্ঠানের network-এ কী কী device, software ও application আছে, তা খুঁজে বের করাই Application Discovery & Enumeration-এর অংশ।

Asset inventory-তে রাখতে হবে:

- Network devices, installed software ও applications।
- Application locally installed নাকি third-party hosted।
- Patch level ও End-of-Life status।
- Unauthorized applications বা `Shadow IT`।
- Strong, non-default passwords ও Multi-Factor Authentication (MFA)।
- Admin portals যেন নির্দিষ্ট IP বা `localhost` থেকে সীমাবদ্ধ করা যায়।

Enumeration করে পাওয়া যেতে পারে:

- ভুলে যাওয়া application ও expired demo version।
- Splunk-এর মতো application-এ authentication ছাড়া access।
- Default/weak credentials, যেমন `admin:admin`।
- Unauthorized/misconfigured application ও public vulnerabilities।

ফলাফল report, host-service list বা scan data হিসেবে client-কে দেওয়া যায়।

## 2. Initial Enumeration

সাধারণ workflow:

`Ping Sweep → Live Hosts → Targeted Port Scan → Deep Port Scan → Service Identification → Screenshots → Manual Testing`

বড় network-এ শত শত application হাতে পরীক্ষা করা সময়সাপেক্ষ। তাই [EyeWitness](https://github.com/FortyNorthSecurity/EyeWitness?utm_source=chatgpt.com) ও [Aquatone](https://github.com/michenriksen/aquatone?utm_source=chatgpt.com) ব্যবহার করা যায়।

- EyeWitness: Nmap XML ও Nessus XML input নিতে পারে।
- Aquatone: Nmap XML ও Masscan XML input নিতে পারে।
- দুটোই web application-এর screenshot নিয়ে report তৈরি করে।

### Nmap — Web Discovery

```
nmap -p 80,443,8000,8080,8180,8888,10000 --open -oA web_discovery -iL scope_list
```

- `-p`: নির্দিষ্ট port scan।
- `--open`: Open port দেখায়।
- `-oA`: বিভিন্ন format-এ output।
- `-iL`: Input host list।

## 5. Using EyeWitness

EyeWitness Nmap/Nessus XML থেকে screenshot report তৈরি করে। Selenium ব্যবহার করে web application screenshot নেয়, application categorize ও fingerprint করতে পারে এবং সম্ভাব্য default credentials suggest করে। IP/URL list থেকেও কাজ করতে পারে; `http://` ও `https://` prepend, DNS resolution ও নির্দিষ্ট port পরীক্ষা করতে পারে।

## 7. Interpreting the Results

Report-এ `High Value Targets` সাধারণত প্রথমে থাকে। বড় report-এর সব page পরীক্ষা করতে হবে; গুরুত্বপূর্ণ host অনেক নিচে থাকতে পারে।

উদাহরণ: ManageEngine OpManager-এ default credentials `admin:admin` ছিল এবং internet থেকে access করা যেত। PowerShell script চালিয়ে code execution পাওয়া যায়। Application-টি Domain Admin account-এর context-এ চলছিল, ফলে internal network সম্পূর্ণ compromise হয়।

### Tomcat

Tomcat দেখলে `/manager` ও `/host-manager`-এ default credentials পরীক্ষা করা যায়। Access পেলে malicious WAR file upload করে [JSP code](https://en.wikipedia.org/wiki/Jakarta_Server_Pages?utm_source=chatgpt.com) দিয়ে underlying host-এ RCE সম্ভব হতে পারে।

ছবি: [EyeWitness report](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/113/eyewitness4.png?utm_source=chatgpt.com)

### Custom Applications ও osTicket

`http://inlanefreight.local`-এর মতো custom application পরীক্ষা করতে হবে; WordPress, Joomla বা Drupal CMS চলছে কি না দেখতে হবে।

`http://support-dev.inlanefreight.local`-এ [osTicket](https://osticket.com/?utm_source=chatgpt.com) থাকতে পারে। Support ticketing system-এ sensitive information পাওয়া যেতে পারে। Social engineering scope-এ থাকলে support personnel-এর সঙ্গে interaction বা company's domain-এর valid email registration কাজে লাগতে পারে।

- [HTB Delivery write-up](https://0xdf.gitlab.io/2021/05/22/htb-delivery.html?utm_source=chatgpt.com)
- [IppSec video](https://www.youtube.com/watch?v=gbs43E71mFM\&utm_source=chatgpt.com)

ছবি: [Web report](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/113/eyewitness3.png?utm_source=chatgpt.com)

সব interesting host-এর URL, application name ও version note করতে হবে। Information gathering শেষ হওয়ার আগে তাড়াহুড়ো করে attack করলে গুরুত্বপূর্ণ তথ্য বাদ পড়তে পারে।

External test-এ custom applications, CMS, Tomcat, Jenkins, Splunk, RDS, SSL VPN, OWA, O365 ও edge-device login page থাকতে পারে।

### File Upload Example

একটি application-এ লেখা ছিল: `"Please only upload .zip and .tar.gz files"`। অনুমোদিত test-এ `.aspx` file upload করা হয়েছিল; client-side বা backend validation ছিল না। Directory brute-force করে directory listing-সহ `/files` পাওয়া যায়, যেখানে `test.aspx` ছিল। পরে `.aspx` web shell upload করে internal environment-এ foothold পাওয়া যায়।

### Internal Penetration Test

এগুলোও দেখা যেতে পারে:

- Printer login pages—কখনো cleartext LDAP credentials পাওয়া যায়।
- ESXi ও vCenter portals।
- iLO ও iDRAC login pages।
- Network ও IoT devices, IP phones।
- Internal code repositories, SharePoint, custom intranet portals ও security appliances।
