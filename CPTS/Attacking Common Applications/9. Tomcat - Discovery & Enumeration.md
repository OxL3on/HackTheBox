## 1. Apache Tomcat কী?

[Apache Tomcat](https://tomcat.apache.org?utm_source=chatgpt.com) একটি open-source web server, যা Java application চালায়। শুরুতে Java Servlets ও JavaServer Pages (JSP) চালানোর জন্য তৈরি হয়েছিল। পরে Spring-এর মতো Java framework এবং Gradle-এর মতো tool-এর সঙ্গে এর ব্যবহার বেড়েছে।

[BuiltWith](https://trends.builtwith.com/Web-Server/Apache-Tomcat-Coyote?utm_source=chatgpt.com)-এর তথ্য অনুযায়ী:

- 220,000-এর বেশি live Tomcat website রয়েছে।
- 904,000-এর বেশি website কোনো একসময় Tomcat ব্যবহার করেছে।
- Top 1 million website-এর 1.22% এবং top 100k website-এর 3.8% Tomcat ব্যবহার করে।
- Web server market share-এ Tomcat-এর অবস্থান [#13](https://webtechsurvey.com/technology/apache-tomcat?utm_source=chatgpt.com)।
- Tomcat ব্যবহারকারী প্রতিষ্ঠানের মধ্যে Alibaba, United States Patent and Trademark Office (USPTO), The American Red Cross এবং LA Times রয়েছে।

Tomcat সাধারণত public internet-এ কম exposed থাকে। তবে external penetration test-এ পাওয়া গেলে internal network-এ প্রবেশের সুযোগ তৈরি হতে পারে। Internal pentest-এ Tomcat ও একাধিক instance প্রায়ই দেখা যায়। EyeWitness report-এর High Value Targets তালিকায় এটি প্রায়ই থাকে। অনেক instance-এ weak বা default credentials থাকতে পারে।

## 2. Discovery / Footprinting

External pentest-এ EyeWitness কোনো host-কে Tomcat হিসেবে শনাক্ত করলে সেটি নিশ্চিত করতে হয়।

Tomcat শনাক্ত করার উপায়:

- HTTP response-এর `Server` header পরীক্ষা করা।
- Reverse proxy থাকলে invalid page request করে server ও version শনাক্ত করার চেষ্টা করা।
- Default documentation page `/docs` পরীক্ষা করা।

`http://app-dev.inlanefreight.local:8080/invalid`

## 3. Tomcat-এর Folder Structure

```
├── bin
├── conf
│   ├── catalina.policy
│   ├── catalina.properties
│   ├── context.xml
│   ├── tomcat-users.xml
│   ├── tomcat-users.xsd
│   └── web.xml
├── lib
├── logs
├── temp
├── webapps
│   ├── manager
│   │   ├── images
│   │   ├── META-INF
│   │   └── WEB-INF
│   │       └── web.xml
│   └── ROOT
│       └── WEB-INF
└── work
    └── Catalina
        └── localhost
```

| Folder / File      | কাজ                                                     |
| ------------------ | ------------------------------------------------------- |
| `bin`              | Tomcat চালু ও পরিচালনার script এবং binary।              |
| `conf`             | Tomcat-এর configuration file।                           |
| `tomcat-users.xml` | User credentials ও তাদের assigned role রাখে।            |
| `lib`              | Tomcat চালানোর প্রয়োজনীয় JAR file।                      |
| `logs`             | Log file রাখে।                                          |
| `temp`             | Temporary file রাখে।                                    |
| `webapps`          | Tomcat-এর default webroot; application-গুলো এখানে থাকে। |
| `work`             | Runtime data ও cache রাখে।                              |

## 4. Web Application-এর Structure

`webapps`-এর প্রতিটি application folder সাধারণত এ ধরনের structure অনুসরণ করে:

```
webapps/customapp
├── images
├── index.jsp
├── META-INF
│   └── context.xml
├── status.xsd
└── WEB-INF
    ├── jsp
    │   └── admin.jsp
    └── web.xml
    └── lib
    │    └── jdbc_drivers.jar
    └── classes
        └── AdminServlet.class
```

গুরুত্বপূর্ণ অংশ:

- `WEB-INF/web.xml` — Deployment descriptor। Application-এর route ও route handle করা class নির্ধারণ করে।
- `WEB-INF/classes` — Application-এর compiled class থাকে। এতে business logic ও sensitive information থাকতে পারে।
- `lib` — Application-এর প্রয়োজনীয় library থাকে।
- `jsp` — [Jakarta Server Pages (JSP)](https://en.wikipedia.org/wiki/Jakarta_Server_Pages?utm_source=chatgpt.com) রাখে। আগে এর নাম ছিল `JavaServer Pages`; Apache server-এর PHP file-এর সঙ্গে তুলনা করা যায়।

এই file-গুলোতে vulnerability থাকলে website সম্পূর্ণ compromise হতে পারে। বিশেষ করে Local File Inclusion (LFI) vulnerability exploit করার সময় `web.xml` গুরুত্বপূর্ণ হতে পারে।

### `web.xml` Example

```
<?xml version="1.0" encoding="ISO-8859-1"?>

<!DOCTYPE web-app PUBLIC "-//Sun Microsystems, Inc.//DTD Web Application 2.3//EN" "http://java.sun.com/dtd/web-app_2_3.dtd">

<web-app>
  <servlet>
    <servlet-name>AdminServlet</servlet-name>
    <servlet-class>com.inlanefreight.api.AdminServlet</servlet-class>
  </servlet>

  <servlet-mapping>
    <servlet-name>AdminServlet</servlet-name>
    <url-pattern>/admin</url-pattern>
  </servlet-mapping>
</web-app>
```

এখানে `AdminServlet` নামের servlet-টি `com.inlanefreight.api.AdminServlet` class-এর সঙ্গে যুক্ত।

Java-তে dot notation দিয়ে package name তৈরি হয়। তাই class-এর disk path হবে:

\- `classes/com/inlanefreight/api/AdminServlet.class`

`/admin`-এ request এলে সেটি `AdminServlet.class`-এ process করার জন্য পাঠানো হয়।

## 5. `tomcat-users.xml`

এই file দিয়ে `/manager` ও `host-manager` admin page-এ access অনুমোদন বা নিষিদ্ধ করা হয়।

```
<?xml version="1.0" encoding="UTF-8"?>

<SNIP>

<tomcat-users xmlns="http://tomcat.apache.org/xml"
              xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
              xsi:schemaLocation="http://tomcat.apache.org/xml tomcat-users.xsd"
              version="1.0">
<!--
  By default, no user is included in the "manager-gui" role required
  to operate the "/manager/html" web application.  If you wish to use this app,
  you must define such a user - the username and password are arbitrary.

  Built-in Tomcat manager roles:
    - manager-gui    - allows access to the HTML GUI and the status pages
    - manager-script - allows access to the HTTP API and the status pages
    - manager-jmx    - allows access to the JMX proxy and the status pages
    - manager-status - allows access to the status pages only

  The users below are wrapped in a comment and are therefore ignored. If you
  wish to configure one or more of these users for use with the manager web
  application, do not forget to remove the <!.. ..> that surrounds them. You
  will also need to set the passwords to something appropriate.
-->

 <SNIP>

!-- user manager can access only manager section -->
<role rolename="manager-gui" />
<user username="tomcat" password="tomcat" roles="manager-gui" />

<!-- user admin can access manager and admin section both -->
<role rolename="admin-gui" />
<user username="admin" password="admin" roles="manager-gui,admin-gui" />

</tomcat-users>
```

### Built-in Manager Roles

| Role             | Access                  |
| ---------------- | ----------------------- |
| `manager-gui`    | HTML GUI ও status page  |
| `manager-script` | HTTP API ও status page  |
| `manager-jmx`    | JMX proxy ও status page |
| `manager-status` | শুধু status page        |

Example-এ:

- Username `tomcat`, password `tomcat`, role `manager-gui`।
- Username `admin`, password `admin`, role `manager-gui,admin-gui`।

এগুলো weak password-এর উদাহরণ। বাস্তব system-এ এমন credentials আছে কি না পরীক্ষা করা গুরুত্বপূর্ণ।

### Login ও পরবর্তী পদক্ষেপ

Weak credential হিসেবে `tomcat:tomcat` বা `admin:admin` পরীক্ষা করা যেতে পারে। এগুলো কাজ না করলে পরবর্তী section-এ login page-এর বিরুদ্ধে password brute-force attack আলোচনা করা হবে।

Login সফল হলে, অনুমোদিত lab environment-এ, একটি [Web Application Resource বা Web Application Archive (WAR)](https://en.wikipedia.org/wiki/WAR_\(file_format\)?utm_source=chatgpt.com#:~:text=In%20software%20engineering%2C%20a%20WAR,that%20together%20constitute%20a%20web) file upload করা সম্ভব হতে পারে। এতে JSP web shell থাকলে Tomcat server-এ remote code execution (RCE) পাওয়া যেতে পারে।
