# Attacking Applications Connecting to Services

## 1. মূল ধারণা

অনেক application অন্য service-এর সঙ্গে connect করার জন্য connection string ব্যবহার করে। এগুলোর মধ্যে username ও password থাকতে পারে।

যদি connection string নিরাপদে রাখা না হয়, attacker সেটি বের করে:

- Service সম্পর্কে তথ্য সংগ্রহ করতে পারে।
- অন্য service-এ access পেতে পারে।
- Lateral movement করতে পারে।
- Privilege escalation করতে পারে।

## 2. ELF Executable Examination

Target machine-এ `octopus_checker` binary পাওয়া গেছে। Locally run করলে দেখা যায় এটি database connection check করে।

### Step 1: Binary Run

```
./octopus_checker

Connecting ...

01000:1:0:[unixODBC][Driver Manager]Can't open lib 'ODBC Driver 17 for SQL Server' : file not found

```

Application সম্ভবত SQL connection string ব্যবহার করছে, যেখানে credentials থাকতে পারে।

### Step 2: GDB দিয়ে Examine

`PEDA` হলো GDB-এর extension, যা C/C++ program debugging ও examination-এ সাহায্য করে।

- GitHub: [PEDA](https://github.com/longld/peda?utm_source=chatgpt.com)
- GDB দিয়ে code step, breakpoint set এবং variable examine/modify করা যায়।

```
gdb ./octopus_checker
```

## 3. DLL File Examination

### Step 3: Further Testing

MS SQL service-এ connect করার পাশাপাশি অন্য service-এর security পরীক্ষা করতে Password Spraying ব্যবহার করা যায়।

মনে রাখবে: Application-এর binary বা DLL-এর মধ্যে থাকা connection string থেকে database credentials বের করা সম্ভব। তাই executable ও .NET assembly examine করে credentials এবং অন্যান্য service connection information খুঁজতে হবে।
