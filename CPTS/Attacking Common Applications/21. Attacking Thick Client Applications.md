# Attacking Thick Client Applications

## Thick Client কী?

- Thick client হলো computer-এ locally installed application।
- Thin client browser দিয়ে remote server-এ চলে; Thick client internet ছাড়াও কাজ করতে পারে।
- Processing, memory ও storage-এর কাজ client computer-এ বেশি হয়।
- Enterprise-এ Project Management, CRM, Inventory ও Productivity software হিসেবে ব্যবহৃত হয়।
- সাধারণত Java, C++, .NET বা Microsoft Silverlight দিয়ে তৈরি।

### Security

- Java Sandbox: Untrusted code-কে আলাদা virtual environment-এ চালায়, যাতে system resource বা অন্য application access/modify করতে না পারে।
- Java API Restrictions: Java-এর API ব্যবহার সীমাবদ্ধ করে।
- Code Signing: Code-এর authenticity যাচাই করতে সাহায্য করে।

.NET environment-এ Thick Client-কে `Rich Client` বা `Fat Client`-ও বলা হয়। এটি client-side-এ বেশি processing করে, তাই Thin Client-এর তুলনায় performance, features ও user experience ভালো হতে পারে।

### Thick Client-এর বৈশিষ্ট্য

- Independent software।
- Internet ছাড়াই কাজ করতে পারে।
- Data locally store করে।
- তুলনামূলক কম secure।
- বেশি system resources ব্যবহার করে।
- বেশি expensive হতে পারে।

উদাহরণ: Web browser, media player, chatting software, video games।

- কিছু application official website বা third-party store থেকে পাওয়া যায়।
- Custom application IT department সরাসরি সরবরাহ করতে পারে।
- Update ও patch local computer-এ দিতে হয়, তাই maintenance কঠিন।

## Thick Client Vulnerabilities

Web-specific vulnerability যেমন XSS, CSRF ও Clickjacking সাধারণত Thick Client-এর ক্ষেত্রে প্রযোজ্য নয়।

তবে অন্যান্য attack হতে পারে:

- Improper Error Handling
- Hardcoded Sensitive Data
- DLL Hijacking
- Buffer Overflow
- SQL Injection
- Insecure Storage
- Session Management

## Retrieving Hardcoded Credentials from Thick-Client Applications

### Scenario

- Corporate network-এ lateral movement করার জন্য Thick Client application পরীক্ষা করা হবে।
- শুরুতে exposed SMB service-এ access পাওয়া গেছে।

### 1. SMB Share থেকে Application সংগ্রহ

SMB-এর `NETLOGON` share-এ `RestartOracle-Service.exe` পাওয়া যায়।

চালানোর চেষ্টা:

```
C:\Apps>.\Restart-OracleService.exe
C:\Apps>
```

- কোনো output দেখা যায় না।
- মনে হয় application কাজ করছে না অথবা background-এ কিছু করছে।

### 2. Process Monitor দিয়ে পরীক্ষা

[SysInternals Process Monitor](https://learn.microsoft.com/en-gb/sysinternals/downloads/procmon?utm_source=chatgpt.com) থেকে `ProcMon64` download করে process monitor করি।

\- দেখা যায় executable একটি temporary file তৈরি করছে:\
`C:\Users\Matt\AppData\Local\Temp`

### 3. Temporary File Delete হওয়া আটকানো

Folder:

`C:\Users\Matt\AppData\Local\Temp`

Permissions পরিবর্তনের ধাপ:

1. Folder-এ Right-click → `Properties`
2. `Security` → `Advanced`
3. `cybervaca` select
4. `Disable inheritance`
5. `Convert inherited permissions into explicit permissions on this object`
6. `Edit` → `Show advanced permissions`
7. `Delete subfolders and files` এবং `Delete` checkbox deselect।
8. `OK` → `Apply` → `OK` → `OK`

এরপর আবার `Restart-OracleService.exe` চালাই।

নতুন file পাওয়া যায়:

```

04/03/2023  02:09 PM         1,730,212 6F39.bat
```

### 8. x64dbg দিয়ে Analysis

`ProcMon64` দিয়ে executable monitor করলে Registry-তে অনেক query দেখা যায়, কিন্তু তেমন useful information পাওয়া যায় না।

এরপর `x64dbg` চালু করি:

1. `Options` → `Preferences`
2. `Exit Breakpoint` ছাড়া বাকি সব option uncheck।
3. `File` → `Open` থেকে `restart-service.exe` import।
4. CPU view-তে Right-click → `Follow in Memory Map`।

- এতে application-এর exit point থেকে debugging শুরু হবে।
- Application শুরু হওয়ার আগে load হওয়া DLL-এর মধ্যে যেতে হবে না।

Memory Map-এ খেয়াল করার মতো entry:

- Size: `0000000000003000`
- Type: `MAP`
- Protection: `-RW--`

Memory-mapped file: বড় file পুরোপুরি memory-তে load না করেই memory region-এর মাধ্যমে access করা যায়। এই জায়গায় hardcoded credentials থাকতে পারে।

### 9. Memory Dump ও Strings

Memory Map entry double-click করলে ASCII column-এ `MZ` দেখা যায়।

\- `MZ` হলো [DOS MZ executable](https://en.wikipedia.org/wiki/DOS_MZ_executable?utm_source=chatgpt.com)-এর magic bytes।

এরপর Memory Map-এ ফিরে address-এ Right-click → `Dump Memory to File`।
