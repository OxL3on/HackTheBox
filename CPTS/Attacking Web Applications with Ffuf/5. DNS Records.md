## **DNS Records**

### 1. The Problem

We discover `/blog` and it says:

```
Admin panel moved to academy.htb
```

When visiting:

```
http://academy.htb:PORT
```

the browser cannot connect because our machine **doesn't know the IP address of `academy.htb`**.

## 2. How Domain Resolution Works

When we visit a domain, our computer needs to resolve:

```
academy.htb → SERVER_IP
```

It checks:

1. **Local `/etc/hosts` file**
2. **DNS servers** (e.g., `8.8.8.8`)

HTB domains are **internal**, so public DNS servers don't know about them.

Therefore, we manually add the domain to `/etc/hosts`.

## 3. Adding the Domain to `/etc/hosts`

```bash
sudo sh -c 'echo "SERVER_IP academy.htb" >> /etc/hosts'
```

Example:

```
10.10.10.10 academy.htb
```

Now:

```
academy.htb
      ↓
/etc/hosts
      ↓
SERVER_IP
```

The browser can resolve and connect to the domain.

> **Remember:** Include the correct `PORT` when accessing the HTB service.
> 

```
http://academy.htb:PORT
```

## 4. Same Domain or Different Website?

After adding `academy.htb`, we visit it and get the **same website** as the IP.

We can verify with:

```
http://academy.htb:PORT/blog/index.php
```

So:

```
SERVER_IP:PORT
       ↓
   same website
       ↑
academy.htb:PORT
```

`academy.htb` is therefore not necessarily a separate hidden website.

## 5. Why Look for Subdomains?

We already performed directory/file fuzzing and didn't find an admin panel:

```
/admin
/admin.php
/panel
/dashboard
...
```

Even recursive scanning didn't reveal anything useful.

So the admin panel may exist as a **subdomain** rather than a directory.

### Main domain

```
academy.htb
```

### Possible subdomains

```
admin.academy.htb
dev.academy.htb
test.academy.htb
api.academy.htb
```

The notation:

```
*.academy.htb
```

means **any subdomain under `academy.htb`**.
