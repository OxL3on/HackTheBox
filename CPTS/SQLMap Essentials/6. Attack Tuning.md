## **Attack Tuning**


## 1. Introduction

SQLMap সাধারণত target details দিলে default configuration-এই কাজ করে। তবে detection আরও ভালো করার জন্য SQLi injection attempts tune করা যায়।

প্রতিটি payload-এর দুটি অংশ থাকে:

- Vector: Payload-এর মূল SQL code, যা target-এ execute হয়। Example: `UNION ALL SELECT 1,2,VERSION()`
- Boundaries: Vector-এর prefix ও suffix, যা vulnerable SQL statement-এর মধ্যে vector সঠিকভাবে inject করতে সাহায্য করে। Example: `'<vector>-- -`

## 2. Prefix/Suffix

কিছু rare case-এ SQLMap-এর regular run যথেষ্ট হয় না। তখন `--prefix` ও `--suffix` ব্যবহার করা যায়।

```
sqlmap -u "www.example.com/?q=test" --prefix="%'))" --suffix="-- -"
```

এতে প্রতিটি vector-এর আগে `%'))` এবং শেষে `-- -` যুক্ত হবে।

Target-এর vulnerable PHP code:

```
$query = "SELECT id,name,surname FROM users WHERE id LIKE (('" . $_GET["q"] . "')) LIMIT 0,1";
$result = mysqli_query($link, $query);
```

Vector:

```
UNION ALL SELECT 1,2,VERSION()
```

Prefix `%'))` ও suffix `-- -` যুক্ত করলে target-এ valid SQL statement হবে:

```
SELECT id,name,surname FROM users WHERE id LIKE (('test%')) UNION ALL SELECT 1,2,VERSION()-- -')) LIMIT 0,1
```

## 3. Level/Risk

Default-এ SQLMap common boundaries (prefix/suffix pairs) এবং সফল হওয়ার সম্ভাবনা বেশি এমন vectors ব্যবহার করে।

বেশি boundaries ও vectors test করতে:

| Option    | Value            | কাজ                                                                                               |
| --------- | ---------------- | ------------------------------------------------------------------------------------------------- |
| `--level` | 1–5, default `1` | Success-এর সম্ভাবনা অনুযায়ী vectors ও boundaries বাড়ায়। সম্ভাবনা যত কম, level তত বেশি প্রয়োজন।    |
| `--risk`  | 1–3, default `1` | Target-এ সমস্যা তৈরির ঝুঁকি অনুযায়ী vectors বাড়ায়। যেমন database entry loss বা denial-of-service। |

কোন level/risk-এ কী payload ব্যবহার হচ্ছে দেখতে `-v` ব্যবহার করা যায়।

Verbosity `3` বা তার বেশি হলে `[PAYLOAD]` message দেখা যায়।

### Payload সংখ্যা

| Configuration        | Payload সংখ্যা (একটি parameter) |
| -------------------- | ------------------------------- |
| `--level=1 --risk=1` | 72                              |
| `--level=5 --risk=3` | 7,865                           |

- SQLMap common boundaries ও vectors-এর জন্য আগে থেকেই tuned।
- সাধারণ user-দের `--level` ও `--risk` পরিবর্তন না করাই ভালো, কারণ এতে detection অনেক slow হয়।
- বিশেষ SQLi case-এ `OR` payload প্রয়োজন হতে পারে, যেমন `login` page। তখন risk level বাড়াতে হতে পারে।
- Default run-এ `OR` payload বিপজ্জনক হতে পারে, কারণ vulnerable SQL statement database modify করতে পারে (যেমন `DELETE` বা `UPDATE`)।

## 4. Advanced Tuning

বিশেষ প্রয়োজনে detection আরও tune করার জন্য বিভিন্ন switches ও options রয়েছে। সাধারণত এগুলোর প্রয়োজন হয় না।

### Status Codes

- TRUE ও FALSE response-এর HTTP code আলাদা হলে `--code` ব্যবহার করা যায়।
- Example: TRUE = `200`, FALSE = `500`।

```
--code=200
```

এতে TRUE response-এর জন্য নির্দিষ্ট HTTP code `200` ব্যবহার হবে।

### Titles

- HTTP page title-এর মধ্যে response difference থাকলে `--titles` ব্যবহার করা হয়।
- HTML `<title>` tag-এর content compare করে।

### Strings

\- TRUE response-এ নির্দিষ্ট string থাকলে এবং FALSE response-এ না থাকলে `--string` ব্যবহার করা যায়।

```
--string=success
```

### Text-only

- HTML page-এ অনেক hidden content থাকলে `--text-only` ব্যবহার করা হয়।
- যেমন `<script>`, `<style>`, `<meta>` ইত্যাদি।
- HTML tags remove করে শুধু visible text compare করে।

### Techniques

নির্দিষ্ট SQLi technique test করতে `--technique` ব্যবহার করা হয়।

যেমন:

- Time-based blind payload response timeout তৈরি করলে।
- নির্দিষ্ট SQLi payload type ব্যবহার করতে চাইলে।

শুধু Boolean-based blind, Error-based ও UNION query test করতে:

```
--technique=BEU
```

এতে Time-based blind ও Stacked queries বাদ যাবে।

### UNION SQLi Tuning

1\. UNION column সংখ্যা নির্ধারণ

Vulnerable SQL query-এর column সংখ্যা manually জানা থাকলে `--union-cols` ব্যবহার করা যায়।

```
--union-cols=17
```

2\. Alternative filling value

SQLMap default-এ `NULL` ও random integer দিয়ে dummy value পূরণ করে। এগুলো vulnerable SQL query-এর result-এর সঙ্গে compatible না হলে `--union-char` ব্যবহার করা যায়।

```
--union-char='a'
```

3\. UNION query-এর শেষে FROM যোগ করা

কিছু ক্ষেত্রে UNION query-এর শেষে `FROM <table>` প্রয়োজন হয়, যেমন Oracle-এর ক্ষেত্রে।

এজন্য `--union-from` ব্যবহার করা হয়।

```
--union-from=users
```

সঠিক `FROM` appendix automatically ব্যবহার না হওয়ার কারণ হতে পারে SQLMap আগে DBMS name detect করতে পারেনি।
