## **SQLMap Output Description**


## 1. SQLMap Output কেন গুরুত্বপূর্ণ?

- SQLMap scan-এর output বুঝলে automated SQLi process সম্পর্কে ধারণা পাওয়া যায়।
- কোন ধরনের vulnerability exploit হচ্ছে তা জানা যায়।
- Web application-এর SQLi type report করতে সাহায্য করে।
- SQLMap injection type ও vulnerable parameter identify করার পর manual exploitation-এও কাজে লাগে।

## 2. Log Messages Description

### 1. URL content is stable

Log Message:

```
"target URL content is stable"
```

- একই request বারবার পাঠালে response-এ বড় কোনো পরিবর্তন হয় না।
- Stable response থাকলে SQLi payload-এর কারণে হওয়া difference সহজে identify করা যায়।
- SQLMap unstable target-এর সম্ভাব্য noise remove করার জন্য advanced mechanism ব্যবহার করে।

### 2. Parameter appears to be dynamic

Log Message:

```
"GET parameter 'id' appears to be dynamic"
```

- Parameter-এর value পরিবর্তন করলে response-ও পরিবর্তন হয়।
- এটি নির্দেশ করে parameter database-এর সাথে যুক্ত থাকতে পারে।
- Output `static` হলে target সম্ভবত parameter value process করছে না, অন্তত বর্তমান context-এ।

### 3. Parameter might be injectable

Log Message:

```
"heuristic (basic) test shows that GET parameter 'id' might be injectable (possible DBMS: 'MySQL')"
```

- SQLMap ইচ্ছাকৃতভাবে invalid value পাঠায়, যেমন:\
  `?id=1",)..).))'`
- MySQL error পাওয়া গেলে parameter SQLi vulnerable হতে পারে এবং target MySQL ব্যবহার করতে পারে।
- এটি SQLi-এর proof নয়, শুধু indication।
- পরবর্তী test দিয়ে finding confirm করতে হবে।

### 4. Parameter might be vulnerable to XSS attacks

Log Message:

```
"heuristic (XSS) test shows that GET parameter 'id' might be vulnerable to cross-site scripting (XSS) attacks"
```

- SQLMap-এর মূল কাজ SQLi হলেও এটি XSS-এর জন্যও quick heuristic test চালায়।
- অনেক parameter একসঙ্গে test করার সময় এটি কাজে লাগে।
- বিশেষ করে SQLi না পাওয়া গেলে এই quick check উপকারী।

### 5. Back-end DBMS is '...'

Log Message:

```
"it looks like the back-end DBMS is 'MySQL'. Do you want to skip test payloads specific for other DBMSes? Y/n"
```

- সাধারণত SQLMap সব supported DBMS-এর payload test করে।
- নির্দিষ্ট DBMS ব্যবহারের clear indication পাওয়া গেলে শুধু সেই DBMS-এর payload test করা যায়।

### 6. Level/risk values

Log Message:

```
"for the remaining tests, do you want to include all tests for 'MySQL' extending provided level (1) and risk (1) values? Y/n"
```

- নির্দিষ্ট DBMS identify হলে সেই DBMS-এর জন্য regular test-এর বাইরেও additional test চালানো যায়।
- অর্থাৎ ওই DBMS-এর সব SQLi payload test করা হয়।
- DBMS identify না হলে শুধু top payload-গুলো test করা হয়।

### 7. Reflective values found

Log Message:

```
"reflective value(s) found and filtering out"
```

- ব্যবহৃত payload-এর কিছু অংশ response-এর মধ্যে পাওয়া গেছে।
- এটি automation tool-এর জন্য junk তৈরি করে সমস্যা করতে পারে।
- SQLMap response compare করার আগে filtering mechanism দিয়ে এই junk remove করে।

### 8. Parameter appears to be injectable

Log Message:

```
"GET parameter 'id' appears to be 'AND boolean-based blind - WHERE or HAVING clause' injectable (with --string="luther")"
```

- Parameter injectable বলে মনে হচ্ছে, তবে false-positive হওয়ার সম্ভাবনা আছে।
- Boolean-based blind ও time-based blind SQLi-তে false-positive-এর সম্ভাবনা বেশি।
- তাই scan শেষে SQLMap simple logic checks দিয়ে extensive testing করে false-positive remove করে।
- `with --string="luther"` অর্থ SQLMap response-এর constant string `luther` ব্যবহার করে `TRUE` ও `FALSE` response আলাদা করেছে।
- এতে dynamicity/reflection removal বা fuzzy comparison-এর মতো advanced internal mechanism প্রয়োজন হয় না।
- এ ধরনের finding-কে false-positive হিসেবে বিবেচনা করা যায় না।

### 9. Time-based comparison statistical model

Log Message:

```
"time-based comparison requires a larger statistical model, please wait........... (done)"
```

- SQLMap regular ও intentionally delayed response চিনতে statistical model ব্যবহার করে।
- Model-এর জন্য যথেষ্ট regular response time collect করতে হয়।
- এতে high-latency network environment-এও intentional delay আলাদা করা যায়।

### 10. Extending UNION query injection technique tests

Log Message:

```
"automatically extending ranges for UNION query injection technique tests as there is at least one other (potential) technique found"
```

- UNION-based SQLi detect করতে অন্য SQLi type-এর তুলনায় বেশি request লাগে।
- Testing time কমাতে UNION test-এর request সংখ্যা সাধারণত `10`-এ সীমাবদ্ধ থাকে।
- অন্য কোনো potential SQLi technique পাওয়া গেলে SQLMap UNION test-এর request সংখ্যা বাড়ায়।
- কারণ তখন vulnerability পাওয়ার সম্ভাবনা বেশি থাকে।

### 11. Technique appears to be usable

Log Message:

```
"ORDER BY' technique appears to be usable. This should reduce the time needed to find the right number of query columns. Automatically extending the range for current UNION query injection technique test"
```

- UNION payload পাঠানোর আগে SQLMap `ORDER BY` technique usable কি না check করে।
- এটি heuristic check হিসেবে কাজ করে।
- Usable হলে binary-search approach দিয়ে প্রয়োজনীয় UNION column-এর সংখ্যা দ্রুত identify করা যায়।
- এটি vulnerable query-এর affected table-এর ওপর নির্ভর করে।

### 12. Parameter is vulnerable

- তবে পুরো web application-এর সব potential vulnerability report করতে চাইলে অন্য parameter-গুলোও test চালিয়ে যেতে হবে।
