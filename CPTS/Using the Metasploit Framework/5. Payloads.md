## **Payloads**

The payload is sent together with the exploit. It helps bypass the normal behavior of the vulnerable service and then runs on the target OS. Usually, the final goal is to create a **reverse connection** from the target back to the attacker.

**Types of Payloads**

Metasploit has 3 types of payload modules: Singles , Stagers , Stages

**Singles :** A `Single` payload contains the exploit and the entire shellcode for the selected task. A complete, self-contained payload where everything needed for the task is contained in one payload.

**Example:**

```
windows/shell_bind_tcp
```

→ Everything is sent together → **Shell**

**Stagers :** `Stager` payloads work together with `Stage` payloads to perform a specific task. A small payload whose main job is to **establish communication** and then receive the larger Stage payload.

**Example:**

```
windows/shell/bind_tcp
              ↑
           bind_tcp
           = Stager
```

**Stages :** `Stages` are payload components that are downloaded by stager's modules. The various payload Stages provide advanced features with no size limits, such as Meterpreter, VNC Injection, and others. Payload stages automatically use middle stagers. The larger payload that is delivered by the Stager and contains the main functionality.

**Example:**

```
windows/shell/bind_tcp
       ↑
     shell
     = Stage
```

### **Staged Payloads**

A staged payload splits the payload into multiple parts (stages). Each part performs a specific job, and they work together to ultimately provide remote access. 

**Flow**

```
Exploit
   ↓
Stage0 / Stager
   ↓
Creates connection
   ↓
Stage1 / Stage
   ↓
Main functionality
   ↓
Shell / Meterpreter
```

**Stage0 / Stager** : Stage0 is the initial shellcode sent to the vulnerable service. Its main job is to initialize a connection back to the attacker (a reverse connection) and prepare to receive the larger payload. For example:

```
windows/x64/meterpreter/reverse_tcp
```

Here, `reverse_tcp` is the Stager, which establishes the reverse TCP connection.

**Stage1 / Stage :** After the connection is established, the attacker sends a larger payload (Stage1) into the target's memory. This contains the main functionality and can provide shell access.

```
Stage0 → "Connect + get the rest"
Stage1 → "Here's the actual functionality"
```

**Meterpreter**

Meterpreter is a multi-purpose payload that uses DLL injection and runs completely in the target's memory. It is designed to make the connection stable and harder to detect with simple checks, and the source describes it as persistent across reboots/system changes. It leaves no traces on the hard drive according to the source.

After execution:

```
Meterpreter payload
        ↓
  Meterpreter session
        ↓
 Meterpreter interface
```

### **Searching for Payloads**

**List all payloads : `show payloads`**

`show payloads` can return a **huge list**, making it difficult to find exactly what you want. That's where **`grep`** helps. EX :  Find all Meterpreter payloads

```bash
grep meterpreter show payloads
```

EX : Suppose we want: Meterpreter + reverse TCP:

```bash
grep meterpreter grep reverse_tcp show payloads
```

### Selecting Payloads

After choosing an Exploit module, select a payload using its index number:

```bash
set payload <number>
```

### **Using Payloads**

| Parameter | Meaning |
| --- | --- |
| `RHOSTS` | Target machine's IP address |
| `RPORT` | Target service port; here, SMB uses `445` |
| `LHOST` | Attacker machine's IP address |
| `LPORT` | Port used for the reverse connection; check that it's free |
- Check your attacker IP : `ifconfig`
- Run the exploit : `run`

Meterpreter ≠ Windows CMD : help, getuid etc etc.
