# PHP Filters - [LINK](https://academy.hackthebox.com/app/module/23/section/1492)

PHP wrappers allow access to different I/O streams (standard I/O, memory streams, file descriptors). Through LFI, the `php://filter` wrapper can be used to bypass execution and read the raw backend PHP source code.

## 1. Fuzzing for PHP Targets

Before attempting to read source files, identify valid PHP pages on the target server.

* **Strategy:** Fuzz for `.php` files. Do not ignore `301`, `302`, or `403` status codes—since LFI reads local files directly via the backend, you can often read files that the web server restricts direct access to.
* **Command (ffuf):**
```bash
ffuf -w /opt/useful/seclists/Discovery/Web-Content/directory-list-2.3-small.txt:FUZZ -u http://<SERVER_IP>:<PORT>/FUZZ.php

```



## 2. Standard PHP Inclusion vs. Base64 Filter

* **Standard Inclusion:** By default, including a `.php` file via LFI (e.g., `?language=config`) causes the server to **execute** the PHP code. If the file (like `config.php`) only contains backend settings or database connections, the page will render completely blank.
* **The Solution:** Use the `php://filter` wrapper to encode the file in Base64 *before* it gets executed. This forces the server to return the raw encoded source code instead of running it.

## 3. The `php://filter` Wrapper Structure

To read source code, utilize the following parameters within the wrapper:

* **`resource=`** (Required): Specifies the target file (e.g., `config`).
* **`read=`** (Used to specify the filter): Applies the `convert.base64-encode` filter (a Conversion Filter) to the resource.

There are four different types of filters available for use, which are [String Filters](https://www.php.net/manual/en/filters.string.php), [Conversion Filters](https://www.php.net/manual/en/filters.convert.php), [Compression Filters](https://www.php.net/manual/en/filters.compression.php), and [Encryption Filters](https://www.php.net/manual/en/filters.encryption.php). 

## 4. Source Code Disclosure Exploitation

If the web application automatically appends `.php` to the input parameter, leave the extension off the resource name in your payload.

* **Payload:**
```text
php://filter/read=convert.base64-encode/resource=config

```


* **Example URL:**
```text
http://<SERVER_IP>:<PORT>/index.php?language=php://filter/read=convert.base64-encode/resource=config

```


* **Decoding the Result:** Once the server returns the Base64 string on the webpage, copy the entire string (viewing the page source ensures you don't miss characters) and decode it in your terminal.
* **Command:**
```bash
echo 'PD9waHAK...SNIP...KICB9Ciov' | base64 -d

```
