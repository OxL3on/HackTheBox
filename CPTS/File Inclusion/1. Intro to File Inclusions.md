## **Intro to File Inclusions**

**Local File Inclusion (LFI)** occurs when a web application uses user-controlled HTTP parameters to dynamically load files or resources without proper sanitization. It is most commonly found in templating engines (e.g., loading dynamic headers/footers based on a `?page=` or `?language=` parameter).

**Impact:**

- **Information Disclosure:** Reading sensitive files (e.g., `/etc/passwd`, credentials, API keys).
- **Source Code Disclosure:** Reading back-end source code to find further vulnerabilities.
- **Remote Code Execution (RCE):** If the vulnerable function executes the file content rather than just reading it.

## 1. Vulnerable Injection Vectors

Attackers manipulate URL parameters or paths to change the file being loaded.

- **GET Parameter:** `http://example.com/index.php?language=es` (Change `es` to a malicious path like `../../../etc/passwd`).
- **URL Path (NodeJS/Express):** `http://example.com/about/en` (Change `en` to a malicious path).

## 2. Vulnerable Code Examples by Language

### PHP

When user input is passed directly into inclusion functions without filtering.

- *Vulnerable Code:**PHP
    
    ```
    if (isset($_GET['language'])) {
        include($_GET['language']);
    }
    ```
    
- *Other vulnerable PHP functions:* `include_once()`, `require()`, `require_once()`, `file_get_contents()`.

### NodeJS

When user input dictates the file path read or rendered by the server.

- *Vulnerable Code (fs.readFile):**JavaScript
    
    ```
    if(req.query.language) {
        fs.readFile(path.join(__dirname, req.query.language), function (err, data){
            res.write(data);
        });
    }
    ```
    
- *Vulnerable Code (Express render):**JavaScript
    
    ```
    app.get("/about/:language", function(req, res){
        res.render(`/${req.params.language}/about.html`);
    });
    ```
    

### Java (JSP)

When front-end templates include files based on parameters.

- *Vulnerable Code (include):**Java
    
    ```
    <c:if test="${not empty param.language}">
        <jsp:include file="<%= request.getParameter('language') %>" />
    </c:if>
    ```
    
- *Vulnerable Code (import):**Java
    
    ```
    <c:import url= "<%= request.getParameter('language') %>"/>
    ```
    

### .NET (C#)

When C# functions write file contents to the HTTP response or render partials based on input.

- *Vulnerable Code (Response.WriteFile):**C#
    
    ```
    @if (!string.IsNullOrEmpty(HttpContext.Request.Query['language'])) {
        <% Response.WriteFile("<% HttpContext.Request.Query['language'] %>"); %>
    }
    ```
    
- *Vulnerable Code (Html.Partial & include):**C#
    
    ```
    @Html.Partial(HttpContext.Request.Query['language'])
    <!--#include file="<% HttpContext.Request.Query['language'] %>"-->
    ```
    

## 3. Read vs. Execute vs. Remote URL (Function Capabilities)

It is crucial to know whether a function **Reads** (leads to source code disclosure), **Executes** (leads to RCE), or accepts **Remote URLs** (leads to Remote File Inclusion - RFI).

| **Language** | **Function** | **Read Content** | **Execute** | **Remote URL (RFI)** |
| --- | --- | --- | --- | --- |
| **PHP** | `include()` / `include_once()` | ✅ | ✅ | ✅ |
|  | `require()` / `require_once()` | ✅ | ✅ | ❌ |
|  | `file_get_contents()` | ✅ | ❌ | ✅ |
|  | `fopen()` / `file()` | ✅ | ❌ | ❌ |
| **NodeJS** | `fs.readFile()` | ✅ | ❌ | ❌ |
|  | `fs.sendFile()` | ✅ | ❌ | ❌ |
|  | `res.render()` | ✅ | ✅ | ❌ |
| **Java** | `include` | ✅ | ❌ | ❌ |
|  | `import` | ✅ | ✅ | ✅ |
| **.NET** | `@Html.Partial()` | ✅ | ❌ | ❌ |
|  | `@Html.RemotePartial()` | ✅ | ❌ | ✅ |
|  | `Response.WriteFile()` | ✅ | ❌ | ❌ |
|  | `include` | ✅ | ✅ | ✅ |
