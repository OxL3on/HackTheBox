# Well-Known URIs - [LINK](https://academy.hackthebox.com/app/module/144/section/3078)


The **.well-known** standard (RFC 8615) acts as a centralized, predictable directory within a website's root domain (e.g., `[https://example.com/.well-known/](https://example.com/.well-known/)`) to store critical metadata, security policies, and protocol configurations. It allows automated tools, clients, and security professionals to discover a site's capabilities without guessing custom paths.

**Common IANA Registered URIs**

| URI Suffix | Purpose | Status |
| --- | --- | --- |
| `security.txt` | Contact info and preferred channels for reporting security vulnerabilities (RFC 9116). | Permanent |
| `change-password` | Standardized URL directing password managers and users to a password change page. | Provisional |
| `openid-configuration` | OpenID Connect (OAuth 2.0 layer) configuration metadata. | Permanent |
| `assetlinks.json` | Verifies domain ownership of associated digital assets like mobile apps. | Permanent |
| `mta-sts.txt` | SMTP MTA Strict Transport Security policy to enforce encrypted email routing. | Permanent |

**Strategic Value in Reconnaissance**

Querying these standardized URIs exposes internal configurations, API endpoints, and identity infrastructure that can broaden the attack surface during a penetration test.

**Exploiting the `openid-configuration` Endpoint**

Accessing `/.well-known/openid-configuration` returns a highly structured JSON document detailing how the target handles OAuth/OpenID authentication. Extracting this provides a direct map to critical infrastructure:

* **Authentication Routing:** Reveals exact URLs for user authorization (`authorization_endpoint`) and token issuance (`token_endpoint`).
* **User Data:** Locates the endpoint where user profile data is queried (`userinfo_endpoint`).
* **Cryptographic Keys (`jwks_uri`):** Exposes the JSON Web Key Set, providing the public keys the server uses to sign its authentication tokens.
* **Supported Capabilities:** Lists supported features (e.g., `scopes_supported`) and token formats (`response_types_supported`), outlining the exact boundaries and potential misconfigurations of the identity implementation.
* **Algorithms:** Discloses the specific signing algorithms (e.g., `RS256`) the server accepts, which is crucial for identifying downgrade vulnerabilities.
