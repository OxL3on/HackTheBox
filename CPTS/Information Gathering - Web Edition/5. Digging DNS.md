**DNS Reconnaissance Tools**

| Tool | Primary Use Case |
| --- | --- |
| **dig** | Versatile, detailed manual DNS lookups and troubleshooting. |
| **nslookup** / **host** | Quick, basic manual checks for A, AAAA, and MX records. |
| **dnsenum** / **dnsrecon** | Automated enumeration, brute-forcing, and zone transfers. |
| **fierce** | Recursive search and wildcard detection for subdomain discovery. |
| **theHarvester** | OSINT tool gathering emails and employee data from DNS and other sources. |

**The `dig` Command Cheat Sheet**

`dig` (Domain Information Groper) is the standard CLI tool for querying DNS name servers.

| Command | Action |
| --- | --- |
| `dig domain.com` | Default lookup (Retrieves the IPv4 **A record**). |
| `dig domain.com [TYPE]` | Retrieves a specific record (Replace `[TYPE]` with `MX`, `NS`, `TXT`, `CNAME`, `SOA`, `AAAA`). |
| `dig @1.1.1.1 domain.com` | Queries a **specific name server** (e.g., Cloudflare's 1.1.1.1) instead of your local default. |
| `dig -x 192.168.1.1` | **Reverse lookup**: Finds the hostname associated with an IP address. |
| `dig +trace domain.com` | Shows the full resolution path (Root ➔ TLD ➔ Authoritative). |
| `dig +short domain.com` | Strips all formatting and returns **only the exact answer** (e.g., just the IP). |
| `dig +noall +answer domain.com` | Displays only the formatted Answer section. |
| `dig domain.com ANY` | Requests all available records. *(Note: Often ignored/blocked by modern servers to prevent abuse).* |

**Understanding `dig` Output Structure**

A standard `dig` response is broken into four distinct sections (plus an optional EDNS section).

* **Header:** Shows the query status (e.g., `status: NOERROR`) and flags.
* `qr`: Query Response (this is a reply).
* `rd`: Recursion Desired (you asked the server to fetch the answer if it didn't know it).
* `ad`: Authentic Data.


* **Question Section:** Echos exactly what you asked (e.g., `google.com. IN A`).
* **Answer Section:** The actual result. Example: `google.com. 0 IN A 142.251.47.142`.
* The number (`0` in this example) represents the **TTL (Time-To-Live)** in seconds before the cache expires.


* **Footer:** Contains metadata including the **Query time** (latency), the **SERVER** that responded (e.g., your local ISP router or a public resolver), the **Timestamp**, and the **Message Size** received.
* *(Optional) OPT Pseudosection:* Appears if Extension Mechanisms for DNS (EDNS) are supported for larger message sizes or DNSSEC.

> **Warning:** Excessive automated DNS queries can be detected and rate-limited by defense systems. Always ensure you have permission before running enumeration tools like `dnsenum` or `fierce` against a target.
