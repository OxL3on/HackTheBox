# Virtual Hosts - [LINK](https://academy.hackthebox.com/app/module/144/section/1257)


Virtual hosting allows a single web server (like Apache or Nginx) to host multiple, distinct websites or applications on the exact same IP address.

## 1. Subdomains vs. Virtual Hosts (VHosts)

While often related, they operate at different levels of the networking stack.

| Feature | Subdomain | Virtual Host (VHost) |
| --- | --- | --- |
| **Layer** | DNS Level | Web Server Level |
| **Definition** | An extension of a main domain (e.g., `dev.example.com`). | A server config block dictating how to route incoming requests. |
| **Public Visibility** | Usually has a public DNS `A` or `CNAME` record. | Can exist entirely hidden on the server without a public DNS record. |
| **Accessing Hidden ones** | Requires a DNS brute-force. | Requires modifying your local `/etc/hosts` file or fuzzing the HTTP `Host` header. |

## 2. Types of Virtual Hosting

1. **Name-Based (Most Common):** Relies entirely on the HTTP `Host` header sent by the browser. The server reads the header (e.g., `Host: admin.example.com`) and serves the corresponding directory.
2. **IP-Based:** Assigns a unique, dedicated IP address to every single website on the server. Does not rely on the `Host` header, but is expensive and hard to scale.
3. **Port-Based:** Hosts different sites on different ports of the same IP (e.g., `[http://example.com:80](http://example.com:80)` vs `[http://example.com:8080](http://example.com:8080)`).

**Apache Name-Based Config Example:**

```apache
<VirtualHost *:80>
    ServerName admin.inlanefreight.htb
    DocumentRoot /var/www/admin
</VirtualHost>

```

## 3. VHost Enumeration (Fuzzing)

Because VHosts can exist without public DNS records, you must proactively test a web server by altering the HTTP `Host` header and analyzing the response.

**Top Tools:** `gobuster`, `ffuf`, `feroxbuster`.

### Using Gobuster for VHost Discovery

Gobuster automates the process of swapping out the `Host` header using a wordlist.

**The Command:**

```bash
gobuster vhost -u http://<TARGET_IP> -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-20000.txt --append-domain

```

**Key Flags to Remember:**

* `vhost`: Tells Gobuster to use Virtual Host discovery mode.
* `-u http://<TARGET_IP>`: The target IP address.
* `-w <wordlist>`: The wordlist of potential prefixes (e.g., dev, admin, test).
* `--append-domain`: **Crucial for newer Gobuster versions.** It appends the base domain to the wordlist (e.g., turning `admin` into `admin.target.com` inside the header).
* `-t 50`: Increases threads for faster scanning.
* `-k`: Ignores SSL/TLS certificate errors.
* `-o results.txt`: Saves output to a file.

*Note: Once you find a hidden VHost (e.g., `forum.inlanefreight.htb`), you must manually add it to your `/etc/hosts` file (`<TARGET_IP> forum.inlanefreight.htb`) to access it in your browser.*
