# DNS Zone Transfers - [LINK](https://academy.hackthebox.com/app/module/144/section/1255)


A **DNS Zone Transfer (AXFR)** is a mechanism used to replicate DNS records wholesale from a primary name server to a secondary name server to maintain redundancy and consistency.

## 1. The Vulnerability

By default, zone transfers should be strictly limited to trusted secondary servers. A critical vulnerability occurs when a DNS server is misconfigured to allow **any** client to request a zone transfer.

If successful, the server dumps its entire zone file to the attacker, providing a complete map of the target's external (and sometimes internal) infrastructure.

## 2. What an Unauthorised Transfer Leaks

* **Hidden Subdomains:** Unlinked development servers, staging environments, and administrative portals.
* **IP Addresses:** The exact network coordinates of every mapped asset within that domain.
* **Infrastructure Details:** Service configurations (SRV records), security policies (TXT records), and routing rules.

## 3. How a Zone Transfer Works

1. **Request:** Client sends an `AXFR` (Full Zone Transfer) request.
2. **SOA Transfer:** Primary server responds with its Start of Authority (SOA) record (contains the zone's serial number).
3. **Data Transmission:** Primary server transmits every DNS record (A, CNAME, MX, TXT, NS) one by one.
4. **Completion:** Primary server signals the end of the transfer.
5. **Acknowledgement:** Client replies with an ACK.

## 4. Exploiting Zone Transfers

To attempt a zone transfer, you must explicitly query the target's **authoritative name server** (not your local ISP resolver) using the `axfr` flag.

* **Syntax:**
```bash
dig axfr @<NameServer> <Domain>

```


* **Example:**
```bash
dig axfr @nsztm1.digi.ninja zonetransfer.me

```



*(Note: If the server is properly secured, the query will fail. If vulnerable, your terminal will flood with a complete list of every DNS record associated with that domain).*

## 5. Remediation (Blue Team)

Network administrators must configure their DNS servers (e.g., BIND, Windows DNS) to strictly limit zone transfers to the specific IP addresses of known, trusted secondary DNS servers.
