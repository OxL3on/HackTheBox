# DNS - [LINK](https://academy.hackthebox.com/app/module/144/section/3074)


The Domain Name System (DNS) acts as the internet's GPS, translating human-readable domain names into machine-readable IP addresses. For penetration testers, DNS data is a critical roadmap that exposes a target's internal infrastructure, third-party services, and hidden assets.

**The DNS Resolution Flow**
When you request a website, the translation happens in a specific "relay" sequence:

* **1. Local Cache:** Your computer checks its own memory first.
* **2. DNS Resolver:** If not cached, the request goes to your ISP's resolver.
* **3. Root Server:** The resolver queries the Root Server, which identifies the correct TLD.
* **4. TLD Server:** The Top-Level Domain server (e.g., `.com`) directs the resolver to the domain's Authoritative Server.
* **5. Authoritative Server:** The final stop; it holds the actual IP address for the requested domain and returns it.

**The Hosts File (Local Override)**
A local text file that forces a specific IP-to-hostname mapping, bypassing the standard DNS process entirely. It is heavily used in pentesting to route traffic to local or rogue servers.

* **Windows path:** `C:\Windows\System32\drivers\etc\hosts`
* **Linux/macOS path:** `/etc/hosts`
* **Format:** `[IP Address] [Hostname]` (e.g., `127.0.0.1 myapp.local`)

**Essential DNS Record Types**
DNS "zones" (administrative containers for a domain) are managed via zone files containing these core records. *(Note: You will often see "IN" in these records, which simply stands for "Internet" protocol).*

| Record Type | Name | Purpose | Example / Note |
| --- | --- | --- | --- |
| **A** | Address | Maps a hostname to an **IPv4** address. | `www IN A 192.0.2.1` |
| **AAAA** | IPv6 Address | Maps a hostname to an **IPv6** address. | `www IN AAAA 2001:db8...` |
| **CNAME** | Canonical Name | Creates an alias, pointing one hostname to another. | `blog IN CNAME web.target.com` |
| **MX** | Mail Exchange | Specifies the servers responsible for handling email. | `IN MX 10 mail.target.com` |
| **NS** | Name Server | Delegates the domain to an authoritative name server. | `IN NS ns1.target.com` |
| **TXT** | Text | Arbitrary text used for verification or security (e.g., SPF). | `IN TXT "v=spf1 mx -all"` |
| **SOA** | Start of Authority | Admin details, primary name server, and TTL timers. | `IN SOA ns1.target.com admin...` |
| **SRV** | Service | Defines the hostname and **port** for specific services. | `_sip._udp IN SRV 10 5 5060...` |
| **PTR** | Pointer | Reverse DNS: Maps an IP address back to a hostname. | `1.2.0.192.in-addr.arpa IN PTR...` |

**Strategic Value for Reconnaissance**

* **Uncovering Hidden Assets:** CNAME records often point to forgotten, vulnerable development servers (e.g., `dev.target.com`).
* **Mapping Infrastructure:** NS records reveal the target's hosting and cloud providers. Specific A records can map out load balancers and network architecture.
* **Monitoring Operational Changes:** A new `vpn.target.com` sub-domain reveals a fresh entry point. TXT records routinely leak third-party software usage (e.g., `_1password=...` hints at the corporate password manager, giving you a direct angle for a phishing campaign).
