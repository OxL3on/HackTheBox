# robots.txt - [LINK](https://academy.hackthebox.com/app/module/144/section/3077)


The **`robots.txt`** file (located in the web root, e.g., `[example.com/robots.txt](https://example.com/robots.txt)`) is a public text document that acts as an "etiquette guide" for web crawlers. It uses the Robots Exclusion Standard to tell automated bots which areas of a website they are allowed or forbidden to visit.

While legitimate search engine bots (like Googlebot) respect these rules, the file is not a strict security control—malicious actors can easily ignore it.

## Anatomy of a robots.txt File

The file is structured into records separated by blank lines. Each record starts with a `User-agent` (the specific bot being addressed) followed by its instructions.

| Directive | Purpose | Example |
| --- | --- | --- |
| **User-agent** | Defines which bot the rules apply to. A wildcard (`*`) targets all bots. | `User-agent: *` or `User-agent: Googlebot` |
| **Disallow** | Specifies paths or directories the bot should NOT crawl. | `Disallow: /admin-panel/` |
| **Allow** | Explicitly permits access to specific paths, overriding broader `Disallow` rules. | `Allow: /public-assets/` |
| **Crawl-delay** | Sets a mandatory waiting period (in seconds) between requests to prevent server overload. | `Crawl-delay: 10` |
| **Sitemap** | Points to an XML file containing a full map of the site's public URLs. | `Sitemap: [https://target.com/sitemap.xml](https://target.com/sitemap.xml)` |

## Strategic Value for Web Reconnaissance

For security professionals and penetration testers, `robots.txt` acts like a roadmap to the target's hidden infrastructure.

* **The "Treasure Map" Effect:** Administrators often mistakenly use `Disallow` as a security measure to hide sensitive areas. By reading the `Disallow` paths, you immediately discover high-value targets like administrative portals (`/admin/`), development environments (`/staging/`), or sensitive endpoints (`/api/v2/`).
* **Uncovering Site Architecture:** It reveals site structures and directories that are not publicly linked in the main website navigation.
* **Identifying Honeypots:** Some defenders intentionally list fake sensitive directories (e.g., `Disallow: /fake-admin/`) as crawler traps. If a scanner touches that endpoint, their IP address gets automatically banned.

## Example Analysis

```text
User-agent: *
Disallow: /backend-admin/
Disallow: /private/
Allow: /public/

User-agent: Bingbot
Crawl-delay: 5

Sitemap: https://www.example.com/sitemap.xml

```

**Takeaway:** A pentester reading this immediately knows to manually navigate to `[example.com/backend-admin/](https://example.com/backend-admin/)` and `[example.com/private/](https://example.com/private/)` to look for login portals or exposed sensitive data, completely bypassing the need to brute-force directory names.
