# Environment Enumeration - [LINK](https://academy.hackthebox.com/app/module/51/section/1592)



হ্যাকিংয়ের দুনিয়ায় একটি কথা আছে: "Enumeration is the key" অর্থাৎ তথ্য সংগ্রহ করাই হলো সফলতার মূল চাবিকাঠি। সিস্টেমে ঢোকার পর প্রথম কাজই হলো চারপাশটা ভালো করে চেনা। **[LinPEAS](https://github.com/carlospolop/PEASS-ng/tree/master/linPEAS)** বা **[LinEnum](https://github.com/rebootuser/LinEnum)** এর মতো অটোমেটেড টুল আছে ঠিকই, কিন্তু ম্যানুয়ালি বা নিজে নিজে কমান্ড দিয়ে সিস্টেমের অবস্থা বুঝতে পারাটা একজন হ্যাকারের জন্য সবচেয়ে জরুরি।



### ১. Situational Awareness (সিস্টেমের প্রাথমিক অবস্থা বোঝা)

ধরে নিন, আপনি একটি ওয়েবসাইট হ্যাক করে রিভার্স শেল (Reverse Shell) পেলেন। এখন আপনি একটি লিনাক্স টার্মিনালের ভেতরে আছেন। প্রথমেই ৫টি বেসিক কমান্ড দিয়ে আমরা চারপাশটা বুঝে নিব:

* **`whoami`**: আমি বর্তমানে কোন ইউজারের হয়ে কাজ করছি?
* **`id`**: আমার ইউজার কোন কোন গ্রুপের সদস্য? (যেমন: সাধারণ গ্রুপ নাকি অ্যাডমিন গ্রুপ?)
* **`hostname`**: এই সার্ভার বা কম্পিউটারের নাম কী?
* **`ifconfig` বা `ip a**`: এই মেশিনের আইপি অ্যাড্রেস কত? এটি অন্য কোনো সাবনেট বা নেটওয়ার্কের সাথে যুক্ত আছে কিনা?
* **`sudo -l`**: আমার ইউজার কি কোনো পাসওয়ার্ড ছাড়াই রুট (root) হিসেবে কোনো কমান্ড চালাতে পারবে? যদি পারে, তবে খুব সহজেই `sudo su` দিয়ে পুরো সিস্টেমের দখল নেওয়া যায়!

### ২. ধাপে ধাপে গভীর তথ্য সংগ্রহ (Step-by-Step Enumeration)

এবার আমরা সিস্টেমের ভেতরের আরও গভীরে যাব।

**ক. অপারেটিং সিস্টেম (OS) এবং কার্নেল (Kernel):**
সিস্টেমটি আসলে কী? Ubuntu, CentOS নাকি অন্য কিছু?

* **পেলোড:** `cat /etc/os-release`
* **কাজ:** এটি আপনাকে লিনাক্সের ভার্সন বলে দিবে (যেমন: Ubuntu 20.04.4 LTS)। যদি ভার্সনটি অনেক পুরোনো হয়, তবে ইন্টারনেটে আগে থেকেই থাকা এক্সপ্লয়েট দিয়ে এটি হ্যাক করা যেতে পারে।
* **পেলোড:** `uname -a`
* **কাজ:** এটি কার্নেল ভার্সন দেখাবে। পুরোনো কার্নেল হলে সরাসরি রুট অ্যাক্সেস পাওয়ার সুযোগ থাকে।

**খ. এনভায়রনমেন্ট এবং পাথ (Environment & PATH):**

* **পেলোড:** `echo $PATH`
* **কাজ:** আপনি যখন টার্মিনালে কোনো কমান্ড লেখেন (যেমন `ls`), সিস্টেম এই PATH এর ভেতরে থাকা ফোল্ডারগুলোতে গিয়ে সেই কমান্ডটি খোঁজে। এই PATH যদি ভুলভাবে কনফিগার করা থাকে, তবে হ্যাকাররা ফেক কমান্ড বানিয়ে রুট অ্যাক্সেস নিতে পারে।
* **পেলোড:** `env`
* **কাজ:** সিস্টেমের সব এনভায়রনমেন্ট ভেরিয়েবল দেখায়। মাঝে মাঝে অ্যাডমিনরা ভুল করে এখানে ডেটাবেসের পাসওয়ার্ড সেভ করে রাখে!

**গ. সিপিইউ এবং শেল (CPU & Shells):**

* **পেলোড:** `lscpu` (প্রসেসর বা সিপিইউ সম্পর্কে বিস্তারিত তথ্য দেয়)।
* **পেলোড:** `cat /etc/shells` (সিস্টেমে কী কী ধরনের টার্মিনাল বা শেল আছে তা দেখায়। যেমন: bash, sh, tmux, screen)।

We should also check to see if any defenses are in place and we can enumerate any information about them. Some things to look for include:

  - Exec Shield
  - iptables
  - AppArmor
  - SELinux
  - Fail2ban
  - Snort
  - Uncomplicated Firewall (ufw)
    
Often we will not have the privileges to enumerate the configurations of these protections but knowing what, if any, are in place, can help us not to waste time on certain tasks.


**ঘ. ড্রাইভ এবং হার্ডডিস্ক (Drives):**

* **পেলোড:** `lsblk`
* **কাজ:** মেশিনে কয়টি হার্ডডিস্ক বা ড্রাইভ লাগানো আছে তা দেখাবে। এমন কোনো ড্রাইভ থাকতে পারে যেখানে গুরুত্বপূর্ণ ব্যাকআপ রাখা আছে।
* The command `lpstat` can be used to find information about any printers attached to the system.
* **পেলোড:** `cat /etc/fstab`
* **কাজ:** কোন ড্রাইভ সিস্টেমের কোথায় যুক্ত (Mount) করা আছে, তার তালিকা। এখানেও মাঝে মাঝে পাসওয়ার্ড পাওয়া যায়।

**ঙ. নেটওয়ার্ক এবং রাউটিং (Network):**

* **পেলোড:** `route` বা `netstat -rn` (মেশিনটি অন্য কোন নেটওয়ার্কের সাথে যুক্ত তা দেখার জন্য)।
* **পেলোড:** `arp -a` (এই মেশিনটি রিসেন্টলি অন্য আর কোন কোন মেশিনের সাথে যোগাযোগ করেছে, তার লিস্ট)।
* In a domain environment we'll definitely want to check /etc/resolv.conf if the host is configured to use internal DNS we may be able to use this as a starting point to query the Active Directory environment.

### ৩. ইউজার এবং গ্রুপ (Users & Groups)

সিস্টেমে কে কে আছে, তা জানা খুবই জরুরি।

**ক. সব ইউজারের লিস্ট দেখা:**

* **পেলোড:** `cat /etc/passwd`
* **ব্যাখ্যা:** এই ফাইলে সিস্টেমের সব ইউজারের তথ্য থাকে। প্রতিটি লাইন একটি নির্দিষ্ট ফরম্যাটে থাকে:
`Username : Password(x) : UID : GID : Info : Home Directory : Shell`
*(যেমন: `root:x:0:0:root:/root:/bin/bash`)*

**খ. পাসওয়ার্ডের হ্যাশ (Hash Algorithms Table):**
মাঝে মাঝে `/etc/passwd` বা `/etc/shadow` ফাইলে পাসওয়ার্ডগুলো হ্যাশ (Hash) করা অবস্থায় থাকে। হ্যাশের শুরুর অংশ দেখে বোঝা যায় এটি কোন অ্যালগরিদম দিয়ে লক করা:

| অ্যালগরিদম (Algorithm) | হ্যাশের শুরু (Starts with) |
| --- | --- |
| **MD5** | `$1$...` |
| **SHA-256** | `$5$...` |
| **SHA-512** | `$6$...` |
| **BCrypt** | `$2a$...` |
| **Scrypt** | `$7$...` |
| **Argon2** | `$argon2i$...` |
| *(হ্যাকাররা এই হ্যাশগুলো কপি করে নিজেদের পিসিতে নিয়ে ক্র্যাক করার চেষ্টা করে)।* |  |

**গ. লগইন করতে পারে এমন ইউজার:**

* **পেলোড:** `grep "sh$" /etc/passwd`
* **কাজ:** সিস্টেমে অনেক ডামি ইউজার থাকে। এই কমান্ডটি শুধু তাদেরকেই ফিল্টার করে দেখাবে যাদের সত্যিকারের শেল (যেমন: bash বা sh) আছে।

**ঘ. গ্রুপ চেক করা:**

* **পেলোড:** `cat /etc/group` (সিস্টেমের সব গ্রুপ দেখাবে)।
* **পেলোড:** `getent group sudo` (অ্যাডমিন বা sudo গ্রুপে কে কে আছে তা দেখাবে)।

### ৪. লুকানো এবং টেম্পোরারি ফাইল (Hidden & Temp Files)

**ক. লুকানো ফাইল (Hidden Files):**
লিনাক্সে যে ফাইলের নামের আগে ডট (`.`) থাকে, সেগুলো সাধারণ `ls` কমান্ডে দেখা যায় না।

* **পেলোড:** `find / -type f -name ".*" -exec ls -l {} \; 2>/dev/null`
* **কাজ:** এটি পুরো সিস্টেম খুঁজে বের করবে কোথায় কোথায় লুকানো ফাইল আছে (যেমন `.bash_history` যেখানে ইউজারের টাইপ করা সব কমান্ড সেভ থাকে)।

**খ. টেম্পোরারি ফোল্ডার (Temporary Directories):**
সিস্টেমে ৩টি ফোল্ডার থাকে যেখানে সবাই ফাইল রাখতে বা পড়তে পারে: `/tmp`, `/var/tmp`, এবং `/dev/shm`।

* **পেলোড:** `ls -l /tmp /var/tmp /dev/shm`
* **পার্থক্য (খুবই গুরুত্বপূর্ণ):**
* `/tmp`: এখানে রাখা ফাইলগুলো **১০ দিন** পর বা কম্পিউটার রিস্টার্ট দিলে মুছে যায়।
* `/var/tmp`: এখানে রাখা ফাইলগুলো **৩০ দিন** পর্যন্ত থাকে এবং রিস্টার্ট দিলেও মুছে যায় না। (হ্যাকাররা তাদের হ্যাকিং টুলস বা স্ক্রিপ্ট লুকিয়ে রাখার জন্য এই ফোল্ডারগুলো বেশি ব্যবহার করে)।

### সারমর্ম (Moving On)

এই সেকশনের মূল উদ্দেশ্য হলো সিস্টেমটাকে আপনার নিজের হাতের তালুর মতো চেনা। রিয়েল-ওয়ার্ল্ড পেনিট্রেশন টেস্টিংয়ে আমরা সময় বাঁচাতে **LinPEAS** টুল চালাই ঠিকই, কিন্তু যখন কোনো টুল কাজ করে না বা সিস্টেমে আপলোড করা যায় না, তখন এই ম্যানুয়াল কমান্ডগুলোই আপনাকে বাঁচাবে। পরবর্তী ধাপে আমরা এই তথ্যগুলো ব্যবহার করে ফাইল পারমিশন চেক করব এবং সিস্টেমের রুট (Root) অ্যাক্সেস নেওয়ার চেষ্টা করব!
