# Linux Hardening - [LINK](https://academy.hackthebox.com/app/module/51/section/479)


সঠিকভাবে লিনাক্স হার্ডেনিং বা সিকিউরিটি কনফিগারেশন করলে লোকাল প্রিভিলেজ এসকালেশনের (Local Privilege Escalation) সুযোগ প্রায় পুরোপুরি নির্মূল করা সম্ভব। কোনো অ্যাটাকার যেন রুট-লেভেল অ্যাক্সেস না পায়, সেই ঝুঁকি কমানোর জন্য অন্তত নিচের পদক্ষেপগুলো নেওয়া উচিত।

## ১. Updates and Patching (আপডেট এবং প্যাচিং)

পুরোনো লিনাক্স কার্নেল এবং থার্ড-পার্টি সার্ভিসগুলোর অনেক পরিচিত দুর্বলতা থাকে, যেগুলোর জন্য আগে থেকেই এক্সপ্লয়ট তৈরি করা থাকে। নিয়মিত সিস্টেম আপডেট করলে এই ধরনের "সহজ লক্ষ্যবস্তু" (Low hanging fruit) বা সাধারণ দুর্বলতাগুলো দূর হয়ে যায়।

* **Ubuntu/Debian:** ഉবুন্টু ১৮.০৪ এর পর থেকে ডিফল্টভাবে `unattended-upgrades` প্যাকেজ ইন্সটল থাকে, যা অটোমেটিক আপডেট ম্যানেজ করে।
* **Red Hat/CentOS:** রেড হ্যাট ভিত্তিক সিস্টেমে একই কাজের জন্য `yum-cron` প্যাকেজ ব্যবহার করা হয়।

## ২. Configuration Management (কনফিগারেশন ম্যানেজমেন্ট)

নিচে কিছু সাধারণ এবং অত্যন্ত কার্যকরী হার্ডেনিং স্টেপ দেওয়া হলো:

* **SUID এবং Writable Files:** যেসব ফাইলে সবার লেখার পারমিশন (world-writable) আছে এবং যেসব বাইনারিতে SUID বিট সেট করা আছে, সেগুলো নিয়মিত অডিট বা চেক করা।
* **অ্যাবসলিউট পাথ (Absolute Path):** ক্রন জব (Cron jobs) এবং সুডো (sudo) পারমিশন সেট করার সময় প্রোগ্রামের শুধু নাম না লিখে তার সম্পূর্ণ পাথ (যেমন: `apache2` এর বদলে `/usr/sbin/apache2`) ব্যবহার করা।
* **পাসওয়ার্ড সুরক্ষা:** সবার পড়ার পারমিশন আছে এমন কোনো ফাইলে ক্লিয়ারটেক্সট বা প্লেইনটেক্সটে পাসওয়ার্ড সেভ না করা।
* **ক্লিনআপ:** ইউজারদের হোম ডিরেক্টরি এবং ব্যাশ হিস্ট্রি (bash history) নিয়মিত ক্লিন করা।
* **লাইব্রেরি মডিফিকেশন বন্ধ করা:** সাধারণ ইউজাররা যেন প্রোগ্রামের ব্যবহৃত কোনো কাস্টম লাইব্রেরি (Shared libraries) মডিফাই করতে না পারে, তা নিশ্চিত করা।
* **অপ্রয়োজনীয় সার্ভিস রিমুভ করা:** যেসব প্যাকেজ বা সার্ভিস দরকার নেই, সেগুলো সিস্টেম থেকে রিমুভ করে অ্যাটাক সারফেস (Attack surface) কমানো।
* **SELinux:** সিস্টেমে অতিরিক্ত অ্যাক্সেস কন্ট্রোল যোগ করার জন্য SELinux ইমপ্লিমেন্ট করার কথা বিবেচনা করা।

## ৩. User Management (ইউজার ম্যানেজমেন্ট)

সিস্টেমে সাধারণ এবং অ্যাডমিন ইউজারের সংখ্যা সীমিত রাখতে হবে। কে কখন লগইন করার চেষ্টা করছে (সফল বা ব্যর্থ), তার লগ রাখা এবং মনিটর করা উচিত।

* **পাসওয়ার্ড পলিসি:** স্ট্রং পাসওয়ার্ড পলিসি নিশ্চিত করা। ঘন ঘন পাসওয়ার্ড পরিবর্তনের চেয়ে লম্বা এবং মনে রাখা যায় এমন পাসফ্রেজ (Passphrases) ব্যবহারে উৎসাহ দেওয়া।
* **পাসওয়ার্ড রিইউজ বন্ধ করা:** PAM মডিউলের সাথে `/etc/security/opasswd` ব্যবহার করে ইউজারদের পুরোনো পাসওয়ার্ড পুনরায় ব্যবহার করা থেকে বিরত রাখা।
* **অপ্রয়োজনীয় গ্রুপ:** ইউজারদের এমন কোনো গ্রুপে রাখা উচিত নয় যা তাদের দৈনন্দিন কাজের জন্য প্রয়োজন নেই।
* **অটোমেশন:** Puppet, SaltStack, Zabbix এবং Nagios এর মতো টুল ব্যবহার করে এই কনফিগারেশন চেকিংগুলো অটোমেট করা যায়। Zabbix এর মতো টুলে চেকসাম ভেরিফিকেশনের (`vfs.file.cksum`) সুবিধাও থাকে, যা দিয়ে কোনো সেনসিটিভ ফাইল পরিবর্তন হয়েছে কিনা তা ধরা যায়।

## ৪. Audit (অডিট বা নিরীক্ষা)

সিস্টেমের কনফিগারেশন এবং সিকিউরিটি নিয়মিত চেক করা উচিত। সিকিউরিটি স্ট্যান্ডার্ড ঠিক করার জন্য DISA STIGs, ISO27001, PCI-DSS এবং HIPAA এর মতো ফ্রেমওয়ার্কগুলো গাইডলাইন হিসেবে ব্যবহার করা যেতে পারে।

তবে মনে রাখতে হবে, অডিট করা মানেই পেনিট্রেশন টেস্টিং নয়। এটি শুধু "চেকলিস্ট" মেলানোর কোনো কাজ হওয়া উচিত নয়। বরং এটি নিয়মিত ভালনারেবিলিটি স্ক্যানিং এবং পেনিট্রেশন টেস্টিংয়ের পাশাপাশি সিস্টেমকে আরও সুরক্ষিত করার একটি অংশ।

## ৫. Lynis (লিনিস টুল দিয়ে অডিট)

ইউনিক্স-ভিত্তিক সিস্টেম (Linux, macOS ইত্যাদি) অডিট করার জন্য **Lynis** একটি অত্যন্ত চমৎকার টুল। এটি সিস্টেমের বর্তমান কনফিগারেশন চেক করে এবং বিভিন্ন সিকিউরিটি স্ট্যান্ডার্ডের ওপর ভিত্তি করে হার্ডেনিং টিপস দেয়।

গিটহাব থেকে টুলটি নামানোর পর নিচের কমান্ড দিয়ে পুরো সিস্টেম অডিট করা যায়:

```bash
htb_student@NIX02:~$ ./lynis audit system

```

**আউটপুট উদাহরণ:**
লিনিস টুলটি স্ক্যান করার পর মূলত তিন ধরনের তথ্য প্রদান করে।

**ক. Warnings (সতর্কবার্তা):**
যেখানে সরাসরি কোনো বড় ভুল বা সিকিউরিটি রিস্ক পাওয়া যায়।

```text
Warnings (2):
  ----------------------------
  ! Found one or more cronjob files with incorrect file permissions (see log for details) [SCHD-7704] 
      https://cisofy.com/lynis/controls/SCHD-7704/

  ! systemd-timesyncd never successfully synchronized time [TIME-3185] 
      https://cisofy.com/lynis/controls/TIME-3185/

```

**খ. Suggestions (পরামর্শ):**
কীভাবে সিস্টেম আরও সুরক্ষিত করা যায়, তার পরামর্শ।

```text
Suggestions (53):
  ----------------------------
  * Set a password on GRUB boot loader to prevent altering boot configuration (e.g. boot in single user mode without password) [BOOT-5122] 
      https://cisofy.com/lynis/controls/BOOT-5122/

  * Run pwck manually and correct any errors in the password file [AUTH-9228] 
      https://cisofy.com/lynis/controls/AUTH-9228/

```

**গ. Scan Details (স্ক্যানের সারাংশ):**
সিস্টেমের বর্তমান সিকিউরিটি বা হার্ডেনিং ইনডেক্স (স্কোর) কত, তা দেখায়।

```text
Lynis security scan details:

  Hardening index : 60 [############        ]
  Tests performed : 256
  Plugins enabled : 2

```

*নোট: টুলটি সাধারণ ইউজার হিসেবে চালালে অনেক কিছু চেক করতে পারে না। রুট (root) ইউজার হিসেবে চালালে এটি আরও গভীরভাবে অডিট করতে পারে।*
