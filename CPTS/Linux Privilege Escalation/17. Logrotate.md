# Logrotate - [LINK](https://academy.hackthebox.com/app/module/51/section/1589)


Logrotate is a system utility designed to automatically archive, compress, rename, or delete old log files to prevent disk space exhaustion. It is typically executed periodically via cron and relies on global settings defined in `/etc/logrotate.conf` alongside service-specific configurations located in `/etc/logrotate.d/`.

## Key Configuration Files

| File/Directory | Description |
| --- | --- |
| `/etc/logrotate.conf` | Global configuration file defining default behaviors (e.g., rotation frequency, compression, creation of new files). |
| `/etc/logrotate.d/` | Directory containing service-specific rotation configurations (e.g., dpkg, apt, samba). |
| `/var/lib/logrotate.status` | Status file tracking the dates of the last rotation for individual log files. Editing this file or using the `-f`/`--force` flag can force a rotation. |

## Identifying the Vulnerability

If logrotate is running a susceptible version and specific permissions exist, it can be exploited to achieve root privilege escalation. To exploit logrotate, three critical requirements must be met:

1. **Write Permissions:** The attacker must have write access to the target log files.
2. **Execution Context:** Logrotate must be executing as a privileged user (typically root).
3. **Vulnerable Version:** The system must be running one of the following vulnerable versions: `3.8.6`, `3.11.0`, `3.15.0`, or `3.18.0`.

## Exploitation with Logrotten

If the prerequisites are satisfied, a pre-built exploit named `logrotten` can be utilized. This tool must be compiled on a system with a similar kernel or directly on the target machine if a compiler is available.

Identify whether logrotate is configured to `create` or `compress` files. The `logrotten` exploit execution must be adapted based on this specific configuration.

```bash

```
