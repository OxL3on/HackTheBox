## ১. PATH আসলে কী?

লিনাক্সে **PATH** হলো একটি এনভায়রনমেন্ট ভেরিয়েবল (Environment Variable)। সহজ কথায়, এটি হলো কিছু নির্দিষ্ট ফোল্ডারের একটি লিস্ট।

যখন আপনি টার্মিনালে কোনো কমান্ড টাইপ করেন (যেমন: `cat /tmp/test.txt`), তখন সিস্টেম ওই কমান্ডের আসল ফাইলটা কোথায় আছে তা জানার জন্য এই PATH লিস্টে থাকা ফোল্ডারগুলোতে খোঁজে। PATH থাকার কারণেই আমাদের প্রতিটি কমান্ডের পুরো ঠিকানা (Absolute Path) লিখতে হয় না (যেমন `cat` এর বদলে `/bin/cat` লিখতে হয় না)।

আপনার বর্তমান PATH কী আছে তা দেখার জন্য নিচের কমান্ডটি ব্যবহার করতে পারেন:

```bash
htb_student@NIX02:~$ echo $PATH

```

**আউটপুট:**

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games

```

এখানে কোলন (`:`) দিয়ে প্রতিটি ফোল্ডারের নাম আলাদা করা আছে।

## ২. PATH এর স্বাভাবিক ব্যবহার

PATH-এর ভেতরে থাকা কোনো ফোল্ডারে (যেমন: `/usr/local/sbin`) আপনি যদি কোনো নতুন স্ক্রিপ্ট বা প্রোগ্রাম তৈরি করেন, তবে সিস্টেমের যেকোনো জায়গা থেকে আপনি সেই প্রোগ্রামটি রান করতে পারবেন।

যেমন, নিচে `conncheck` নামের একটি স্ক্রিপ্ট `/usr/local/sbin` ফোল্ডারে রাখা আছে:

```bash
htb_student@NIX02:~$ pwd && conncheck 

```

**আউটপুট:**

```text

Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name
tcp        0      0 0.0.0.0:22              0.0.0.0:*               LISTEN      1189/sshd       
tcp        0     88 10.129.2.12:22          10.10.14.3:43218        ESTABLISHED 1614/sshd: mrb3n [p
tcp6       0      0 :::22                   :::*                    LISTEN      1189/sshd       
tcp6       0      0 :::80                   :::*                    LISTEN      1304/apache2    

```

যেহেতু স্ক্রিপ্টটি PATH-এ থাকা একটি ফোল্ডারে আছে, তাই আমরা যদি অন্য কোনো ফোল্ডারে (যেমন `/tmp`) গিয়েও কমান্ডটি দিই, তবুও সেটি ঠিকঠাক কাজ করবে:

```bash

htb_student@NIX02:~$ pwd && conncheck 

```

## ৩. হ্যাকিংয়ের শুরু: PATH-এ `.` (ডট) যোগ করা

লিনাক্সে `.` (ডট) মানে হলো **"বর্তমান ফোল্ডার" (Current Working Directory)**।

যদি কোনো ইউজারের PATH-এ `.` যোগ করা থাকে, তবে এটি একটি বড় ধরনের সিকিউরিটি রিস্ক তৈরি করে। কারণ লিনাক্স সবসময় PATH লিস্টের বাম থেকে ডান দিকে কমান্ড খোঁজে। যদি `.` একদম শুরুতে থাকে, তবে সিস্টেম আসল কমান্ডগুলো চেক করার আগেই আপনার বর্তমান ফোল্ডারে কমান্ডটি খুঁজবে।

নিচের উদাহরণে আমরা PATH এর শুরুতে `.` যোগ করছি:

```bash
htb_student@NIX02:~$ PATH=.:${PATH}
htb_student@NIX02:~$ export PATH
htb_student@NIX02:~$ echo $PATH

```

**আউটপুট:**

```text
.:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games

```

খেয়াল করুন, এখন PATH এর একদম শুরুতে `.:` যুক্ত হয়েছে।

## ৪. Path Abuse অ্যাটাক (প্র্যাকটিক্যাল উদাহরণ)

যেহেতু সিস্টেম এখন সবার আগে আমাদের বর্তমান ফোল্ডারে কমান্ড খুঁজবে, আমরা সাধারণ কমান্ডগুলোর (যেমন `ls`) নাম দিয়ে নকল ফাইল তৈরি করে সিস্টেমকে বোকা বানাতে পারি।

চলুন, আমরা বর্তমান ফোল্ডারে `ls` নামে একটি ফেক বা নকল স্ক্রিপ্ট তৈরি করি:

**ধাপ ১: নকল ফাইল তৈরি করা এবং হ্যাকিং কোড ঢোকানো**

```bash
htb_student@NIX02:~$ touch ls
htb_student@NIX02:~$ echo 'echo "PATH ABUSE!!"' > ls

```

(এখানে আমরা নকল `ls` এর ভেতরে লিখে দিলাম যে, এটি রান হলে স্ক্রিনে "PATH ABUSE!!" লেখা দেখাবে। রিয়েল লাইফ অ্যাটাকে এখানে রিভার্স শেলের কোড দেওয়া হয়।)

**ধাপ ২: ফাইলটিকে রান করার পারমিশন দেওয়া (Executable বানানো)**

```bash
htb_student@NIX02:~$ chmod +x ls

```

**ধাপ ৩: কমান্ড রান করা**
এবার আমরা সাধারণ ফাইলের লিস্ট দেখার জন্য `ls` কমান্ড দিব:

```bash
htb_student@NIX02:~$ ls

```

**আউটপুট:**

```text
PATH ABUSE!!

```

**এখানে কী ঘটল?**
ইউজার ভেবেছিল সে ফোল্ডারের ফাইলগুলো দেখবে। কিন্তু লিনাক্স PATH চেক করতে গিয়ে সবার আগে বর্তমান ফোল্ডারে আমাদের বানানো নকল `ls` ফাইলটি পেয়ে যায় এবং আসল `/bin/ls` এর বদলে আমাদের ফেক স্ক্রিপ্টটি রান করে দেয়।

যদি কোনো রুট (Root) বা অ্যাডমিন ইউজার ভুল করে এমন ফোল্ডারে এসে `ls` কমান্ড দেয় যেখানে আমাদের এই ফেক ফাইলটি রাখা আছে, তবে আমাদের দেওয়া ম্যালিশিয়াস স্ক্রিপ্টটি রুট পারমিশন নিয়েই রান হয়ে যাবে!
