### ১. PATH আসলে কী? (What is PATH?)

ধরুন, আপনি টার্মিনালে `cat /tmp/test.txt` বা `ls` কমান্ড দিলেন এবং সেটি কাজ করলো। কিন্তু লিনাক্স কীভাবে বুঝলো যে `cat` বা `ls` কমান্ডের আসল প্রোগ্রামটা সিস্টেমের কোথায় রাখা আছে?

**PATH** হলো লিনাক্সের এমন একটি লিস্ট বা ম্যাপ, যেখানে কিছু ফোল্ডারের ঠিকানা দেওয়া থাকে। আপনি যখনই কোনো কমান্ড লেখেন, লিনাক্স ওই ফোল্ডারগুলোতে গিয়ে খুঁজতে থাকে যে কমান্ডটি সেখানে আছে কিনা।
PATH না থাকলে আপনাকে প্রতিটি কমান্ড তার পুরো ঠিকানা (Absolute Path) দিয়ে লিখতে হতো (যেমন: `ls` এর বদলে `/bin/ls` লিখতে হতো)।

**আপনার PATH চেক করার পেলোড:**

```bash
echo $PATH

```

**আউটপুট:** `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games`
*(এখানে কোলন `:` দিয়ে প্রতিটি ফোল্ডারের নাম আলাদা করা আছে)।*

### ২. PATH-এর সুবিধা (এবং হ্যাকিংয়ের শুরু)

PATH-এর ভেতরে থাকা কোনো ফোল্ডারে (যেমন: `/usr/local/sbin`) আপনি যদি নিজের বানানো কোনো স্ক্রিপ্ট (যেমন `conncheck`) রাখেন, তাহলে সিস্টেমের যেকোনো জায়গা (যেমন `/tmp`) থেকে আপনি শুধু `conncheck` লিখলেই সেটি রান হবে।

টেক্সটে দেখানো উদাহরণে ঠিক এটাই হয়েছে। `conncheck` নামের স্ক্রিপ্টটি `/usr/local/sbin` ফোল্ডারে রাখা আছে। তাই ইউজার `/tmp` ফোল্ডারে থাকা অবস্থাতেও যখন `conncheck` লিখেছে, লিনাক্স PATH লিস্ট ঘেঁটে সেটা ঠিকই রান করে দিয়েছে।

### ৩. সবচেয়ে বড় ভুল: PATH-এ `.` (ডট) যোগ করা

লিনাক্সে `.` (ডট) মানে হলো **"Current Directory" বা বর্তমান ফোল্ডার** (যেখানে আপনি এখন আছেন)।

অনেক সময় অ্যাডমিনরা কাজের সুবিধার জন্য PATH-এর একদম শুরুতে একটি `.` যোগ করে দেয়।
**কমান্ড:** `PATH=.:$PATH` এবং তারপর `export PATH`

এর ফলে PATH-টি দেখতে এমন হয়ে যায়:
**`.:/usr/local/sbin:/usr/local/bin...`**

**মজাটা এখানেই!**
লিনাক্স সবসময় PATH লিস্টের **বাম থেকে ডান দিকে** খোঁজা শুরু করে এবং প্রথম যেখানে কমান্ডটি পায়, সেখান থেকেই রান করে দেয়। যেহেতু `.` (বর্তমান ফোল্ডার) একদম শুরুতে আছে, তাই লিনাক্স এখন যেকোনো কমান্ড রান করার আগে সবার প্রথমে চেক করবে যে কমান্ডটি আপনার বর্তমান ফোল্ডারে আছে কিনা!

### ৪. Path Abuse অ্যাটাক (আসল কমান্ডকে নকল কমান্ড দিয়ে বোকা বানানো)

যেহেতু লিনাক্স সবার আগে বর্তমান ফোল্ডারে কমান্ড খুঁজবে, আমরা এই সুযোগটাই কাজে লাগাবো।

আমরা জানি সিস্টেমের আসল `ls` কমান্ড থাকে `/bin/ls` ফোল্ডারে। কিন্তু আমরা আমাদের বর্তমান ফোল্ডারে `ls` নামে একটি ভুয়া বা নকল ফাইল বানাবো এবং তার ভেতর আমাদের হ্যাকিং কোড ঢুকিয়ে দেব।

চলুন অ্যাটাকটি ধাপে ধাপে করি:

**ধাপ ১: নকল `ls` ফাইল বানানো**

```bash
touch ls

```

*(এটি বর্তমান ফোল্ডারে `ls` নামে একটি খালি ফাইল তৈরি করবে)*

**ধাপ ২: ম্যালিশিয়াস কোড ঢোকানো**

```bash
echo 'echo "PATH ABUSE!!"' > ls

```

*(আমরা নকল `ls` ফাইলের ভেতর লিখে দিলাম যে, কেউ যদি এটা রান করে, তবে স্ক্রিনে "PATH ABUSE!!" লেখা উঠবে। রিয়েল হ্যাকিংয়ে এখানে রিভার্স শেলের কোড দেওয়া হয়)*

**ধাপ ৩: ফাইলটিকে এক্সিকিউটেবল বা রান করার যোগ্য বানানো**

```bash
chmod +x ls

```

**ধাপ ৪: ম্যাজিক দেখা! (বোকা বনে যাওয়া লিনাক্স)**

```bash
ls

```

**আউটপুট:** `PATH ABUSE!!`

**কী ঘটলো এখানে?**
ইউজার টার্মিনালে `ls` লিখেছিল সিস্টেমের ফাইলগুলো দেখার জন্য। কিন্তু লিনাক্স PATH চেক করতে গিয়ে সবার আগে `.` (বর্তমান ফোল্ডার) পেলো। সে দেখলো বর্তমান ফোল্ডারেই তো `ls` নামের একটি ফাইল আছে! সে আর `/bin/ls` এর কাছে গেলই না, সরাসরি আমাদের বানানো নকল `ls` টাকে রান করে দিলো!

### 💡 এটি দিয়ে কীভাবে Root বা অ্যাডমিন হওয়া যায়?

ধরুন, সিস্টেমে এমন একটি স্ক্রিপ্ট আছে যা `root` (অ্যাডমিন) পাওয়ার নিয়ে রান হয়। আর সেই স্ক্রিপ্টের ভেতরে লেখা আছে `curl [http://example.com](http://example.com)` (অর্থাৎ curl কমান্ড ব্যবহার করা হয়েছে, পুরো পাথ `/usr/bin/curl` দেওয়া হয়নি)।

আপনি যদি PATH Abuse করে আপনার ফোল্ডারে `curl` নামের একটি ফেক ফাইল বানান এবং তার ভেতর রিভার্স শেলের কোড দিয়ে দেন, তবে ওই রুট স্ক্রিপ্টটি যখনই রান হবে, সে আসল `curl` এর বদলে আপনার হ্যাকিং `curl` রান করে ফেলবে। আর যেহেতু স্ক্রিপ্টটি রুট হিসেবে রান হচ্ছে, আপনি সাথে সাথে পুরো সিস্টেমের রুট শেল পেয়ে যাবেন!
