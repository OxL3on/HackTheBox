# Server Message Block (SMB)

## Introduction (ভূমিকা)

**Server Message Block (SMB)** হলো একটি client-server protocol যা ফাইল, সম্পূর্ণ ডিরেক্টরি এবং নেটওয়ার্কের অন্যান্য রিসোর্স (যেমন—প্রিন্টার, রাউটার বা নেটওয়ার্কের জন্য উন্মুক্ত ইন্টারফেস) অ্যাক্সেস নিয়ন্ত্রণ করে। বিভিন্ন সিস্টেম প্রসেসের মধ্যে তথ্য আদান-প্রদানও SMB প্রোটোকলের উপর ভিত্তি করে পরিচালিত হতে পারে।

SMB সর্বপ্রথম ব্যাপকভাবে পরিচিতি পায় OS/2 নেটওয়ার্ক অপারেটিং সিস্টেমের LAN Manager এবং LAN Server-এর অংশ হিসেবে। তখন থেকে এই প্রোটোকলের প্রধান ব্যবহারের ক্ষেত্র হয়ে দাঁড়ায় **Windows operating system series**, যাদের নেটওয়ার্ক সার্ভিসগুলো SMB-কে downward-compatible (পশ্চাদগামী সামঞ্জস্যপূর্ণ) উপায়ে সাপোর্ট করে। এর মানে হলো, নতুন সংস্করণের উইন্ডোজ ডিভাইসগুলো সহজেই পুরোনো সংস্করণের মাইক্রোসফট অপারেটিং সিস্টেম ইনস্টল করা ডিভাইসগুলোর সাথে যোগাযোগ করতে পারে।

এছাড়া, **Samba** নামের ফ্রি সফটওয়্যার প্রজেক্টের মাধ্যমে Linux এবং Unix ডিস্ট্রিবিউশনগুলোতেও SMB ব্যবহার করা সম্ভব, যা SMB-এর মাধ্যমে cross-platform communication সক্ষম করে।

## How It Works (এটি কীভাবে কাজ করে)

SMB প্রোটোকল একটি ক্লায়েন্টকে একই নেটওয়ার্কের অন্যান্য ডিভাইসের সাথে যোগাযোগ করতে এবং নেটওয়ার্কে শেয়ার করা ফাইল বা সার্ভিসে অ্যাক্সেস পেতে সক্ষম করে। এর জন্য অপর সিস্টেমটিতেও এই নেটওয়ার্ক প্রোটোকলটি ইমপ্লিমেন্ট করা থাকতে হবে এবং একটি SMB server application ব্যবহার করে ক্লায়েন্টের রিকোয়েস্ট রিসিভ এবং প্রসেস করতে হবে। তবে ডেটা আদান-প্রদানের আগে উভয় পক্ষকে একটি কানেকশন স্থাপন করতে হয়, যে কারণে তারা প্রথমে প্রয়োজনীয় ম্যাসেজ বিনিময় করে।

IP নেটওয়ার্কে SMB এই উদ্দেশ্যে **TCP protocol** ব্যবহার করে, যা কানেকশন স্থাপন করার আগে ক্লায়েন্ট এবং সার্ভারের মধ্যে একটি **three-way handshake** সম্পন্ন করে।

### Access Control Lists (ACL)

একটি SMB সার্ভার তার লোকাল ফাইল সিস্টেমের যেকোনো অংশ শেয়ার হিসেবে প্রদান করতে পারে। তাই ক্লায়েন্টের কাছে যে স্ট্রাকচারটি দৃশ্যমান হয়, তা সার্ভারের মূল স্ট্রাকচার থেকে আংশিকভাবে স্বাধীন থাকে।
অ্যাক্সেসের অধিকারগুলো **Access Control Lists (ACL)** দ্বারা সংজ্ঞায়িত করা হয়। এর মাধ্যমে নির্দিষ্ট ব্যবহারকারী (individual users) বা ব্যবহারকারী গ্রুপের (user groups) জন্য execute, read এবং full access-এর মতো অ্যাট্রিবিউটগুলো অত্যন্ত সূক্ষ্মভাবে (fine-grained manner) নিয়ন্ত্রণ করা যায়। ACL-গুলো শেয়ারের ওপর ভিত্তি করে তৈরি হয়, তাই এগুলো সার্ভারে লোকালি অ্যাসাইন করা রাইটস বা অধিকারের সাথে সবসময় মেলে না।

## Samba and CIFS (সাম্বা এবং সিআইএফএস)

**Samba** হলো Unix-ভিত্তিক অপারেটিং সিস্টেমের জন্য ডেভেলপ করা SMB সার্ভারের একটি বিকল্প ইমপ্লিমেন্টেশন। Samba মূলত **Common Internet File System (CIFS)** নেটওয়ার্ক প্রোটোকল ইমপ্লিমেন্ট করে।

CIFS হলো SMB-এর একটি উপভাষা (dialect), যার মানে হলো এটি মাইক্রোসফট দ্বারা তৈরি মূল SMB প্রোটোকলের একটি নির্দিষ্ট ইমপ্লিমেন্টেশন। এটি Samba-কে নতুন Windows সিস্টেমগুলোর সাথে কার্যকরভাবে যোগাযোগ করতে সাহায্য করে। তাই একে প্রায়শই **SMB/CIFS** বলা হয়।

তবে CIFS-কে SMB প্রোটোকলের একটি নির্দিষ্ট সংস্করণ হিসেবে বিবেচনা করা হয়, যা মূলত **SMB version 1**-এর সাথে সামঞ্জস্যপূর্ণ। যখন Samba-এর মাধ্যমে কোনো পুরোনো NetBIOS সার্ভিসে SMB কমান্ড ট্রান্সমিট করা হয়, তখন কানেকশনগুলো সাধারণত **TCP ports 137, 138, এবং 139** ব্যবহার করে ঘটে। এর বিপরীতে, CIFS একচেটিয়াভাবে **TCP port 445**-এর মাধ্যমে কাজ করে।

### SMB Versions (SMB সংস্করণসমূহ)

SMB-এর বেশ কয়েকটি সংস্করণ রয়েছে। আধুনিক ইনফ্রাস্ট্রাকচারে উন্নত পারফরম্যান্সের জন্য SMB 2 এবং SMB 3 ব্যবহার করা হয়, অন্যদিকে SMB 1 (CIFS) পুরোনো বা আউটডেটেড হিসেবে বিবেচিত হলেও কিছু নির্দিষ্ট এনভায়রনমেন্টে এখনও ব্যবহৃত হয়।

| SMB Version | Supported | Features |
| --- | --- | --- |
| **CIFS** | Windows NT 4.0 | Communication via NetBIOS interface |
| **SMB 1.0** | Windows 2000 | Direct connection via TCP |
| **SMB 2.0** | Windows Vista, Windows Server 2008 | Performance upgrades, improved message signing, caching feature |
| **SMB 2.1** | Windows 7, Windows Server 2008 R2 | Locking mechanisms |
| **SMB 3.0** | Windows 8, Windows Server 2012 | Multichannel connections, end-to-end encryption, remote storage access |
| **SMB 3.0.2** | Windows 8.1, Windows Server 2012 R2 |  |
| **SMB 3.1.1** | Windows 10, Windows Server 2016 | Integrity checking, AES-128 encryption |

### Active Directory Integration

Version 3 থেকে Samba সার্ভার একটি **Active Directory domain**-এর পূর্ণ সদস্য হওয়ার সক্ষমতা লাভ করে। Version 4-এর সাথে Samba নিজেই একটি Active Directory domain controller প্রদান করে। এর জন্য এটি বেশ কয়েকটি Unix background programs বা **daemons** ব্যবহার করে:

* **smbd (SMB server daemon):** ফাইল এবং প্রিন্ট শেয়ারিং সুবিধা দেয়।
* **nmbd (NetBIOS message block daemon):** NetBIOS নাম রেজোলিউশন সুবিধা দেয়।

### Workgroups and NetBIOS

একটি নেটওয়ার্কে প্রতিটি হোস্ট একই **workgroup**-এ অংশগ্রহণ করে। Workgroup হলো একটি গ্রুপের নাম, যা SMB নেটওয়ার্কে একাধিক কম্পিউটার এবং তাদের রিসোর্সগুলোকে আইডেন্টিফাই করে।

IBM নেটওয়ার্কিং কম্পিউটারের জন্য **NetBIOS (Network Basic Input/Output System)** নামে একটি API তৈরি করে। NetBIOS পরিবেশে যখন কোনো মেশিন অনলাইনে আসে, তখন তার একটি নামের প্রয়োজন হয়, যা name registration প্রক্রিয়ার মাধ্যমে সম্পন্ন হয়। এটি হয় হোস্ট নিজেই করে, অথবা **NetBIOS Name Server (NBNS)** ব্যবহার করে করা হয় (যাকে পরবর্তীতে **WINS** বা Windows Internet Name Service-এ উন্নত করা হয়েছে)।

## Default Configuration (ডিফল্ট কনফিগারেশন)

Samba কনফিগারেশনের জন্য একটি টেক্সট ফাইল ব্যবহার করে। এই ফাইলের ভেতরের কিছু সেটিংস নিচে দেওয়া হলো:

```bash
00Luffy00@htb[/htb]$ cat /etc/samba/smb.conf | grep -v "#\|\;" 

[global]
   workgroup = DEV.INFREIGHT.HTB
   server string = DEVSMB
   log file = /var/log/samba/log.%m
   max log size = 1000
   logging = file
   panic action = /usr/share/samba/panic-action %d

   server role = standalone server
   obey pam restrictions = yes
   unix password sync = yes

   passwd program = /usr/bin/passwd %u
   passwd chat = *Enter\snew\s*\spassword:* %n\n *Retype\snew\s*\spassword:* %n\n *password\supdated\ssuccessfully* .

   pam password change = yes
   map to guest = bad user
   usershare allow guests = yes

[printers]
   comment = All Printers
   browseable = no
   path = /var/spool/samba
   printable = yes
   guest ok = no
   read only = yes
   create mask = 0700

[print$]
   comment = Printer Drivers
   path = /var/lib/samba/printers
   browseable = yes
   read only = yes
   guest ok = no

```

এখানে `[global]` সেকশনে সম্পূর্ণ সার্ভারের সেটিংস থাকে। তবে নির্দিষ্ট শেয়ারের (যেমন `[printers]`) ভেতরে গ্লোবাল সেটিংস ওভাররাইট (overwrite) করা যায়, যা অনেক সময় ভুলভাবে কনফিগার হওয়ার সম্ভাবনা থাকে।

### Key Samba Settings

| Setting | Description |
| --- | --- |
| `[sharename]` | নেটওয়ার্ক শেয়ারের নাম। |
| `workgroup` | ক্লায়েন্ট কোয়েরি করার সময় যে Workgroup বা ডোমেইন নাম দেখাবে। |
| `path` | ইউজারকে যে ডিরেক্টরির অ্যাক্সেস দেওয়া হবে। |
| `server string` | কানেকশন ইনিশিয়েট করার সময় যে স্ট্রিং দেখাবে। |
| `unix password sync` | SMB পাসওয়ার্ডের সাথে UNIX পাসওয়ার্ড সিঙ্ক করবে কি না। |
| `usershare allow guests` | নন-অথেনটিকেটেড ইউজারদের শেয়ার অ্যাক্সেস করার অনুমতি দেবে কি না। |
| `map to guest` | ইনভ্যালিড লগইন রিকোয়েস্টের ক্ষেত্রে কী করা হবে (যেমন: `bad user`)। |
| `browseable` | অ্যাভেইলেবল শেয়ারের লিস্টে এই শেয়ারটি দেখানো হবে কি না। |
| `guest ok` | পাসওয়ার্ড ছাড়া সার্ভিসে কানেক্ট করার অনুমতি। |
| `read only` | ইউজাররা শুধু ফাইল পড়তে পারবে কি না। |
| `create mask` | নতুন তৈরি করা ফাইলের জন্য কী পারমিশন সেট করা হবে। |

## Dangerous Settings (ঝুঁকিপূর্ণ কনফিগারেশন)

অ্যাডমিনিস্ট্রেটররা যদি নিজেদের সুবিধার জন্য কিছু নির্দিষ্ট সেটিংস অন করে রাখেন, তবে তা অ্যাটাকারদের জন্যও সুবিধা তৈরি করে। যেমন— `browseable = yes` থাকলে অ্যাটাকারও শেয়ারের ভেতরের ফোল্ডারগুলো দেখতে পারবে।

| Setting | Description |
| --- | --- |
| `browseable = yes` | বর্তমান শেয়ারের ভেতরে থাকা শেয়ারগুলোর তালিকা দেখার অনুমতি। |
| `read only = no` | ফাইল তৈরি বা মডিফাই করার ওপর নিষেধাজ্ঞা তুলে নেয়। |
| `writable = yes` | ইউজারদের ফাইল তৈরি ও মডিফাই করার অনুমতি দেয়। |
| `guest ok = yes` | পাসওয়ার্ড ছাড়া সার্ভিসে কানেক্ট করার অনুমতি। |
| `enable privileges = yes` | নির্দিষ্ট SID-কে দেওয়া প্রিভিলেজ গ্রহণ করে। |
| `create mask = 0777` | নতুন ফাইলের জন্য ফুল পারমিশন। |
| `directory mask = 0777` | নতুন ডিরেক্টরির জন্য ফুল পারমিশন। |
| `logon script = script.sh` | ইউজারের লগইনের সময় যে স্ক্রিপ্ট এক্সিকিউট হবে। |
| `magic script = script.sh` | স্ক্রিপ্ট ক্লোজ হওয়ার সময় যে স্ক্রিপ্ট এক্সিকিউট হবে। |
| `magic output = script.out` | ম্যাজিক স্ক্রিপ্টের আউটপুট কোথায় স্টোর হবে। |

### Example Target Share: [notes]

ধরা যাক সার্ভারে `[notes]` নামে একটি শেয়ার এভাবে কনফিগার করা আছে:

```bash
[notes]
    comment = CheckIT
    path = /mnt/notes/

    browseable = yes
    read only = no
    writable = yes
    guest ok = yes

    enable privileges = yes
    create mask = 0777
    directory mask = 0777

```

এই ধরনের কনফিগারেশনে অ্যাটাকার খুব সহজেই অ্যাক্সেস নিয়ে ফাইল রিড/রাইট করতে পারে।

**Restarting Samba Service:**
কনফিগারেশন ফাইলে পরিবর্তনের পর সার্ভিস রিস্টার্ট করতে হয়:

```bash
root@samba:~# sudo systemctl restart smbd

```

## Interacting with the SMB Service

**SMBclient** ব্যবহার করে আমরা সার্ভারের শেয়ার লিস্ট দেখতে পারি। আমরা **null session (`-N`)** ব্যবহার করব, যার মানে হলো কোনো ভ্যালিড ইউজারনেম বা পাসওয়ার্ড ছাড়া অ্যানোনিমাস অ্যাক্সেস।

```bash
00Luffy00@htb[/htb]$ smbclient -N -L //10.129.14.128

        Sharename       Type      Comment
        ---------       ----      -------
        print$          Disk      Printer Drivers
        home            Disk      INFREIGHT Samba
        dev             Disk      DEVenv
        notes           Disk      CheckIT
        IPC$            IPC       IPC Service (DEVSM)
SMB1 disabled -- no workgroup available

```

যেহেতু `notes` শেয়ারটি ওপেন আছে, আমরা এটিতে কানেক্ট করে দেখতে পারি:

```bash
00Luffy00@htb[/htb]$ smbclient //10.129.14.128/notes

Enter WORKGROUP\<username>'s password: 
Anonymous login successful

smb: \> ls
  .                                   D        0  Wed Sep 22 18:17:51 2021
  ..                                  D        0  Wed Sep 22 12:03:59 2021
  prep-prod.txt                       N       71  Sun Sep 19 15:45:21 2021

```

### Download Files & Run Local Commands

ফাইল ডাউনলোড করার জন্য `get` কমান্ড এবং লোকাল কমান্ড রান করার জন্য কমান্ডের আগে `!` (exclamation mark) ব্যবহার করা হয়।

```bash
smb: \> get prep-prod.txt 
getting file \prep-prod.txt of size 71 as prep-prod.txt (8,7 KiloBytes/sec) 

smb: \> !ls
prep-prod.txt

smb: \> !cat prep-prod.txt
[] check your code with the templates
[] run code-assessment.py
[] …    

```

## Footprinting and Enumeration

### 1. Nmap Scan

Nmap-এর মাধ্যমে পোর্ট 139 এবং 445 স্ক্যান করা যায়:

```bash
00Luffy00@htb[/htb]$ sudo nmap 10.129.14.128 -sV -sC -p139,445

```

তবে Nmap অনেক সময় বিস্তারিত তথ্য দিতে পারে না। তাই অন্যান্য টুলের প্রয়োজন হয়।

### 2. RPCclient

**Remote Procedure Call (RPC)** হলো ক্লায়েন্ট-সার্ভার আর্কিটেকচারে কাজ করার একটি কনসেপ্ট। `rpcclient` টুল ব্যবহার করে আমরা SMB সার্ভারে স্পেসিফিক রিকোয়েস্ট পাঠাতে পারি।

```bash
00Luffy00@htb[/htb]$ rpcclient -U "" 10.129.14.128

Enter WORKGROUP\'s password:
rpcclient $> 

```

**Common RPCclient Commands:**

| Query | Description |
| --- | --- |
| `srvinfo` | সার্ভার ইনফরমেশন। |
| `enumdomains` | নেটওয়ার্কের সমস্ত ডোমেইন এনুমারেট করে। |
| `querydominfo` | ডোমেইন, সার্ভার এবং ইউজারের ইনফো দেয়। |
| `netshareenumall` | অ্যাভেইলেবল সব শেয়ারের লিস্ট দেয়। |
| `netsharegetinfo <share>` | নির্দিষ্ট একটি শেয়ারের বিস্তারিত তথ্য দেয়। |
| `enumdomusers` | সমস্ত ডোমেইন ইউজারদের এনুমারেট করে। |
| `queryuser <RID>` | নির্দিষ্ট ইউজারের ইনফরমেশন দেয়। |
| `querygroup <RID>` | গ্রুপের ইনফরমেশন দেয়। |

**Brute Forcing User RIDs (Bash Loop):**
যদি আমাদের কাছে ইউজারদের অ্যাক্সেস না থাকে, আমরা লুপ ব্যবহার করে RID ব্রুটফোর্স করতে পারি:

```bash
00Luffy00@htb[/htb]$ for i in $(seq 500 1100);do rpcclient -N -U "" 10.129.14.128 -c "queryuser 0x$(printf '%x\n' $i)" | grep "User Name\|user_rid\|group_rid" && echo "";done

```

### 3. Impacket - samrdump.py

পিসিতে Python স্ক্রিপ্ট ব্যবহার করে খুব সহজেই ইউজার এনুমারেট করা যায়:

```bash
00Luffy00@htb[/htb]$ samrdump.py 10.129.14.128

```

### 4. SMBmap

এটি একটি চমৎকার টুল যা শেয়ারের পারমিশন এবং কন্টেন্ট লিস্ট করে:

```bash
00Luffy00@htb[/htb]$ smbmap -H 10.129.14.128

```

### 5. CrackMapExec

আরেকটি পাওয়ারফুল টুল, যা নেটওয়ার্কে এনুমারেশনের কাজকে অনেক সহজ করে দেয়:

```bash
00Luffy00@htb[/htb]$ crackmapexec smb 10.129.14.128 --shares -u '' -p ''

```

### 6. Enum4Linux-ng

এটি পুরোনো `enum4linux`-এর একটি আপডেট ভার্সন যা স্বয়ংক্রিয়ভাবে অনেকগুলো কোয়েরি করে।

**Installation:**

```bash
00Luffy00@htb[/htb]$ git clone https://github.com/cddmp/enum4linux-ng.git
00Luffy00@htb[/htb]$ cd enum4linux-ng
00Luffy00@htb[/htb]$ pip3 install -r requirements.txt

```

**Usage:**

```bash
00Luffy00@htb[/htb]$ ./enum4linux-ng.py 10.129.14.128 -A

```

এই টুলটি সার্ভার, ডোমেইন, ইউজার, শেয়ার এবং পাসওয়ার্ড পলিসি সম্পর্কে বিস্তারিত তথ্য প্রদান করে।

> **Important Note:** শুধুমাত্র একটি অটোমেটেড টুলের ওপর নির্ভর করা উচিত নয়, কারণ অনেক সময় ভুল কনফিগারেশন বা প্রোগ্রামিংয়ের কারণে টুলগুলো ভিন্ন ভিন্ন ফলাফল দিতে পারে। তাই ম্যানুয়াল ভেরিফিকেশন অত্যন্ত গুরুত্বপূর্ণ।
