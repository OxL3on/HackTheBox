## 1. Introduction

`Server Message Block (SMB)` হলো একটি client-server network protocol, যা network-এর মধ্যে file, directory, printer এবং অন্যান্য shared resource access করতে ব্যবহৃত হয়। SMB-এর মাধ্যমে বিভিন্ন system process-এর মধ্যেও information exchange করা যায়।

### SMB কীভাবে কাজ করে?

ধরো, একটি network-এ Windows server-এর একটি folder অন্য ব্যবহারকারীদের জন্য share করা আছে। SMB client সেই server-এর সঙ্গে connection স্থাপন করে folder-এর file দেখতে, download করতে বা permission থাকলে পরিবর্তন করতে পারে।

SMB communication-এর জন্য সাধারণত:

1. Client server-এর সঙ্গে connection স্থাপন করে।
2. Server client-এর request গ্রহণ ও process করে।
3. Permission অনুযায়ী client shared resource ব্যবহার করে।

IP network-এ SMB সাধারণত TCP ব্যবহার করে। TCP connection স্থাপনের আগে client ও server-এর মধ্যে three-way handshake সম্পন্ন হয়।

SMB-এর মূল কাজগুলো:

- File ও directory share করা।
- Printer এবং অন্যান্য network resource access করা।
- User ও group অনুযায়ী access control করা।
- Network-এর বিভিন্ন system-এর মধ্যে data exchange করা।

মূল reference: [Microsoft SMB Protocol Specification](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-smb/f210069c-7086-4dc2-885e-861d837df688?utm_source=chatgpt.com)

### Shares ও Access Control Lists (ACLs)

SMB server তার local filesystem-এর নির্দিষ্ট directory বা resource network-এর জন্য share করতে পারে। Client-এর কাছে দৃশ্যমান share structure server-এর সম্পূর্ণ filesystem structure-এর সঙ্গে সরাসরি মিলতেই হবে, এমন নয়।

`Access Control List (ACL)` নির্ধারণ করে কোন user বা group কী করতে পারবে।

| Permission    | অর্থ                                       |
| ------------- | ------------------------------------------ |
| `Read`        | File পড়তে পারবে                           |
| `Execute`     | অনুমোদিত executable চালাতে পারবে           |
| `Full access` | অনুমোদিত resource-এর ওপর পূর্ণ access পাবে |

গুরুত্বপূর্ণ: Share-এর ACL এবং server-এর local filesystem permission এক জিনিস নয়। Share permission অনুমতি দিলেও local filesystem permission access সীমিত করতে পারে।

## 2. Samba ও SMB Versions

### 2.1 Samba কী?

`Samba` হলো Unix-based operating system, যেমন Linux, থেকে SMB network resource ব্যবহার ও share করার একটি implementation। এটি Windows system-এর সঙ্গে cross-platform communication সম্ভব করে।

Samba-এর সঙ্গে `Common Internet File System (CIFS)` নামটিও ব্যবহৃত হয়।

`CIFS` হলো SMB protocol-এর একটি dialect, যা মূলত SMB version 1-এর সঙ্গে সম্পর্কিত। তাই `SMB/CIFS` নামটিও প্রচলিত।

Reference:

\- [Microsoft CIFS Specification](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-cifs/934c2faa-54af-4526-ac74-6a24d126724e?utm_source=chatgpt.com)

### 2.2 SMB-এর গুরুত্বপূর্ণ Port

| Port      | Protocol/ব্যবহার                                  |
| --------- | ------------------------------------------------- |
| TCP `137` | NetBIOS Name Service                              |
| TCP `138` | মূল source-এ NetBIOS connection-এর সঙ্গে উল্লেখিত |
| TCP `139` | NetBIOS session-এর মাধ্যমে SMB                    |
| TCP `445` | Direct SMB over TCP                               |

নোট: প্রচলিত NetBIOS port mapping-এ UDP `137` ও UDP `138` ব্যবহৃত হয়; TCP `139` ব্যবহৃত হয় session service-এর জন্য। Direct-hosted SMB সাধারণত TCP `445` ব্যবহার করে।

CIFS/SMB1 পুরোনো technology। আধুনিক environment-এ SMB2 ও SMB3 বেশি উপযোগী।

### 2.3 SMB Version ও Features

| Version   | সমর্থিত OS                          | প্রধান বৈশিষ্ট্য                                            |
| --------- | ----------------------------------- | ----------------------------------------------------------- |
| CIFS      | Windows NT 4.0                      | NetBIOS interface-এর মাধ্যমে communication                  |
| SMB 1.0   | Windows 2000                        | TCP-এর মাধ্যমে direct connection                            |
| SMB 2.0   | Windows Vista, Windows Server 2008  | Performance উন্নতি, improved message signing ও caching      |
| SMB 2.1   | Windows 7, Windows Server 2008 R2   | উন্নত locking mechanism                                     |
| SMB 3.0   | Windows 8, Windows Server 2012      | Multichannel, end-to-end encryption ও remote storage access |
| SMB 3.0.2 | Windows 8.1, Windows Server 2012 R2 | Source-এ আলাদা feature উল্লেখ নেই                           |
| SMB 3.1.1 | Windows 10, Windows Server 2016     | Integrity checking ও AES-128 encryption                     |

### 2.4 Samba Daemons

Samba-এর বিভিন্ন version Active Directory-এর সঙ্গে কাজ করার ক্ষমতা বাড়িয়েছে:

- Samba version 3 থেকে Active Directory domain-এর member হিসেবে কাজ করার সুবিধা এসেছে।
- Samba version 4 থেকে Active Directory Domain Controller হিসেবেও কাজ করা যায়।

প্রধান daemon:

- `smbd` — SMB file ও printer sharing service পরিচালনা করে।
- `nmbd` — NetBIOS-সম্পর্কিত name service ও browsing functionality পরিচালনা করে।

Samba service এই background process-গুলো পরিচালনা করে।

### 2.5 Workgroup, NetBIOS, NBNS ও WINS

Workgroup: SMB network-এ computer ও resource-এর একটি group-কে শনাক্ত করার নাম। একই network-এ একাধিক workgroup থাকতে পারে।

NetBIOS (Network Basic Input/Output System): Network-এ computer-গুলোর মধ্যে যোগাযোগ ও data sharing-এর জন্য তৈরি API।

Name registration: NetBIOS environment-এ একটি machine network-এ যুক্ত হলে তার নাম register করতে হয়।

NBNS (NetBIOS Name Server): Network-এ NetBIOS name register ও resolve করতে ব্যবহৃত হয়।

WINS (Windows Internet Name Service): NetBIOS name resolution-এর জন্য ব্যবহৃত একটি Windows service।

References:

- [NetBIOS Name Server](https://networkencyclopedia.com/netbios-name-server-nbns/?utm_source=chatgpt.com)
- [Windows Internet Name Service](https://networkencyclopedia.com/windows-internet-name-service-wins/?utm_source=chatgpt.com)

## 3. Samba Default Configuration

Samba-এর configuration সাধারণত নিচের file-এ থাকে:

```
/etc/samba/smb.conf
```

Configuration থেকে comment ও semicolon-যুক্ত line বাদ দিয়ে দেখার command:

```
cat /etc/samba/smb.conf | grep -v "#\|\;"
```

### 3.1 Example Configuration

```
[global]
   workgroup = DEV.INFREIGHT.HTB
   server string = DEVSMB
   log file = /var/log/samba/log.%m
   max log size = 1000
   logging = file
   panic action = /usr/share/samba/panic-action %d

   server role = standalone server
   obey pam restrictions = yes
   unix password sync = yes

   passwd program = /usr/bin/passwd %u
   passwd chat = *Enter\snew\s*\spassword:* %n\n *Retype\snew\s*\
password:* %n\n *password\supdated\ssuccessfully* .

   pam password change = yes
   map to guest = bad user
   usershare allow guests = yes

[printers]
   comment = All Printers
   browseable = no
   path = /var/spool/samba
   printable = yes
   guest ok = no
   read only = yes
   create mask = 0700

[print$]
   comment = Printer Drivers
   path = /var/lib/samba/printers
   browseable = yes
   read only = yes
   guest ok = no
```

উপরের configuration-এ তিনটি প্রধান অংশ রয়েছে:

- `[global]` — সব share-এর জন্য প্রযোজ্য server-wide settings।
- `[printers]` — Printer service-এর জন্য share।
- `[print$]` — Printer driver সংরক্ষণ ও access করার share।

প্রয়োজনে individual share-এর configuration global setting-কে override করতে পারে। ভুল configuration হলে অনিচ্ছাকৃতভাবে বেশি access দেওয়া হতে পারে।

### 3.2 গুরুত্বপূর্ণ Configuration Parameters

| Setting                        | সহজ ব্যাখ্যা                                                 |
| ------------------------------ | ------------------------------------------------------------ |
| `[sharename]`                  | Network share-এর নাম                                         |
| `workgroup = WORKGROUP/DOMAIN` | Client-দের কাছে প্রদর্শিত workgroup/domain                   |
| `path = /path/here/`           | যে local directory share করা হবে                             |
| `server string = STRING`       | Connection-এর সময় প্রদর্শিত server description              |
| `unix password sync = yes`     | UNIX ও SMB password synchronize করার সুবিধা                  |
| `usershare allow guests = yes` | Guest user-দের defined share access-এর অনুমতি                |
| `map to guest = bad user`      | Invalid UNIX username হলে guest mapping-এর আচরণ নির্ধারণ করে |
| `browseable = yes`             | Share-টি available share list-এ দেখা যাবে কি না              |
| `guest ok = yes`               | Password ছাড়া guest connection অনুমোদন করবে কি না           |
| `read only = yes`              | Share-এ শুধু read access অনুমোদন করবে                        |
| `create mask = 0700`           | নতুন file তৈরির সময় permission mask নির্ধারণ করে            |

## 4. Dangerous SMB Settings

SMB-এর কিছু configuration convenience বাড়ালেও security risk তৈরি করতে পারে। বিশেষত guest access, writable share এবং অতিরিক্ত file permission attacker-কে sensitive data পড়তে বা file পরিবর্তন করতে দিতে পারে।

### 4.1 Risky Settings

| Setting                     | সহজ ব্যাখ্যা ও সম্ভাব্য ঝুঁকি                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| `browseable = yes`          | Share-এর list দেখা যায়। অননুমোদিত user-ও share discover করতে পারে, যদি অন্য control বাধা না দেয় |
| `read only = no`            | Share-এ file creation ও modification অনুমোদিত হতে পারে                                            |
| `writable = yes`            | User-কে file তৈরি ও পরিবর্তনের অনুমতি দেয়                                                        |
| `guest ok = yes`            | Password ছাড়া connection অনুমোদন করে                                                             |
| `enable privileges = yes`   | নির্দিষ্ট SID-কে দেওয়া privilege কার্যকর করে                                                     |
| `create mask = 0777`        | নতুন file-এর জন্য বিস্তৃত permission mask নির্ধারণ করে                                            |
| `directory mask = 0777`     | নতুন directory-এর জন্য বিস্তৃত permission mask নির্ধারণ করে                                       |
| `logon script = script.sh`  | User login-এর সময় সংশ্লিষ্ট script ব্যবহারের configuration                                       |
| `magic script = script.sh`  | নির্দিষ্ট magic-script functionality-এর মাধ্যমে script execution configuration                    |
| `magic output = script.out` | Magic script-এর output সংরক্ষণের path নির্ধারণ করে                                                |

Security implication: `0777` permission mask file বা directory-তে owner, group এবং others-এর জন্য বিস্তৃত permission তৈরি করতে পারে। কার্যকর permission নির্ধারণে mask, filesystem permission ও Samba configuration একসঙ্গে বিবেচনা করতে হয়।

### 4.2 Example: Risky Share

```
[notes]
    comment = CheckIT
    path = /mnt/notes/

    browseable = yes
    read only = no
    writable = yes
    guest ok = yes

    enable privileges = yes
    create mask = 0777
    directory mask = 0777
```

এই configuration-এর প্রভাব:

1. `[notes]` নামে share তৈরি হয়েছে।
2. Share-এর local path `/mnt/notes/`।
3. `browseable = yes` থাকায় share discover করা যায়।
4. `read only = no` ও `writable = yes` file modification-এর অনুমতি দিতে পারে।
5. `guest ok = yes` থাকায় authentication ছাড়াই access সম্ভব হতে পারে।
6. `0777` mask নতুন file ও directory-তে অতিরিক্ত permission তৈরি করতে পারে।

Testing-এর জন্য তৈরি করা এমন configuration পরে reset না করলে production network-এ sensitive file expose হতে পারে।

Samba configuration reference: [smb.conf Manual](https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html?utm_source=chatgpt.com)

### 4.3 Configuration পরিবর্তনের পর Service Restart

Server-এ `smb.conf` পরিবর্তনের পর Samba service restart করার command:

```
sudo systemctl restart smbd
```

## 5. Anonymous Access ও smbclient

`smbclient` হলো SMB share access, enumeration এবং file transfer-এর জন্য ব্যবহৃত command-line client।

### 5.1 Null Session

`Null session` বলতে এমন SMB session বোঝায় যেখানে client খালি username/password ব্যবহার করে connection করার চেষ্টা করে। একে anonymous access-এর সঙ্গে সম্পর্কিতভাবে ব্যবহার করা হয়।

সব server null session অনুমোদন করে না। অনুমোদন করলেও কোন তথ্য দেখা বা ব্যবহার করা যাবে, তা server-এর configuration ও permission-এর ওপর নির্ভর করে।

### 5.2 Available Share Enumerate করা

```
smbclient -N -L //10.129.14.128
```

Command-এর অংশগুলো:

- `smbclient` — SMB client চালায়।
- `-N` — Password prompt ছাড়া চেষ্টা করে।
- `-L` — Server-এর available share list দেখায়।
- `//10.129.14.128` — Target SMB server।

Example output:

```
Sharename       Type      Comment
---------       ----      -------
print$          Disk      Printer Drivers
home            Disk      INFREIGHT Samba
dev             Disk      DEVenv
notes           Disk      CheckIT
IPC$            IPC       IPC Service (DEVSM)
SMB1 disabled -- no workgroup available
```

এখানে পাঁচটি share দেখা যাচ্ছে:

- `print$` — Printer Drivers
- `home` — INFREIGHT Samba
- `dev` — DEVenv
- `notes` — CheckIT
- `IPC$` — IPC service

`IPC$` হলো SMB-এর একটি special share, যা inter-process communication-সম্পর্কিত কাজের জন্য ব্যবহৃত হয়। `print$` সাধারণত printer driver-এর জন্য ব্যবহৃত হয়।

গুরুত্বপূর্ণ: Share-এর তালিকায় নাম দেখা যাওয়া মানেই সেটির file পড়া বা পরিবর্তন করার permission আছে, এমন নয়।

### 5.3 Share-এ Connect করা

```
smbclient //10.129.14.128/notes
```

Example session:

```
Enter WORKGROUP\<username>'s password:
Anonymous login successful
Try "help" to get a list of possible commands.
```

এখানে server anonymous login গ্রহণ করেছে।

Download সফল হয়েছে কি না দেখতে local directory list:

```
smb: \> !ls
```

Example output:

```
prep-prod.txt
```

Local file-এর content পড়তে:

```
smb: \> !cat prep-prod.txt
```

Example output:

```
[] check your code with the templates
[] run code-assessment.py
[] ...
```

`!ls` ও `!cat` local system-এ চলে; এগুলো remote share-এর command নয়। তাই SMB session চালু রেখেই downloaded file পরীক্ষা করা যায়।

### Domain-level Security

Domain-level security-তে Samba server Windows domain-এর member হিসেবে কাজ করতে পারে। Domain-এর Domain Controller সাধারণত authentication পরিচালনা করে।

Windows domain-এর user ও credential-সংক্রান্ত গুরুত্বপূর্ণ storage-এর মধ্যে রয়েছে:

- `NTDS.dit` — Active Directory database।
- `SAM` — Security Account Manager; local account ও password hash-সংক্রান্ত তথ্য সংরক্ষণের সঙ্গে সম্পর্কিত।

Domain Controller user authentication এবং domain resource access নিয়ন্ত্রণে গুরুত্বপূর্ণ ভূমিকা পালন করে।

## 7. SMB Service Footprinting

`Footprinting` হলো target service সম্পর্কে যতটা সম্ভব তথ্য সংগ্রহ করা। SMB enumeration-এর মাধ্যমে server version, open ports, shares, users, groups, domain information এবং security configuration জানা যেতে পারে।

শুধু automated tool-এর ওপর নির্ভর না করে manual enumeration-ও করা উচিত। কারণ automated tool সব তথ্য নাও দেখাতে পারে এবং বিভিন্ন tool-এর output-এ পার্থক্য থাকতে পারে।

## 8. rpcclient ও MS-RPC Enumeration

### 8.1 RPC কী?

`Remote Procedure Call (RPC)` হলো network-এর মাধ্যমে অন্য system-এ কোনো function বা procedure চালানোর ধারণা। Client request পাঠায়, server সেটি process করে এবং result ফেরত দেয়।

SMB environment-এ `rpcclient` ব্যবহার করে MS-RPC function call করা যায়। এর সাহায্যে server, domain, share, user এবং group সম্পর্কে তথ্য সংগ্রহ করা সম্ভব।

Reference: [Remote Procedure Call (RPC)](https://www.geeksforgeeks.org/remote-procedure-call-rpc-in-operating-system/?utm_source=chatgpt.com)

### 8.2 rpcclient Connection

```
rpcclient -U "" 10.129.14.128
```

এখানে:

- `rpcclient` — RPC enumeration tool।
- `-U ""` — Empty username দিয়ে connection করার চেষ্টা করে।
- `10.129.14.128` — Target IP।

Example:

```
Enter WORKGROUP\'s password:
rpcclient $>
```

Prompt পাওয়া গেলে command চালানো যায়। Empty username ব্যবহার করলেই anonymous connection নিশ্চিত হয় না; server-এর configuration ও access policy-এর ওপর এটি নির্ভর করে।

## 11. RID Brute-Forcing দিয়ে User Enumeration

কখনো সব RPC query অনুমোদিত থাকে না। তবে `queryuser <RID>`-এর মতো query অনুমোদিত থাকলে সম্ভাব্য RID পরীক্ষা করে user information পাওয়া যেতে পারে।

### 11.1 Bash For-loop

```
for i in $(seq 500 1100);do rpcclient -N -U "" 10.129.14.128 -c "queryuser 0x$(printf '%x\n' $i)" | grep "User Name\|user_rid\|group_rid" && echo "";done
```

#### Command-এর ব্যাখ্যা

- `seq 500 1100` — `500` থেকে `1100` পর্যন্ত integer তৈরি করে।
- `for i in ...` — প্রতিটি integer-এর জন্য loop চালায়।
- `printf '%x\n' $i` — Decimal integer-কে hexadecimal-এ রূপান্তর করে।
- `0x...` — RID-কে hexadecimal format-এ পাঠায়।
- `rpcclient -N -U ""` — Password prompt ছাড়া empty username ব্যবহার করে query চালায়।
- `-c "queryuser ..."` — নির্দিষ্ট RPC command চালায়।
- `grep "User Name\|user_rid\|group_rid"` — শুধু উল্লেখিত field-গুলো filter করে।
- `&& echo ""` — আগের command সফল হলে একটি ফাঁকা line যোগ করে।

Example output:

```
User Name   :   sambauser
user_rid :      0x1f5
group_rid:      0x201

User Name   :   mrb3n
user_rid :      0x3e8
group_rid:      0x201

User Name   :   cry0l1t3
user_rid :      0x3e9
group_rid:      0x201
```

এখানে তিনটি user পাওয়া গেছে:

| Username    | RID     | Group RID |
| ----------- | ------- | --------- |
| `sambauser` | `0x1f5` | `0x201`   |
| `mrb3n`     | `0x3e8` | `0x201`   |
| `cry0l1t3`  | `0x3e9` | `0x201`   |

| `force_logoff_time`                               | Force-logoff সময়সংক্রান্ত তথ্য                               |

এই ফলাফল দুর্বল password policy-এর সম্ভাব্য ইঙ্গিত দিতে পারে। তবে policy field-এর সঠিক ব্যাখ্যার জন্য target-এর বাস্তব configuration এবং tool-এর output format যাচাই করা দরকার।

## 16. SMB Enumeration-এর গুরুত্বপূর্ণ শিক্ষা

একটি SMB target পরীক্ষা করার সময় বিভিন্ন tool-এর ফলাফল একসঙ্গে বিবেচনা করতে হবে।

### Enumeration Workflow

1. Port ও service শনাক্ত করা
   ```
   sudo nmap 10.129.14.128 -sV -sC -p139,445
   ```
2. Share list সংগ্রহ করা
   ```
   smbclient -N -L //10.129.14.128
   ```
3. Share-এর content পরীক্ষা করা
   ```
   smbclient //10.129.14.128/notes
   ```
4. RPC দিয়ে server ও domain information সংগ্রহ করা
   ```
   rpcclient -U "" 10.129.14.128
   ```
5. User ও group enumerate করা
   ```
   enumdomusers
   queryuser 0x3e9
   querygroup 0x201
   ```
6. RID range পরীক্ষা করা
   ```
   for i in $(seq 500 1100);do rpcclient -N -U "" 10.129.14.128 -c "queryuser 0x$(printf '%x\n' $i)" | grep "User Name\|user_rid\|group_rid" && echo "";done
   ```
7. বিকল্প enumeration tool ব্যবহার করা
   ```
   samrdump.py 10.129.14.128
   smbmap -H 10.129.14.128
   crackmapexec smb 10.129.14.128 --shares -u '' -p ''
   ./enum4linux-ng.py 10.129.14.128 -A
   ```

### কেন একাধিক Tool ব্যবহার করা জরুরি?

একটি tool-এর implementation, permissions বা query method-এর কারণে তথ্য বাদ পড়তে পারে। এই section-এ তার উদাহরণ রয়েছে:

- `smbmap`-এ share-গুলো `NO ACCESS` দেখিয়েছে।
- `CrackMapExec`-এ `notes` share-এর `READ,WRITE` permission দেখা গেছে।
- `enum4linux-ng`-এ share enumerate হলেও কিছু share test করার সময় error এসেছে।
- RPC query-তে domain/workgroup-সংক্রান্ত তথ্য একাধিক রূপে এসেছে।

তাই automated tool-এর output যাচাই করতে manual `smbclient` ও `rpcclient` query ব্যবহার করা উচিত।

### Security Perspective

SMB service-এ বিশেষভাবে পরীক্ষা করতে হবে:

- Anonymous বা null-session access অনুমোদিত কি না।
- Sensitive share browse করা যায় কি না।
- কোনো share-এ read/write access আছে কি না।
- User ও group information অননুমোদিতভাবে প্রকাশিত হচ্ছে কি না।
- SMB signing বাধ্যতামূলক কি না।
- পুরোনো SMB dialect সক্রিয় আছে কি না।
- Password policy দুর্বল কি না।
- Share configuration-এ অতিরিক্ত permission দেওয়া হয়েছে কি না।

মূল শিক্ষা: SMB enumeration-এর লক্ষ্য শুধু open port খুঁজে বের করা নয়; বরং service configuration, exposed resources, access permissions এবং information disclosure-এর সম্মিলিত প্রভাব বোঝা।
