# File Transfer Protocol (FTP) - [LINK](https://academy.hackthebox.com/app/module/112/section/1066)

## Introduction (ভূমিকা)

ইন্টারনেটের অন্যতম প্রাচীন প্রোটোকল হলো **File Transfer Protocol (FTP)**। FTP মূলত TCP/IP প্রোটোকল স্ট্যাকের **application layer**-এ কাজ করে। অর্থাৎ, এটি HTTP বা POP-এর মতোই একই লেয়ারে অবস্থান করে। এই প্রোটোকলগুলো তাদের সার্ভিস প্রদানের জন্য browsers বা email clients-এর সহায়তা নিয়ে কাজ করে। এছাড়াও File Transfer Protocol-এর জন্য বিশেষ কিছু FTP প্রোগ্রাম বা ক্লায়েন্ট রয়েছে।

ধরা যাক, আমরা FTP প্রোটোকল ব্যবহার করে একটি সার্ভারে লোকাল ফাইল আপলোড করতে এবং অন্য ফাইল ডাউনলোড করতে চাই। একটি FTP কানেকশনে দুটি চ্যানেল ওপেন করা হয়:

1. **Control Channel:** প্রথমে ক্লায়েন্ট এবং সার্ভার **TCP port 21**-এর মাধ্যমে একটি control channel স্থাপন করে। ক্লায়েন্ট সার্ভারে কমান্ড পাঠায় এবং সার্ভার এর জবাবে স্ট্যাটাস কোড (status codes) প্রদান করে।
2. **Data Channel:** এরপর উভয় পক্ষ **TCP port 20**-এর মাধ্যমে data channel স্থাপন করতে পারে। এই চ্যানেলটি একচেটিয়াভাবে ডেটা ট্রান্সমিশনের জন্য ব্যবহৃত হয় এবং প্রোটোকলটি এই প্রক্রিয়া চলাকালীন ত্রুটি (errors) পর্যবেক্ষণ করে। ট্রান্সমিশনের সময় কানেকশন বিচ্ছিন্ন হয়ে গেলে, পুনরায় কানেকশন স্থাপনের পর ট্রান্সপোর্ট আবার শুরু (resume) করা যায়।

FTP মূলত একটি **clear-text protocol**। নেটওয়ার্কের পরিস্থিতি অনুকূল হলে এর ট্রাফিক স্নিফ (sniff) করা সম্ভব।

## Active vs. Passive FTP

FTP-তে প্রধানত দুটি মোড রয়েছে:

* **Active FTP:** এই ভ্যারিয়েন্টে ক্লায়েন্ট **TCP port 21** ব্যবহার করে কানেকশন স্থাপন করে এবং সার্ভারকে জানিয়ে দেয় যে সার্ভার কোন ক্লায়েন্ট-সাইড পোর্টের মাধ্যমে রেসপন্স পাঠাতে পারবে। তবে ক্লায়েন্ট যদি ফায়ারওয়াল (firewall) দ্বারা সুরক্ষিত থাকে, তবে সার্ভার রিপ্লাই দিতে পারে না কারণ সমস্ত বাহ্যিক (external) কানেকশন ব্লক করা থাকে।
* **Passive FTP:** এই ফায়ারওয়াল সমস্যা সমাধানের জন্য passive mode তৈরি করা হয়েছে। এখানে সার্ভার নিজেই একটি পোর্টের কথা ঘোষণা করে, যার মাধ্যমে ক্লায়েন্ট data channel স্থাপন করতে পারে। যেহেতু এই পদ্ধতিতে ক্লায়েন্ট কানেকশন ইনিশিয়েট (initiate) করে, তাই ফায়ারওয়াল ডেটা ট্রান্সফার ব্লক করে না।

FTP বিভিন্ন commands এবং status codes ব্যবহার করে কাজ করে, তবে সার্ভারে সবসময় সব কমান্ড ইমপ্লিমেন্ট করা থাকে না। ক্লায়েন্ট ফাইল আপলোড, ডাউনলোড, ডিরেক্টরি অর্গানাইজ করা বা ফাইল মুছে ফেলার নির্দেশ দেয় এবং সার্ভার স্ট্যাটাস কোডের মাধ্যমে জানায় কমান্ডটি সফল হয়েছে কিনা।

**Anonymous FTP:** সার্ভারে FTP ব্যবহারের জন্য সাধারণত credentials-এর প্রয়োজন হয়। তবে কোনো সার্ভার **anonymous FTP** অফার করতে পারে। এক্ষেত্রে সার্ভার অপারেটর যেকোনো ব্যবহারকারীকে পাসওয়ার্ড ছাড়াই FTP-এর মাধ্যমে ফাইল আপলোড বা ডাউনলোড করার অনুমতি দেয়। নিরাপত্তা ঝুঁকির কারণে এই ধরনের পাবলিক সার্ভারে ব্যবহারকারীদের অপশন সাধারণত সীমিত থাকে।

## TFTP (Trivial File Transfer Protocol)

TFTP হলো FTP-এর চেয়ে অনেক সহজ একটি প্রোটোকল, যা ক্লায়েন্ট এবং সার্ভার প্রসেসের মধ্যে ফাইল ট্রান্সফার করে। তবে এটি user authentication এবং FTP-তে থাকা অন্যান্য ভ্যালুয়েবল ফিচার সাপোর্ট করে না।

* **Protocol:** FTP যেখানে TCP ব্যবহার করে, TFTP সেখানে **UDP** ব্যবহার করে। এর ফলে এটি একটি unreliable প্রোটোকল এবং এটি UDP-assisted application layer recovery-এর ওপর নির্ভর করে।
* **Security:** TFTP-তে কোনো user authentication-এর প্রয়োজন হয় না এবং এটি পাসওয়ার্ড-ভিত্তিক সুরক্ষিত লগইন সাপোর্ট করে না। এটি শুধুমাত্র অপারেটিং সিস্টেমের ফাইলের read এবং write permissions-এর ওপর ভিত্তি করে কাজ করে।
* **Usage:** নিরাপত্তার অভাবে TFTP সাধারণত শুধুমাত্র **local এবং protected networks**-এ ব্যবহার করা হয়। এটি এমন ডিরেক্টরি এবং ফাইলেই কাজ করতে পারে যা সব ব্যবহারকারীর জন্য গ্লোবালি read এবং write করার অনুমতিপ্রাপ্ত।

> **Important Note:** FTP ক্লায়েন্টের মতো TFTP-তে কোনো directory listing কার্যক্ষমতা নেই।

### TFTP Commands

| Commands | Description |
| --- | --- |
| `connect` | ফাইল ট্রান্সফারের জন্য remote host এবং ঐচ্ছিকভাবে (optionally) পোর্ট সেট করে। |
| `get` | Remote host থেকে local host-এ একটি ফাইল বা ফাইলের সেট ট্রান্সফার করে। |
| `put` | Local host থেকে remote host-এ একটি ফাইল বা ফাইলের সেট ট্রান্সফার করে। |
| `quit` | TFTP থেকে বের হয়ে যায় (exit)। |
| `status` | TFTP-এর বর্তমান স্ট্যাটাস দেখায়, যার মধ্যে current transfer mode (ascii/binary), connection status, time-out value ইত্যাদি অন্তর্ভুক্ত থাকে। |
| `verbose` | Verbose mode অন বা অফ করে, যা ফাইল ট্রান্সফারের সময় অতিরিক্ত তথ্য প্রদর্শন করে। |

## Default Configuration (vsFTPd)

Linux-ভিত্তিক ডিস্ট্রিবিউশনগুলোতে সবচেয়ে বেশি ব্যবহৃত FTP সার্ভারগুলোর একটি হলো **vsFTPd**। এর ডিফল্ট কনফিগারেশন `/etc/vsftpd.conf` ফাইলে পাওয়া যায় এবং কিছু সেটিংস ডিফল্টভাবে প্রি-ডিফাইন করা থাকে।

**Install vsFTPd:**

```bash
00Luffy00@htb[/htb]$ sudo apt install vsftpd
```

### vsFTPd Config File

কনফিগারেশন ফাইলে অনেক অপশন রয়েছে। বিদ্যমান এবং অনুপস্থিত সকল অপশন `man page`-এ পাওয়া যায়।

```bash
00Luffy00@htb[/htb]$ cat /etc/vsftpd.conf | grep -v "#"

```

| Setting | Description |
| --- | --- |
| `listen=NO` | এটি কি inetd থেকে রান করবে নাকি standalone daemon হিসেবে রান করবে? |
| `listen_ipv6=YES` | IPv6-এ লিসেন করবে কি? |
| `anonymous_enable=NO` | Anonymous অ্যাক্সেস এনাবল করা হবে কি? |
| `local_enable=YES` | লোকাল ইউজারদের লগইন করার অনুমতি দেওয়া হবে কি? |
| `dirmessage_enable=YES` | ইউজাররা নির্দিষ্ট ডিরেক্টরিতে গেলে কি অ্যাক্টিভ ডিরেক্টরি মেসেজ প্রদর্শিত হবে? |
| `use_localtime=YES` | লোকাল টাইম ব্যবহার করা হবে কি? |
| `xferlog_enable=YES` | আপলোড/ডাউনলোডের লগিং অ্যাক্টিভেট করা হবে কি? |
| `connect_from_port_20=YES` | পোর্ট ২০ থেকে কানেক্ট করা হবে কি? |
| `secure_chroot_dir=/var/run/vsftpd/empty` | একটি ফাঁকা ডিরেক্টরির নাম। |
| `pam_service_name=vsftpd` | এটি হলো সেই PAM সার্ভিসের নাম যা vsftpd ব্যবহার করবে। |
| `rsa_cert_file=/etc/ssl/certs/ssl-cert-snakeoil.pem` | SSL এনক্রিপ্টেড কানেকশনের জন্য ব্যবহারযোগ্য RSA সার্টিফিকেটের লোকেশন। |
| `rsa_private_key_file=/etc/ssl/private/ssl-cert-snakeoil.key` | প্রাইভেট কী-এর লোকেশন। |
| `ssl_enable=NO` | SSL এনাবল করা হবে কি? |

### FTPUSERS File

এছাড়াও `/etc/ftpusers` নামে একটি ফাইল থাকে যা কিছু নির্দিষ্ট ইউজারকে FTP সার্ভিসে অ্যাক্সেস দিতে অস্বীকার (deny) করে। নিচের উদাহরণে, `guest`, `john`, এবং `kevin` লিনাক্স সিস্টেমে থাকা সত্ত্বেও তারা FTP সার্ভিসে লগইন করার অনুমতি পাবে না।

```bash
00Luffy00@htb[/htb]$ cat /etc/ftpusers

guest
john
kevin

```

## Dangerous Settings

প্রতিটি FTP সার্ভারে আমরা বিভিন্ন security-related সেটিংস করতে পারি। এর মধ্যে একটি হলো **anonymous user** মেকানিজম। এটি প্রায়শই ইন্টারনাল নেটওয়ার্কে সবার সাথে ডেটা শেয়ার করার জন্য ব্যবহৃত হয়।

**vsFTPd Anonymous Settings:**

| Setting | Description |
| --- | --- |
| `anonymous_enable=YES` | Anonymous লগইন করার অনুমতি দেয়। |
| `anon_upload_enable=YES` | Anonymous ইউজারকে ফাইল আপলোড করার অনুমতি দেয়। |
| `anon_mkdir_write_enable=YES` | Anonymous ইউজারকে নতুন ডিরেক্টরি তৈরি করার অনুমতি দেয়। |
| `no_anon_password=YES` | Anonymous ইউজারের কাছে পাসওয়ার্ড চাইবে না। |
| `anon_root=/home/username/ftp` | Anonymous ইউজারদের জন্য নির্ধারিত ডিরেক্টরি। |
| `write_enable=YES` | FTP কমান্ডসমূহ (STOR, DELE, RNFR, RNTO, MKD, RMD, APPE, SITE) ব্যবহারের অনুমতি দেয়। |

### Anonymous Login Example

উপরের সেটিংসগুলো প্রয়োগ করা থাকলে আমরা স্ট্যান্ডার্ড FTP ক্লায়েন্ট (`ftp`) ব্যবহার করে সার্ভারে `anonymous` ইউজার হিসেবে লগইন করতে পারি।

কানেক্ট করার সাথে সাথেই রেসপন্স কোড `220` এবং FTP সার্ভারের ব্যানার (Banner) প্রদর্শিত হয়, যেখানে সার্ভিসটির বর্ণনা, ভার্সন এবং সিস্টেমের ধরন উল্লেখ থাকে।

### Additional Security & User Settings

| Setting | Description |
| --- | --- |
| `dirmessage_enable=YES` | নতুন ডিরেক্টরিতে প্রবেশের সময় মেসেজ দেখায়। |
| `chown_uploads=YES` | Anonymous আপলোড করা ফাইলের ownership পরিবর্তন করে। |
| `chown_username=username` | যাকে anonymous আপলোড করা ফাইলের ownership দেওয়া হবে তার ইউজারনেম। |
| `local_enable=YES` | লোকাল ইউজারদের লগইন এনাবল করে। |
| `chroot_local_user=YES` | লোকাল ইউজারদের তাদের home directory-তে সীমাবদ্ধ (place) করে। |
| `chroot_list_enable=YES` | এমন ইউজারদের লিস্ট ব্যবহার করে যাদের home directory-তে রাখা হবে। |
| `hide_ids=YES` | ডিরেক্টরি লিস্টিংয়ে সব ইউজার এবং গ্রুপের তথ্য "ftp" হিসেবে দেখায়। |
| `ls_recurse_enable=YES` | Recurse লিস্টিং (`ls -R`) ব্যবহারের অনুমতি দেয়। |

**Hiding IDs - YES**
`hide_ids=YES` সেটিং উপস্থিত থাকলে সার্ভিসের UID এবং GUID ওভ্যাররাইট হয়ে যায়। এটি একটি সিকিউরিটি ফিচার যা লোকাল ইউজারনেমগুলো ফাঁস হওয়া রোধ করে।

```bash

200 Switching to ASCII mode.
ftp: setsockopt (ignored): Permission denied

200 PORT command successful. Consider using PASV.
```

## Interacting with the FTP Server

### Download a File

FTP থেকে ফাইল ডাউনলোড করা (যেমন, LFI vulnerabilities ব্যবহার করে কমান্ড এক্সিকিউট করা বা FTP লগ থেকে RCE বা Remote Command Execution) আমাদের অ্যাটাকের সুযোগ তৈরি করতে পারে। ফাইল ডাউনলোড করতে `get` কমান্ড ব্যবহৃত হয়।

```bash
ftp> get Important\ Notes.txt

local: Important Notes.txt remote: Important Notes.txt
200 PORT command successful. Consider using PASV.
150 Opening BINARY mode data connection for Important Notes.txt (41 bytes).
226 Transfer complete.
41 bytes received in 0.00 secs (606.6525 kB/s)

ftp> exit
221 Goodbye.

00Luffy00@htb[/htb]$ ls | grep Notes.txt
'Important Notes.txt'

```

### Download All Available Files

একসাথে সব ফাইল এবং ফোল্ডার ডাউনলোড করতে `wget` টুলটি খুবই কার্যকরী। এটি একটি বড় ডিরেক্টরি স্ট্রাকচার থেকে একসাথে সমস্ত কন্টেন্ট ডাউনলোড করে লোকাল মেশিনে টার্গেট আইপির নামে একটি ফোল্ডারে সেভ করে।

### Upload a File

যদি আমাদের FTP সার্ভারে আপলোড করার অনুমতি থাকে, তবে আমরা `put` কমান্ডের মাধ্যমে লোকাল ফাইল সার্ভারে আপলোড করতে পারি। ওয়েব সার্ভারের সাথে সংযুক্ত FTP-তে ফাইল আপলোড করার সক্ষমতা আমাদেরকে রিভার্স শেল (reverse shell) বা সরাসরি কমান্ড এক্সিকিউট করার সুযোগ দিতে পারে।

```bash
00Luffy00@htb[/htb]$ touch testupload.txt

ftp> put testupload.txt

---> PORT 10,10,14,4,184,33
200 PORT command successful. Consider using PASV.
---> STOR testupload.txt
150 Ok to send data.
226 Transfer complete.

```

## Footprinting the Service

নেটওয়ার্ক স্ক্যানার (যেমন Nmap) ব্যবহার করে সার্ভিসের ফুটপ্রিন্টিং করা অত্যন্ত কার্যকর। Nmap-এর সাথে **Nmap Scripting Engine (NSE)** যুক্ত থাকে, যা নির্দিষ্ট সার্ভিসের জন্য লেখা স্ক্রিপ্টের একটি সংগ্রহ।

**NSE ডাটাবেস আপডেট করা:**

```bash
00Luffy00@htb[/htb]$ sudo nmap --script-updatedb

```

**FTP স্ক্রিপ্টসমূহ খুঁজে বের করা:**

```bash
00Luffy00@htb[/htb]$ find / -type f -name ftp* 2>/dev/null | grep scripts

/usr/share/nmap/scripts/ftp-syst.nse
/usr/share/nmap/scripts/ftp-vsftpd-backdoor.nse
...

```
