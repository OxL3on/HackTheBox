## **FTP**

It operates at the **Application Layer** of the TCP/IP model.

### How FTP Works

FTP uses **two separate channels**.

**1. Control Channel :** Uses **TCP Port 21 ,** Client sends commands. , Server returns status codes.

**2. Data Channel :** Uses **TCP Port 20 ,** Transfers the actual files. , Checks for transmission errors. , If the connection breaks, the transfer can continue after reconnecting.

### Active vs Passive FTP

**Active FTP**

1. Client connects to **TCP 21**.
2. Client tells the server which client port to use.
3. Server opens a connection back to the client.

**Passive FTP**

1. Server tells the client which port to use.
2. Client initiates the data connection.

Since the client starts both connections, firewalls usually allow it. Passive FTP is therefore more firewall-friendly.

### TFTP (Trivial FTP)

TFTP is a simplified version of FTP. It transfers files between client and server but removes many FTP features.

| FTP | TFTP |
| --- | --- |
| Uses TCP | Uses UDP |
| Reliable | Less reliable |
| Supports authentication | No authentication |
| Supports many commands | Very limited |
| Directory listing available | No directory listing |

#### **Common TFTP Commands**

| Command | Purpose |
| --- | --- |
| connect | Connect to a remote host |
| get | Download files |
| put | Upload files |
| quit | Exit TFTP |
| status | Show transfer status |
| verbose | Enable detailed output |

### Default FTP Server (vsFTPd)

One of the most popular Linux FTP servers is. Default configuration file: `/etc/vsftpd.conf`

Install it with:

```bash
sudo apt install vsftpd
```

| Setting | Purpose |
| --- | --- |
| listen=NO | Run via inetd or standalone |
| listen_ipv6=YES | Listen on IPv6 |
| anonymous_enable=NO | Disable anonymous login |
| local_enable=YES | Allow local users |
| dirmessage_enable=YES | Show directory messages |
| use_localtime=YES | Use local time |
| xferlog_enable=YES | Enable upload/download logs |
| connect_from_port_20=YES | Use port 20 |
| secure_chroot_dir | Empty chroot directory |
| pam_service_name | PAM authentication service |
| rsa_cert_file | SSL certificate |
| rsa_private_key_file | SSL private key |
| ssl_enable=NO | SSL disabled by default |
- Another important file: `/etc/ftpusers` . This file blocks users from logging in.

**Dangerous Settings**

| Setting | Purpose |
| --- | --- |
| anonymous_enable=YES | Allow anonymous login |
| anon_upload_enable=YES | Allow uploads |
| anon_mkdir_write_enable=YES | Allow directory creation |
| no_anon_password=YES | Don't ask for password |
| anon_root | Anonymous home directory |
| write_enable=YES | Allow write commands |

**Why Hide IDs?**

`hide_ids=YES` It hides usernames, So it makes brute-force harder. Also most servers use: `fail2ban` which blocks IP addresses after too many failed login attempts.

**Recursive Listing**

`ls_recurse_enable=YES` This lists every directory and file recursively.

**Download Everything**

```bash
wget -m --no-passive ftp://anonymous:anonymous@<IP>
```

**Upload Files**

Create a file: `touch testupload.txt`

Upload it: `put testupload.txt`

If successful, the uploaded file appears in the FTP directory.

### Footprinting FTP

**Update NSE scripts :** `sudo nmap --script-updatedb`

**Find FTP NSE scripts :** 

```bash
find / -type f -name ftp* 2>/dev/null | grep scripts
```

**Basic FTP Scan : `sudo nmap -sV -p21 -sC -A <IP>`** 

- Important NSE Scripts : ftp-anon , ftp-syst

**Script Trace : `--script-trace`** 

**Manual Interaction : `nc <IP> 21` or `telnet <IP> 21`**

**FTPS (FTP over TLS/SSL)**

If FTP uses TLS, regular FTP clients may not work.

Use:

```
openssl s_client-connect <IP>:21-starttls ftp
```
