# File Transfer Protocol (FTP) - [LINK](https://academy.hackthebox.com/app/module/112/section/1066)


FTP (File Transfer Protocol) হলো ইন্টারনেটের অন্যতম পুরোনো একটি প্রোটোকল। এটি TCP/IP প্রোটোকল স্ট্যাকের অ্যাপ্লিকেশন লেয়ারে (application layer) কাজ করে। এর মানে হলো এটি HTTP বা POP-এর মতোই একই লেয়ারে কাজ করে। এই প্রোটোকলগুলো সাধারণত ব্রাউজার বা ইমেইল ক্লায়েন্টের সাহায্যে কাজ করলেও, FTP-এর জন্য বিশেষায়িত ফাইল ট্রান্সফার প্রোগ্রাম রয়েছে।

### FTP কীভাবে কাজ করে?

ধরুন, আপনি FTP ব্যবহার করে একটি সার্ভারে আপনার লোকাল ফাইল আপলোড করতে চান বা সেখান থেকে কোনো ফাইল ডাউনলোড করতে চান। একটি FTP কানেকশনে দুটি চ্যানেল খোলা হয়:

1. **Control Channel (TCP Port 21):** প্রথমে ক্লায়েন্ট এবং সার্ভার TCP পোর্ট 21-এর মাধ্যমে একটি কন্ট্রোল চ্যানেল স্থাপন করে। ক্লায়েন্ট এই চ্যানেলের মাধ্যমে সার্ভারে কমান্ড পাঠায় এবং সার্ভার স্ট্যাটাস কোড (status codes) রিটার্ন করে।
2. **Data Channel (TCP Port 20):** এরপর উভয় পক্ষ TCP পোর্ট 20-এর মাধ্যমে ডেটা চ্যানেল তৈরি করতে পারে। এই চ্যানেলটি শুধুমাত্র ডেটা ট্রান্সমিশনের জন্য ব্যবহৃত হয় এবং প্রোটোকলটি এই প্রক্রিয়ায় কোনো ভুল হচ্ছে কি না তা পর্যবেক্ষণ করে। যদি ডেটা ট্রান্সফারের মাঝখানে কানেকশনটি বিচ্ছিন্ন হয়ে যায়, তবে পুনরায় কানেকশন স্থাপন করে ট্রান্সফারটি যেখানে বন্ধ হয়েছিল সেখান থেকেই আবার শুরু করা সম্ভব।

### Active এবং Passive FTP

FTP দুটি ভিন্ন মোডে কাজ করতে পারে: Active এবং Passive।

* **Active FTP:** এই পদ্ধতিতে, ক্লায়েন্ট TCP পোর্ট 21 ব্যবহার করে কানেকশন তৈরি করে এবং সার্ভারকে জানিয়ে দেয় যে ক্লায়েন্টের কোন পোর্ট দিয়ে সার্ভার তার রেসপন্স পাঠাতে পারবে। কিন্তু, যদি ক্লায়েন্ট একটি ফায়ারওয়াল দিয়ে সুরক্ষিত থাকে, তবে ফায়ারওয়াল সব এক্সটার্নাল কানেকশন ব্লক করে দেওয়ায় সার্ভার রিপ্লাই দিতে পারে না।
* **Passive FTP:** এই সমস্যার সমাধানের জন্যই প্যাসিভ মোড তৈরি করা হয়েছে। এই মোডে, সার্ভার একটি পোর্ট ঘোষণা করে, যার মাধ্যমে ক্লায়েন্ট ডেটা চ্যানেল স্থাপন করতে পারে। যেহেতু এই পদ্ধতিতে ক্লায়েন্ট নিজেই কানেকশন ইনিশিয়েট (initiate) করে, তাই ফায়ারওয়াল ডেটা ট্রান্সফার ব্লক করে না।

### FTP Commands এবং Status Codes

FTP-এর বিভিন্ন কমান্ড এবং স্ট্যাটাস কোড রয়েছে, তবে সব কমান্ড সবসময় সব সার্ভারে একইভাবে বাস্তবায়ন (implement) করা থাকে না। যেমন, ক্লায়েন্ট সার্ভারকে ফাইল আপলোড/ডাউনলোড, ডিরেক্টরি অর্গানাইজ করা বা ফাইল ডিলিট করার নির্দেশ দিতে পারে। সার্ভার প্রতিটি কমান্ডের বিপরীতে একটি স্ট্যাটাস কোড দিয়ে জানায় যে কমান্ডটি সফলভাবে সম্পন্ন হয়েছে কি না।

সাধারণত সার্ভারে FTP ব্যবহার করতে ইউজারনেম এবং পাসওয়ার্ড (credentials) লাগে। তবে মনে রাখা জরুরি, FTP একটি **clear-text protocol**। এর মানে হলো, নেটওয়ার্কের পরিবেশ যদি অনুকূলে থাকে, তবে ডেটা প্যাকেটগুলো স্নিফ (sniff) বা চুরি করে পড়া সম্ভব।

অনেক সময় সার্ভার অপারেটররা **Anonymous FTP**-এর সুযোগ দেয়, যেখানে যেকোনো ইউজার পাসওয়ার্ড ছাড়াই ফাইল আপলোড বা ডাউনলোড করতে পারে। তবে এটি বেশ ঝুঁকিপূর্ণ, তাই পাবলিক FTP সার্ভারগুলোতে সাধারণত ইউজারদের ক্ষমতা সীমিত করে দেওয়া হয়।

## TFTP (Trivial File Transfer Protocol)

TFTP (Trivial File Transfer Protocol) হলো FTP-এর একটি অনেক সহজ ভার্সন। এটি ক্লায়েন্ট এবং সার্ভার প্রসেসের মধ্যে ফাইল ট্রান্সফারের কাজ করে। তবে, এটিতে ইউজার অথেনটিকেশন (user authentication) এবং FTP-তে থাকা অন্যান্য দরকারি ফিচারগুলো থাকে না। সবচেয়ে বড় পার্থক্য হলো, FTP যেখানে নির্ভরযোগ্য TCP ব্যবহার করে, TFTP সেখানে UDP ব্যবহার করে। ফলে এটি একটি আনরিলায়েবল (unreliable) প্রোটোকলে পরিণত হয় এবং একে অ্যাপ্লিকেশন লেয়ারের রিকভারির ওপর নির্ভর করতে হয়।

### TFTP-এর সীমাবদ্ধতা:

* **No Authentication:** এতে পাসওয়ার্ড দিয়ে লগইন করার কোনো ব্যবস্থা নেই।
* **File Permissions Only:** এটি অপারেটিং সিস্টেমের ফাইল পারমিশনের (read/write) ওপর ভিত্তি করে কাজ করে।
* **Global Access Required:** এটি শুধুমাত্র সেই সব ডিরেক্টরি এবং ফাইলেই কাজ করে যেগুলো সবার জন্য শেয়ার করা (globally readable and writable)।
* **Local Network Use:** সিকিউরিটির অভাবে এটি সাধারণত শুধুমাত্র লোকাল এবং সুরক্ষিত নেটওয়ার্কেই ব্যবহার করা হয়।
* **No Directory Listing:** FTP-এর মতো এতে ডিরেক্টরির ফাইলগুলো লিস্ট করে দেখার সুযোগ নেই।

### TFTP-এর সাধারণ কমান্ডসমূহ:

| Command | Description (বিবরণ) |
| --- | --- |
| `connect` | ফাইল ট্রান্সফারের জন্য রিমোট হোস্ট এবং অপশনালি পোর্ট সেট করে। |
| `get` | রিমোট হোস্ট থেকে লোকাল হোস্টে ফাইল ট্রান্সফার করে। |
| `put` | লোকাল হোস্ট থেকে রিমোট হোস্টে ফাইল ট্রান্সফার করে। |
| `quit` | tftp থেকে বের হয়ে যায়। |
| `status` | tftp-এর বর্তমান অবস্থা দেখায় (ট্রান্সফার মোড, কানেকশন স্ট্যাটাস, টাইম-আউট ইত্যাদি)। |
| `verbose` | ফাইল ট্রান্সফারের সময় অতিরিক্ত তথ্য দেখানোর জন্য ভার্বোস মোড অন/অফ করে। |

## Default Configuration (ডিফল্ট কনফিগারেশন)

Linux সিস্টেমে অন্যতম বহুল ব্যবহৃত FTP সার্ভার হলো **vsFTPd**। এর ডিফল্ট কনফিগারেশন ফাইলটি `/etc/vsftpd.conf`-এ থাকে এবং এতে কিছু সেটিংস আগে থেকেই প্রি-ডিফাইন করা থাকে। এটি কীভাবে কাজ করে তা ভালোভাবে বুঝতে একটি ভার্চুয়াল মেশিনে vsFTPd সার্ভার ইন্সটল করে দেখা খুবই রেকমেন্ডেড।

### Install vsFTPd

```bash
00Luffy00@htb[/htb]$ sudo apt install vsftpd 

```

vsFTPd ছাড়াও আরও অনেক FTP সার্ভার রয়েছে যেগুলোতে বিভিন্ন ধরনের ফিচার ও কনফিগারেশন অপশন পাওয়া যায়। তবে আমরা vsFTPd ব্যবহার করব কারণ এটি খুব সহজ ও সুন্দরভাবে একটি FTP সার্ভারের কনফিগারেশন সম্ভাবনাগুলো তুলে ধরে।

কনফিগারেশন ফাইলটি দেখলে বোঝা যাবে এতে অনেক অপশন ও সেটিংস রয়েছে যেগুলোর অনেকগুলোই কমেন্টেড বা কমেন্টেড আউট (commented out) করা। তবে সব অপশন এই ফাইলে থাকে না, বাকিগুলো ম্যান পেজে (man page) পাওয়া যায়।

### vsFTPd Config File Analysis

```bash
00Luffy00@htb[/htb]$ cat /etc/vsftpd.conf | grep -v "#"

```

| Setting | Description (বিবরণ) |
| --- | --- |
| `listen=NO` | এটি inetd থেকে চলবে নাকি স্ট্যান্ডঅ্যালোন ডেমন (standalone daemon) হিসেবে চলবে তা নির্ধারণ করে। |
| `listen_ipv6=YES` | IPv6-এ লিসেন (listen) করবে কি না। |
| `anonymous_enable=NO` | অ্যানোনিমাস অ্যাক্সেস (Anonymous access) এনাবল করবে কি না। |
| `local_enable=YES` | লোকাল ইউজারদের লগইন করার অনুমতি দেবে কি না। |
| `dirmessage_enable=YES` | ইউজাররা নির্দিষ্ট ডিরেক্টরিতে ঢুকলে অ্যাক্টিভ ডিরেক্টরি মেসেজ দেখাবে কি না। |
| `use_localtime=YES` | লোকাল টাইম ব্যবহার করবে কি না। |
| `xferlog_enable=YES` | আপলোড/ডাউনলোডের লগিং চালু করবে কি না। |
| `connect_from_port_20=YES` | পোর্ট 20 থেকে কানেক্ট করবে কি না। |
| `secure_chroot_dir=/var/run/vsftpd/empty` | একটি ফাঁকা ডিরেক্টরির নাম। |
| `pam_service_name=vsftpd` | vsftpd যে PAM সার্ভিস ব্যবহার করবে তার নাম। |
| `rsa_cert_file=/etc/ssl/certs/ssl-cert-snakeoil.pem` | SSL এনক্রিপ্টেড কানেকশনের জন্য RSA সার্টিফিকেটের লোকেশন। |
| `rsa_private_key_file=/etc/ssl/private/ssl-cert-snakeoil.key` | প্রাইভেট কি-এর লোকেশন। |
| `ssl_enable=NO` | SSL এনাবল করবে কি না। |

এছাড়া `/etc/ftpusers` নামে একটি ফাইল থাকে, যা নির্দিষ্ট কিছু ইউজারকে FTP সার্ভিসে অ্যাক্সেস দেওয়া থেকে বিরত রাখতে ব্যবহৃত হয়।

### FTPUSERS File Example

নিচের উদাহরণে, Linux সিস্টেমে ইউজারগুলো থাকলেও তারা FTP সার্ভিসে লগইন করতে পারবে না।

```bash
00Luffy00@htb[/htb]$ cat /etc/ftpusers

guest
john
kevin

```

## Dangerous Settings (বিপজ্জনক সেটিংস)

একটি FTP সার্ভারে আমরা বিভিন্ন ধরনের সিকিউরিটি-সম্পর্কিত সেটিংস কনফিগার করতে পারি, যার অনেক উদ্দেশ্য থাকতে পারে। যেমন ফায়ারওয়ালের মাধ্যমে কানেকশন চেক করা, রুট টেস্ট করা, এবং অথেনটিকেশন মেকানিজম পরীক্ষা করা।

এরকম একটি অথেনটিকেশন মেকানিজম হলো **Anonymous User**। ইন্টারনাল নেটওয়ার্কে এক কম্পিউটারের তথ্য অন্য কম্পিউটারে সহজে আদান-প্রদানের জন্য প্রায়শই এটি ব্যবহার করা হয়।

vsFTPd-তে অ্যানোনিমাস লগইনের জন্য কনফিগারেশন ফাইলে যে অপশনাল সেটিংসগুলো যুক্ত করা যেতে পারে তা নিচে দেওয়া হলো:

| Setting | Description (বিবরণ) |
| --- | --- |
| `anonymous_enable=YES` | অ্যানোনিমাস লগইন অ্যালাউ করবে কি না। |
| `anon_upload_enable=YES` | অ্যানোনিমাস ইউজারকে ফাইল আপলোডের অনুমতি দেবে কি না। |
| `anon_mkdir_write_enable=YES` | অ্যানোনিমাস ইউজারকে নতুন ডিরেক্টরি তৈরির অনুমতি দেবে কি না। |
| `no_anon_password=YES` | অ্যানোনিমাস ইউজারের কাছে পাসওয়ার্ড চাইবে কি না। |
| `anon_root=/home/username/ftp` | অ্যানোনিমাস ইউজারের জন্য নির্ধারিত ডিরেক্টরি। |
| `write_enable=YES` | FTP কমান্ড (যেমন STOR, DELE, RNFR, RNTO, MKD, RMD, APPE, SITE) ব্যবহারের অনুমতি দেবে কি না। |

উপরের সেটিংসগুলো থাকলে স্ট্যান্ডার্ড FTP ক্লায়েন্ট (`ftp`) ব্যবহার করে আমরা খুব সহজেই অ্যানোনিমাস ইউজার হিসেবে লগইন করতে পারি। সাধারণত পরিচিত ইন্টারনাল এনভায়রনমেন্টে দ্রুত ফাইল ট্রান্সফারের জন্যই এই সেটিংস ব্যবহার করা হয়।

vsFTPd সার্ভারে কানেক্ট করা মাত্রই `220` রেসপন্স কোডসহ সার্ভারের ব্যানার দেখা যায়। এই ব্যানারে প্রায়ই সার্ভিসটির ডেসক্রিপশন এবং এর ভার্সন দেওয়া থাকে।

অনেক সময় FTP সার্ভারগুলো এমনভাবে কনফিগার করা থাকে যেখানে অ্যানোনিমাস লগইন অ্যালাউ করা থাকে, কিন্তু ফাইল ডাউনলোডের অনুমতি থাকে না। তারপরও শুধু ডিরেক্টরির কন্টেন্ট লিস্ট করে দেখাই আমাদের জন্য অনেক উপকারী হতে পারে, কারণ এখান থেকে পাওয়া তথ্য পরবর্তীতে অন্য কোনো অ্যাটাক ভেক্টরে কাজে লাগতে পারে।

যদি আমরা এমন কোনো FTP সার্ভারে ফাইল আপলোড করতে পারি, তবে ওয়েব সার্ভারে ডাইরেক্ট অ্যাক্সেস এমনকি রিভার্স শেল (reverse shell) পাওয়ার সম্ভাবনাও অনেক বেড়ে যায়। এর মাধ্যমে আমরা সিস্টেম কমান্ড রান করতে পারি এবং হয়তো আমাদের পারমিশনও বাড়িয়ে (privilege escalation) নিতে পারি।

## Footprinting the Service (সার্ভিসের তথ্য সংগ্রহ করা)

বিভিন্ন নেটওয়ার্ক স্ক্যানার ব্যবহার করে ফুটপ্রিন্টিং করা একটি খুব জনপ্রিয় পদ্ধতি। এই টুলগুলোর সাহায্যে সার্ভিসগুলো স্ট্যান্ডার্ড পোর্টে রান না করলেও আমরা খুব সহজে সেগুলোকে আইডেন্টিফাই করতে পারি। এর জন্য সবচেয়ে বেশি ব্যবহৃত টুল হলো **Nmap**। Nmap-এর সাথে **NSE (Nmap Scripting Engine)** থাকে, যা নির্দিষ্ট সার্ভিসের জন্য লেখা অনেকগুলো স্ক্রিপ্টের একটি কালেকশন।

আমরা নিচের কমান্ডটি দিয়ে NSE স্ক্রিপ্টের ডাটাবেস আপডেট করে নিতে পারি:

### Nmap FTP Scripts Update

```bash
00Luffy00@htb[/htb]$ sudo nmap --script-updatedb

Starting Nmap 7.80 ( https://nmap.org ) at 2021-09-19 13:49 CEST
NSE: Updating rule database.
NSE: Script Database updated successfully.
Nmap done: 0 IP addresses (0 hosts up) scanned in 0.28 seconds

```

Pwnbox-এ সব NSE স্ক্রিপ্ট `/usr/share/nmap/scripts/`-এ থাকে। আমরা সহজেই `find` কমান্ড ব্যবহার করে FTP রিলেটেড স্ক্রিপ্টগুলো খুঁজে বের করতে পারি:

```bash
00Luffy00@htb[/htb]$ find / -type f -name ftp* 2>/dev/null | grep scripts

/usr/share/nmap/scripts/ftp-syst.nse
/usr/share/nmap/scripts/ftp-vsftpd-backdoor.nse
/usr/share/nmap/scripts/ftp-vuln-cve2010-4221.nse
/usr/share/nmap/scripts/ftp-proftpd-backdoor.nse
/usr/share/nmap/scripts/ftp-bounce.nse
/usr/share/nmap/scripts/ftp-libopie.nse
/usr/share/nmap/scripts/ftp-anon.nse
/usr/share/nmap/scripts/ftp-brute.nse

```

যেহেতু আমরা জানি যে FTP সার্ভার সাধারণত স্ট্যান্ডার্ড TCP পোর্ট 21-এ রান করে, আমরা Nmap দিয়ে এটি স্ক্যান করতে পারি। আমরা ভার্সন স্ক্যান (`-sV`), অ্যাগ্রেসিভ স্ক্যান (`-A`) এবং ডিফল্ট স্ক্রিপ্ট স্ক্যান (`-sC`) ব্যবহার করে টার্গেটের বিস্তারিত তথ্য বের করতে পারি।

Nmap সার্ভিস ডিটেক্ট করার পর, এটি চিহ্নিত স্ক্রিপ্টগুলো একের পর এক রান করে বিভিন্ন ধরনের তথ্য দেয়। যেমন `ftp-anon` স্ক্রিপ্টটি চেক করে যে সার্ভার অ্যানোনিমাস অ্যাক্সেস অ্যালাউ করে কি না, আর করলে রুট ডিরেক্টরির সব ফাইল রেন্ডার করে দেখায়।

আরেকটি স্ক্রিপ্ট `ftp-syst` মূলত `STAT` কমান্ড এক্সিকিউট করে, যা সার্ভারের স্ট্যাটাস, কনফিগারেশন এবং ভার্সন বিস্তারিতভাবে দেখায়। আমরা চাইলে `--script-trace` অপশন ব্যবহার করে দেখতে পারি যে Nmap ব্যাকগ্রাউন্ডে কী কী কমান্ড পাঠাচ্ছে এবং সার্ভার কী রিপ্লাই দিচ্ছে।

স্ক্র্যান হিস্ট্রি থেকে দেখা যায় যে একই সাথে ৪টি প্যারালাল স্ক্যান চলছে। আমাদের লোকাল মেশিন অন্যান্য পোর্ট ব্যবহার করে `CONNECT` কমান্ডের মাধ্যমে কানেকশন ইনিশিয়েট করে এবং রেসপন্স হিসেবে সার্ভারের ব্যানার পায়।

প্রয়োজন হলে আমরা `netcat` বা `telnet`-এর মতো অন্য অ্যাপ্লিকেশন ব্যবহার করেও FTP সার্ভারের সাথে ইন্টারঅ্যাক্ট করতে পারি।

### Service Interaction

```bash
00Luffy00@htb[/htb]$ nc -nv 10.129.14.136 21

```

```bash
00Luffy00@htb[/htb]$ telnet 10.129.14.136 21

```

তবে, যদি FTP সার্ভারটি TLS/SSL এনক্রিপশন ব্যবহার করে, তখন আমাদের এমন ক্লায়েন্ট লাগবে যা TLS/SSL সাপোর্ট করে। এক্ষেত্রে আমরা `openssl` ব্যবহার করতে পারি। এর সবচেয়ে বড় সুবিধা হলো এটি আমাদেরকে সার্ভারের SSL সার্টিফিকেট দেখায়, যা অনেক সময় বেশ কাজের তথ্য প্রদান করে।
