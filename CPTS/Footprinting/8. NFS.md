# Network File System (NFS) - [LINK]()

## Introduction (ভূমিকা)

**Network File System (NFS)** হলো Sun Microsystems দ্বারা তৈরি একটি নেটওয়ার্ক ফাইল সিস্টেম। এর উদ্দেশ্য SMB-এর মতোই—একটি নেটওয়ার্কের মাধ্যমে ফাইল সিস্টেমগুলো এমনভাবে অ্যাক্সেস করা যেন সেগুলো লোকাল (local) ড্রাইভ। তবে, এটি সম্পূর্ণ ভিন্ন একটি প্রোটোকল ব্যবহার করে।

NFS সাধারণত Linux এবং Unix সিস্টেমের মধ্যে ব্যবহৃত হয়। এর মানে হলো, NFS ক্লায়েন্টরা সরাসরি SMB সার্ভারের সাথে যোগাযোগ করতে পারে না। NFS একটি ইন্টারনেট স্ট্যান্ডার্ড যা ডিস্ট্রিবিউটেড ফাইল সিস্টেমে পদ্ধতিগুলো পরিচালনা করে। বহু বছর ধরে ব্যবহৃত হওয়া NFSv3 প্রোটোকল যেখানে ক্লায়েন্ট কম্পিউটারকে অথেনটিকেট (authenticate) করে, সেখানে **NFSv4**-এ Windows SMB প্রোটোকলের মতো ইউজারকে (user) অথেনটিকেট করতে হয়।

## NFS Versions (NFS ভার্সনসমূহ)

| Version | Features |
| --- | --- |
| **NFSv2** | এটি পুরোনো তবে অনেক সিস্টেম দ্বারা সাপোর্টেড। শুরুতে এটি সম্পূর্ণভাবে UDP-এর ওপর অপারেট করত। |
| **NFSv3** | এতে আরও বেশি ফিচার রয়েছে, যেমন variable file size এবং উন্নত error reporting। তবে এটি NFSv2 ক্লায়েন্টদের সাথে সম্পূর্ণভাবে কম্প্যাটিবল নয়। |
| **NFSv4** | এতে Kerberos অন্তর্ভুক্ত রয়েছে, ফায়ারওয়ালের ভেতর দিয়ে এবং ইন্টারনেটে কাজ করে, portmappers-এর আর প্রয়োজন হয় না, ACLs সাপোর্ট করে, state-based অপারেশন অ্যাপ্লাই করে এবং পারফরম্যান্স ও উচ্চ নিরাপত্তা প্রদান করে। এটি প্রথম ভার্সন যা একটি stateful protocol। |

**NFS version 4.1 (RFC 8881):** এটি cluster server deployment-কে সাপোর্ট করে, যার মধ্যে একাধিক সার্ভারে ডিস্ট্রিবিউট করা ফাইলের scalable parallel access (pNFS extension) অন্তর্ভুক্ত। এছাড়া এতে session trunking মেকানিজম রয়েছে, যা **NFS multipathing** নামেও পরিচিত।
পূর্ববর্তী ভার্সনগুলোর তুলনায় NFSv4-এর একটি বড় সুবিধা হলো এটি সার্ভিস রান করার জন্য শুধুমাত্র একটি **UDP বা TCP port 2049** ব্যবহার করে, যা ফায়ারওয়ালের ভেতর দিয়ে প্রোটোকলের ব্যবহার অনেক সহজ করে।

## Architecture & Authentication (আর্কিটেকচার এবং অথেনটিকেশন)

NFS মূলত **ONC-RPC/SUN-RPC (Open Network Computing Remote Procedure Call)** প্রোটোকলের ওপর ভিত্তি করে কাজ করে, যা **TCP এবং UDP port 111**-এ এক্সপোজড থাকে। এটি সিস্টেম-স্বাধীনভাবে ডেটা আদান-প্রদানের জন্য **External Data Representation (XDR)** ব্যবহার করে।

NFS প্রোটোকলের নিজস্ব কোনো authentication বা authorization মেকানিজম নেই। এর বদলে অথেনটিকেশন সম্পূর্ণভাবে RPC প্রোটোকলের অপশনগুলোর ওপর নির্ভর করে। Authorization মূলত ফাইল সিস্টেমের ইনফরমেশন থেকে নেওয়া হয়। এক্ষেত্রে সার্ভার ক্লায়েন্টের ইউজার ইনফরমেশনকে ফাইল সিস্টেমের ফরম্যাটে ট্রান্সলেট করে এবং সে অনুযায়ী UNIX সিনট্যাক্সে তা রূপান্তর করে।

সবচেয়ে প্রচলিত অথেনটিকেশন হলো **UNIX UID/GID এবং group memberships**-এর মাধ্যমে।

> **Important Note:** সমস্যা হলো, ক্লায়েন্ট এবং সার্ভারে UID/GID-এর ম্যাপিং একই হতে হবে এমন কোনো বাধ্যবাধকতা নেই এবং সার্ভার অতিরিক্ত কোনো চেকও করে না। এ কারণে NFS শুধুমাত্র **trusted networks**-এই ব্যবহার করা উচিত।

## Default Configuration (ডিফল্ট কনফিগারেশন)

NFS কনফিগার করা বেশ সহজ কারণ এতে FTP বা SMB-এর মতো এত বেশি অপশন নেই। `/etc/exports` ফাইলে ক্লায়েন্টদের অ্যাক্সেসযোগ্য ফিজিক্যাল ফাইল সিস্টেমের একটি টেবিল থাকে।

### Exports File

```bash
00Luffy00@htb[/htb]$ cat /etc/exports 

# /etc/exports: the access control list for filesystems which may be exported
#               to NFS clients.  See exports(5).
#
# Example for NFSv2 and NFSv3:
# /srv/homes       hostname1(rw,sync,no_subtree_check) hostname2(ro,sync,no_subtree_check)
#
# Example for NFSv4:
# /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt,no_subtree_check)
# /srv/nfs4/homes  gss/krb5i(rw,sync,no_subtree_check)

```

ডিফল্ট exports ফাইলে NFS শেয়ার কনফিগার করার কিছু উদাহরণ থাকে। প্রথমে ফোল্ডার নির্দিষ্ট করা হয়, তারপর হোস্ট বা সাবনেট উল্লেখ করে তাদের পারমিশন সেট করা হয়।

### NFS Options

| Option | Description |
| --- | --- |
| `rw` | Read এবং write পারমিশন। |
| `ro` | শুধুমাত্র Read পারমিশন। |
| `sync` | Synchronous data transfer. (কিছুটা ধীরগতির) |
| `async` | Asynchronous data transfer. (কিছুটা দ্রুতগতির) |
| `secure` | 1024-এর ওপরের পোর্টগুলো ব্যবহার করা হবে না। |
| `insecure` | 1024-এর ওপরের পোর্টগুলো ব্যবহার করা হবে। |
| `no_subtree_check` | এটি সাবডিরেক্টরি ট্রি চেকিং (subdirectory trees) নিষ্ক্রিয় করে। |
| `root_squash` | Root UID/GID 0-এর ফাইলের সকল পারমিশন anonymous-এর UID/GID-তে অ্যাসাইন করে, যা root-কে NFS mount-এর ফাইলে অ্যাক্সেস করতে বাধা দেয়। |

### ExportFS (নতুন শেয়ার তৈরি করা)

টেস্ট করার জন্য আমরা একটি নতুন এন্ট্রি তৈরি করতে পারি:

```bash
root@nfs:~# echo '/mnt/nfs  10.129.14.0/24(sync,no_subtree_check)' >> /etc/exports
root@nfs:~# systemctl restart nfs-kernel-server 
root@nfs:~# exportfs

/mnt/nfs        10.129.14.0/24

```

উপরের সেটিং অনুযায়ী, `10.129.14.0/24` সাবনেটের যেকোনো হোস্ট এই `/mnt/nfs` শেয়ারটি মাউন্ট করতে পারবে এবং ভেতরের কন্টেন্ট দেখতে পারবে।

## Dangerous Settings (ঝুঁকিপূর্ণ কনফিগারেশন)

NFS-এ এমন কিছু সেটিংস আছে যা কোম্পানির ইনফ্রাস্ট্রাকচারের জন্য বিপজ্জনক হতে পারে:

| Option | Description |
| --- | --- |
| `rw` | Read এবং write পারমিশন। |
| `insecure` | 1024-এর ওপরের পোর্টগুলো ব্যবহার করা হবে। |
| `nohide` | এক্সপোর্ট করা ডিরেক্টরির নিচে অন্য ফাইল সিস্টেম মাউন্ট করা থাকলে, সেটিও এক্সপোর্ট হয়ে যায়। |
| `no_root_squash` | Root দ্বারা তৈরি করা সকল ফাইল UID/GID 0 হিসেবেই থেকে যায়। |

**`insecure` অপশনটির ঝুঁকি:**
সাধারণত প্রথম 1024টি পোর্ট শুধুমাত্র root ব্যবহার করতে পারে। এই নিয়মটি সাধারণ ইউজারদের 1024-এর ওপরের সকেট ব্যবহার করে NFS সার্ভিসের সাথে ইন্টারঅ্যাক্ট করতে বাধা দেয়। কিন্তু `insecure` অপশন সেট করা থাকলে ব্যবহারকারীরা 1024-এর ওপরের পোর্ট ব্যবহার করতে পারে, যা একটি বড় সিকিউরিটি রিস্ক।

## Footprinting the Service (সার্ভিস ফুটপ্রিন্টিং)

NFS ফুটপ্রিন্টিংয়ের জন্য **TCP ports 111 এবং 2049** খুবই গুরুত্বপূর্ণ। RPC-এর মাধ্যমে আমরা NFS সার্ভিস এবং হোস্ট সম্পর্কে তথ্য পেতে পারি।

## Interacting with NFS (NFS মাউন্ট এবং ব্যবহার)

একবার NFS সার্ভিস আবিষ্কার করার পর আমরা আমাদের লোকাল মেশিনে সেটি মাউন্ট (mount) করতে পারি। প্রথমে আমরা উপলব্ধ শেয়ারগুলো দেখে নেব এবং তারপর মাউন্ট করব।

### Show Available NFS Shares

```bash
00Luffy00@htb[/htb]$ showmount -e 10.129.14.128

Export list for 10.129.14.128:
/mnt/nfs 10.129.14.0/24

```

### Mounting NFS Share

```bash
00Luffy00@htb[/htb]$ mkdir target-NFS
00Luffy00@htb[/htb]$ sudo mount -t nfs 10.129.14.128:/ ./target-NFS/ -o nolock
00Luffy00@htb[/htb]$ cd target-NFS
00Luffy00@htb[/htb]$ tree .

.
└── mnt
    └── nfs
        ├── id_rsa
        ├── id_rsa.pub
        └── nfs.share

2 directories, 3 files

```

মাউন্ট হয়ে গেলে আমরা লোকাল ড্রাইভের মতোই শেয়ারের ভেতরে নেভিগেট করতে পারি।

### Inspecting Contents (UID/GID Enumeration)

এখানে আমরা ফাইলগুলোর পারমিশন, ইউজারনেম এবং গ্রুপ দেখতে পারি। একবার ইউজারনেম, গ্রুপ, UID এবং GID পেয়ে গেলে, আমরা চাইলে ফাইল মডিফাই করার জন্য আমাদের লোকাল সিস্টেমে ওই একই নামের/আইডির ইউজার তৈরি করে অ্যাক্সেস মডিফাই করতে পারি।

**Usernames & Group Names দেখা:**

```bash
00Luffy00@htb[/htb]$ ls -l mnt/nfs/

total 16
-rw-r--r-- 1 cry0l1t3 cry0l1t3 1872 Sep 25 00:55 cry0l1t3.priv
-rw-r--r-- 1 root     root     1872 Sep 19 17:27 id_rsa

```

**UIDs & GUIDs দেখা:**

```bash
00Luffy00@htb[/htb]$ ls -n mnt/nfs/

total 16
-rw-r--r-- 1 1000 1000 1872 Sep 25 00:55 cry0l1t3.priv
-rw-r--r-- 1    0 1000 1221 Sep 19 18:21 backup.sh
-rw-r--r-- 1    0    0 1872 Sep 19 17:27 id_rsa

```

> **Important Note:** যদি `root_squash` অপশন সেট করা থাকে, তবে আমরা `root` হিসেবেও `backup.sh` ফাইলটি এডিট করতে পারব না।

**Privilege Escalation-এর জন্য ব্যবহার:**
আমরা চাইলে NFS ব্যবহার করে privilege escalation করতে পারি। উদাহরণস্বরূপ, যদি আমাদের SSH অ্যাক্সেস থাকে এবং আমরা অন্য ইউজারের ফাইল পড়তে চাই, তবে আমরা NFS শেয়ারে ওই ইউজারের SUID সম্বলিত একটি শেল (shell) আপলোড করতে পারি এবং পরবর্তীতে SSH ইউজারের মাধ্যমে সেই শেলটি রান করতে পারি।

### Unmounting (মাউন্ট রিমুভ করা)

প্রয়োজনীয় তথ্য সংগ্রহের পর আমরা NFS শেয়ারটি আনমাউন্ট করতে পারি:

```bash
00Luffy00@htb[/htb]$ cd ..
00Luffy00@htb[/htb]$ sudo umount ./target-NFS

```
