# MySQL - [LINK](https://academy.hackthebox.com/app/module/112/section/1238)


MySQL হলো Oracle দ্বারা ডেভেলপকৃত এবং নিয়ন্ত্রিত একটি open-source SQL relational database management system। ডেটাবেস (database) হলো মূলত ডেটার একটি স্ট্রাকচার্ড কালেকশন, যা সহজে ব্যবহার এবং ডেটা রিট্রিভ (retrieve) করার জন্য সুসংগঠিতভাবে রাখা হয়। ডেটাবেস সিস্টেম উচ্চ পারফরম্যান্সের সাথে দ্রুত বিপুল পরিমাণ ডেটা প্রসেস করতে পারে। ডেটাবেসের ভেতরে ডেটা এমনভাবে স্টোর করা হয় যেন তা সম্ভাব্য সর্বনিম্ন স্পেস (space) দখল করে।

ডেটাবেস নিয়ন্ত্রণ করার জন্য SQL (Structured Query Language) ব্যবহার করা হয়। MySQL মূলত client-server নীতির ওপর ভিত্তি করে কাজ করে এবং এটি একটি MySQL server এবং এক বা একাধিক MySQL clients নিয়ে গঠিত। এখানে MySQL server হলো মূল ডেটাবেস ম্যানেজমেন্ট সিস্টেম, যা ডেটা স্টোরেজ এবং ডিস্ট্রিবিউশনের দায়িত্ব পালন করে। ডেটা বিভিন্ন কলাম (columns), সারি (rows) এবং ডেটা টাইপ (data types) সম্বলিত টেবিলের মধ্যে স্টোর করা হয়। এই ডেটাবেসগুলোকে প্রায়শই একটি সিঙ্গেল `.sql` ফাইল হিসেবে এক্সপোর্ট বা ব্যাকআপ নেওয়া হয়, যেমন: `wordpress.sql`।

## MySQL Clients

MySQL ক্লায়েন্টরা ডেটাবেস ইঞ্জিনে structured queries পাঠিয়ে ডেটা রিট্রিভ এবং এডিট করতে পারে। SQL ডেটাবেস ল্যাঙ্গুয়েজ ব্যবহার করে ডেটা insert, delete, modify এবং retrieve করা হয়। ক্লায়েন্টরা একই সাথে একাধিক কোয়েরি পাঠাতে পারে বলে অনেকগুলো ভিন্ন ভিন্ন ডেটাবেস পরিচালনা করার জন্য MySQL অত্যন্ত উপযোগী। ডেটাবেসের ব্যবহারের ওপর ভিত্তি করে internal network অথবা পাবলিক ইন্টারনেটের মাধ্যমে এতে অ্যাক্সেস করা সম্ভব।

ডেটাবেস ব্যবহারের অন্যতম সেরা একটি উদাহরণ হলো CMS (Content Management System) WordPress। WordPress তার তৈরি করা সমস্ত পোস্ট, ইউজারনেম এবং পাসওয়ার্ড নিজস্ব ডেটাবেসে স্টোর করে, যা শুধুমাত্র localhost থেকে অ্যাক্সেসযোগ্য। তবে ওয়েব অ্যাপ্লিকেশনের আর্কিটেকচার অনুযায়ী এমন ডেটাবেস স্ট্রাকচারও থাকতে পারে যা একাধিক সার্ভার জুড়ে ডিস্ট্রিবিউটেড (distributed) থাকে।

## MySQL Databases

ডায়নামিক ওয়েবসাইটের মতো অ্যাপ্লিকেশনগুলোর জন্য MySQL আদর্শ, যেখানে এফিশিয়েন্ট সিনট্যাক্স এবং উচ্চ রেসপন্স স্পিড (response speed) অত্যন্ত জরুরি। এটি প্রায়শই Linux OS, PHP এবং Apache ওয়েব সার্ভারের সাথে যুক্ত করে ব্যবহার করা হয়, যা একত্রে **LAMP** (Linux, Apache, MySQL, PHP) স্ট্যাক নামে পরিচিত। আর যদি Apache-এর বদলে Nginx ব্যবহার করা হয়, তবে সেটিকে **LEMP** বলা হয়।

MySQL ডেটাবেস সম্বলিত একটি ওয়েব হোস্টিংয়ে এটি একটি সেন্ট্রাল ইন্সট্যান্স (central instance) হিসেবে কাজ করে, যেখানে PHP স্ক্রিপ্টের জন্য প্রয়োজনীয় কন্টেন্ট স্টোর করা থাকে। এর মধ্যে উল্লেখযোগ্য হলো:

* Headers (হেডারসমূহ)
* Texts (টেক্সট)
* Meta tags (মেটা ট্যাগ)
* Forms (ফর্ম)
* Customers (কাস্টমারদের তথ্য)
* Usernames (ইউজারনেম)
* Administrators (অ্যাডমিনিস্ট্রেটর)
* Moderators (মডারেটর)
* Email addresses (ইমেইল অ্যাড্রেস)
* User information (ইউজার ইনফরমেশন)
* Permissions (পারমিশন বা অনুমতি)
* Passwords (পাসওয়ার্ড)
* External/Internal links (এক্সটার্নাল/ইন্টারনাল লিংক)
* Links to Files (ফাইলের লিংক)
* Specific contents (নির্দিষ্ট কন্টেন্ট)
* Values (ভ্যালুসমূহ)

পাসওয়ার্ডের মতো সংবেদনশীল ডেটা (sensitive data) MySQL প্লেইন-টেক্সট (plain-text) আকারে স্টোর করতে পারে। তবে, সাধারণত স্টোর করার আগেই PHP স্ক্রিপ্টগুলো নিরাপদ পদ্ধতি ব্যবহার করে (যেমন: One-Way-Encryption) সেগুলোকে এনক্রিপ্ট করে নেয়।

## MySQL Commands

একটি MySQL ডেটাবেস কমান্ডগুলোকে ইন্টারনালি এক্সিকিউটেবল কোডে (executable code) রূপান্তর করে এবং রিকোয়েস্ট করা অ্যাকশনগুলো সম্পাদন করে। প্রসেসিংয়ের সময় কোনো এরর (error) দেখা দিলে ওয়েব অ্যাপ্লিকেশন তা ইউজারকে জানিয়ে দেয়। বিভিন্ন ধরনের SQL injection এই এররগুলোকে ট্রিগার করতে পারে। প্রায়শই এই এরর ডেসক্রিপশনগুলোতে (error descriptions) গুরুত্বপূর্ণ তথ্য থাকে এবং এগুলো প্রমাণ করে যে ওয়েব অ্যাপ্লিকেশনটি ডেভেলপারদের নির্ধারিত পদ্ধতির বাইরে গিয়ে ডেটাবেসের সাথে ইন্টারঅ্যাক্ট করছে।

ডেটা সঠিকভাবে প্রসেস হলে ওয়েব অ্যাপ্লিকেশন জেনারেট করা তথ্য ক্লায়েন্টের কাছে ফেরত পাঠায়। এই তথ্যগুলো হতে পারে কোনো টেবিল থেকে তুলে আনা ডেটা, যা লগইন বা সার্চ ফাংশনের মতো পরবর্তী প্রসেসিংয়ের জন্য প্রয়োজনীয় রেকর্ড হিসেবে কাজ করে। SQL কমান্ড ব্যবহার করে টেবিলের সারি (rows) প্রদর্শন (display), মডিফাই (modify), যুক্ত (add) বা ডিলিট (delete) করা যায়। এছাড়াও, SQL ডেটাবেসের টেবিলের স্ট্রাকচার পরিবর্তন করতে, রিলেশনশিপ (relationships) এবং ইনডেক্স (indexes) তৈরি বা ডিলিট করতে এবং ইউজারদের ম্যানেজ করতে পারে।

**MariaDB:**
MariaDB প্রায়শই MySQL-এর সাথে যুক্ত থাকে। এটি মূলত অরিজিনাল MySQL কোডের একটি ফর্ক (fork)। Oracle কর্তৃক MySQL অধিগ্রহণের পর MySQL-এর প্রধান ডেভেলপার কোম্পানিটি ছেড়ে চলে যান এবং MySQL-এর সোর্স কোডের ওপর ভিত্তি করে নতুন একটি open-source SQL ডেটাবেস ম্যানেজমেন্ট সিস্টেম তৈরি করেন, যার নাম দেওয়া হয় MariaDB।

## Default Configuration (ডিফল্ট কনফিগারেশন)

SQL ডেটাবেস এবং এর কনফিগারেশন পরিচালনা করা একটি বিশাল বিষয়। এটি এতটাই বিস্তৃত যে "ডেটাবেস অ্যাডমিনিস্ট্রেটর" নামে একটি সম্পূর্ণ পেশাই রয়েছে, যারা মূলত ডেটাবেস নিয়েই কাজ করেন। এই স্ট্রাকচারগুলো খুব দ্রুত বড় হয়ে ওঠে এবং এগুলোর প্ল্যানিং অত্যন্ত জটিল হতে পারে। সফটওয়্যার ডেভেলপার এবং ইনফরমেশন সিকিউরিটি অ্যানালিস্টদের জন্য ডেটাবেস ম্যানেজমেন্ট একটি কোর কম্পিটেন্সি (core competency)।

MySQL/MariaDB-এর ফাংশনালিটি এবং কনফিগারেশন অপশনগুলো ভালোভাবে বোঝার জন্য একটি ইন্সট্যান্স সেটআপ করে পরীক্ষা (experiment) করা রেকমেন্ডেড। নিচে MySQL-এর একটি ডিফল্ট কনফিগারেশনের উদাহরণ দেওয়া হলো:

```bash
00Luffy00@htb[/htb]$ sudo apt install mysql-server -y
00Luffy00@htb[/htb]$ cat /etc/mysql/mysql.conf.d/mysqld.cnf | grep -v "#" | sed -r '/^\s*$/d'

[client]
port        = 3306
socket      = /var/run/mysqld/mysqld.sock

[mysqld_safe]
pid-file    = /var/run/mysqld/mysqld.pid
socket      = /var/run/mysqld/mysqld.sock
nice        = 0

[mysqld]
skip-host-cache
skip-name-resolve
user        = mysql
pid-file    = /var/run/mysqld/mysqld.pid
socket      = /var/run/mysqld/mysqld.sock
port        = 3306
basedir     = /usr
datadir     = /var/lib/mysql
tmpdir      = /tmp
lc-messages-dir = /usr/share/mysql
explicit_defaults_for_timestamp

symbolic-links=0

!includedir /etc/mysql/conf.d/

```

## Dangerous Settings (ঝুঁকিপূর্ণ সেটিংস)

MySQL-এ অনেক কিছু ভুলভাবে কনফিগার করা হতে পারে। সার্ভার কনফিগারেশনে কী কী অপশন ব্যবহার করা যায়, তা নির্ধারণ করতে আমরা MySQL-এর রেফারেন্স বিস্তারিতভাবে দেখতে পারি। সিকিউরিটির জন্য সবচেয়ে বেশি প্রাসঙ্গিক এবং ঝুঁকিপূর্ণ প্রধান অপশনগুলো নিচে দেওয়া হলো:

| Settings | Description (বিবরণ) |
| --- | --- |
| `user` | MySQL সার্ভিস কোন ইউজারের অধীনে রান করবে তা নির্ধারণ করে। |
| `password` | MySQL ইউজারের জন্য পাসওয়ার্ড সেট করে। |
| `admin_address` | অ্যাডমিনিস্ট্রেটিভ নেটওয়ার্ক ইন্টারফেসে TCP/IP কানেকশনের জন্য যে IP অ্যাড্রেসে লিসেন (listen) করা হবে। |
| `debug` | এই ভ্যারিয়েবলটি বর্তমান ডিবাগিং সেটিংস নির্দেশ করে। |
| `sql_warnings` | কোনো ওয়ার্নিং (warnings) দেখা দিলে সিঙ্গেল-রো (single-row) INSERT স্টেটমেন্টগুলো ইনফরমেশন স্ট্রিং জেনারেট করবে কি না, তা এই ভ্যারিয়েবল নিয়ন্ত্রণ করে। |
| `secure_file_priv` | এই ভ্যারিয়েবলটি ডেটা ইমপোর্ট এবং এক্সপোর্ট অপারেশনের প্রভাব সীমিত (limit) করতে ব্যবহৃত হয়। |

**Security Risks (নিরাপত্তা ঝুঁকি):**
`user`, `password` এবং `admin_address` সেটিংসগুলো সিকিউরিটির জন্য খুবই গুরুত্বপূর্ণ কারণ এই এন্ট্রিগুলো প্লেইন টেক্সটে (plain text) থাকে। প্রায়শই MySQL সার্ভারের কনফিগারেশন ফাইলের রাইটস (rights/permissions) সঠিকভাবে অ্যাসাইন করা থাকে না। যদি কোনোভাবে আমরা ফাইল রিড করার সুযোগ পাই বা একটি শেল (shell) পেয়ে যাই, তবে আমরা কনফিগারেশন ফাইল থেকে MySQL সার্ভারের ইউজারনেম এবং পাসওয়ার্ড দেখে ফেলতে পারব। যদি অননুমোদিত অ্যাক্সেস (unauthorized access) ঠেকানোর জন্য অন্য কোনো সিকিউরিটি মেকানিজম না থাকে, তবে সম্পূর্ণ ডেটাবেস এবং বিদ্যমান কাস্টমারদের সমস্ত তথ্য, ইমেইল অ্যাড্রেস, পাসওয়ার্ড এবং ব্যক্তিগত ডেটা দেখা এবং এডিট করা সম্ভব।

`debug` এবং `sql_warnings` সেটিংসের কারণে এরর দেখা দিলে বিস্তারিত (verbose) আউটপুট পাওয়া যায়। এগুলো অ্যাডমিনিস্ট্রেটরের জন্য প্রয়োজনীয় হলেও অন্যদের দেখা উচিত নয়। এই ইনফরমেশনে প্রায়শই সংবেদনশীল (sensitive) কন্টেন্ট থাকে, যা ট্রায়াল অ্যান্ড এররের (trial and error) মাধ্যমে পরবর্তী অ্যাটাকের পথ বের করতে সাহায্য করতে পারে। এই এরর মেসেজগুলো প্রায়ই সরাসরি ওয়েব অ্যাপ্লিকেশনে প্রদর্শিত হয়। এর ফলে SQL injection ব্যবহার করে MySQL সার্ভারের মাধ্যমে সিস্টেম কমান্ডও (system commands) এক্সিকিউট করানো যেতে পারে।

## Footprinting the Service (সার্ভিস ফুটপ্রিন্টিং)

একটি বহিরাগত নেটওয়ার্ক (external network) থেকে MySQL সার্ভারে অ্যাক্সেস করার পেছনে অনেক কারণ থাকতে পারে। তারপরও এটি কোনোভাবেই best practices-এর আওতায় পড়ে না, কিন্তু আমরা প্রায়শই এমন ডেটাবেস খুঁজে পাই যা বাইরে থেকে অ্যাক্সেসযোগ্য। অনেক সময় এই ধরনের সেটিংস সাময়িক (temporary) সময়ের জন্য করা হলেও অ্যাডমিনিস্ট্রেটররা তা পরে বন্ধ করতে ভুলে যান। অথবা টেকনিক্যাল সমস্যার কারণে একটি সাময়িক সমাধান বা ওয়ার্কঅ্যারাউন্ড (workaround) হিসেবেও এ ধরনের সার্ভার সেটআপ ব্যবহৃত হতে পারে।

সাধারণত MySQL সার্ভার **TCP port 3306**-এ রান করে এবং বিস্তারিত তথ্য পেতে আমরা Nmap ব্যবহার করে এই পোর্টটি স্ক্যান করতে পারি।

## Important MySQL Commands (গুরুত্বপূর্ণ MySQL কমান্ডসমূহ)

MySQL ডেটাবেসের সাথে কাজ করার জন্য কিছু প্রয়োজনীয় কমান্ড নিচে বর্ণনা করা হলো। বিভিন্ন ডেটাবেসের সাথে কীভাবে ইন্টারঅ্যাক্ট করতে হয় তা আমাদের জানা থাকা আবশ্যক।

| Command | Description (বিবরণ) |
| --- | --- |
| `mysql -u <user> -p<password> -h <IP address>` | MySQL সার্ভারের সাথে কানেক্ট করার জন্য। (এখানে `-p` ফ্ল্যাগ এবং পাসওয়ার্ডের মাঝে কোনো স্পেস/ফাঁকা স্থান থাকা যাবে না)। |
| `show databases;` | সকল ডেটাবেস প্রদর্শন করে। |
| `use <database>;` | বিদ্যমান ডেটাবেসগুলোর মধ্যে নির্দিষ্ট একটি নির্বাচন (select) করে। |
| `show tables;` | নির্বাচিত ডেটাবেসের সকল অ্যাভেইলেবল টেবিল প্রদর্শন করে। |
| `show columns from <table>;` | নির্বাচিত টেবিলের সকল কলাম প্রদর্শন করে। |
| `select * from <table>;` | কাঙ্ক্ষিত টেবিলের সবকিছু (everything) প্রদর্শন করে। |
| `select * from <table> where <column> = "<string>";` | কাঙ্ক্ষিত টেবিলের নির্দিষ্ট কলামে প্রয়োজনীয় স্ট্রিং (string) খোঁজার জন্য ব্যবহৃত হয়। |

MySQL সার্ভার সিকিউর করার বেস্ট প্র্যাকটিস সম্পর্কে MySQL-এর রেফারেন্স ম্যানুয়ালে একটি বিস্তারিত সেকশন রয়েছে। যখনই কোনো কমান্ড কাজ করবে না, তখন সেটি কেন কাজ করছে না তা আরও ভালোভাবে বুঝতে ম্যানুয়ালটি ব্যবহার করা উচিত।
