# IMAP / POP3 - [LINK](https://academy.hackthebox.com/app/module/112/section/1073)

## Introduction (ভূমিকা)

**Internet Message Access Protocol (IMAP)**-এর মাধ্যমে একটি মেইল সার্ভার থেকে ইমেইলগুলোতে অ্যাক্সেস করা সম্ভব হয়।
অন্যদিকে **Post Office Protocol (POP3)** ইমেইলের অনলাইন ম্যানেজমেন্ট সাপোর্ট করে না, এটি শুধুমাত্র মেইল সার্ভার থেকে ইমেইল লিস্ট করা, রিট্রিভ করা (ডাউনলোড) এবং ডিলিট করার সুবিধা প্রদান করে।

IMAP সার্ভারে সরাসরি ইমেইলগুলোর অনলাইন ম্যানেজমেন্ট (যেমন: ফোল্ডার স্ট্রাকচার তৈরি) সাপোর্ট করে। এটি একটি client-server-based প্রোটোকল যা একটি লোকাল ইমেইল ক্লায়েন্টের সাথে সার্ভারের মেইলবক্সের সিঙ্ক্রোনাইজেশন করে। এর ফলে একাধিক ইনডিপেন্ডেন্ট ক্লায়েন্ট থেকে (যেমন: পিসি, ফোন) কোনো সমস্যা ছাড়াই ইমেইল সিঙ্ক্রোনাইজ করা যায়।

মেইল সার্ভারে সরাসরি হায়ারার্কিক্যাল মেইলবক্স, একটি সেশনে একাধিক মেইলবক্সে অ্যাক্সেস এবং ইমেইলের প্রি-সিলেকশনের মতো অতিরিক্ত ফাংশনালিটির জন্য IMAP ব্যবহার করতে হয়।

### IMAP Features (IMAP-এর বৈশিষ্ট্য)

* ক্লায়েন্টরা অনলাইনে এই স্ট্রাকচারগুলোতে অ্যাক্সেস করে এবং চাইলে লোকাল কপি তৈরি করতে পারে।
* একাধিক ক্লায়েন্ট ব্যবহার করলেও ইমেইলের ডেটাবেস সব জায়গায় একই থাকে।
* ডিলিট না করা পর্যন্ত ইমেইলগুলো সার্ভারেই থেকে যায়।
* এটি টেক্সট-বেজড (text-based) এবং এতে সার্ভারে সরাসরি ইমেইল ব্রাউজ করার মতো এক্সটেন্ডেড ফাংশন রয়েছে।
* একাধিক ইউজার একই সময়ে মেইল সার্ভারে অ্যাক্সেস করতে পারে।
* অফলাইন মোডে করা পরিবর্তনগুলো ক্লায়েন্ট পরবর্তীতে অনলাইনে এলে সার্ভারের সাথে সিঙ্ক করে নেয়।

### How it Connects (কানেকশন প্রক্রিয়া)

ক্লায়েন্ট **port 143** ব্যবহার করে সার্ভারের সাথে কানেকশন তৈরি করে। যোগাযোগের জন্য এটি ASCII ফরম্যাটের text-based কমান্ড ব্যবহার করে। সার্ভারের কনফার্মেশনের জন্য অপেক্ষা না করেই পর পর একাধিক কমান্ড পাঠানো যায়।
কানেকশন তৈরির পরপরই ইউজারনেম এবং পাসওয়ার্ড দিয়ে ইউজারকে সার্ভারে অথেনটিকেট করতে হয়। সফল অথেনটিকেশনের পরেই কেবল মেইলবক্সে অ্যাক্সেস করা সম্ভব হয়।

### Security (নিরাপত্তা)

ডিফল্টভাবে IMAP এনক্রিপশন ছাড়াই কাজ করে এবং কমান্ড, ইমেইল বা ইউজারনেম ও পাসওয়ার্ড প্লেইন টেক্সটে (plain text) ট্রান্সমিট করে। ইমেইল ট্রাফিকের নিরাপত্তা নিশ্চিত করতে এবং মেইলবক্সে অননুমোদিত অ্যাক্সেস রোধ করতে বেশিরভাগ মেইল সার্ভার একটি এনক্রিপ্টেড IMAP সেশন স্থাপন করা বাধ্যতামূলক করে। এর জন্য সাধারণত **SSL/TLS** ব্যবহৃত হয়।
এনক্রিপ্টেড কানেকশনের ক্ষেত্রে সাধারণত স্ট্যান্ডার্ড **port 143** অথবা একটি অল্টারনেটিভ পোর্ট যেমন **993** ব্যবহৃত হয়।

## Commands

কমান্ড লাইনের মাধ্যমে আমরা সরাসরি IMAP এবং POP3-এর সাথে ইন্টারঅ্যাক্ট করতে পারি।

### IMAP Commands

| Command | Description (বিবরণ) |
| --- | --- |
| `1 LOGIN username password` | ইউজারের লগইন। |
| `1 LIST "" *` | সমস্ত ডিরেক্টরি লিস্ট করে। |
| `1 CREATE "INBOX"` | নির্দিষ্ট নামের একটি মেইলবক্স তৈরি করে। |
| `1 DELETE "INBOX"` | একটি মেইলবক্স ডিলিট করে। |
| `1 RENAME "ToRead" "Important"` | মেইলবক্সের নাম পরিবর্তন করে। |
| `1 LSUB "" *` | ইউজারের অ্যাক্টিভ বা সাবস্ক্রাইব করা মেইলবক্সের নামের একটি সাবসেট রিটার্ন করে। |
| `1 SELECT INBOX` | একটি মেইলবক্স সিলেক্ট করে যাতে এর ভেতরের মেসেজগুলোতে অ্যাক্সেস করা যায়। |
| `1 UNSELECT INBOX` | সিলেক্ট করা মেইলবক্স থেকে বের হয়ে যায়। |
| `1 FETCH <ID> all` | মেইলবক্সের কোনো নির্দিষ্ট মেসেজের সাথে সম্পর্কিত ডেটা রিট্রিভ করে। |
| `1 CLOSE` | 'Deleted' ফ্ল্যাগ সেট করা সমস্ত মেসেজ রিমুভ করে। |
| `1 LOGOUT` | IMAP সার্ভারের সাথে কানেকশন ক্লোজ করে। |

### POP3 Commands

| Command | Description (বিবরণ) |
| --- | --- |
| `USER username` | ইউজারকে আইডেন্টিফাই করে। |
| `PASS password` | পাসওয়ার্ড ব্যবহার করে ইউজারকে অথেনটিকেট করে। |
| `STAT` | সার্ভার থেকে সেভ করা ইমেইলের সংখ্যা রিকোয়েস্ট করে। |
| `LIST` | সার্ভার থেকে সমস্ত ইমেইলের সংখ্যা এবং সাইজ রিকোয়েস্ট করে। |
| `RETR id` | আইডি দিয়ে রিকোয়েস্ট করা ইমেইলটি ডেলিভার করার জন্য সার্ভারকে নির্দেশ দেয়। |
| `DELE id` | আইডি দিয়ে রিকোয়েস্ট করা ইমেইলটি ডিলিট করার জন্য সার্ভারকে নির্দেশ দেয়। |
| `CAPA` | সার্ভারের সক্ষমতা (capabilities) দেখানোর জন্য রিকোয়েস্ট করে। |
| `RSET` | ট্রান্সমিট করা ইনফরমেশন রিসেট করার জন্য রিকোয়েস্ট করে। |
| `QUIT` | POP3 সার্ভারের সাথে কানেকশন ক্লোজ করে। |

## Dangerous Settings (ঝুঁকিপূর্ণ কনফিগারেশন)

ভুল কনফিগারেশনের কারণে আমরা অনেক সময় অতিরিক্ত তথ্য পেতে পারি (যেমন, সার্ভিসে এক্সিকিউট করা কমান্ড ডিবাগ করা বা FTP সার্ভিসের মতো অ্যানোনিমাস হিসেবে লগইন করা)। অ্যাডমিনিস্ট্রেটরদের করা ভুলের কারণে সবচেয়ে খারাপ পরিস্থিতিতে আমরা সমস্ত পাঠানো এবং প্রাপ্ত ইমেইল পড়তে সক্ষম হতে পারি, যার মধ্যে গোপনীয় (confidential) বা সংবেদনশীল (sensitive) তথ্য থাকতে পারে।

এরকম কিছু ঝুঁকিপূর্ণ কনফিগারেশন নিচে দেওয়া হলো:

| Setting | Description (বিবরণ) |
| --- | --- |
| `auth_debug` | সমস্ত অথেনটিকেশন ডিবাগ লগিং এনাবল করে। |
| `auth_debug_passwords` | এই সেটিং লগ ভার্বোসিটি (log verbosity) অ্যাডজাস্ট করে এবং সাবমিট করা পাসওয়ার্ড ও স্কিম (scheme) লগ করে। |
| `auth_verbose` | ব্যর্থ অথেনটিকেশনের প্রচেষ্টা (unsuccessful authentication attempts) এবং এর কারণগুলো লগ করে। |
| `auth_verbose_passwords` | অথেনটিকেশনের জন্য ব্যবহৃত পাসওয়ার্ডগুলো লগ করে। |
| `auth_anonymous_username` | ANONYMOUS SASL মেকানিজম দিয়ে লগইন করার সময় কোন ইউজারনেম ব্যবহার করা হবে তা নির্দিষ্ট করে। |

## Footprinting the Service (সার্ভিস ফুটপ্রিন্টিং)

ডিফল্টভাবে POP3-এর জন্য পোর্ট **110** এবং **995**, এবং IMAP-এর জন্য পোর্ট **143** এবং **993** ব্যবহৃত হয়। ওপরের দিকের পোর্টগুলো (993 এবং 995) ক্লায়েন্ট এবং সার্ভারের মধ্যে কমিউনিকেশন এনক্রিপ্ট করতে TLS/SSL ব্যবহার করে।

### Nmap Scan

Nmap ব্যবহার করে আমরা এই পোর্টগুলো স্ক্যান করতে পারি। সার্ভারটি যদি এমবেডেড সার্টিফিকেট ব্যবহার করে, তবে স্ক্যান রেজাল্টে আমরা এর বিস্তারিত তথ্য পাব।

### Connecting with cURL

যদি আমরা কোনো ইউজারের ক্রেডেনশিয়াল (credentials) বের করতে পারি, তবে `curl` ব্যবহার করে মেইল সার্ভারে লগইন করতে পারব এবং ইমেইলগুলো দেখতে পাব।

```bash
00Luffy00@htb[/htb]$ curl -k 'imaps://10.129.14.128' --user user:p4ssw0rd

* LIST (\HasNoChildren) "." Important
* LIST (\HasNoChildren) "." INBOX
```

### Connecting with OpenSSL

SSL-এর ওপর IMAP বা POP3 সার্ভারের সাথে ইন্টারঅ্যাক্ট করার জন্য আমরা `openssl` বা `ncat` ব্যবহার করতে পারি।

**POP3 Encrypted Interaction:**

```bash
00Luffy00@htb[/htb]$ openssl s_client -connect 10.129.14.128:pop3s

CONNECTED(00000003)
...
    Start Time: 1632081313
    Timeout   : 7200 (sec)
    Verify return code: 18 (self signed certificate)
---
read R BLOCK
+OK HTB-Academy POP3 Server

```

**IMAP Encrypted Interaction:**

```bash
00Luffy00@htb[/htb]$ openssl s_client -connect 10.129.14.128:imaps

CONNECTED(00000003)
...
    Start Time: 1632081604
    Timeout   : 7200 (sec)
    Verify return code: 18 (self signed certificate)
---
read R BLOCK
* OK [CAPABILITY IMAP4rev1 SASL-IR LOGIN-REFERRALS ID ENABLE IDLE LITERAL+ AUTH=PLAIN] HTB-Academy IMAP4 v.0.21.4

```

একবার সফলভাবে কানেকশন তৈরি করে মেইল সার্ভারে লগইন করার পর, আমরা কমান্ডগুলো ব্যবহার করে সার্ভারটি নেভিগেট করতে এবং এর সাথে কাজ করতে পারব। যদি আমরা অন্য কোনো সার্ভিসে (যেমন SMTP-তে) ইউজারের ক্রেডেনশিয়াল পেয়ে থাকি (যেমন `robin:robin`), তবে সেগুলো ব্যবহার করেও আমরা IMAP/POP3 সার্ভিসে লগইন করার চেষ্টা করতে পারি।
