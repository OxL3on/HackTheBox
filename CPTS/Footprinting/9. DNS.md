## 1. DNS কী?

`DNS` হলো এমন একটি distributed system, যা domain name-কে IP address-এর সঙ্গে resolve করে। এর কোনো single central database নেই; তথ্য বিভিন্ন DNS server-এ সংরক্ষিত থাকে।

উদাহরণ: `www.hackthebox.com` → সংশ্লিষ্ট IP address।

**Domain hierarchy:**
- `Root` → `.com`, `.org`, `.net` হলো `TLD (Top-Level Domain)`
- `Second-Level Domain` → `inlanefreight.com`
- `Subdomain` → `dev.inlanefreight.com`, `www.inlanefreight.com`
- `Host` → `WS01.dev.inlanefreight.com`

[DNS Hierarchy Diagram](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/27/tooldev-dns.png)

## 2. DNS Server Types

| Server Type | কাজ |
|---|---|
| `DNS Root Server` | TLD-এর DNS hierarchy-তে নির্দেশনা দেয়। ICANN root-server system সমন্বয় করে; ১৩টি logical root-server identity রয়েছে। |
| `Authoritative Nameserver` | নির্দিষ্ট DNS zone-এর authoritative records রাখে। |
| `Non-authoritative Nameserver` | অন্য server থেকে recursive বা iterative query করে তথ্য সংগ্রহ করে। |
| `Caching DNS Server` | নির্দিষ্ট সময়ের জন্য DNS response cache করে। |
| `Forwarding Server` | DNS query অন্য DNS server-এ forward করে। |
| `Resolver` | Client computer বা router-এর জন্য domain name resolve করে। |

## 3. DNS Encryption

সাধারণ DNS query সাধারণত encrypted নয়। ফলে network-এর অন্য পক্ষ query দেখতে পারে।

| Protocol | কাজ |
|---|---|
| `DoT` — DNS over TLS | TLS দিয়ে DNS traffic encrypt করে। |
| `DoH` — DNS over HTTPS | HTTPS-এর মাধ্যমে DNS query পাঠায়। |
| `DNSCrypt` | Client ও DNS server-এর traffic encrypt করে। |

## 4. DNS Records

| Record | কাজ |
|---|---|
| `A` | Domain-এর IPv4 address দেয়। |
| `AAAA` | Domain-এর IPv6 address দেয়। |
| `MX` | Mail server শনাক্ত করে। |
| `NS` | Domain-এর nameserver শনাক্ত করে। |
| `TXT` | SPF, DMARC, domain verification ইত্যাদি তথ্য রাখতে পারে। |
| `CNAME` | অন্য domain/hostname-এর alias হিসেবে কাজ করে। |
| `PTR` | Reverse lookup: IP address থেকে hostname বের করে। |
| `SOA` | DNS zone-এর administrative ও synchronization তথ্য দেয়। |

### SOA Record

`SOA (Start of Authority)` record-এ zone administrator-এর তথ্য, responsible nameserver এবং zone synchronization-এর parameters থাকে।

```bash
dig soa www.inlanefreight.com
```

SOA record-এর উদাহরণ:

```text
inlanefreight.com. 900 IN SOA ns-161.awsdns-20.com. awsdns-hostmaster.amazon.com. 1 7200 900 1209600 86400
```

SOA record-এর email field-এ প্রথম `.`-এর জায়গায় `@` বসে। উদাহরণ:

```text
awsdns-hostmaster.amazon.com.
```

এটি administrator email হিসেবে `awsdns-hostmaster@amazon.com` নির্দেশ করে।

## 5. DNS Default Configuration (BIND9)

Linux-এ বহুল ব্যবহৃত DNS server software হলো [BIND9](https://www.isc.org/bind/)।

প্রধান configuration files:

- `named.conf.local`
- `named.conf.options`
- `named.conf.log`

সাধারণ configuration path: `/etc/bind/`

`Global options` সব zone-এর ওপর প্রযোজ্য; `Zone options` শুধু নির্দিষ্ট zone-এর ওপর প্রযোজ্য। একই setting উভয় জায়গায় থাকলে zone-specific option অগ্রাধিকার পায়।

### Local DNS Configuration

ফাইল: `/etc/bind/named.conf.local`

```conf
zone "domain.com" {
    type master;
    file "/etc/bind/db.domain.com";
    allow-update { key rndc-key; };
};
```

এখানে:
- `zone` — যে domain-এর zone define করা হচ্ছে।
- `type master` — server zone data-এর master source।
- `file` — zone file-এর path।
- `allow-update` — authenticated dynamic update-এর অনুমতি নিয়ন্ত্রণ করে।

Reference: [Debian BIND9 Documentation](https://wiki.debian.org/Bind9)

### Zone File

Zone file-এ domain-এর DNS records থাকে। সাধারণত এতে ঠিক একটি `SOA` record এবং অন্তত একটি `NS` record থাকতে হয়। Syntax error হলে zone load ব্যর্থ হতে পারে এবং DNS server `SERVFAIL` দিতে পারে।

উদাহরণ: `/etc/bind/db.domain.com`

```dns
$ORIGIN domain.com
$TTL 86400

@  IN SOA dns1.domain.com. hostmaster.domain.com. (
      2001062501 ; serial
      21600      ; refresh
      3600       ; retry
      604800     ; expire
      86400 )    ; minimum TTL

@      IN NS     ns1.domain.com.
@      IN NS     ns2.domain.com.

@      IN MX 10  mx.domain.com.
@      IN MX 20  mx2.domain.com.

@      IN A      10.129.14.5
server1 IN A     10.129.14.5
server2 IN A     10.129.14.7
ns1     IN A     10.129.14.2
ns2     IN A     10.129.14.3

ftp     IN CNAME server1
mx      IN CNAME server1
mx2     IN CNAME server2
www     IN CNAME server2
```

গুরুত্বপূর্ণ:
- `$ORIGIN` — zone-এর base domain।
- `$TTL` — record-এর default Time To Live।
- `serial` — zone version; বড় serial দিয়ে update বোঝানো হয়।
- `refresh`, `retry`, `expire` — master/slave synchronization-এর সময়সীমা।

### Reverse Lookup Zone File

IP address থেকে `FQDN (Fully Qualified Domain Name)` বের করতে reverse DNS zone ও `PTR` record ব্যবহৃত হয়।

```dns
$ORIGIN 14.129.10.in-addr.arpa
$TTL 86400

@ IN SOA dns1.domain.com. hostmaster.domain.com. (
    2001062501
    21600
    3600
    604800
    86400 )

@ IN NS  ns1.domain.com.
@ IN NS  ns2.domain.com.

5 IN PTR server1.domain.com.
```

উদাহরণস্বরূপ, `10.129.14.5`-এর reverse lookup zone-এ শেষ octet `5`-এর জন্য PTR record থাকতে পারে।

## 6. Dangerous DNS Settings

DNS configuration ভুল হলে sensitive তথ্য প্রকাশ হতে পারে বা DNS server অপব্যবহৃত হতে পারে।

| Option | কাজ |
|---|---|
| `allow-query` | কোন host DNS query করতে পারবে তা নির্ধারণ করে। |
| `allow-recursion` | কোন host recursive query করতে পারবে তা নিয়ন্ত্রণ করে। |
| `allow-transfer` | কোন host DNS zone transfer করতে পারবে তা নির্ধারণ করে। |
| `zone-statistics` | Zone-এর statistical data সংগ্রহ করে। |

Misconfiguration-এর উদাহরণ: `allow-transfer` অতিরিক্ত বিস্তৃত রাখা বা `any` অনুমোদন করা। এতে attacker পুরো zone file, internal hostname ও IP address পেতে পারে।

References: [BIND CVEs](https://www.cvedetails.com/product/144/ISC-Bind.html?vendor_id=64) · [Common DNS Attacks](https://web.archive.org/web/20250329174745/https://securitytrails.com/blog/most-popular-types-dns-attacks)

## 7. DNS Footprinting ও Enumeration

DNS footprinting-এর উদ্দেশ্য হলো nameserver, records, subdomain, server version এবং সম্ভাব্য misconfiguration শনাক্ত করা।

### 7.1 NS Query

Domain-এর nameserver খুঁজতে:

```bash
dig ns inlanefreight.htb @10.129.14.128
```

`@10.129.14.128` নির্দিষ্ট DNS server-কে query করার নির্দেশ দেয়।

### 7.2 DNS Version Query

কখনো `CHAOS` class-এর `TXT` query দিয়ে DNS server-এর version প্রকাশ পেতে পারে। এটি কাজ করবে কেবল server-এ version entry থাকলে।

```bash
dig CH TXT version.bind 10.129.120.85
```

উদাহরণ response:

```text
version.bind. 0 CH TXT "9.10.6-P1"
version.bind. 0 CH TXT "9.10.6-P1-Debian"
```

### 7.3 ANY Query

Server যে records প্রকাশ করে, সেগুলো দেখতে:

```bash
dig any inlanefreight.htb @10.129.14.128
```

`ANY` সবসময় zone-এর সব record দেখায় না; server-এর disclosure ও implementation-এর ওপর ফল নির্ভর করে।

### 7.4 Zone Transfer (AXFR)

`AXFR (Asynchronous Full Transfer Zone)` হলো DNS zone-এর records অন্য DNS server-এ transfer করার পদ্ধতি। সাধারণত zone transfer `TCP/53` ব্যবহার করে।

- `Primary nameserver`: Zone-এর মূল data source।
- `Secondary nameserver`: Availability ও redundancy-এর জন্য অতিরিক্ত server।
- `Master`: যে server থেকে zone data transfer হয়।
- `Slave`: যে server master থেকে zone data সংগ্রহ করে।
- `SOA serial`: Master ও slave-এর zone version তুলনা করতে ব্যবহৃত হয়।
- `Refresh time`: Slave কখন master-এর SOA serial পরীক্ষা করবে তা নির্ধারণ করে।
- `rndc-key`: BIND configuration-এ server control/update authentication-এর জন্য ব্যবহৃত key।

Zone transfer পরীক্ষা:

```bash
dig axfr inlanefreight.htb @10.129.14.128
```

Internal zone পরীক্ষা:

```bash
dig axfr internal.inlanefreight.htb @10.129.14.128
```

Zone transfer ভুলভাবে অনুমোদিত হলে subdomain, internal hostname এবং private IP প্রকাশিত হতে পারে।

### 7.5 Subdomain Brute Forcing

সম্ভাব্য hostname-এর wordlist ব্যবহার করে DNS query পাঠিয়ে subdomain খোঁজা যায়।

Wordlist: [SecLists — DNS subdomains](https://github.com/danielmiessler/SecLists/blob/master/Discovery/DNS/subdomains-top1million-5000.txt)

Bash loop:

```bash
for sub in $(cat /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt); do
    dig "$sub.inlanefreight.htb" @10.129.14.128 |
    grep -v ';\|SOA' |
    sed -r '/^\s*$/d' |
    grep "$sub" |
    tee -a subdomains.txt
done
```

এটি wordlist-এর প্রতিটি candidate subdomain query করে এবং matching output `subdomains.txt`-এ যুক্ত করে।

### 7.6 DNSenum

[DNSenum GitHub](https://github.com/fwaeytens/dnsenum) হলো DNS enumeration-এর একটি tool। এটি nameserver, mail server, zone transfer ও subdomain brute forcing চেষ্টা করতে পারে।

```bash
dnsenum --dnsserver 10.129.14.128 --enum -p 0 -s 0 \
-o subdomains.txt \
-f /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt \
inlanefreight.htb
```

গুরুত্বপূর্ণ options:
- `--dnsserver` — নির্দিষ্ট DNS server।
- `--enum` — enumeration চালানো।
- `-p 0 -s 0` — source command-এ দেওয়া range-related options।
- `-o subdomains.txt` — output file।
- `-f` — wordlist path।

## 8. Quick Command Reference

| উদ্দেশ্য | Command |
|---|---|
| SOA record | `dig soa example.com` |
| Nameserver | `dig ns example.com @DNS_IP` |
| Version query | `dig CH TXT version.bind DNS_IP` |
| Available records | `dig any example.com @DNS_IP` |
| Zone transfer | `dig axfr example.com @DNS_IP` |
| Internal zone transfer | `dig axfr internal.example.com @DNS_IP` |
| Subdomain enumeration | `dnsenum --dnsserver DNS_IP --enum -p 0 -s 0 -o subdomains.txt -f wordlist.txt example.com` |

**মূল কথা:** DNS enumeration থেকে nameserver, mail server, TXT data, subdomain ও internal IP পাওয়া যেতে পারে। বিশেষভাবে exposed `AXFR` এবং অনিরাপদ DNS configuration গুরুত্বপূর্ণ misconfiguration।
