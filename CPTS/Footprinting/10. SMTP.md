# SMTP - [LINK](https://academy.hackthebox.com/app/module/112/section/1072)


SMTP is a client-server protocol used for sending and forwarding emails across IP networks. By default, it transmits data in plaintext, making it vulnerable to interception unless paired with encryption (SSL/TLS) via Extended SMTP (ESMTP).

## 1. Key Ports & Components

* **Port 25 (TCP):** Default, unencrypted SMTP routing.
* **Port 587 (TCP):** Used by authenticated clients, usually upgrades to encryption via `STARTTLS`.
* **Port 465 (TCP):** Implicit SSL/TLS encrypted SMTP (legacy but still used).
* **MUA (Mail User Agent):** The email client (e.g., Outlook, Thunderbird).
* **MTA (Mail Transfer Agent):** The server software that routes/stores emails (e.g., Postfix).
* **MSA (Mail Submission Agent):** Optional relay server that checks validity/origin before passing to the MTA.
* **MDA (Mail Delivery Agent):** Transfers the email to the recipient's actual mailbox (IMAP/POP3).

## 2. Common SMTP Commands

| Command | Description |
| --- | --- |
| `HELO` / `EHLO` | Initializes the session and identifies the client. (EHLO is for ESMTP). |
| `AUTH PLAIN` | Service extension used to authenticate the client. |
| `MAIL FROM` | Specifies the sender's email address. |
| `RCPT TO` | Specifies the recipient's email address. |
| `DATA` | Initiates the transmission of the email body. Ends with `<CR><LF>.<CR><LF>` (a single dot). |
| `VRFY` | Checks if a specific mailbox/user exists on the server. |
| `EXPN` | Expands a mailing list or alias. |
| `RSET` | Aborts the current transaction but keeps the connection open. |
| `NOOP` | No operation. Keeps the connection alive to prevent timeouts. |
| `QUIT` | Terminates the session. |

*Note on `VRFY`:* Relying solely on `VRFY` for user enumeration is risky. Many modern servers are configured to return code `252 2.0.0` (cannot verify, but will attempt delivery) for *any* username to prevent enumeration.

## 3. Footprinting & Enumeration (Nmap)

**Basic Service and Command Enumeration:**

```bash
sudo nmap <TARGET_IP> -sC -sV -p25

```

*(Uses default scripts, including `smtp-commands` which utilizes `EHLO` to list supported features).*

**Checking for Open Relays:**

```bash
sudo nmap <TARGET_IP> -p25 --script smtp-open-relay -v

```

*(Runs 16 different tests to see if the server processes unauthenticated mail routing).*

## 4. Manual Interaction via Telnet

You can interact with an SMTP server directly using Telnet to enumerate users or forge/send emails.

**Connecting:**

```bash
telnet <TARGET_IP> 25

```

*(If forced through a web proxy, use: `CONNECT <TARGET_IP>:25 HTTP/1.0`)*

**Enumerating Users with VRFY:**

```text
VRFY root
252 2.0.0 root

VRFY fakeuser123
252 2.0.0 fakeuser123

```

**Sending a Forged Email via CLI (Payload):**

```text
EHLO inlanefreight.htb
MAIL FROM: <spoofed@inlanefreight.htb>
RCPT TO: <victim@inlanefreight.htb> NOTIFY=success,failure
DATA
From: <spoofed@inlanefreight.htb>
To: <victim@inlanefreight.htb>
Subject: Urgent Password Update
Date: Tue, 28 Sept 2026 16:32:51 +0200

Please update your credentials immediately at the link below.
.
QUIT

```

## 5. Vulnerability: Open Relay Configuration

An **Open Relay** occurs when an SMTP server is misconfigured to allow unauthenticated users from any IP address to route emails through it. This is widely abused by spammers for mail spoofing and phishing campaigns.

* **Vulnerable Postfix Configuration (`/etc/postfix/main.cf`):**
```ini
mynetworks = 0.0.0.0/0

```


*(This setting allows any IP address on the internet to relay mail through the server without authentication).*
