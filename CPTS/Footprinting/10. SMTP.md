# Simple Mail Transfer Protocol (SMTP) - [LINK](https://academy.hackthebox.com/app/module/112/section/1072)

## Introduction (ভূমিকা)

**Simple Mail Transfer Protocol (SMTP)** হলো IP নেটওয়ার্কে ইমেইল পাঠানোর একটি প্রোটোকল। এটি একটি ইমেইল ক্লায়েন্ট এবং আউটগোয়িং মেইল সার্ভারের মধ্যে অথবা দুটি SMTP সার্ভারের মধ্যে ব্যবহৃত হতে পারে। SMTP প্রায়শই IMAP বা POP3 প্রোটোকলের সাথে যুক্ত করে ব্যবহার করা হয়, যেগুলো ইমেইল ফেচ (fetch) এবং রিসিভ করতে পারে। মূলত এটি একটি client-server-based প্রোটোকল, যদিও দুটি সার্ভারের মধ্যে কাজ করার সময় একটি সার্ভার কার্যকরভাবে ক্লায়েন্ট হিসেবে কাজ করে।

### Ports and Encryption (পোর্ট এবং এনক্রিপশন)

* **Port 25:** ডিফল্টভাবে SMTP সার্ভার পোর্ট 25-এ কানেকশন রিকোয়েস্ট গ্রহণ করে।
* **Port 587:** নতুন SMTP সার্ভারগুলো সাধারণত এই পোর্ট ব্যবহার করে। এটি অথেনটিকেটেড ইউজার বা সার্ভার থেকে মেইল রিসিভ করতে ব্যবহৃত হয়। সাধারণত `STARTTLS` কমান্ডের মাধ্যমে বিদ্যমান plaintext কানেকশনকে একটি এনক্রিপ্টেড কানেকশনে সুইচ করার জন্য এটি ব্যবহৃত হয়।
* **Port 465:** বিশেষ পরিস্থিতিতে এনক্রিপ্টেড কানেকশনের জন্য স্ট্যান্ডার্ড পোর্ট 25-এর পরিবর্তে পোর্ট 465 ব্যবহৃত হতে পারে।

SMTP ডিফল্টভাবে এনক্রিপশন ছাড়াই কাজ করে এবং সমস্ত কমান্ড, ডেটা বা অথেনটিকেশন ইনফরমেশন প্লেইনটেক্সটে (plaintext) ট্রান্সমিট করে। অননুমোদিত ডেটা রিডিং প্রতিরোধ করতে SMTP-কে **SSL/TLS** এনক্রিপশনের সাথে ব্যবহার করা হয়।

## How SMTP Works (SMTP কীভাবে কাজ করে)

একটি অত্যাবশ্যকীয় ফাংশন হিসেবে SMTP সার্ভার স্প্যাম (spam) প্রতিরোধ করার জন্য অথেনটিকেশন মেকানিজম ব্যবহার করে, যাতে শুধুমাত্র অনুমোদিত ইউজাররাই ইমেইল পাঠাতে পারে।

ইমেইল পাঠানোর প্রক্রিয়াটি নিচের ধাপগুলোতে সম্পন্ন হয়:

1. **MUA (Mail User Agent):** ইমেইল পাঠানোর পর SMTP ক্লায়েন্ট (MUA) এটিকে header এবং body-তে কনভার্ট করে এবং SMTP সার্ভারে আপলোড করে।
2. **MTA (Mail Transfer Agent):** SMTP সার্ভারে MTA নামের একটি সফটওয়্যার থাকে যা ইমেইল রিসিভ এবং সেন্ড করার মূল ভিত্তি। MTA ইমেইলের সাইজ এবং স্প্যাম চেক করে সেটি স্টোর করে।
3. **MSA (Mail Submission Agent):** MTA-এর কাজের চাপ কমাতে অনেক সময় এর আগে একটি MSA থাকে, যা ইমেইলের ভ্যালিডিটি বা অরিজিন (origin) চেক করে। এই MSA-কে **Relay server**-ও বলা হয়। (ভুল কনফিগারেশনের কারণে অনেক সময় এই রিলায় সার্ভারে Open Relay Attack করা সম্ভব হয়)।
4. এরপর MTA DNS-এ সার্চ করে প্রাপকের (recipient) মেইল সার্ভারের IP অ্যাড্রেস খুঁজে বের করে।
5. গন্তব্যের (destination) SMTP সার্ভারে পৌঁছানোর পর ডেটা প্যাকেটগুলো পুনরায় অ্যাসেম্বল (reassemble) হয়ে সম্পূর্ণ ইমেইল তৈরি করে।
6. **MDA (Mail delivery agent):** সবশেষে MDA ইমেইলটিকে প্রাপকের মেইলবক্সে ট্রান্সফার করে।

**Communication Flow:**
`Client (MUA) ➞ Submission Agent (MSA) ➞ Open Relay (MTA) ➞ Mail Delivery Agent (MDA) ➞ Mailbox (POP3/IMAP)`

## Limitations and Security (সীমাবদ্ধতা এবং নিরাপত্তা)

নেটওয়ার্ক প্রোটোকল হিসেবে SMTP-এর দুটি প্রধান অসুবিধা রয়েছে:

1. **No Delivery Confirmation:** SMTP ব্যবহার করে ইমেইল পাঠালে ব্যবহারযোগ্য কোনো ডেলিভারি কনফার্মেশন পাওয়া যায় না। প্রোটোকলের স্পেসিফিকেশনে এই ধরনের নোটিফিকেশন থাকলেও ডিফল্টভাবে এর ফরম্যাটিং নির্দিষ্ট করা থাকে না। ফলে সাধারণত শুধু ইংরেজি ভাষার একটি এরর মেসেজ (যার মধ্যে আনডেলিভারড মেসেজের হেডার থাকে) রিটার্ন করা হয়।
2. **Lack of Authentication (Spoofing):** কানেকশন স্থাপনের সময় ইউজারদের ডিফল্টভাবে অথেনটিকেট করা হয় না, ফলে ইমেইলের প্রেরক (sender) অবিশ্বস্ত হতে পারে। এর ফলে ওপেন SMTP রিলায় (Open SMTP relays) ব্যবহার করে প্রচুর পরিমাণে স্প্যাম পাঠানো হয়। স্প্যামাররা ট্র্যাক হওয়া থেকে বাঁচতে ফেক সেন্ডার অ্যাড্রেস (mail spoofing) ব্যবহার করে।

বর্তমানে এই সমস্যা সমাধানের জন্য **DomainKeys (DKIM)** এবং **Sender Policy Framework (SPF)**-এর মতো সিকিউরিটি মেকানিজম ব্যবহার করা হয়।

**ESMTP (Extended SMTP):**
এই উদ্দেশ্যে SMTP-এর একটি এক্সটেনশন তৈরি করা হয়েছে যাকে ESMTP বলা হয়। সাধারণত SMTP বলতে বর্তমানে ESMTP-কেই বোঝানো হয়। এটি TLS ব্যবহার করে, যা `EHLO` কমান্ডের পর `STARTTLS` পাঠানোর মাধ্যমে সম্পন্ন হয়। এরপর সম্পূর্ণ কানেকশনটি এনক্রিপ্টেড হয়ে যায় এবং অথেনটিকেশনের জন্য নিরাপদে `AUTH PLAIN` এক্সটেনশন ব্যবহার করা সম্ভব হয়।

## Default Configuration (ডিফল্ট কনফিগারেশন)

অন্যান্য সার্ভিসের মতো SMTP সার্ভারকেও বিভিন্নভাবে কনফিগার করা যায়। তবে এটি শুধুমাত্র ইমেইল পাঠানো এবং ফরোয়ার্ড করার জন্য দায়ী। নিচে **Postfix** মেইল সার্ভারের `main.cf` কনফিগারেশন ফাইলের একটি উদাহরণ দেওয়া হলো:

```bash
00Luffy00@htb[/htb]$ cat /etc/postfix/main.cf | grep -v "#" | sed -r "/^\s*$/d"

smtpd_banner = ESMTP Server 
biff = no
append_dot_mydomain = no
readme_directory = no
compatibility_level = 2
smtp_tls_session_cache_database = btree:${data_directory}/smtp_scache
myhostname = mail1.inlanefreight.htb
alias_maps = hash:/etc/aliases
alias_database = hash:/etc/aliases
smtp_generic_maps = hash:/etc/postfix/generic
mydestination = $myhostname, localhost 
masquerade_domains = $myhostname
mynetworks = 127.0.0.0/8 10.129.0.0/16
mailbox_size_limit = 0
recipient_delimiter = +
smtp_bind_address = 0.0.0.0
inet_protocols = ipv4
smtpd_helo_restrictions = reject_invalid_hostname
home_mailbox = /home/postfix

```

## SMTP Commands (এসএমটিপি কমান্ডসমূহ)

ইমেইল পাঠানো এবং যোগাযোগের জন্য বিশেষ কিছু কমান্ড ব্যবহার করা হয়, যা SMTP সার্ভারকে ইউজারের রিকোয়েস্ট অনুযায়ী কাজ করতে নির্দেশ দেয়।

| Command | Description (বিবরণ) |
| --- | --- |
| **AUTH PLAIN** | এটি ক্লায়েন্টকে অথেনটিকেট করার জন্য ব্যবহৃত একটি সার্ভিস এক্সটেনশন। |
| **HELO** | ক্লায়েন্ট তার কম্পিউটার নাম দিয়ে লগইন করে এবং এর মাধ্যমে সেশন (session) শুরু করে। |
| **MAIL FROM** | ক্লায়েন্ট ইমেইলের প্রেরকের (sender) নাম নির্দিষ্ট করে। |
| **RCPT TO** | ক্লায়েন্ট ইমেইলের প্রাপকের (recipient) নাম নির্দিষ্ট করে। |
| **DATA** | ক্লায়েন্ট ইমেইলের ট্রান্সমিশন শুরু করে। |
| **RSET** | ক্লায়েন্ট শুরু করা ট্রান্সমিশন বাতিল (abort) করে কিন্তু ক্লায়েন্ট ও সার্ভারের কানেকশন বজায় রাখে। |
| **VRFY** | ক্লায়েন্ট চেক করে যে মেসেজ ট্রান্সফারের জন্য নির্দিষ্ট মেইলবক্স অ্যাভেইলেবল আছে কিনা। |
| **EXPN** | এই কমান্ড দিয়েও ক্লায়েন্ট মেসেজিংয়ের জন্য মেইলবক্স অ্যাভেইলেবল আছে কিনা তা চেক করে। |
| **NOOP** | টাইম-আউটের কারণে কানেকশন যেন বিচ্ছিন্ন না হয়, সেজন্য ক্লায়েন্ট সার্ভারের কাছ থেকে একটি রেসপন্স রিকোয়েস্ট করে। |
| **QUIT** | ক্লায়েন্ট সেশন শেষ (terminate) করে দেয়। |

## Interacting with the Service (সার্ভিসের সাথে ইন্টারঅ্যাক্ট করা)

SMTP সার্ভারের সাথে ইন্টারঅ্যাক্ট করার জন্য আমরা `telnet` টুল ব্যবহার করে TCP কানেকশন তৈরি করতে পারি। সেশনের প্রকৃত ইনিশিয়ালাইজেশন `HELO` বা `EHLO` কমান্ড দিয়ে করা হয়।

### Telnet - HELO/EHLO

```bash
00Luffy00@htb[/htb]$ telnet 10.129.14.128 25

Trying 10.129.14.128...
Connected to 10.129.14.128.
Escape character is '^]'.
220 ESMTP Server 

HELO mail1.inlanefreight.htb
250 mail1.inlanefreight.htb

EHLO mail1
250-mail1.inlanefreight.htb
250-PIPELINING
250-SIZE 10240000
250-ETRN
250-ENHANCEDSTATUSCODES
250-8BITMIME
250-DSN
250-SMTPUTF8
250 CHUNKING

```

### Enumerating Users (VRFY)

সিস্টেমে থাকা ইউজারদের এনুমারেট করার জন্য `VRFY` কমান্ড ব্যবহার করা যেতে পারে। তবে এটি সব সময় কাজ করে না। সার্ভার কনফিগারেশনের ওপর ভিত্তি করে, SMTP সার্ভার **code 252** ইস্যু করতে পারে এবং এমন ইউজারের উপস্থিতিও নিশ্চিত করতে পারে যার আসলে সিস্টেমে কোনো অস্তিত্বই নেই।

```bash
00Luffy00@htb[/htb]$ telnet 10.129.14.128 25

Trying 10.129.14.128...
Connected to 10.129.14.128.
Escape character is '^]'.
220 ESMTP Server 

VRFY root
252 2.0.0 root

VRFY cry0l1t3
252 2.0.0 cry0l1t3

VRFY testuser
252 2.0.0 testuser

VRFY aaaaaaaaaaaaaaaaaaaaaaaaaaaa
252 2.0.0 aaaaaaaaaaaaaaaaaaaaaaaaaaaa

```

> **Important Note:** স্বয়ংক্রিয় টুলের (automatic tools) ফলাফলের ওপর কখনোই পুরোপুরি নির্ভর করা উচিত নয়, কারণ অ্যাডমিনিস্ট্রেটর কীভাবে সার্ভার কনফিগার করেছেন তা টুলের প্রি-কনফিগার করা কমান্ডগুলো নিশ্চিতভাবে জানতে পারে না।

### Connecting via Web Proxy

মাঝে মাঝে আমাদের ওয়েব প্রক্সির মাধ্যমে কাজ করতে হতে পারে। আমরা এই প্রক্সি ব্যবহার করেও SMTP সার্ভারে কানেক্ট করতে পারি। এক্ষেত্রে কমান্ডটি দেখতে এরকম হবে:

```bash
CONNECT 10.129.14.128:25 HTTP/1.0

```

### Send an Email via Telnet

Thunderbird, Gmail বা Outlook-এর মতো ক্লায়েন্ট থেকে ইমেইল পাঠানোর পুরো প্রক্রিয়াটি আমরা কমান্ড লাইন থেকেও করতে পারি।

```bash
00Luffy00@htb[/htb]$ telnet 10.129.14.128 25

Trying 10.129.14.128...

250-mail1.inlanefreight.htb
...
```

### Mail Header (মেইল হেডার)

একটি ইমেইলের মেইল হেডার অনেক গুরুত্বপূর্ণ তথ্য বহন করে। এটি প্রেরক, প্রাপক, পাঠানোর সময়, ইমেইলটি আসার পথে কোন কোন স্টেশন পার হয়েছে এবং মেসেজের ফরম্যাট সম্পর্কিত তথ্য প্রদান করে। এর গঠন (structure) **RFC 5322** দ্বারা সংজ্ঞায়িত করা হয়।

## Dangerous Settings (ঝুঁকিপূর্ণ কনফিগারেশন)

অ্যাডমিনিস্ট্রেটররা স্প্যাম ফিল্টার এড়াতে অনেক সময় এমন একটি রিলায় সার্ভার (relay server) ব্যবহার করেন যাকে সবাই ট্রাস্ট করে। এর জন্য প্রেরককে প্রথমে রিলায় সার্ভারে অথেনটিকেট করতে হয়।

তবে অনেক সময় অ্যাডমিনিস্ট্রেটররা বুঝতে পারেন না যে কোন IP রেঞ্জগুলোকে তাদের অ্যালাউ (allow) করা উচিত। ইমেইল ট্রাফিকে যেন কোনো এরর না আসে এবং কাস্টমার কমিউনিকেশনে যেন ব্যাঘাত না ঘটে, সে জন্য তারা সমস্ত IP অ্যাড্রেস অ্যালাউ করে দেন। এটি একটি মারাত্মক misconfiguration যা পেনিট্রেশন টেস্টিংয়ে প্রায়ই দেখা যায়।

**Open Relay Configuration:**

```bash
mynetworks = 0.0.0.0/0

```

এই সেটিংটির কারণে উক্ত SMTP সার্ভার ব্যবহার করে ফেক (fake) ইমেইল পাঠানো সম্ভব হয়। এর মাধ্যমে বিভিন্ন পক্ষের মধ্যে ভুয়া যোগাযোগ শুরু করা বা ইমেইল স্পুফ (spoof) করে তা পড়ার মতো অ্যাটাক করা যেতে পারে।
