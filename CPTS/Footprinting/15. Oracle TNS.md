# Oracle TNS - [LINK](https://academy.hackthebox.com/app/module/112/section/2117)


## Introduction (ভূমিকা)

**Oracle Transparent Network Substrate (TNS)** সার্ভার হলো একটি কমিউনিকেশন প্রোটোকল যা নেটওয়ার্কের মাধ্যমে Oracle ডেটাবেস এবং অ্যাপ্লিকেশনগুলোর মধ্যে যোগাযোগ (communication) সহজতর করে। প্রাথমিকভাবে Oracle Net Services সফটওয়্যার স্যুটের অংশ হিসেবে নিয়ে আসা TNS, Oracle ডেটাবেস এবং ক্লায়েন্ট অ্যাপ্লিকেশনগুলোর মধ্যে বিভিন্ন নেটওয়ার্কিং প্রোটোকল যেমন **IPX/SPX** এবং **TCP/IP** প্রোটোকল স্ট্যাক সাপোর্ট করে।

এর ফলে, এটি হেলথকেয়ার, ফাইন্যান্স এবং রিটেইল ইন্ডাস্ট্রির বড় ও জটিল ডেটাবেসগুলো ম্যানেজ করার জন্য একটি পছন্দের সলিউশন হয়ে উঠেছে। এর বিল্ট-ইন এনক্রিপশন মেকানিজম ট্রান্সমিট করা ডেটার সিকিউরিটি নিশ্চিত করে, যা এন্টারপ্রাইজ এনভায়রনমেন্টের জন্য একে একটি আদর্শ সলিউশন করে তোলে, যেখানে ডেটা সিকিউরিটি অত্যন্ত গুরুত্বপূর্ণ।

সময়ের সাথে সাথে TNS-কে আপডেট করা হয়েছে যাতে এটি **IPv6** এবং **SSL/TLS এনক্রিপশন** সাপোর্ট করে। এটি মূলত নিচের উদ্দেশ্যগুলোর জন্য বেশি উপযুক্ত:

* Name resolution
* Connection management
* Load balancing
* Security

এছাড়া, এটি TCP/IP প্রোটোকল লেয়ারের ওপর নিরাপত্তার একটি অতিরিক্ত লেয়ার যুক্ত করে ক্লায়েন্ট এবং সার্ভারের মধ্যকার কমিউনিকেশন এনক্রিপ্ট করতে সাহায্য করে। এই ফিচারটি ডেটাবেস আর্কিটেকচারকে অননুমোদিত অ্যাক্সেস (unauthorized access) বা নেটওয়ার্ক ট্রাফিকের ডেটা কম্প্রোমাইজ করার অ্যাটাক থেকে সুরক্ষিত রাখে। এটি ডেটাবেস অ্যাডমিনিস্ট্রেটর এবং ডেভেলপারদের জন্য অ্যাডভান্সড টুলস এবং ক্যাপাবিলিটি প্রদান করে, যার মধ্যে রয়েছে কম্প্রিহেনসিভ পারফরম্যান্স মনিটরিং এবং অ্যানালাইসিস টুলস, এরর রিপোর্টিং এবং লগিং ক্যাপাবিলিটি, ওয়ার্কলোড ম্যানেজমেন্ট এবং ডেটাবেস সার্ভিসের মাধ্যমে ফল্ট টলারেন্স (fault tolerance)।

## Default Configuration (ডিফল্ট কনফিগারেশন)

Oracle TNS সার্ভারের ডিফল্ট কনফিগারেশন মূলত ইনস্টল করা Oracle সফটওয়্যারের ভার্সন এবং এডিশনের ওপর নির্ভর করে পরিবর্তিত হয়। তবে কিছু সাধারণ সেটিংস ডিফল্টভাবেই কনফিগার করা থাকে:

* **Default Port:** ডিফল্টভাবে লিসেনার (listener) ইনকামিং কানেকশনের জন্য **TCP/1521** পোর্টে লিসেন করে। তবে ইনস্টলেশনের সময় বা পরে কনফিগারেশন ফাইল থেকে এই পোর্ট পরিবর্তন করা যায়।
* **Supported Protocols:** TNS লিসেনার বিভিন্ন নেটওয়ার্ক প্রোটোকল সাপোর্ট করার জন্য কনফিগার করা থাকে, যার মধ্যে রয়েছে TCP/IP, UDP, IPX/SPX এবং AppleTalk। এটি একাধিক নেটওয়ার্ক ইন্টারফেস সাপোর্ট করতে পারে এবং নির্দিষ্ট IP অ্যাড্রেস বা সব অ্যাভেইলেবল নেটওয়ার্ক ইন্টারফেসে লিসেন করতে পারে।
* **Remote Management:** ডিফল্টভাবে, Oracle 8i/9i-তে Oracle TNS রিমোটলি ম্যানেজ করা যায়, কিন্তু **Oracle 10g/11g-তে নয়**।
* **Basic Security:** লিসেনার শুধুমাত্র অথোরাইজড হোস্টদের থেকেই কানেকশন গ্রহণ করে এবং হোস্টনেম, IP অ্যাড্রেস, ইউজারনেম এবং পাসওয়ার্ডের সংমিশ্রণ ব্যবহার করে বেসিক অথেনটিকেশন সম্পন্ন করে। এছাড়া, এটি ক্লায়েন্ট এবং সার্ভারের মধ্যে কমিউনিকেশন এনক্রিপ্ট করতে Oracle Net Services ব্যবহার করে।

### Configuration Files

Oracle TNS-এর কনফিগারেশন ফাইলগুলোর নাম হলো `tnsnames.ora` এবং `listener.ora`, যা সাধারণত `$ORACLE_HOME/network/admin` ডিরেক্টরিতে থাকে। এই প্লেইন টেক্সট ফাইলগুলোতে Oracle ডেটাবেস ইন্সট্যান্স এবং TNS প্রোটোকল ব্যবহার করা অন্যান্য নেটওয়ার্ক সার্ভিসগুলোর কনফিগারেশন ইনফরমেশন থাকে।

### Passwords and Risky Services

Oracle সার্ভিসের ডিফল্ট ইনস্টলেশনে অনেক পরিবর্তন আনা হয়েছে:

* **Oracle 9:** এর একটি ডিফল্ট পাসওয়ার্ড রয়েছে, যা হলো `CHANGE_ON_INSTALL`।
* **Oracle 10:** এতে ডিফল্ট কোনো পাসওয়ার্ড সেট করা থাকে না।
* **Oracle DBSNMP Service:** এই সার্ভিসটি একটি ডিফল্ট পাসওয়ার্ড ব্যবহার করে: `dbsnmp`। (পেনটেস্টিংয়ের সময় এটি মনে রাখা জরুরি)।

> **Warning:** অনেক প্রতিষ্ঠান এখনও Oracle-এর সাথে `finger` সার্ভিস ব্যবহার করে। যদি আমাদের কোনো হোম ডিরেক্টরি সম্পর্কে জ্ঞান থাকে, তবে এই `finger` সার্ভিসটি Oracle-এর সার্ভিসকে ঝুঁকিতে ফেলতে পারে এবং ভালনারেবল করে তুলতে পারে।

### Tnsnames.ora (Client-side Configuration)

প্রতিটি ডেটাবেস বা সার্ভিসের জন্য `tnsnames.ora` ফাইলে একটি ইউনিক এন্ট্রি থাকে, যেখানে ক্লায়েন্টদের ওই সার্ভিসে কানেক্ট করার জন্য প্রয়োজনীয় তথ্য থাকে। এতে সার্ভিসের নাম, নেটওয়ার্ক লোকেশন এবং ডেটাবেস বা সার্ভিসের নাম থাকে।

**উদাহরণ:**

```txt
ORCL =
  (DESCRIPTION =
    (ADDRESS_LIST =
      (ADDRESS = (PROTOCOL = TCP)(HOST = 10.129.11.102)(PORT = 1521))
    )
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = orcl)
    )
  )

```

এখানে আমরা `ORCL` নামের একটি সার্ভিস দেখতে পাচ্ছি, যা `10.129.11.102` IP অ্যাড্রেসে TCP/1521 পোর্টে লিসেন করছে। কানেক্ট করার সময় ক্লায়েন্টদের `orcl` সার্ভিস নেম ব্যবহার করতে হবে। এই ফাইলে বিভিন্ন ডেটাবেস এবং সার্ভিসের জন্য এমন অনেক এন্ট্রি থাকতে পারে। এতে অথেনটিকেশন ডিটেইলস, কানেকশন পুলিং সেটিংস এবং লোড ব্যালেন্সিং কনফিগারেশনও থাকতে পারে।

### Listener.ora (Server-side Configuration)

`listener.ora` হলো একটি সার্ভার-সাইড কনফিগারেশন ফাইল যা লিসেনার প্রসেসের প্রপার্টি এবং প্যারামিটারগুলো ডিফাইন করে। এই প্রসেসটি ইনকামিং ক্লায়েন্ট রিকোয়েস্টগুলো রিসিভ করে এবং সেগুলোকে উপযুক্ত Oracle ডেটাবেস ইন্সট্যান্সে ফরোয়ার্ড করে।

**উদাহরণ:**

```txt
SID_LIST_LISTENER =
  (SID_LIST =
    (SID_DESC =
      (SID_NAME = PDB1)
      (ORACLE_HOME = C:\oracle\product\19.0.0\dbhome_1)
      (GLOBAL_DBNAME = PDB1)
      (SID_DIRECTORY_LIST =
        (SID_DIRECTORY =
          (DIRECTORY_TYPE = TNS_ADMIN)
          (DIRECTORY = C:\oracle\product\19.0.0\dbhome_1\network\admin)
        )
      )
    )
  )

LISTENER =
  (DESCRIPTION_LIST =
    (DESCRIPTION =
      (ADDRESS = (PROTOCOL = TCP)(HOST = orcl.inlanefreight.htb)(PORT = 1521))
      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )
  )

ADR_BASE_LISTENER = C:\oracle

```

**মূল কথা:** ক্লায়েন্ট-সাইড সফটওয়্যার সার্ভিস নেমকে নেটওয়ার্ক অ্যাড্রেসে রূপান্তর করতে `tnsnames.ora` ব্যবহার করে, আর লিসেনার প্রসেস `listener.ora` ব্যবহার করে নির্ধারণ করে সে কোন সার্ভিসগুলোতে লিসেন করবে এবং তার আচরণ কেমন হবে।

### PL/SQL Exclusion List

Oracle ডেটাবেসকে **PL/SQL Exclusion List (PlsqlExclusionList)** ব্যবহার করে সুরক্ষিত করা যায়। এটি একটি ইউজার-তৈরি টেক্সট ফাইল যা `$ORACLE_HOME/sqldeveloper` ডিরেক্টরিতে রাখতে হয়। এতে সেই PL/SQL প্যাকেজ বা টাইপগুলোর নাম থাকে যেগুলোর এক্সিকিউশন (execution) এক্সক্লুড বা বন্ধ করা উচিত। ফাইলটি তৈরি করার পর এটি ডেটাবেস ইন্সট্যান্সে লোড করা যায়। এটি একটি ব্ল্যাকলিস্ট (blacklist) হিসেবে কাজ করে যা Oracle Application Server-এর মাধ্যমে অ্যাক্সেস করা যায় না।

## TNS Settings (কনফিগারেশন সেটিংসমূহ)

| Setting | Description (বিবরণ) |
| --- | --- |
| **DESCRIPTION** | একটি ডেসক্রিপ্টর যা ডেটাবেস এবং এর কানেকশন টাইপের নাম প্রদান করে। |
| **ADDRESS** | ডেটাবেসের নেটওয়ার্ক অ্যাড্রেস, যার মধ্যে হোস্টনেম এবং পোর্ট নাম্বার থাকে। |
| **PROTOCOL** | সার্ভারের সাথে যোগাযোগের জন্য ব্যবহৃত নেটওয়ার্ক প্রোটোকল। |
| **PORT** | সার্ভারের সাথে যোগাযোগের জন্য ব্যবহৃত পোর্ট নাম্বার। |
| **CONNECT_DATA** | কানেকশনের অ্যাট্রিবিউটগুলো নির্দিষ্ট করে, যেমন সার্ভিস নেম বা SID, প্রোটোকল এবং ডেটাবেস ইন্সট্যান্স আইডেন্টিফায়ার। |
| **INSTANCE_NAME** | ক্লায়েন্ট যে ডেটাবেস ইন্সট্যান্সে কানেক্ট করতে চায় তার নাম। |
| **SERVICE_NAME** | ক্লায়েন্ট যে সার্ভিসে কানেক্ট করতে চায় তার নাম। |
| **SERVER** | ডেটাবেস কানেকশনের জন্য ব্যবহৃত সার্ভারের ধরন, যেমন dedicated বা shared। |
| **USER** | ডেটাবেস সার্ভারে অথেনটিকেট করার জন্য ব্যবহৃত ইউজারনেম। |
| **PASSWORD** | ডেটাবেস সার্ভারে অথেনটিকেট করার জন্য ব্যবহৃত পাসওয়ার্ড। |
| **SECURITY** | কানেকশনের সিকিউরিটি টাইপ। |
| **VALIDATE_CERT** | SSL/TLS ব্যবহার করে সার্টিফিকেট ভ্যালিডেট করা হবে কিনা। |
| **SSL_VERSION** | কানেকশনের জন্য SSL/TLS-এর কোন ভার্সন ব্যবহৃত হবে। |
| **CONNECT_TIMEOUT** | ডেটাবেসের সাথে কানেকশন স্থাপন করতে ক্লায়েন্টের জন্য নির্ধারিত সময়সীমা (সেকেন্ডে)। |
| **RECEIVE_TIMEOUT** | ডেটাবেস থেকে রেসপন্স রিসিভ করতে ক্লায়েন্টের জন্য নির্ধারিত সময়সীমা (সেকেন্ডে)। |
| **SEND_TIMEOUT** | ডেটাবেসে রিকোয়েস্ট পাঠাতে ক্লায়েন্টের জন্য নির্ধারিত সময়সীমা (সেকেন্ডে)। |
| **SQLNET.EXPIRE_TIME** | কানেকশন ফেইল হয়েছে কিনা তা ডিটেক্ট করতে ক্লায়েন্টের জন্য নির্ধারিত সময়সীমা (সেকেন্ডে)। |
| **TRACE_LEVEL** | ডেটাবেস কানেকশনের ট্রেসিং লেভেল (tracing level)। |
| **TRACE_DIRECTORY** | যে ডিরেক্টরিতে ট্রেস ফাইলগুলো স্টোর করা হয়। |
| **TRACE_FILE_NAME** | ট্রেস ফাইলের নাম। |
| **LOG_FILE** | যে ফাইলে লগ ইনফরমেশন স্টোর করা হয়। |

### System Identifier (SID)

Oracle RDBMS-এ **SID** হলো একটি ইউনিক নাম যা একটি নির্দিষ্ট ডেটাবেস ইন্সট্যান্সকে আইডেন্টিফাই করে। একটি সার্ভারে একাধিক ইন্সট্যান্স থাকতে পারে এবং প্রতিটির নিজস্ব SID থাকে। ক্লায়েন্ট যখন কানেক্ট করতে চায়, তখন সে কানেকশন স্ট্রিংয়ের সাথে SID উল্লেখ করে। যদি ক্লায়েন্ট কোনো SID নির্দিষ্ট না করে, তবে `tnsnames.ora` ফাইলে থাকা ডিফল্ট ভ্যালু ব্যবহৃত হয়। ভুল SID দিলে কানেকশন ফেইল করবে।

### Nmap - SID Bruteforcing

SID এনুমারেট বা গেস (guess) করার জন্য আমরা nmap, hydra, odat-এর মতো টুল ব্যবহার করতে পারি। Nmap দিয়ে স্ক্যান করার উদাহরণ:

```bash
00Luffy00@htb[/htb]$ sudo nmap -p1521 -sV 10.129.204.235 --open --script oracle-sid-brute

Starting Nmap 7.93 ( https://nmap.org ) at 2023-03-06 11:01 EST
...

| oracle-sid-brute: 
|_  XE
...

```

এখানে আমরা দেখতে পাচ্ছি যে স্ক্যানের মাধ্যমে `XE` নামের একটি SID পাওয়া গেছে।

### File Upload (Web Shell)

আরেকটি কার্যকরী উপায় হলো টার্গেটে একটি ওয়েব শেল (web shell) আপলোড করা। তবে এর জন্য সার্ভারে একটি ওয়েব সার্ভার রান করতে হবে এবং আমাদের ওয়েব সার্ভারের রুট ডিরেক্টরির সঠিক লোকেশন জানতে হবে। ডিফল্ট পাথগুলো হলো:

| OS | Path |
| --- | --- |
| **Linux** | `/var/www/html` |
| **Windows** | `C:\inetpub\wwwroot` |

অ্যান্টিভাইরাস বা IDS/IPS-এর কাছে সন্দেহজনক মনে হবে না, এমন একটি সাধারণ টেক্সট ফাইল আপলোড করে প্রথমে চেক করা সবসময় ভালো।
