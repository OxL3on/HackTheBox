# MSSQL - [LINK](https://academy.hackthebox.com/app/module/112/section/1246)


## Introduction (ভূমিকা)

**Microsoft SQL (MSSQL)** হলো Microsoft-এর তৈরি একটি SQL-ভিত্তিক রিলেশনাল ডেটাবেস ম্যানেজমেন্ট সিস্টেম। এর আগের সেকশনে আলোচনা করা MySQL-এর মতো এটি ওপেন সোর্স নয়; এটি সম্পূর্ণ **closed source** এবং প্রাথমিকভাবে এটি Windows অপারেটিং সিস্টেমের জন্য লেখা হয়েছিল।

Microsoft-এর `.NET framework`-এর জন্য এর শক্তিশালী নেটিভ সাপোর্ট (native support) থাকায়, .NET-এ রান করে এমন অ্যাপ্লিকেশন তৈরির ক্ষেত্রে এটি ডেটাবেস অ্যাডমিনিস্ট্রেটর এবং ডেভেলপারদের কাছে অত্যন্ত জনপ্রিয়। যদিও Linux এবং MacOS-এর জন্যও MSSQL-এর ভার্সন রয়েছে, তবুও পেনিট্রেশন টেস্টিংয়ের সময় আমরা বেশিরভাগ ক্ষেত্রেই Windows-এ চলা MSSQL ইন্সট্যান্সের সম্মুখীন হব।

## MSSQL Clients (MSSQL ক্লায়েন্ট)

**SQL Server Management Studio (SSMS)** এমন একটি ফিচার যা MSSQL ইন্সটল প্যাকেজের সাথেই ইন্সটল করা যায় অথবা চাইলে আলাদাভাবে ডাউনলোড করেও ইন্সটল করা সম্ভব। অ্যাডমিনরা সাধারণত ডেটাবেসের প্রাথমিক কনফিগারেশন এবং দীর্ঘমেয়াদী ম্যানেজমেন্টের জন্য এটি সার্ভারে ইন্সটল করে থাকেন।

মনে রাখা জরুরি যে, SSMS যেহেতু একটি ক্লায়েন্ট-সাইড অ্যাপ্লিকেশন, তাই ডেটাবেস ম্যানেজ করার উদ্দেশ্যে অ্যাডমিন বা ডেভেলপার তাদের যেকোনো সিস্টেমে এটি ইন্সটল এবং ব্যবহার করতে পারেন। এটি শুধুমাত্র ডেটাবেস হোস্ট করা সার্ভারেই সীমাবদ্ধ থাকে না। এর মানে হলো, আমরা এমন কোনো ভালনারেবল (vulnerable) সিস্টেম পেতে পারি যেখানে SSMS-এ সেভ করা ক্রেডেনশিয়াল (saved credentials) রয়েছে, যা ব্যবহার করে আমরা সরাসরি ডেটাবেসে কানেক্ট করতে সক্ষম হতে পারি।

SSMS ছাড়াও MSSQL ডেটাবেস অ্যাক্সেস করার জন্য আরও অনেক ক্লায়েন্ট ব্যবহার করা যেতে পারে, যার মধ্যে কয়েকটি উল্লেখযোগ্য হলো:

* mssql-cli
* SQL Server PowerShell
* HeidiSQL
* SQLPro
* **Impacket's mssqlclient.py**

ওপরের লিস্টে থাকা ক্লায়েন্টগুলোর মধ্যে পেনটেস্টারদের (pentesters) কাছে সবচেয়ে দরকারী ক্লায়েন্টটি হলো **Impacket's mssqlclient.py**। কারণ SecureAuthCorp-এর Impacket প্রজেক্টটি অনেক পেনটেস্টিং ডিস্ট্রিবিউশনে আগে থেকেই ইন্সটল করা থাকে। আমাদের হোস্টে এই ক্লায়েন্টটি আছে কিনা এবং কোথায় আছে তা খুঁজে বের করতে আমরা নিচের কমান্ডটি ব্যবহার করতে পারি:

```bash
00Luffy00@htb[/htb]$ locate mssqlclient

/usr/bin/impacket-mssqlclient
/usr/share/doc/python3-impacket/examples/mssqlclient.py

```

## MSSQL Databases (MSSQL ডেটাবেসসমূহ)

MSSQL-এ কিছু ডিফল্ট সিস্টেম ডেটাবেস থাকে, যা একটি টার্গেট সার্ভারে হোস্ট করা সমস্ত ডেটাবেসের স্ট্রাকচার বুঝতে আমাদের সাহায্য করে। নিচে ডিফল্ট ডেটাবেস এবং তাদের সংক্ষিপ্ত বিবরণ দেওয়া হলো:

| Default System Database | Description (বিবরণ) |
| --- | --- |
| **master** | একটি SQL সার্ভার ইন্সট্যান্সের সমস্ত সিস্টেম ইনফরমেশন ট্র্যাক করে। |
| **model** | এটি একটি টেমপ্লেট ডেটাবেস যা নতুন তৈরি হওয়া প্রতিটি ডেটাবেসের স্ট্রাকচার হিসেবে কাজ করে। model ডেটাবেসে কোনো সেটিংস পরিবর্তন করা হলে, পরবর্তীতে তৈরি হওয়া যেকোনো নতুন ডেটাবেসে তার প্রতিফলন ঘটবে। |
| **msdb** | SQL Server Agent জব শিডিউল (schedule jobs) এবং অ্যালার্টের জন্য এই ডেটাবেসটি ব্যবহার করে। |
| **tempdb** | অস্থায়ী অবজেক্টগুলো (temporary objects) এখানে স্টোর করা হয়। |
| **resource** | এটি একটি read-only ডেটাবেস, যার মধ্যে SQL সার্ভারের সাথে থাকা সিস্টেম অবজেক্টগুলো অন্তর্ভুক্ত থাকে। |

*(টেবিল সোর্স: System Databases Microsoft Doc)*

## Default Configuration (ডিফল্ট কনফিগারেশন)

অ্যাডমিন যখন নেটওয়ার্কে অ্যাক্সেসযোগ্য করার জন্য প্রাথমিকভাবে MSSQL ইন্সটল ও কনফিগার করেন, তখন SQL সার্ভিসটি সম্ভবত `NT SERVICE\MSSQLSERVER` হিসেবে রান করে। ক্লায়েন্ট-সাইড থেকে কানেক্ট করার জন্য **Windows Authentication** ব্যবহার করা যায়, এবং ডিফল্টভাবে কানেক্ট করার সময় এনক্রিপশন প্রয়োগ (enforced) করা থাকে না।

**Windows Authentication** সেট করা থাকার মানে হলো, ডেটাবেস ম্যানেজমেন্ট সিস্টেমে কানেকশন অ্যালাউ করার আগে মূল Windows OS লগইন রিকোয়েস্টটি প্রসেস করবে এবং স্থানীয় **SAM database** অথবা **domain controller (Active Directory হোস্টিং)** ব্যবহার করবে।

Windows এনভায়রনমেন্টে অ্যাক্টিভিটি অডিটিং এবং অ্যাক্সেস নিয়ন্ত্রণের জন্য Active Directory ব্যবহার করাটা আদর্শ হতে পারে। কিন্তু যদি কোনো অ্যাকাউন্টের অ্যাক্সেস হ্যাক বা কম্প্রোমাইজ (compromised) হয়ে যায়, তবে এটি ব্যবহার করে একটি Windows ডোমেইন এনভায়রনমেন্টে **privilege escalation** এবং **lateral movement** করা সম্ভব হতে পারে।
যেকোনো OS, সার্ভিস, সার্ভার রোল বা অ্যাপ্লিকেশনের মতোই, ইন্সটলেশন থেকে শুরু করে কনফিগারেশন পর্যন্ত সবকিছু একটি VM-এ সেটআপ করে দেখা আমাদের জন্য উপকারী হতে পারে। এতে আমরা সকল ডিফল্ট কনফিগারেশন এবং অ্যাডমিনিস্ট্রেটরদের সম্ভাব্য ভুলগুলো সম্পর্কে ধারণা লাভ করতে পারব।

## Dangerous Settings (ঝুঁকিপূর্ণ সেটিংস)

পেনটেস্টিং এনগেজমেন্টের সময় নিজেদের একজন IT অ্যাডমিনিস্ট্রেটরের দৃষ্টিকোণ থেকে চিন্তা করাটা উপকারী। এই মানসিকতা আমাদেরকে বিভিন্ন এমন সেটিংস খুঁজতে সাহায্য করবে, যেগুলো অ্যাডমিন ভুলভাবে (misconfigured) বা বিপজ্জনক উপায়ে কনফিগার করে রেখেছেন। IT সেক্টরে কাজের চাপ অনেক বেশি থাকে, একই সময়ে অনেকগুলো প্রজেক্ট চলতে থাকে এবং দ্রুত ও নির্ভুলভাবে কাজ করার চাপের কারণে সহজেই ভুল হয়ে যেতে পারে। একটি ছোট ভুল কনফিগারেশনের কারণেই নেটওয়ার্কে একটি ক্রিটিকাল সার্ভার বা সার্ভিসের নিয়ন্ত্রণ হাতছাড়া হয়ে যেতে পারে। এটি MSSQL-সহ কনফিগার করা যায় এমন প্রায় প্রতিটি নেটওয়ার্ক সার্ভিস এবং সার্ভার রোলের ক্ষেত্রেই প্রযোজ্য।

নিচের তালিকাটি সম্পূর্ণ নয়, কারণ প্রতিষ্ঠানগুলোর প্রয়োজনীয়তার ওপর ভিত্তি করে অ্যাডমিনরা অসংখ্য উপায়ে MSSQL ডেটাবেস কনফিগার করতে পারেন। তবে নিচে উল্লেখিত বিষয়গুলো খুঁজলে আমরা বিশেষ সুবিধা পেতে পারি:

* MSSQL সার্ভারে কানেক্ট করার জন্য MSSQL ক্লায়েন্ট কর্তৃক **এনক্রিপশন (encryption)** ব্যবহার না করা।
* এনক্রিপশন ব্যবহার করা হলেও **self-signed certificates**-এর ব্যবহার। কারণ, self-signed certificates খুব সহজেই স্পুফ (spoof) করা সম্ভব।
* **Named pipes**-এর ব্যবহার।
* দুর্বল এবং ডিফল্ট **sa (system administrator)** ক্রেডেনশিয়াল। অ্যাডমিনরা অনেক সময় এই অ্যাকাউন্টটি ডিজেবল (disable) করতে ভুলে যান।

## Footprinting the Service (সার্ভিস ফুটপ্রিন্টিং)

MSSQL সার্ভিস ফুটপ্রিন্টিংয়ের জন্য আমরা অনেক উপায় অবলম্বন করতে পারি। আমাদের স্ক্যান যত বেশি নির্দিষ্ট (specific) হবে, আমরা তত বেশি কার্যকরী তথ্য সংগ্রহ করতে পারব। MSSQL ডিফল্টভাবে **TCP port 1433**-এ লিসেন (listen) করে এবং এটিকে টার্গেট করার জন্য NMAP-এ কিছু ডিফল্ট `mssql` স্ক্রিপ্ট রয়েছে।

## Connecting with Mssqlclient.py (Mssqlclient.py ব্যবহার করে কানেক্ট করা)

যদি আমরা সফলভাবে ক্রেডেনশিয়াল অনুমান করতে পারি বা অ্যাক্সেস লাভ করতে পারি, তবে এটি আমাদেরকে রিমোটলি MSSQL সার্ভারে কানেক্ট করার এবং **T-SQL (Transact-SQL)** ব্যবহার করে ডেটাবেসের সাথে ইন্টারঅ্যাক্ট করার সুযোগ দেবে। MSSQL-এ অথেনটিকেট করার ফলে আমরা SQL Database Engine-এর মাধ্যমে সরাসরি ডেটাবেসের সাথে ইন্টারঅ্যাক্ট করতে পারব।

Pwnbox বা যেকোনো ব্যক্তিগত অ্যাটাক হোস্ট (attack host) থেকে আমরা কানেক্ট করার জন্য Impacket-এর `mssqlclient.py` ব্যবহার করতে পারি, যা নিচের আউটপুটে দেখানো হয়েছে। সার্ভারে কানেক্ট হওয়ার পর, সিস্টেমটিতে উপস্থিত ডেটাবেসগুলোর লিস্ট তৈরি করা এবং সেখানকার পরিস্থিতি (lay of the land) সম্পর্কে ধারণা নেওয়াটা একটি ভালো পদক্ষেপ।
