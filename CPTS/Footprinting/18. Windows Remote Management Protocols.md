# Windows Remote Management Protocols - [LINK](https://academy.hackthebox.com/app/module/112/section/1242)


## Introduction (ভূমিকা)

Windows সার্ভারগুলোকে রিমোট সার্ভারে থাকা Server Manager administration tasks ব্যবহার করে লোকালি (locally) ম্যানেজ করা যায়। Windows Server 2016 থেকে রিমোট ম্যানেজমেন্ট ডিফল্টভাবে এনাবল (enabled) করা থাকে। রিমোট ম্যানেজমেন্ট হলো Windows হার্ডওয়্যার ম্যানেজমেন্ট ফিচারের একটি অংশ যা সার্ভার হার্ডওয়্যারকে লোকালি এবং রিমোটলি ম্যানেজ করে।

এই ফিচারগুলোর মধ্যে রয়েছে:

* একটি সার্ভিস যা **WS-Management** প্রোটোকল ইমপ্লিমেন্ট করে।
* বেসবোর্ড ম্যানেজমেন্ট কন্ট্রোলার (baseboard management controllers) ব্যবহার করে হার্ডওয়্যার ডায়াগনস্টিকস (diagnostics) এবং কন্ট্রোল।
* একটি **COM API** এবং স্ক্রিপ্ট অবজেক্টস যা এমন অ্যাপ্লিকেশন তৈরি করতে সাহায্য করে যেগুলো WS-Management প্রোটোকলের মাধ্যমে রিমোটলি যোগাযোগ করতে পারে।

Windows এবং Windows সার্ভার রিমোটলি ম্যানেজ করার জন্য মূলত তিনটি প্রধান কম্পোনেন্ট বা প্রোটোকল ব্যবহৃত হয়:

1. **Remote Desktop Protocol (RDP)**
2. **Windows Remote Management (WinRM)**
3. **Windows Management Instrumentation (WMI)**

---

## 1. Remote Desktop Protocol (RDP)

**Remote Desktop Protocol (RDP)** হলো Microsoft-এর তৈরি একটি প্রোটোকল, যার মাধ্যমে Windows অপারেটিং সিস্টেমে চালিত কোনো কম্পিউটারে রিমোট অ্যাক্সেস করা যায়। এই প্রোটোকলটি IP নেটওয়ার্কের মাধ্যমে এনক্রিপ্ট করা অবস্থায় GUI (Graphical User Interface) ব্যবহার করে ডিসপ্লে এবং কন্ট্রোল কমান্ডগুলো ট্রান্সমিট করার সুযোগ দেয়।

RDP মূলত TCP/IP রেফারেন্স মডেলের **application layer**-এ কাজ করে এবং সাধারণত ট্রান্সপোর্ট প্রোটোকল হিসেবে **TCP port 3389** ব্যবহার করে। তবে, রিমোট অ্যাডমিনিস্ট্রেশনের জন্য কানেকশনলেস UDP প্রোটোকলও পোর্ট 3389 ব্যবহার করতে পারে।

### Requirements and Network Setup

একটি RDP সেশন স্থাপন করার জন্য নেটওয়ার্ক ফায়ারওয়াল এবং সার্ভারের ফায়ারওয়াল—উভয়কেই বাহির থেকে আসা কানেকশন অ্যালাউ (allow connections) করতে হবে। ক্লায়েন্ট এবং সার্ভারের মাঝে যদি **Network Address Translation (NAT)** ব্যবহৃত হয় (যেমনটা ইন্টারনেট কানেকশনের ক্ষেত্রে প্রায়ই হয়), তবে সার্ভারে পৌঁছানোর জন্য রিমোট কম্পিউটারের একটি পাবলিক IP অ্যাড্রেস প্রয়োজন হবে। এছাড়া NAT রাউটারে সার্ভারের দিকে পোর্ট ফরোয়ার্ডিং (port forwarding) সেটআপ করা থাকতে হবে।

### Security and Encryption

Windows Vista থেকে RDP-তে **Transport Layer Security (TLS/SSL)** ব্যবহৃত হচ্ছে, যার ফলে সমস্ত ডেটা এবং বিশেষ করে লগইন প্রসেসটি নেটওয়ার্কে ভালো এনক্রিপশনের মাধ্যমে সুরক্ষিত থাকে। তবে, অনেক Windows সিস্টেম এই সিকিউরিটির জন্য জোর (insist) দেয় না বরং RDP Security-এর মাধ্যমে অপর্যাপ্ত এনক্রিপশন (inadequate encryption) গ্রহণ করে।

তা সত্ত্বেও, এই অবস্থায়ও কোনো অ্যাটাকার সহজেই সিস্টেমে ঢুকতে পারে না কারণ আইডেন্টিটি প্রদানকারী সার্টিফিকেটগুলো ডিফল্টভাবে **self-signed (স্ব-স্বাক্ষরিত)** থাকে। এর ফলে ক্লায়েন্ট আসল এবং নকল বা ফোর্জড (forged) সার্টিফিকেটের মধ্যে পার্থক্য করতে পারে না এবং ইউজারের জন্য একটি সার্টিফিকেট ওয়ার্নিং জেনারেট করে।

Windows সার্ভারগুলোতে Remote Desktop সার্ভিসটি ডিফল্টভাবে ইন্সটল করা থাকে এবং এর জন্য অতিরিক্ত কোনো এক্সটারনাল অ্যাপ্লিকেশন প্রয়োজন হয় না। Server Manager ব্যবহার করে এই সার্ভিসটি অ্যাক্টিভেট করা যায় এবং ডিফল্ট সেটিং অনুযায়ী এটি শুধুমাত্র **Network level authentication (NLA)** আছে এমন হোস্টদেরই কানেক্ট করার অনুমতি দেয়।

### Footprinting the Service (RDP)

RDP সার্ভিসটি স্ক্যান করলে আমরা খুব দ্রুত হোস্ট সম্পর্কে অনেক গুরুত্বপূর্ণ তথ্য পেতে পারি। উদাহরণস্বরূপ, সার্ভারে NLA এনাবল করা আছে কিনা, প্রোডাক্ট ভার্সন এবং হোস্টনেম জানা যায়।

> **Warning:** Nmap যখন RDP সার্ভারের সাথে ইন্টারঅ্যাক্ট করে, তখন এটি `mstshash=nmap` নামের একটি RDP কুকি ব্যবহার করে। থ্রেট হান্টার (threat hunters) এবং Endpoint Detection and Response (EDR)-এর মতো সিকিউরিটি সার্ভিসগুলো এই কুকি আইডেন্টিফাই করতে পারে এবং পেনিট্রেশন টেস্টার হিসেবে আমাদেরকে হার্ডেনড নেটওয়ার্ক (hardened networks) থেকে লক আউট (lock out) করে দিতে পারে।

## 2. WinRM (Windows Remote Management)

**Windows Remote Management (WinRM)** হলো কমান্ড লাইনের ওপর ভিত্তি করে তৈরি একটি সহজ এবং Windows-এর সাথে ইন্টিগ্রেটেড রিমোট ম্যানেজমেন্ট প্রোটোকল। রিমোট হোস্ট এবং এর অ্যাপ্লিকেশনগুলোর সাথে কানেকশন তৈরি করতে WinRM **Simple Object Access Protocol (SOAP)** ব্যবহার করে।

Windows 10 থেকে WinRM-কে এক্সপ্লিসিটলি (explicitly) এনাবল এবং কনফিগার করতে হয়। যোগাযোগের জন্য WinRM **TCP port 5985 (HTTP)** এবং **5986 (HTTPS)** এর ওপর নির্ভর করে। আগে এই কাজের জন্য পোর্ট 80 এবং 443 ব্যবহার করা হতো, কিন্তু সিকিউরিটির কারণে পোর্ট 80 ব্লক করে দেওয়ায় বর্তমানে নতুন পোর্ট 5985 এবং 5986 ব্যবহৃত হচ্ছে।

অ্যাডমিনিস্ট্রেশনের জন্য WinRM-এর সাথে মানানসই আরেকটি কম্পোনেন্ট হলো **Windows Remote Shell (WinRS)**, যা রিমোট সিস্টেমে যেকোনো আর্বিট্রারি (arbitrary) কমান্ড এক্সিকিউট করতে দেয়। এই প্রোগ্রামটি Windows 7-এ ডিফল্টভাবে যুক্ত থাকে।

PowerShell রিমোট সেশন এবং ইভেন্ট লগ মার্জিং (event log merging)-এর মতো সার্ভিসগুলোর জন্য WinRM প্রয়োজন হয়। **Windows Server 2012** ভার্সন থেকে WinRM ডিফল্টভাবে এনাবল করা থাকে। তবে পুরোনো সার্ভার ভার্সন এবং ক্লায়েন্টদের জন্য এটি প্রথমে কনফিগার করতে হয় এবং প্রয়োজনীয় ফায়ারওয়াল এক্সেপশন (firewall exceptions) তৈরি করতে হয়।

### Footprinting the Service (WinRM)

#### Interacting with WinRM

কোনো রিমোট সার্ভার WinRM-এর মাধ্যমে অ্যাক্সেস করা যাবে কিনা, তা আমরা PowerShell-এর `Test-WsMan` কমান্ডলেট (cmdlet) ব্যবহার করে দেখতে পারি। এর সাথে নির্দিষ্ট হোস্টের নাম পাস করতে হয়।

Linux-ভিত্তিক এনভায়রনমেন্টে WinRM-এর সাথে ইন্টারঅ্যাক্ট করার জন্য আমরা `evil-winrm` নামক একটি পেনিট্রেশন টেস্টিং টুল ব্যবহার করতে পারি।

## 3. WMI (Windows Management Instrumentation)

**Windows Management Instrumentation (WMI)** হলো Microsoft-এর নিজস্ব ইমপ্লিমেন্টেশন এবং এটি Windows প্ল্যাটফর্মের জন্য স্ট্যান্ডার্ডাইজড **Web-Based Enterprise Management (WBEM)**-এর কোর ফাংশনালিটি **Common Information Model (CIM)**-এর একটি এক্সটেনশন।

WMI Windows সিস্টেমের প্রায় সমস্ত সেটিংসে রিড এবং রাইট (read and write) অ্যাক্সেস প্রদান করে। এর ফলে, এটি পিসি বা সার্ভার নির্বিশেষে যেকোনো Windows কম্পিউটারের অ্যাডমিনিস্ট্রেশন এবং রিমোট মেইনটেন্যান্সের জন্য সবচেয়ে ক্রিটিকাল ইন্টারফেস হিসেবে কাজ করে।

সাধারণত **PowerShell**, **VBScript** অথবা **Windows Management Instrumentation Console (WMIC)** ব্যবহার করে WMI-তে অ্যাক্সেস করা হয়। WMI কোনো সিঙ্গেল প্রোগ্রাম নয়, বরং এটি অনেকগুলো প্রোগ্রাম এবং রিপোজিটরি (repositories) নামক বিভিন্ন ডেটাবেস নিয়ে গঠিত।

### Footprinting the Service (WMI)

WMI কমিউনিকেশনের ইনিশিয়ালাইজেশন (initialization) সবসময় **TCP port 135**-এ শুরু হয়। এরপর সফলভাবে কানেকশন তৈরি হওয়ার পর, কমিউনিকেশনটি একটি র‍্যান্ডম পোর্টে (random port) ট্রান্সফার হয়ে যায়।

WMI-এর সাথে ইন্টারঅ্যাক্ট করার জন্য আমরা Impacket টুলকিটের `wmiexec.py` প্রোগ্রামটি ব্যবহার করতে পারি।

#### WMIexec.py

| অংশ | অর্থ |
| --- | --- |
| `Cry0l1t3:"P455w0rD!"@10.129.201.248` | `Username:Password@Target_IP` ফরম্যাট। |
| `"hostname"` | রিমোট সিস্টেমে এক্সিকিউট করার জন্য কমান্ড। |
