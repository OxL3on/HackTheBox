# Cloud Resources - [LINK](https://academy.hackthebox.com/app/module/112/section/1062)

বর্তমান সময়ে অনেক কোম্পানির জন্য Cloud-এর ব্যবহার, যেমন— **AWS, GCP, Azure** এবং অন্যান্য প্ল্যাটফর্মগুলো একটি অপরিহার্য (essential) উপাদানে পরিণত হয়েছে। কারণ, সব কোম্পানিই চায় যেকোনো জায়গা থেকে তাদের কাজ পরিচালনা করতে, তাই তাদের সমস্ত management-এর জন্য একটি central point-এর প্রয়োজন হয়। এ কারণেই **Amazon (AWS), Google (GCP)**, এবং **Microsoft (Azure)**-এর service-গুলো এই উদ্দেশ্যের জন্য সবচেয়ে আদর্শ।

Cloud provider-রা তাদের infrastructure centrally সুরক্ষিত রাখলেও, এর মানে এই নয় যে কোম্পানিগুলো vulnerabilities থেকে সম্পূর্ণ মুক্ত। Administrator-দের করা configurations-এর ভুলের কারণে কোম্পানির cloud resources ঝুঁকিপূর্ণ (vulnerable) হতে পারে। এটি প্রায়শই নিচের cloud resource-গুলো দিয়ে শুরু হয়:

* **S3 buckets** (AWS)
* **Blobs** (Azure)
* **Cloud storage** (GCP)

যদি এগুলো ভুলভাবে configure করা থাকে, তবে **authentication ছাড়াই** এগুলোতে অ্যাক্সেস করা সম্ভব হয়।

## Company Hosted Servers

প্রায়শই cloud storage-কে DNS list-এ যুক্ত করা হয় যখন এটি অন্যান্য employees দ্বারা administrative কাজের জন্য ব্যবহৃত হয়। এই পদক্ষেপটি employees-দের জন্য cloud resources-এ পৌঁছানো এবং সেগুলো পরিচালনা (manage) করা অনেক সহজ করে দেয়।

ধরে নেওয়া যাক, একটি কোম্পানি আমাদেরকে টেস্টিংয়ের জন্য নিয়োগ দিয়েছে এবং IP lookup করার সময় আমরা দেখতে পেয়েছি যে একটি IP address `s3-website-us-west-2.amazonaws.com` সার্ভারের অন্তর্গত।

```bash
00Luffy00@htb[/htb]$ for i in $(cat subdomainlist);do host $i | grep "has address" | grep inlanefreight.com | cut -d" " -f1,4;done

blog.inlanefreight.com 10.129.24.93
inlanefreight.com 10.129.27.33
matomo.inlanefreight.com 10.129.127.22
www.inlanefreight.com 10.129.127.33
s3-website-us-west-2.amazonaws.com 10.129.95.250

```

> **Note:** উপরের কমান্ডে `host` ব্যবহার করে `subdomainlist`-এ থাকা প্রতিটি সাবডোমেইনের IP address বের করা হয়েছে এবং `grep`-এর মাধ্যমে শুধুমাত্র `inlanefreight.com`-এর সাথে সম্পর্কিত আইপিগুলো ফিল্টার করা হয়েছে। আউটপুটের শেষ লাইনে আমরা একটি AWS S3 bucket-এর উপস্থিতি স্পষ্টভাবে দেখতে পাচ্ছি।

## Discovering Cloud Storage (Cloud Storage খুঁজে বের করার উপায়)

এই ধরনের cloud storage খুঁজে বের করার অনেকগুলো ভিন্ন উপায় রয়েছে। নিচে সবচেয়ে সহজ এবং বহুল ব্যবহৃত কয়েকটি পদ্ধতি আলোচনা করা হলো:

### ১. Google Dorks ব্যবহার করা

Cloud storage খোঁজার অন্যতম সহজ পদ্ধতি হলো Google search-এর সাথে **Google Dorks** ব্যবহার করা। উদাহরণস্বরূপ, আমরা নির্দিষ্ট terms বা শব্দ দিয়ে আমাদের সার্চকে আরও সুনির্দিষ্ট (narrow) করতে `inurl:` এবং `intext:` Dorks ব্যবহার করতে পারি।

এর মাধ্যমে সার্চ করলে সার্চ রেজাল্টে কোম্পানির নাম সম্বলিত বিভিন্ন ক্লাউড লিংক পাওয়া যায়।

* **Google Search for AWS:** [https://www.google.com](https://www.google.com)
* **Google Search for Azure:** [https://www.google.com](https://www.google.com)

Google-এর প্রদান করা এই লিংকগুলোতে প্রায়ই বিভিন্ন PDFs পাওয়া যায়। যখন আমরা এমন কোনো কোম্পানি খুঁজি যাকে আমরা আগে থেকেই চিনি বা জানতে চাই, তখন আমরা PDF ছাড়াও অন্যান্য ফাইল যেমন— text documents, presentations, codes, এবং আরও অনেক কিছু খুঁজে পেতে পারি।

### ২. Target Website-এর Source Code বিশ্লেষণ

এই ধরনের cloud content প্রায়শই ওয়েব পেজের source code-এর মধ্যেও অন্তর্ভুক্ত (included) থাকে, যেখান থেকে ওয়েবসাইটের images, JavaScript codes, অথবা CSS লোড করা হয়। এই পদ্ধতিটি ওয়েব সার্ভারের উপর থেকে চাপ (load) কমায় এবং সার্ভারে অপ্রয়োজনীয় content স্টোর করা থেকে বিরত রাখে।

### ৩. Third-party Providers (Domain.Glass)

**Domain.Glass**-এর মতো third-party providers আমাদেরকে কোম্পানির infrastructure সম্পর্কে অনেক গুরুত্বপূর্ণ তথ্য দিতে পারে। এর একটি ইতিবাচক দিক (positive side effect) হিসেবে, আমরা দেখতে পারি যে Cloudflare-এর security assessment status "Safe" হিসেবে ক্লাসিফাই করা হয়েছে কিনা। এর মানে হলো, আমরা ইতোমধ্যেই একটি security measure খুঁজে পেয়েছি, যা আমাদের Enumeration Methodology-এর **second layer (Gateway)**-এর জন্য নোট করে রাখা যেতে পারে।

### ৪. GrayHatWarfare ব্যবহার করা

**GrayHatWarfare** হলো আরেকটি অত্যন্ত কার্যকরী provider। এর মাধ্যমে আমরা অনেক ধরনের ভিন্ন ভিন্ন সার্চ করতে পারি, AWS, Azure, এবং GCP cloud storage আবিষ্কার (discover) করতে পারি এবং এমনকি file format অনুযায়ী সেগুলোকে sort এবং filter করতে পারি।
সুতরাং, একবার Google-এর মাধ্যমে cloud storage খুঁজে পাওয়ার পর, আমরা GrayHatWarfare-এ সেগুলো সার্চ করে passively দেখতে পারি যে নির্দিষ্ট cloud storage-এ কী ধরনের ফাইল স্টোর করা আছে।

### ৫. Company Abbreviations (কোম্পানির নামের সংক্ষিপ্ত রূপ)

অনেক কোম্পানি তাদের নামের সংক্ষিপ্ত রূপ (abbreviations) ব্যবহার করে, যা পরবর্তীতে তাদের IT infrastructure-এর ভেতরে ব্যবহৃত হয়। কোম্পানির নতুন cloud storage আবিষ্কার করার জন্য এই ধরনের সংক্ষিপ্ত শব্দ বা terms ব্যবহার করা একটি চমৎকার (excellent) approach। আমরা চাইলে একই সময়ে একসাথে একাধিক ফাইল সার্চ করে দেখতে পারি যে কোন ফাইলগুলোতে অ্যাক্সেস করা সম্ভব।

## The Risk of Human Error: Leaked SSH Keys

কখনো কখনো employees-রা যখন অতিরিক্ত কাজের চাপে (overworked) বা উচ্চ চাপের মধ্যে থাকেন, তখন তাদের করা ছোট ভুলগুলোও সম্পূর্ণ কোম্পানির জন্য মারাত্মক (fatal) হতে পারে।

> **Warning:** এই ধরনের ভুলের কারণে অনেক সময় **SSH private keys** ইন্টারনেটে leak হয়ে যেতে পারে।

একবার একটি SSH private key leak হয়ে গেলে, যে কেউই সেটি ডাউনলোড করে পাসওয়ার্ড (password) ব্যবহার না করেই কোম্পানির এক বা একাধিক মেশিনে (machines) সফলভাবে লগইন করতে সক্ষম হতে পারে। এটি cloud security এবং information exposure-এর ক্ষেত্রে একটি অত্যন্ত গুরুতর ঝুঁকি।
