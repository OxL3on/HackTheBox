# Attacking Windows Credential Manager - [LINK](https://academy.hackthebox.com/app/module/147/section/3714)


উইন্ডোজ সিস্টেমে ইউজারদের সেভ করা পাসওয়ার্ডগুলো কীভাবে খুঁজে বের করতে হয় এবং সেগুলো কাজে লাগিয়ে কীভাবে সিস্টেমের অ্যাক্সেস নেওয়া যায়, তা এই সেকশনে আলোচনা করা হয়েছে।

## Windows Vault এবং Credential Manager

Windows Server 2008 R2 এবং Windows 7 থেকে উইন্ডোজে **Credential Manager** নামে একটি ফিচার যুক্ত করা হয়েছে। এর কাজ হলো ইউজার এবং বিভিন্ন অ্যাপ্লিকেশনের সেভ করা পাসওয়ার্ডগুলো (যেমন: ওয়েবসাইটের পাসওয়ার্ড, নেটওয়ার্ক ড্রাইভের পাসওয়ার্ড) নিরাপদে স্টোর করে রাখা। ইউজাররা কন্ট্রোল প্যানেল থেকে গ্রাফিকাল ইন্টারফেসের মাধ্যমে এই ক্রেডেনশিয়াল ম্যানেজার দেখতে এবং ম্যানেজ করতে পারেন।

উইন্ডোজ এই পাসওয়ার্ডগুলো সাধারণ টেক্সট হিসেবে রাখে না, বরং ইউজার এবং সিস্টেম প্রোফাইলের অধীনে কিছু বিশেষ এনক্রিপ্টেড ফোল্ডারে লুকিয়ে রাখে। ফোল্ডারগুলোর লোকেশন নিচে দেওয়া হলো:

```text
%UserProfile%\AppData\Local\Microsoft\Vault\
%UserProfile%\AppData\Local\Microsoft\Credentials\
%UserProfile%\AppData\Roaming\Microsoft\Vault\
%ProgramData%\Microsoft\Vault\
%SystemRoot%\System32\config\systemprofile\AppData\Roaming\Microsoft\Vault\

```

**পাসওয়ার্ডগুলো কীভাবে সুরক্ষিত থাকে?**
এই ফোল্ডারগুলোর (যাদের মাইক্রোসফট Credential Lockers বা Windows Vaults বলে) প্রত্যেকটির ভেতরে `Policy.vpol` নামের একটি ফাইল থাকে। এই ফাইলে AES (AES-128 বা AES-256) কি (Key) থাকে, যা উইন্ডোজের DPAPI দ্বারা সুরক্ষিত থাকে। এই AES কিগুলো ব্যবহার করেই মূলত পাসওয়ার্ডগুলো এনক্রিপ্ট করা হয়। আধুনিক উইন্ডোজ ভার্সনগুলোতে "Credential Guard" ব্যবহার করে এই কিগুলোকে মেমোরির একটি সুরক্ষিত জায়গায় রাখা হয়, যাতে হ্যাকাররা সহজে অ্যাক্সেস করতে না পারে।

উইন্ডোজ মূলত দুই ধরনের ক্রেডেনশিয়াল স্টোর করে:

| নাম (Name) | বর্ণনা (Description) |
| --- | --- |
| **Web Credentials** | ওয়েবসাইট এবং অনলাইন অ্যাকাউন্টের পাসওয়ার্ড। ইন্টারনেট এক্সপ্লোরার এবং লিগ্যাসি মাইক্রোসফট এজ (Edge) ব্রাউজার এটি ব্যবহার করে। |
| **Windows Credentials** | উইন্ডোজের নিজস্ব সার্ভিসের লগইন টোকেন (যেমন: OneDrive), ডোমেইন ইউজারের তথ্য, লোকাল নেটওয়ার্ক রিসোর্স এবং শেয়ার করা ফোল্ডারের পাসওয়ার্ড এখানে থাকে। |

**পাসওয়ার্ড ব্যাকআপ বা এক্সপোর্ট করা:**
আমরা চাইলে কন্ট্রোল প্যানেল থেকে অথবা কমান্ড লাইনের মাধ্যমে এই পাসওয়ার্ডগুলো `.crd` ফাইলে এক্সপোর্ট বা ব্যাকআপ করতে পারি। উইন্ডোজে Stored User Names and Passwords নামের একটি ডায়ালগ বক্সের মাধ্যমে এগুলো ম্যানেজ করা যায়। কমান্ড প্রম্পট থেকে এটি ওপেন করার কমান্ড হলো:

```cmd
C:\Users\sadams>rundll32 keymgr.dll,KRShowKeyMgr

```

এই এক্সপোর্ট করা ব্যাকআপ ফাইলগুলো ইউজারের দেওয়া একটি পাসওয়ার্ড দিয়ে এনক্রিপ্ট করা থাকে এবং অন্য উইন্ডোজ মেশিনে ইমপোর্ট করা যায়।

## cmdkey দিয়ে ক্রেডেনশিয়াল খোঁজা (Enumerating credentials)

টার্গেট মেশিনে অ্যাক্সেস পাওয়ার পর আমাদের প্রথম কাজ হলো কারেন্ট ইউজারের প্রোফাইলে কোনো দরকারি পাসওয়ার্ড সেভ করা আছে কিনা তা চেক করা। এর জন্য আমরা `cmdkey` কমান্ড ব্যবহার করব:

```cmd
C:\Users\sadams>whoami
srv01\sadams

C:\Users\sadams>cmdkey /list

```

কমান্ডটি রান করলে সিস্টেমে সেভ থাকা পাসওয়ার্ডগুলোর একটি লিস্ট আসবে। আউটপুটটি নিচের ছকে দেওয়া ফরম্যাটে থাকে:

| ফিল্ড (Key) | অর্থ (Value) |
| --- | --- |
| **Target** | এটি কোন রিসোর্স বা অ্যাকাউন্টের পাসওয়ার্ড তা নির্দেশ করে (যেমন: কোনো কম্পিউটার বা ডোমেইনের নাম)। |
| **Type** | ক্রেডেনশিয়ালের ধরন। সাধারণত সাধারণ পাসওয়ার্ডের জন্য `Generic` এবং ডোমেইন লগইনের জন্য `Domain Password` লেখা থাকে। |
| **User** | যে ইউজার অ্যাকাউন্টের পাসওয়ার্ড সেভ করা আছে, তার নাম। |
| **Persistence** | পাসওয়ার্ডটি কীভাবে সেভ করা আছে। যদি `Local machine persistence` লেখা থাকে, তার মানে কম্পিউটার রিস্টার্ট দিলেও এই পাসওয়ার্ডটি সিস্টেমে সেভ থাকবে। |

**আউটপুট বিশ্লেষণ এবং হ্যাকিং ট্রিক:**

লিস্টে যদি `virtualapp/didlogical` নামের কোনো টার্গেট দেখেন, তবে সেটি এড়িয়ে যাবেন। এটি মাইক্রোসফটের উইন্ডোজ লাইভ সার্ভিসের একটি জেনেরিক ক্রেডেনশিয়াল, যা আমাদের হ্যাকিংয়ের কোনো কাজে আসবে না।

তবে লিস্টে যদি এমন কিছু পান: `Target: Domain:interactive=SRV01\mcharles`
এর মানে হলো, `SRV01\mcharles` নামের ইউজারের ডোমেইন পাসওয়ার্ড এখানে সেভ করা আছে এবং এটি ইন্টারঅ্যাকটিভ লগইনের জন্য ব্যবহার করা যাবে! এটি পেলে আমরা `runas` কমান্ড ব্যবহার করে পাসওয়ার্ড না জেনেই ওই ইউজারের পারমিশন নিয়ে নতুন একটি কমান্ড প্রম্পট (cmd) চালু করতে পারি।

**পেলোড (Payload):**

```cmd
C:\Users\sadams>runas /savecred /user:SRV01\mcharles cmd

```

*সহজ ব্যাখ্যা: `runas` দিয়ে আমরা অন্য ইউজারের পরিচয়ে প্রোগ্রাম রান করছি, আর `/savecred` দিয়ে সিস্টেমকে বলছি সেভ করা পাসওয়ার্ডটি ব্যবহার করতে। ফলে কমান্ডটি রান করার সাথে সাথেই `SRV01\mcharles` ইউজারের এক্সেসসহ একটি নতুন টার্মিনাল ওপেন হয়ে যাবে*।

## [Mimikatz](https://github.com/gentilkiwi/mimikatz) দিয়ে ক্রেডেনশিয়াল বের করা (Extracting credentials)

সেভ করা পাসওয়ার্ডগুলো শুধু ব্যবহার করাই নয়, আমরা চাইলে সেগুলো ডিক্রিপ্ট করে আসল পাসওয়ার্ড বা ক্লিয়ারটেক্সট বের করে আনতে পারি। এর জন্য SharpDPAPI, LaZagne, DonPAPI এবং Mimikatz এর মতো টুল ব্যবহার করা হয়।

আমরা এখানে **Mimikatz** ব্যবহার করে সরাসরি LSASS প্রসেসের মেমোরি থেকে পাসওয়ার্ডগুলো ডাম্প করব। এর জন্য `sekurlsa` মডিউলটি ব্যবহার করা হবে:

**ধাপসমূহ:**

১. প্রথমে Mimikatz চালু করে আমাদের অ্যাডমিন প্রিভিলেজ নিশ্চিত করতে হবে:

```cmd
mimikatz # privilege::debug
Privilege '20' OK

```

২. এরপর ক্রেডেনশিয়াল ম্যানেজারের পাসওয়ার্ডগুলো ডাম্প করার কমান্ড দিতে হবে:

```cmd
mimikatz # sekurlsa::credman

```

**ফলাফল:**
আউটপুটে আপনি লগইন করা ইউজারদের সেশনের তথ্য দেখতে পাবেন। সবচেয়ে গুরুত্বপূর্ণ অংশটি হলো `credman` সেকশন। সেখানে আপনি ইউজারের নাম, ডোমেইন এবং তার আসল পাসওয়ার্ডটি (ক্লিয়ারটেক্সট বা প্লেইন টেক্সট হিসেবে) পেয়ে যাবেন!

```text
        credman :
         [00000000]
         * Username : mcharles@inlanefreight.local
         * Domain   : onedrive.live.com
         * Password : (এখানে আসল পাসওয়ার্ডটি দেখা যাবে)

```


Note: Some other tools which may be used to enumerate and extract stored credentials included [SharpDPAPI](https://github.com/GhostPack/SharpDPAPI), [LaZagne](https://github.com/AlessandroZ/LaZagne), and [DonPAPI](https://github.com/login-securite/DonPAPI).
