# Linux Authentication Process - [LINK](https://academy.hackthebox.com/app/module/147/section/1319)


লিনাক্স সিস্টেমে ইউজারদের লগইন বা পরিচয় যাচাই করার জন্য বেশ কিছু পদ্ধতি আছে। এর মধ্যে সবচেয়ে বেশি ব্যবহৃত এবং গুরুত্বপূর্ণ পদ্ধতিটি হলো **PAM (Pluggable Authentication Modules)**। চলুন এই পুরো প্রক্রিয়াটি একদম সহজ ভাষায় ধাপে ধাপে বুঝে নিই।

## ১. PAM কী এবং কীভাবে কাজ করে?

PAM হলো লিনাক্স সিস্টেমের একটি মডিউল বা প্রোগ্রাম, যা মূলত ইউজারদের অথেনটিকেশন (পাসওয়ার্ড যাচাই), সেশন এবং পাসওয়ার্ড পরিবর্তনের বিষয়গুলো নিয়ন্ত্রণ করে।

ডেবিয়ান-ভিত্তিক (Debian-based) সিস্টেমে এই মডিউলগুলো (যেমন: `pam_unix.so`) সাধারণত `/usr/lib/x86_64-linux-gnu/security/` ফোল্ডারে থাকে।
উদাহরণস্বরূপ, আপনি যখন `passwd` কমান্ড দিয়ে নিজের পাসওয়ার্ড পরিবর্তন করেন, তখন ব্যাকগ্রাউন্ডে এই PAM মডিউলটি চালু হয় এবং আপনার নতুন পাসওয়ার্ডটি নিরাপদে সেভ করার দায়িত্ব পালন করে।

পাসওয়ার্ড সেভ করা এবং পড়ার জন্য PAM মূলত দুটি ফাইলের ওপর সবচেয়ে বেশি নির্ভর করে: `/etc/passwd` এবং `/etc/shadow`।

## ২. Passwd ফাইল (`/etc/passwd`)

এই ফাইলটিতে সিস্টেমের সব ইউজারের সাধারণ তথ্য থাকে। সবচেয়ে বড় বিষয় হলো, এই ফাইলটি সিস্টেমের **যেকোনো ইউজার পড়তে পারে (world-readable)**।

এই ফাইলে প্রতিটি ইউজারের জন্য একটি করে লাইন থাকে এবং প্রতিটি লাইনে ৭টি ফিল্ড বা অংশ থাকে, যেগুলো কোলন (`:`) দিয়ে আলাদা করা থাকে।

**উদাহরণ:**

```text
htb-student:x:1000:1000:,,,:/home/htb-student:/bin/bash

```

**ফিল্ডগুলোর ব্যাখ্যা:**

1. **Username:** ইউজারের নাম (htb-student)
2. **Password:** পাসওয়ার্ড ফিল্ড (এখানে সাধারণত `x` লেখা থাকে)
3. **User ID (UID):** ইউজারের আইডি (1000)
4. **Group ID (GID):** গ্রুপের আইডি (1000)
5. **GECOS:** ইউজারের সাধারণ তথ্য বা কমেন্ট (,,,)
6. **Home directory:** ইউজারের নিজস্ব ফোল্ডার (/home/htb-student)
7. **Default shell:** ইউজারের ডিফল্ট টার্মিনাল বা শেল (/bin/bash)

**হ্যাকিং ট্রিক:**
সাধারণত পাসওয়ার্ড ফিল্ডে `x` থাকে, যার মানে হলো আসল পাসওয়ার্ডটি এখানে নেই, বরং সেটি `/etc/shadow` ফাইলে লুকানো আছে। কিন্তু কোনো অ্যাডমিনের ভুলের কারণে যদি এই ফাইলে আপনার লেখার (Write) পারমিশন থাকে, তবে আপনি রুট (root) ইউজারের লাইনে থাকা `x` টি মুছে দিতে পারেন।

```text
root::0:0:root:/root:/bin/bash

```

`x` মুছে দিলে সিস্টেম ভাববে রুট ইউজারের কোনো পাসওয়ার্ড নেই! তখন আপনি শুধু `su` কমান্ড দিলেই কোনো পাসওয়ার্ড ছাড়া রুট হয়ে যেতে পারবেন।

## ৩. Shadow ফাইল (`/etc/shadow`)

যেহেতু `/etc/passwd` সবাই পড়তে পারে, তাই সেখানে পাসওয়ার্ডের হ্যাশ রাখাটা খুবই বিপজ্জনক। এই সমস্যা সমাধানের জন্যই `/etc/shadow` ফাইলের জন্ম।

এই ফাইলে শুধুমাত্র ইউজারদের পাসওয়ার্ডের হ্যাশ এবং পাসওয়ার্ড ম্যানেজমেন্টের তথ্য থাকে। এটি অত্যন্ত সুরক্ষিত একটি ফাইল এবং শুধুমাত্র **অ্যাডমিন বা রুট ইউজাররাই এটি পড়তে পারে**।

**উদাহরণ:**

```text
htb-student:$y$j9T$3QSBB6CbHEu...SNIP...f8Ms:18955:0:99999:7:::

```

এই ফাইলে ৯টি ফিল্ড থাকে। এর মধ্যে সবচেয়ে গুরুত্বপূর্ণ হলো দ্বিতীয় ফিল্ডটি, যেখানে পাসওয়ার্ডের হ্যাশ থাকে।
যদি পাসওয়ার্ড ফিল্ডে `!` বা `*` থাকে, তার মানে হলো ওই ইউজার সাধারণ পাসওয়ার্ড দিয়ে লগইন করতে পারবে না (তবে SSH Key দিয়ে লগইন করতে পারে)।

**হ্যাশ চেনার উপায়:**
হ্যাশগুলো সাধারণত তিনটি অংশে ভাগ করা থাকে: `$<id>$<salt>$<hashed>`
প্রথম অংশটি অর্থাৎ `<id>` দেখে বোঝা যায় এটি কোন অ্যালগরিদম দিয়ে হ্যাশ করা হয়েছে।

| ID | ক্রিপ্টোগ্রাফিক হ্যাশ অ্যালগরিদম (Algorithm) |
| --- | --- |
| 1 | MD5 |
| 2a | Blowfish |
| 5 | SHA-256 |
| 6 | SHA-512 |
| sha1 | SHA1 |
| y / yescrypt | Yescrypt (বর্তমানে ডেবিয়ানে ডিফল্ট হিসেবে ব্যবহৃত হয়) |
| gy | Gost-yescrypt |
| 7 | Scrypt |

*হ্যাকাররা এই ID দেখেই বুঝতে পারে যে হ্যাশটি ক্র্যাক করার জন্য Hashcat বা John the Ripper-এ কোন মোড ব্যবহার করতে হবে।*

## ৪. Opasswd ফাইল (পুরানো পাসওয়ার্ডের স্টোররুম)

PAM মডিউল চাইলে ইউজারদের পুরানো পাসওয়ার্ড পুনরায় ব্যবহার করা থেকে আটকাতে পারে। এই পুরানো পাসওয়ার্ডের হ্যাশগুলো `/etc/security/opasswd` নামের একটি ফাইলে সেভ করা থাকে। এটি পড়ার জন্যও রুট পারমিশন লাগে।

**উদাহরণ:**

```text
cry0l1t3:1000:2:$1$HjFAfYTG$qNDkF0zJ3v8ylCOrKB0kt0,$1$kcUjWZJX$E9uMSmiQeRh4pAAgzuvkq1

```

এখানে খেয়াল করুন, হ্যাশগুলো `$1$` দিয়ে শুরু হয়েছে। টেবিল অনুযায়ী এর মানে হলো এগুলো MD5 হ্যাশ, যা খুব সহজেই ক্র্যাক করা যায়। মানুষ সাধারণত তাদের পুরানো পাসওয়ার্ডের সাথে মিল রেখেই নতুন পাসওয়ার্ড বানায়। তাই পুরানো পাসওয়ার্ড ক্র্যাক করতে পারলে ইউজারের বর্তমান পাসওয়ার্ড গেস করা হ্যাকারদের জন্য অনেক সহজ হয়ে যায়।

## ৫. Cracking Linux Credentials (লিনাক্স পাসওয়ার্ড ক্র্যাক করা)

যদি আপনি লিনাক্স সিস্টেমে কোনোভাবে রুট (root) অ্যাক্সেস পেয়ে যান, তবে আপনার প্রথম কাজ হবে সবার পাসওয়ার্ড হ্যাশগুলো বের করে অফলাইনে ক্র্যাক করা।

এর জন্য **John the Ripper (JtR)** এর সাথে থাকা `unshadow` নামের একটি টুল ব্যবহার করা হয়। এটি `/etc/passwd` এবং `/etc/shadow` ফাইল দুটিকে একীভূত (combine) করে একটি নতুন ফাইল বানায়, যা ক্র্যাক করা সহজ।

**ধাপ ১: ফাইলগুলো কপি করা**

```bash
sudo cp /etc/passwd /tmp/passwd.bak 
sudo cp /etc/shadow /tmp/shadow.bak 

```

**ধাপ ২: Unshadow টুলের মাধ্যমে একীভূত করা**

```bash
unshadow /tmp/passwd.bak /tmp/shadow.bak > /tmp/unshadowed.hashes

```

এই কমান্ডের ফলে `/tmp/unshadowed.hashes` নামের একটি ফাইল তৈরি হবে, যার ভেতর সবার ইউজারনেম এবং হ্যাশ একসাথে থাকবে।

**ধাপ ৩: Hashcat দিয়ে ক্র্যাক করা**
এবার এই ফাইলটি অ্যাটাকিং মেশিনে নিয়ে Hashcat বা JtR দিয়ে ক্র্যাক করা যাবে। (SHA-512 এর জন্য মোড ১৮০০ ব্যবহার করা হয়েছে)।

```bash
hashcat -m 1800 -a 0 /tmp/unshadowed.hashes rockyou.txt -o /tmp/unshadowed.cracked

```

ক্র্যাক সম্পন্ন হলে `/tmp/unshadowed.cracked` ফাইলে আপনি ইউজারদের আসল পাসওয়ার্ডগুলো (Clear-text) পেয়ে যাবেন!
