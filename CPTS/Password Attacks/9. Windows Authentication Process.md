## Windows Authentication Process

![](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/Auth_process1.png)

- **Local Security Authority (LSA)** is a protected Windows subsystem responsible for security.

### Windows Authentication Flow

```
User
   ↓
Winlogon
   ↓
LogonUI
   ↓
Credential Provider
   ↓
Authentication Package
   ↓
LSASS
```

Authentication can occur using:

- AD (Domain)
- SAM (Local)

### Winlogon

Starts the login screen (LogonUI), handles password changes, locking & unlocking the computer.

### LogonUI

Simply the graphical login screen.

### Credential Provider

Credential Providers are DLLs (COM objects) that collect login information.

### LSASS

**Local Security Authority Subsystem Service**

Heart of Windows authentication. It doesn't perform authentication alone.

It loads several DLLs called **authentication packages**:

- lsasrv.dll
- Msv1_0.dll
- Samsrv.dll
- Kerberos.dll
- Netlogon.dll
- Ntdsa.dll

### Winlogon Session

Modern Windows versions use **Credential Providers** instead of **GINA**.

### SAM Database

**Security Account Manager (SAM)**

- Stores local user accounts & password hashes.
- Stored in:

```
%SystemRoot%\System32\Config\SAM
```

(NTLM hashes)

Registry location:

```
HKLM\SAM
```

### Workgroup

Everything is local.

```
Computer → SAM DB
```

Authentication happens locally.

### Domain

Authentication is sent to the Domain Controller.

```
User → DC → NTDS.dit
```
(AD database. Every DC keeps its NTDS.dit synchronized with others through AD replication.)

The DC checks credentials stored in Active Directory.

**SYSKEY**

It encrypts the SAM database on disk.

# Credential Manager

![](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/authn_credman_credprov.png)

Lets Windows users save credentials for:

- Network shares
- Websites
- Applications

Instead of entering passwords repeatedly.

Stored in:

```
C:\Users\<username>\AppData\Local\Microsoft
```
