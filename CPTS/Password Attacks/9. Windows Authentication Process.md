# Windows Authentication Process - [LINK](https://academy.hackthebox.com/app/module/147/section/1313)

<img width="2480" height="1424" alt="image" src="https://github.com/user-attachments/assets/1dc8c6b0-a3d7-43f1-a98f-f9a3fa7653f1" />


উইন্ডোজ ক্লায়েন্ট অথেনটিকেশন প্রক্রিয়ায় অনেকগুলো মডিউল একসাথে কাজ করে, যেগুলো লগইন, ক্রেডেনশিয়াল সংগ্রহ এবং তা যাচাই করার দায়িত্ব পালন করে। উইন্ডোজের বিভিন্ন অথেনটিকেশন মেকানিজমের মধ্যে Kerberos অন্যতম জনপ্রিয় এবং জটিল একটি মেকানিজম। Local Security Authority (LSA) হলো একটি সুরক্ষিত সাবসিস্টেম যা ইউজারদের অথেনটিকেট করে, লোকাল লগইন ম্যানেজ করে এবং Security Identifiers (SIDs) এর সাথে ইউজারনেমের অনুবাদ (Translation) করে।

লগইন প্রক্রিয়ার বিভিন্ন ধাপ এবং কম্পোনেন্টগুলোর একটি ভিজ্যুয়াল ডায়াগ্রাম `image_a7e9a2.png` ফাইলে দেখানো হয়েছে।

লোকাল ইন্টারঅ্যাকটিভ লগইন মূলত কয়েকটি কম্পোনেন্টের সমন্বয়ে কাজ করে:

* WinLogon (লগইন প্রসেস)
* LogonUI (লগইন ইউজার ইন্টারফেস)
* Credential Providers
* LSASS (Local Security Authority Subsystem Service)
* Authentication Packages (এগুলো মূলত DLL ফাইল যা ভেরিফিকেশন করে, যেমন: Msv1_0.dll)
* SAM (Security Accounts Manager) অথবা Active Directory

**WinLogon** হলো একটি বিশ্বস্ত সিস্টেম প্রসেস যা সিকিউরিটি সম্পর্কিত ইউজার ইন্টারঅ্যাকশনগুলো ম্যানেজ করে। এর প্রধান কাজগুলো হলো:

* লগইনের সময় পাসওয়ার্ড চাওয়ার জন্য LogonUI চালু করা।
* পাসওয়ার্ড পরিবর্তনের কাজ সামলানো।
* ওয়ার্কস্টেশন লক (Lock) এবং আনলক (Unlock) করা।

WinLogon হলো একমাত্র প্রসেস যা কীবোর্ড থেকে লগইন রিকোয়েস্ট (Win32k.sys এর মাধ্যমে) গ্রহণ করে। ইউজারের দেওয়া ইউজারনেম ও পাসওয়ার্ড (ক্রেডেনশিয়াল) সংগ্রহ করার পর WinLogon সেটি ভেরিফাই করার জন্য LSASS এর কাছে পাঠিয়ে দেয়। ইউজারের ক্রেডেনশিয়াল ইনপুট থেকে শুরু করে ভেরিফিকেশন পর্যন্ত পুরো প্রক্রিয়ার ফ্লো `image_a7e99b.png` ফাইলে দেখা যায়।

## LSASS (Local Security Authority Subsystem Service)

LSASS অনেকগুলো মডিউল নিয়ে গঠিত এবং উইন্ডোজের সব ধরনের অথেনটিকেশন প্রসেস নিয়ন্ত্রণ করে। সিস্টেমে এর অবস্থান হলো: `%SystemRoot%\System32\Lsass.exe`।

এটি লোকাল সিকিউরিটি পলিসি প্রয়োগ করে, ইউজারদের ভেরিফাই করে এবং সিকিউরিটি অডিট লগগুলো Event Log-এ পাঠায়। সহজ কথায়, LSASS উইন্ডোজ অপারেটিং সিস্টেমের "গেটকিপার" বা পাহারাদার হিসেবে কাজ করে।

**Authentication Packages (অথেনটিকেশন প্যাকেজসমূহ):**

| প্যাকেজের নাম | বর্ণনা (Description) |
| --- | --- |
| **Lsasrv.dll** | এটি LSA সার্ভার সার্ভিস, যা সিকিউরিটি পলিসি প্রয়োগ করে এবং প্যাকেজ ম্যানেজার হিসেবে কাজ করে। এটি নির্ধারণ করে লগইনের জন্য NTLM নাকি Kerberos প্রোটোকল ব্যবহার করা হবে। |
| **Msv1_0.dll** | এটি লোকাল মেশিনে লগইনের জন্য ব্যবহৃত ডিফল্ট অথেনটিকেশন প্যাকেজ (যেখানে কাস্টম অথেনটিকেশনের প্রয়োজন হয় না)। |
| **Samsrv.dll** | Security Accounts Manager (SAM), যা লোকাল সিকিউরিটি অ্যাকাউন্টগুলো স্টোর করে এবং লোকাল পলিসি প্রয়োগ করে। |
| **Kerberos.dll** | Kerberos-বেজড অথেনটিকেশনের জন্য LSA দ্বারা লোড করা সিকিউরিটি প্যাকেজ। |
| **Netlogon.dll** | নেটওয়ার্ক-বেজড লগইন সার্ভিস। |
| **Ntdsa.dll** | Directory System Agent (DSA) যা Active Directory ডাটাবেস (ntds.dit) ম্যানেজ করে এবং LDAP কুয়েরি প্রসেস করে। এটি শুধুমাত্র Domain Controller মেশিনে লোড হয়। |

## SAM Database (Security Account Manager)

SAM হলো উইন্ডোজের একটি ডাটাবেস ফাইল যা ইউজারদের পাসওয়ার্ড বা ক্রেডেনশিয়াল সেভ করে রাখে। এটি লোকাল এবং রিমোট—উভয় ইউজারকেই অথেনটিকেট করতে ব্যবহৃত হয়। পাসওয়ার্ডগুলো সরাসরি টেক্সট হিসেবে না থেকে **LM** বা **NTLM হ্যাশ (Hash)** হিসেবে রেজিস্ট্রিতে সেভ থাকে।

* **অবস্থান:** `%SystemRoot%\system32\config\SAM`
* **মাউন্ট পয়েন্ট:** `HKLM\SAM`
* **অ্যাক্সেস:** এই ফাইলটি দেখতে বা অ্যাক্সেস করতে SYSTEM লেভেলের প্রিভিলেজ (সর্বোচ্চ ক্ষমতা) প্রয়োজন হয়।

উইন্ডোজ সিস্টেম দুই ধরনের পরিবেশে থাকতে পারে:

1. **Workgroup:** সিস্টেমটি যদি ওয়ার্কগ্রুপে থাকে, তবে এটি সম্পূর্ণ লোকালি SAM ডাটাবেস ব্যবহার করে ইউজারদের ভেরিফাই করে।
2. **Domain:** সিস্টেমটি যদি কোনো ডোমেইনের অধীনে থাকে, তবে Domain Controller (DC) এর Active Directory ডাটাবেস (`%SystemRoot%\ntds.dit`) থেকে ক্রেডেনশিয়াল ভেরিফাই করতে হয়।

**SYSKEY (অফলাইন প্রোটেকশন):**
SAM ডাটাবেস যাতে কেউ অফলাইনে ক্র্যাক করতে না পারে, সেজন্য Microsoft Windows NT 4.0 তে SYSKEY ফিচার নিয়ে আসে। এটি চালু থাকলে SAM ফাইলটি একটি সিস্টেম-জেনারেটেড কী (Key) দ্বারা আংশিকভাবে এনক্রিপ্ট করা থাকে।

## Credential Manager

<img width="749" height="716" alt="image" src="https://github.com/user-attachments/assets/74eb9f9e-9694-4082-adb2-00502965389b" />


Credential Manager হলো উইন্ডোজের একটি বিল্ট-ইন ফিচার যা বিভিন্ন নেটওয়ার্ক রিসোর্স, ওয়েবসাইট এবং অ্যাপ্লিকেশনের সেভ করা পাসওয়ার্ডগুলো ম্যানেজ করে। প্রতিটি ইউজারের পাসওয়ার্ড তার নিজস্ব প্রোফাইলের "Credential Locker" এ এনক্রিপ্ট করা অবস্থায় সেভ থাকে।

পাসওয়ার্ডগুলো সাধারণত নিচের লোকেশনে পাওয়া যায়:

```powershell
PS C:\Users\[Username]\AppData\Local\Microsoft\[Vault/Credentials]\

```

পেনিট্রেশন টেস্টিংয়ের সময় বিভিন্ন মেথড ব্যবহার করে এই সেভ করা পাসওয়ার্ডগুলো ডিক্রিপ্ট (Decrypt) করে বের করা সম্ভব।

## NTDS (NT Directory Services)

কর্পোরেট নেটওয়ার্ক পরিবেশে উইন্ডোজ সিস্টেমগুলো সাধারণত একটি Windows Domain-এর সাথে যুক্ত থাকে। এটি অ্যাডমিনিস্ট্রেটরদের জন্য পুরো অর্গানাইজেশনের সব সিস্টেমকে একটি নির্দিষ্ট জায়গা থেকে (Centralized) ম্যানেজ করার সুবিধা দেয়।

এই ধরনের পরিবেশে লগইন রিকোয়েস্টগুলো Active Directory ফরেস্টের Domain Controller (DC) এর কাছে পাঠানো হয়। প্রতিটি Domain Controller-এর কাছে **NTDS.dit** নামের একটি অত্যন্ত গুরুত্বপূর্ণ ডাটাবেস ফাইল থাকে।

**NTDS.dit** ডাটাবেসে মূলত নিচের তথ্যগুলো সেভ করা থাকে:

* User accounts (ইউজারদের নাম এবং তাদের পাসওয়ার্ড হ্যাশ)
* Group accounts (বিভিন্ন গ্রুপের তথ্য)
* Computer accounts (নেটওয়ার্কে যুক্ত কম্পিউটারের তথ্য)
* Group policy objects (সিকিউরিটি রুলস বা পলিসি)

অ্যাডভান্সড পেনিট্রেশন টেস্টিংয়ে, ডোমেইন কন্ট্রোলার কম্প্রোমাইজ করার পর হ্যাকারদের মূল লক্ষ্য থাকে এই NTDS.dit ফাইলটি থেকে সব ইউজারের পাসওয়ার্ড হ্যাশ বের করে আনা।
