## 1. DNS Overview

`DNS (Domain Name System)` domain name-কে IP address-এ resolve করে।

- **UDP/53:** সাধারণ DNS query-এর default transport।
- **TCP/53:** Zone transfer এবং বড় response-এর মতো ক্ষেত্রে ব্যবহৃত হয়।
- DNS enumeration করে organization-এর subdomain, nameserver, mail server এবং internal infrastructure সম্পর্কে তথ্য পাওয়া যায়।

Reference: [Cloudflare — What Is DNS?](https://www.cloudflare.com/learning/dns/what-is-dns/)

## 2. DNS Enumeration

প্রথমে Nmap দিয়ে DNS service ও version শনাক্ত করা যায়।

```bash
nmap -p53 -Pn -sV -sC 10.10.110.213
```

- `-p53` — Port 53 scan।
- `-Pn` — Host discovery skip করে scan করা।
- `-sV` — Service version detection।
- `-sC` — Default NSE scripts চালানো।

## 3. DNS Zone Transfer (AXFR)

`DNS Zone Transfer` হলো একটি DNS server থেকে অন্য server-এ zone-এর records copy করার প্রক্রিয়া। সাধারণত `TCP/53` ব্যবহৃত হয়।

যদি `allow-transfer` ভুলভাবে configured থাকে, unauthorized user zone-এর records পেতে পারে।

### dig দিয়ে Zone Transfer

```bash
dig AXFR @ns1.inlanefreight.htb inlanefreight.htb
```

Internal zone-ও পরীক্ষা করা যেতে পারে, যদি অনুমোদিত হয়।

Zone transfer থেকে পাওয়া যেতে পারে:
- Subdomain ও hostname
- IP address
- Admin, HR, support-এর মতো service names
- Internal infrastructure সম্পর্কে তথ্য

### Fierce

[Fierce](https://github.com/mschwager/fierce) DNS enumeration এবং zone transfer পরীক্ষা করার tool।

```bash
fierce --domain zonetransfer.me
```

## 4. Domain Takeover ও Subdomain Takeover

**Domain takeover:** Expired বা আর নিবন্ধিত নেই এমন domain register করে তার ওপর control নেওয়া।

**Subdomain takeover:** কোনো subdomain-এর DNS record এমন external service-এ point করে, যেটির resource আর বিদ্যমান নেই বা অন্য কেউ claim করতে পারে।

উদাহরণ:

```dns
sub.target.com. 60 IN CNAME anotherdomain.com.
```

যদি `anotherdomain.com`-এর resource অন্য কেউ claim করতে পারে এবং `target.com`-এর CNAME record অপরিবর্তিত থাকে, তাহলে `sub.target.com` takeover-এর ঝুঁকিতে থাকতে পারে।

### Subdomain Enumeration Tools

| Tool | কাজ |
|---|---|
| [Subfinder](https://github.com/projectdiscovery/subfinder) | Public sources ব্যবহার করে subdomain সংগ্রহ। |
| [Sublist3r](https://github.com/aboul3la/Sublist3r) | Subdomain enumeration ও wordlist-based discovery। |
| [Subbrute](https://github.com/TheRook/subbrute) | Custom resolver দিয়ে DNS brute forcing; internal testing-এও কাজে লাগে। |
| [DNSenum](https://github.com/fwaeytens/dnsenum) | DNS records, zone transfer ও subdomain enumeration। |

### Subfinder

```bash
subfinder -d inlanefreight.com -v
```

- `-d` — Target domain।
- `-v` — Verbose output।

### Subbrute

```bash
git clone https://github.com/TheRook/subbrute.git
cd subbrute

echo "ns1.inlanefreight.com" > ./resolvers.txt

./subbrute.py inlanefreight.com \
-s ./names.txt -r ./resolvers.txt
```

- `-s` — Subdomain candidates-এর wordlist।
- `-r` — DNS resolver list।

### CNAME পরীক্ষা

`host` বা `nslookup` দিয়ে subdomain-এর CNAME পরীক্ষা করা যায়।

```bash
host support.inlanefreight.com
```

উদাহরণ response:

```text
support.inlanefreight.com is an alias for inlanefreight.s3.amazonaws.com
```

যদি সংশ্লিষ্ট cloud resource না থাকে, তাহলে subdomain takeover-এর সম্ভাবনা থাকতে পারে। শুধু error দেখেই vulnerability নিশ্চিত করা যায় না; service-specific validation প্রয়োজন।

Reference: [Can I Take Over XYZ?](https://github.com/EdOverflow/can-i-take-over-xyz)

## 5. DNS Spoofing (DNS Cache Poisoning)

`DNS Spoofing` হলো legitimate DNS response-এর বদলে forged response দিয়ে user-কে ভুল IP address বা website-এ redirect করা।

সম্ভাব্য attack paths:
- `MITM (Man-in-the-Middle)` attack-এর মাধ্যমে DNS communication intercept করা।
- DNS server compromise করে records পরিবর্তন করা।
- Local network-এ forged DNS response পাঠানো।

### Local DNS Spoofing with Ettercap

[Ettercap](https://www.ettercap-project.org/) একটি network MITM tool, যা DNS spoofing-এর জন্যও ব্যবহার করা যায়।

প্রাসঙ্গিক configuration file:

```text
/etc/ettercap/etter.dns
```

উদাহরণ configuration:

```text
inlanefreight.com      A   192.168.225.110
*.inlanefreight.com    A   192.168.225.110
```

এখানে domain এবং এর subdomain-গুলোকে নির্দিষ্ট IP address-এ resolve করার mapping দেওয়া হয়েছে।

Source-এর lab workflow:
1. Ettercap দিয়ে local network-এর live hosts scan করা।
2. Victim-কে `Target1` এবং default gateway-কে `Target2` হিসেবে নির্ধারণ করা।
3. `Plugins > Manage Plugins` থেকে `dns_spoof` সক্রিয় করা।
4. Lab-এ victim-এর DNS resolution নির্ধারিত IP-তে যাচ্ছে কি না পরীক্ষা করা।

এই পরীক্ষা কেবল অনুমোদিত lab বা network-এ করা উচিত।

## 6. Quick Reference

| উদ্দেশ্য | Command / Tool |
|---|---|
| DNS service enumeration | `nmap -p53 -Pn -sV -sC TARGET_IP` |
| Zone transfer | `dig AXFR @DNS_SERVER DOMAIN` |
| DNS enumeration | `fierce --domain DOMAIN` |
| Subdomain discovery | `subfinder -d DOMAIN -v` |
| CNAME lookup | `host SUBDOMAIN` |
| Custom resolver দিয়ে brute force | `subbrute.py DOMAIN -s WORDLIST -r RESOLVERS` |
| Local DNS spoofing | Ettercap + `dns_spoof` plugin |

## Key Takeaways

- DNS enumeration থেকে subdomain, IP address ও internal hostname পাওয়া যায়।
- Misconfigured `AXFR` zone transfer সম্পূর্ণ DNS zone-এর তথ্য প্রকাশ করতে পারে।
- Expired external resources-এর দিকে থাকা CNAME records subdomain takeover-এর ঝুঁকি তৈরি করতে পারে।
- DNS spoofing forged DNS response ব্যবহার করে traffic redirect করতে পারে।
- Pentest-এ সব পরীক্ষা নির্ধারিত scope ও অনুমতি অনুযায়ী করতে হবে।
