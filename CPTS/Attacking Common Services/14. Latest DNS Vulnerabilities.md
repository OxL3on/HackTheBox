## 1. Subdomain Takeover

`Subdomain Takeover` হলো এমন একটি vulnerability, যেখানে কোনো subdomain-এর DNS record একটি third-party service বা domain-এ point করে, কিন্তু সেই resource আর বিদ্যমান নেই বা অন্য কেউ register করতে পারে।

### কেন হয়?

- Company AWS, GitHub বা অন্য third-party service ব্যবহার করে।
- পরে service বাতিল করলেও DNS-এর `CNAME` record মুছে ফেলে না।
- Third-party resource আর claim করা না থাকলে attacker সেটি নিজের control-এ নিতে পারে।
- ফলে attacker company-এর legitimate subdomain-এর content নিয়ন্ত্রণ করতে পারে।

Reference: [HackerOne](https://www.hackerone.com/)

## 2. Attack Concept

ধরা যাক, company-এর DNS-এ এমন একটি record রয়েছে:

```
customer-drive.inlanefreight.com. 60 IN CNAME abandoned-resource.example.com.
```

যদি `abandoned-resource.example.com`-এর সংশ্লিষ্ট third-party resource মুছে ফেলা হয় এবং সেটি অন্য কেউ register করতে পারে, তাহলে takeover-এর সম্ভাবনা তৈরি হয়।

**Attack flow:**

1. **Source:** Company-এর পুরোনো subdomain ও `CNAME` record শনাক্ত করা।
2. **Process:** Third-party provider-এ সংশ্লিষ্ট resource আর বিদ্যমান নেই কি না যাচাই করা।
3. **Privileges:** মূল domain-এর DNS record company-এর নিয়ন্ত্রণে থাকে; attacker সাধারণত সেটি পরিবর্তন করতে পারে না।
4. **Destination:** Provider-এর resource claim করা সম্ভব হলে subdomain-এর traffic attacker-controlled content-এ পৌঁছাতে পারে।

### Trigger the Forwarding

| Step | Category      | কী ঘটে                                                                                              |
| ---- | ------------- | --------------------------------------------------------------------------------------------------- |
| 5    | `Source`      | Visitor পুরোনো subdomain-এ request পাঠায়।                                                           |
| 6    | `Process`     | DNS-এর পুরোনো `CNAME` record ব্যবহার করে destination resolve হয়।                                    |
| 7    | `Privileges`  | DNS record-টি domain owner-এর নিয়ন্ত্রণে থাকলেও stale record visitor-কে ভুল resource-এ পাঠাতে পারে। |
| 8    | `Destination` | Visitor attacker-controlled resource-এ পৌঁছাতে পারে।                                                |

এই attack-এর জন্য মূল domain-এর DNS পরিবর্তন করার প্রয়োজন নাও হতে পারে; stale `CNAME` record-টিই ঝুঁকির কারণ হতে পারে।

## 3. Subdomain Takeover শনাক্তকরণ

1. `Subfinder` বা অন্যান্য enumeration tools দিয়ে subdomain সংগ্রহ করা।
2. `CNAME` record পরীক্ষা করা।
3. Record যে third-party service-এ point করে, সেখানে resource এখনও আছে কি না যাচাই করা।
4. `HTTP 404` বা provider-specific error দেখা গেলে সম্ভাব্য misconfiguration হিসেবে তদন্ত করা।
5. Resource claim করা সম্ভব কি না এবং takeover সত্যিই সম্ভব কি না যাচাই করা।

**গুরুত্বপূর্ণ:** শুধু `HTTP 404` দেখলেই takeover নিশ্চিত হয় না। Resource-টি অন্য কেউ register করতে পারে কি না এবং provider-এর শর্ত কী, তা যাচাই করতে হবে।

Reference: [Can I Take Over XYZ?](https://github.com/EdOverflow/can-i-take-over-xyz)

## 4. সম্ভাব্য Impact

Subdomain takeover ব্যবহার করে attacker:

- **Phishing:** Legitimate company domain-এর subdomain ব্যবহার করে fake login page তৈরি করতে পারে।
- **Cookie Theft:** দুর্বল cookie configuration থাকলে session cookie চুরির ঝুঁকি তৈরি হতে পারে।
- **CSRF:** Cross-Site Request Forgery attack-এর সুযোগ তৈরি হতে পারে।
- **CORS Abuse:** ভুল CORS configuration কাজে লাগানো হতে পারে।
- **CSP Bypass:** Content Security Policy-এর কিছু সুরক্ষা দুর্বল হতে পারে।

এসব impact-এর জন্য অতিরিক্ত configuration বা security weakness প্রয়োজন হতে পারে; প্রতিটি takeover-এ সব impact সম্ভব নয়।

## Key Takeaways

- পুরোনো `CNAME` record subdomain takeover-এর সাধারণ কারণ।
- Third-party resource বাতিল করার সময় সংশ্লিষ্ট DNS record-ও পরিষ্কার করতে হবে।
- `404` বা provider error সম্ভাব্য clue, vulnerability-এর চূড়ান্ত প্রমাণ নয়।
- সফল takeover company-এর domain reputation ও users-এর নিরাপত্তার জন্য ঝুঁকি তৈরি করতে পারে।
- Pentest বা bug bounty testing অবশ্যই অনুমোদিত scope-এর মধ্যে করতে হবে।
