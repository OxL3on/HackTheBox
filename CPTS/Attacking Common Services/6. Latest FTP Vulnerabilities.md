# Latest FTP Vulnerabilities - [LINK](https://academy.hackthebox.com/app/module/116/section/1166)


## Introduction (ভূমিকা)

সাম্প্রতিক ভালনারেবিলিটি বা দুর্বলতাগুলো নিয়ে আলোচনা করার জন্য আমরা এই সেকশনে একটি সুনির্দিষ্ট অ্যাটাকের ওপর ফোকাস করব। খুব বেশি টেকনিক্যাল জটিলতায় না গিয়ে, একটি নির্দিষ্ট সার্ভিসের উদাহরণের মাধ্যমে অ্যাটাকের মূল কনসেপ্টটি (concept of the attack) সহজভাবে বোঝার চেষ্টা করব।

এখানে আমরা **CoreFTP (build 727 এর পূর্ববর্তী ভার্সন)** এর একটি ভালনারেবিলিটি নিয়ে আলোচনা করব, যার নাম দেওয়া হয়েছে **CVE-2022-22836**।

### সহজ কথায় এই দুর্বলতাটি কী?

এটি মূলত FTP সার্ভিসের এমন একটি দুর্বলতা যেখানে সার্ভিসটি `HTTP PUT` রিকোয়েস্টকে সঠিকভাবে প্রসেস করতে পারে না। এর ফলে দুটি বড় সিকিউরিটি ইস্যু তৈরি হয়:

1. **Authenticated Directory/Path Traversal:** ইউজার অথেনটিকেট করার পর ডিরেক্টরি ট্রাভার্সাল করে মূল ফোল্ডারের বাইরে চলে যেতে পারে।
2. **Arbitrary File Write:** সার্ভিসের যতটুকু ফোল্ডারের অ্যাক্সেস দেওয়ার কথা, আমরা তার বাইরের ফোল্ডারেও নিজেদের ইচ্ছেমতো ফাইল লিখতে (write) বা তৈরি করতে পারি।

## The Concept of the Attack (অ্যাটাকের মূল ধারণা)

সাধারণত এই FTP সার্ভিসটি ফাইল আপলোডের জন্য `HTTP POST` রিকোয়েস্ট ব্যবহার করে থাকে। কিন্তু সমস্যা হলো, CoreFTP সার্ভিসটি `HTTP PUT` রিকোয়েস্টও গ্রহণ করে (allow করে), যা ব্যবহার করে আমরা ফাইলে কন্টেন্ট লিখতে পারি।

চলুন আমাদের কনসেপ্টের ওপর ভিত্তি করে এই অ্যাটাকটি কীভাবে কাজ করে তা দেখে নেওয়া যাক। এই অ্যাটাকের এক্সপ্লয়েট (exploit) খুবই সোজা, এর জন্য শুধুমাত্র একটি `cURL` কমান্ডের প্রয়োজন হয়।

### CoreFTP Exploitation

```bash
00Luffy00@htb[/htb]$ curl -k -X PUT -H "Host: <IP>" --basic -u <username>:<password> --data-binary "PoC." --path-as-is https://<IP>/../../../../../../whoops

```

### কমান্ডটির সহজ ব্যাখ্যা:

এখানে আমরা একটি raw `HTTP PUT` রিকোয়েস্ট তৈরি করছি। কমান্ডের প্রতিটি অংশের কাজ নিচে দেওয়া হলো:

| অংশ (Flag / Option) | এর কাজ কী? |
| --- | --- |
| `curl` | এটি কমান্ড-লাইন টুল যা দিয়ে সার্ভারে ডেটা ট্রান্সফার বা রিকোয়েস্ট পাঠানো হয়। |
| `-k` | ইনসিকিউর (insecure) SSL কানেকশন অ্যালাউ করে (সার্টিফিকেট ভেরিফিকেশন ইগনোর করে)। |
| `-X PUT` | রিকোয়েস্টের ধরন হিসেবে `PUT` মেথড নির্দিষ্ট করে দেয়। |
| `-H "Host: <IP>"` | Host হেডার যুক্ত করে, যেখানে আমাদের টার্গেট সিস্টেমের IP অ্যাড্রেস দেওয়া থাকে। |
| `--basic -u <username>:<password>` | Basic Authentication ব্যবহার করে ইউজারনেম এবং পাসওয়ার্ড দিয়ে লগইন করে। |
| `--data-binary "PoC."` | ফাইলে যে কন্টেন্ট বা ডেটা লেখা হবে তা নির্দিষ্ট করে (এখানে "PoC." লেখা হবে)। |
| `--path-as-is` | এটি curl-কে নির্দেশ দেয় যে URL-এ দেওয়া পাথটি কোনো পরিবর্তন ছাড়া হুবহু পাঠাতে হবে (যাতে `../` ডট-ডট-স্ল্যাশ গুলো কাজ করে)। |
| `https://<IP>/../../../../../../whoops` | এটি হলো টার্গেট ফাইলের পাথ। `../` ব্যবহার করে আমরা রেস্ট্রিক্টেড ডিরেক্টরি থেকে বের হয়ে `whoops` নামের একটি ফাইল তৈরি করছি। |

## The Concept of Attacks (অ্যাটাক বিশ্লেষণ)

[cite: 8]

সংক্ষেপে বলতে গেলে, অ্যাটাকের মূল কারণ হলো প্রসেসটি ইউজারের দেওয়া ইনপুট পাথটিকে (path) ভুলভাবে ব্যাখ্যা (misinterpret) করে। এর ফলে অ্যাপ্লিকেশন যে ফোল্ডারে ইউজারকে আটকে রাখতে চায় (restricted folder), সেটি সহজেই বাইপাস (bypass) হয়ে যায়।

যেহেতু `HTTP PUT` রিকোয়েস্টের ওপর রাইট পারমিশনগুলো (write permissions) ঠিকমতো কন্ট্রোল করা থাকে না, তাই আমরা অনুমোদিত ফোল্ডারের বাইরে গিয়ে আমাদের ইচ্ছেমতো ফাইল তৈরি করতে পারি। (এখানে Basic Auth প্রসেসের ব্যাখ্যাটি বাদ দিয়ে সরাসরি এক্সপ্লয়েটের মূল অংশে ফোকাস করা হয়েছে)।

অ্যাটাকের এই সম্পূর্ণ প্রক্রিয়াটিকে দুটি ধাপে ভাগ করা যায়:

### 1. Directory Traversal (ডিরেক্টরি ট্রাভার্সাল)

প্রথম ধাপে আমরা অ্যাপ্লিকেশনের দেওয়া সীমানা বা রেস্ট্রিকশন ভেঙে বাইরে বের হই।

| Step | Directory Traversal (বিবরণ) | Concept of Attacks - Category |
| --- | --- | --- |
| **1.** | ইউজার HTTP রিকোয়েস্টের ধরন, ফাইলের কন্টেন্ট এবং রেস্ট্রিক্টেড এরিয়া থেকে বের হওয়ার জন্য এস্কেপিং ক্যারেক্টার (escaping characters - যেমন `../`) নির্দিষ্ট করে দেয়। | **Source** |
| **2.** | ইউজারের দেওয়া এই পরিবর্তিত HTTP রিকোয়েস্ট, ফাইলের কন্টেন্ট এবং পাথটি প্রসেস দ্বারা গ্রহণ এবং প্রসেস করা হয়। | **Process** |
| **3.** | অ্যাপ্লিকেশন চেক করে যে ইউজারের ওই নির্দিষ্ট পাথে যাওয়ার অনুমতি আছে কি না। যেহেতু রেস্ট্রিকশনগুলো শুধুমাত্র একটি নির্দিষ্ট ফোল্ডারের জন্য প্রযোজ্য ছিল, তাই ডিরেক্টরি ট্রাভার্সাল ব্যবহার করে ওই ফোল্ডার থেকে বের হয়ে যাওয়ার কারণে পারমিশন চেকিং বাইপাস হয়ে যায়। | **Privileges** |
| **4.** | ডেস্টিনেশন হলো অন্য আরেকটি প্রসেস, যার কাজ হলো ইউজারের দেওয়া কন্টেন্টগুলো লোকাল সিস্টেমে রাইট (write) করা। | **Destination** |

এই পর্যায় পর্যন্ত আমরা এস্কেপিং ক্যারেক্টার (`../../../../`) ব্যবহার করে অ্যাপ্লিকেশনের দেওয়া সীমাবদ্ধতা বাইপাস করেছি। এরপর আমরা দ্বিতীয় ধাপে চলে আসি, যেখানে প্রসেসটি আমাদের দেওয়া কন্টেন্ট একটি নির্দিষ্ট ফাইলে রাইট করে। এখান থেকে সাইকেলটি আবার শুরু হয়, তবে এবার উদ্দেশ্য হলো টার্গেট সিস্টেমে কন্টেন্ট রাইট করা।

### 2. Arbitrary File Write (ইচ্ছেমতো ফাইল রাইট করা)

| Step | Arbitrary File Write (বিবরণ) | Concept of Attacks - Category |
| --- | --- | --- |
| **5.** | ইউজার যে তথ্যগুলো ইনপুট দিয়েছিল, সেগুলোকেই সোর্স হিসেবে ব্যবহার করা হয়। এক্ষেত্রে ফাইলের নাম (`whoops`) এবং কন্টেন্ট (`--data-binary "PoC."`)। | **Source** |
| **6.** | প্রসেসটি এই তথ্যগুলো নেয় এবং নির্দিষ্ট ফাইলে কাঙ্ক্ষিত কন্টেন্ট লেখার কাজ শুরু করে। | **Process** |
| **7.** | যেহেতু ডিরেক্টরি ট্রাভার্সাল দুর্বলতার সময় সমস্ত রেস্ট্রিকশন বা সীমাবদ্ধতা বাইপাস করা হয়েছিল, তাই সার্ভিসটি নির্দিষ্ট ফাইলে কন্টেন্ট রাইট করার পারমিশন অ্যাপ্রুভ (approve) করে দেয়। | **Privileges** |
| **8.** | ইউজারের দেওয়া ফাইলের নাম (`whoops`) এবং এর ভেতরে থাকা কাঙ্ক্ষিত কন্টেন্ট (`"PoC."`) এখন লোকাল সিস্টেমে ডেস্টিনেশন হিসেবে কাজ করে। | **Destination** |

টাস্কটি সফলভাবে সম্পন্ন হওয়ার পর, আমরা টার্গেট সিস্টেমে আমাদের তৈরি করা ফাইলটি এর ভেতরের কন্টেন্টসহ খুঁজে পাব।

### Target System (ফলাফল যাচাই)

আমরা Windows-এর `type` কমান্ড (যা ফাইলের ভেতরের লেখা দেখায়) ব্যবহার করে চেক করতে পারি ফাইলটি ঠিকমতো তৈরি হয়েছে কি না।

```cmd
C:\> type C:\whoops

PoC.

```

**ব্যাখ্যা:** এই কমান্ডটি `C:\` ড্রাইভের ভেতরে থাকা `whoops` ফাইলের কন্টেন্ট প্রিন্ট করেছে, যা হলো `PoC.`। এর মানে আমাদের এক্সপ্লয়েট সফল হয়েছে এবং আমরা সিস্টেমের রুটে (root) ইচ্ছেমতো ফাইল তৈরি করতে পেরেছি।
