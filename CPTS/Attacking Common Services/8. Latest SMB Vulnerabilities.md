## 1. SMBGhost (CVE-2020-0796)

SMBGhost হলো SMB v3.1.1-এর compression mechanism-সংক্রান্ত একটি vulnerability। এটি Windows 10 version 1903 ও 1909-কে প্রভাবিত করেছিল।

- Vulnerability: CVE-2020-0796
- মূল কারণ: Integer Overflow এবং যথাযথ bounds checking-এর অভাব।
- আক্রমণকারী: Authentication ছাড়াই দূর থেকে আক্রমণ করতে পারত।
- সম্ভাব্য প্রভাব: Remote Code Execution (RCE) এবং target system-এ উচ্চ privilege-এ access।

## 2. Integer Overflow কী?

Integer Overflow ঘটে যখন কোনো arithmetic operation-এর ফলাফল নির্দিষ্ট integer variable-এর ধারণক্ষমতার বাইরে চলে যায়। এতে ভুল value তৈরি হতে পারে, যার ফলে program-এর আচরণ অপ্রত্যাশিত হয়ে যায়।

SMBGhost-এর ক্ষেত্রে, SMB driver-এর একটি function-এ পাঠানো data-এর size সঠিকভাবে যাচাই করা হতো না। ফলে অতিরিক্ত data process করার সময় memory buffer-এর সীমা অতিক্রম করে পরবর্তী memory content overwrite হতে পারত।

- Bounds Checking: Data নির্ধারিত memory limit-এর মধ্যে আছে কি না, তা যাচাই করা।
- Buffer Overwrite: Buffer-এর নির্ধারিত সীমার বাইরে data লিখে পাশের memory content পরিবর্তন করা।
- RCE: Remote system-এ নিজের পছন্দমতো code execute করাতে পারা।

## 3. Attack Concept

Attack flow: Source → Processes → Privileges → Destination

| ধাপ         | অর্থ                         | উদাহরণ                                           |
| ----------- | ---------------------------- | ------------------------------------------------ |
| Source      | Data বা input কোথা থেকে আসে  | Code, libraries, configuration, user input       |
| Processes   | Input কীভাবে process হয়     | PID, input, data processing, variables, logging  |
| Privileges  | Process কোন permission-এ চলে | System, user, groups, policies, rules            |
| Destination | Process-এর ফলাফল কোথায় যায় | Local files/processes অথবা network address/route |

এই চারটি অংশ ব্যবহার করে বোঝা যায়, একটি vulnerability কীভাবে input থেকে শুরু হয়ে privilege ব্যবহার করে target resource পর্যন্ত প্রভাব ফেলতে পারে।

## 4. SMBGhost কীভাবে কাজ করেছিল?

SMB communication-এ client ও server প্রথমে `Negotiate Protocol` ধাপের মাধ্যমে communication parameters নির্ধারণ করে। এরপর malformed compressed message process করার সময় vulnerability trigger হতে পারত।

1. Source: Attacker SMB server-এ specially crafted request পাঠায়।
2. Process: Server negotiated protocol অনুযায়ী compressed packet process করে।
3. Privileges: Vulnerable process SMB server-এর privileges-এ চলে—এই ক্ষেত্রে system বা administrator-level privilege থাকতে পারে।
4. Destination: Local process-এর memory-তে buffer overwrite ঘটে।
5. RCE: Integer overflow-এর কারণে memory corruption হলে attacker-এর নিয়ন্ত্রিত data program execution-কে প্রভাবিত করতে পারে।
6. Access: সফল exploitation হলে attacker remote system-এ code execute করতে পারে।

SMB সাধারণত TCP port `445` ব্যবহার করে। SMB compression সমর্থিত থাকা এবং vulnerable implementation ব্যবহার করা এই attack-এর গুরুত্বপূর্ণ শর্ত ছিল।

## 5. Attack-এর দুটি Cycle

| ধাপ             | প্রথম Cycle: Attack Initiation       | দ্বিতীয় Cycle: RCE Trigger                         |
| --------------- | ------------------------------------ | --------------------------------------------------- |
| 1 — Source      | Attacker manipulated request পাঠায়  | আগের process থেকে তৈরি হওয়া data ব্যবহৃত হয়       |
| 2 — Process     | Compressed packet process হয়        | Integer overflow ও buffer overwrite ঘটে             |
| 3 — Privileges  | SMB server-এর privileges ব্যবহৃত হয় | একই process privilege ব্যবহৃত হয়                   |
| 4 — Destination | Local process packet process করে     | Attacker remote system থেকে target access পেতে পারে |

দ্বিতীয় cycle-এ memory corruption-কে কাজে লাগিয়ে CPU-কে স্বাভাবিক execution flow থেকে সরিয়ে attacker-এর নির্দেশনা execute করানোর চেষ্টা করা হয়।

মনে রাখবে: Vulnerability থাকলেই RCE নিশ্চিত নয়। সফল exploitation নির্ভর করে target-এর version, configuration, memory layout এবং exploit-এর কার্যকারিতার ওপর।
