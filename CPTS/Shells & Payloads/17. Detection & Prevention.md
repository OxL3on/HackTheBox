**MITRE ATT&CK Framework Mapping**

| Tactic | Description |
| --- | --- |
| **Initial Access** | Compromising public-facing services (web apps, misconfigured SMB) or exploiting bugs to gain a foothold. |
| **Execution** | Running malicious code on the victim host (e.g., executing web shells, PowerShell one-liners, or exploit payloads). |
| **Command & Control (C2)** | Maintaining access by communicating with the victim host. Attackers often blend into standard ports (HTTP/S, DNS, third-party apps like Slack) or use default payload ports (e.g., 4444). |

**Key Indicators of Compromise (IoCs) to Monitor**

* **Malicious File Uploads:** Monitor web application logs for unauthorized script uploads (PHP, ASPX, JSP) bypassing normal filters.
* **Anomalous User Behavior:** Standard users interacting with CLI environments (`cmd.exe`, `/bin/bash`), running enumeration commands (e.g., `whoami`), or accessing non-standard infrastructure SMB shares. Enable PowerShell logging to catch obfuscated execution.
* **Suspicious Network Sessions:** Unusual baseline deviations, such as bulk GET/POST requests, remote login attempts, or steady heartbeat traffic to unknown external IPs.

**Network Visibility & Deep Packet Inspection**

You cannot defend what you cannot see. Establish a baseline of normal traffic using visual network topologies and Layer 7 network controllers. Deep Packet Inspection (DPI) acts as a network-level antivirus—it can intercept, flag, and block unencrypted reverse shell traffic (like a standard Netcat session) by reading the clear-text commands being transmitted over the wire.

**Core Mitigation Strategies**

* **Application Sandboxing:** Isolates public-facing applications so a compromised web shell cannot easily pivot to the underlying host operating system.
* **Least Privilege:** Ensure users and service accounts (such as the web server daemon) only possess the absolute minimum permissions necessary to function.
* **Network Segmentation (DMZ):** Quarantine internet-facing assets (web servers, VPNs) away from the internal network to physically prevent lateral movement.
* **Strict Egress Firewalls:** Restrict outbound firewall rules. If a server cannot initiate an outbound connection to the internet, traditional reverse shells will fail.
* **Endpoint Hardening:** Enforce rapid patch management, maintain active AV/EDR (like Windows Defender with all profiles enabled), and apply STIG configuration guides.
