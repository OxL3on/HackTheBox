# Communication with Processes

## 1. Processes থেকে Privilege Escalation

Running process privilege escalation-এর গুরুত্বপূর্ণ জায়গা।

- IIS বা XAMPP-এর মতো web server খুঁজে পেলে সেখানে `aspx/php` shell upload করে web server-এর user হিসেবে shell পাওয়া যেতে পারে।
- এই user সাধারণত Administrator নয়, তবে তার `SeImpersonate` token থাকতে পারে।
- এটি ব্যবহার করে `Rogue Potato`, `Juicy Potato` বা `Lonely Potato` দিয়ে `SYSTEM` privilege পাওয়া সম্ভব।

## 2. Access Tokens

- Windows-এর Access Token কোনো process বা thread-এর security context নির্ধারণ করে।
- এতে user identity ও privilege সম্পর্কিত তথ্য থাকে।
- User authentication সফল হলে তাকে একটি access token দেওয়া হয়।
- User কোনো process-এর সঙ্গে interact করলে সেই token-এর copy ব্যবহার করে তার privilege level নির্ধারণ করা হয়।

Reference: [Windows Access Tokens](https://docs.microsoft.com/en-us/windows/win32/secauthz/access-tokens?utm_source=chatgpt.com)

## 3. Enumerating Network Services

Process একে অপরের সঙ্গে DNS, HTTP, SMB ইত্যাদি network socket দিয়ে communicate করে।

`netstat` দিয়ে active TCP/UDP connection ও listening port দেখা যায়। কিছু vulnerable service শুধু localhost-এ accessible হতে পারে, যা privilege escalation-এর সুযোগ তৈরি করে।

### কী খুঁজবে?

বিশেষ করে loopback address-এ listening service:

- `127.0.0.1`
- `::1`

এগুলো network IP (`10.129.43.8`) বা `0.0.0.0`, `::/0`-এ listen না করলেও localhost থেকে access করা যায়।

এই উদাহরণে গুরুত্বপূর্ণ port: `14147`

- এটি FileZilla-এর administrative interface।
- এই port-এ connect করলে FTP password পাওয়া এবং FileZilla Server user-এর permission-এ `C:\`-তে FTP Share তৈরি করা সম্ভব হতে পারে।
- Server user Administrator হলে আরও বেশি privilege পাওয়া যেতে পারে।

## 4. Named Pipes

Named Pipe হলো memory-তে থাকা file-এর মতো communication channel, যা read হওয়ার পর clear হয়ে যায়।

- দুটি application বা process-এর মধ্যে shared memory ব্যবহার করে communication হয়।
- দুই ধরনের pipe: Named Pipe ও Anonymous Pipe।
- Windows-এ সাধারণত client-server implementation ব্যবহার হয়।
- Pipe তৈরি করা process হলো Server; যে process communicate করে সেটি Client।

### Named Pipe-এর Communication

Named Pipe-এর উদাহরণ:

```
\\.\PipeName\ExampleNamedPipeServer
```

দুই ধরনের communication:

| Type        | কাজ                                                           |
| ----------- | ------------------------------------------------------------- |
| Half-duplex | একদিকে communication; Client শুধু Server-এ data পাঠায়         |
| Duplex      | দুইদিকে communication; Client ও Server উভয়েই data পাঠাতে পারে |

একটি Named Pipe-এর একাধিক simultaneous instance থাকতে পারে। প্রতিটি client connection আলাদা data buffer ব্যবহার করে।

### Cobalt Strike Example

Cobalt Strike প্রতিটি command-এর জন্য Named Pipe ব্যবহার করে (BOF ছাড়া)।

Workflow:

1. Beacon Named Pipe তৈরি করে: `\\.\pipe\msagent_12`
2. নতুন process চালু করে এবং command-এর output ওই pipe-এ পাঠায়।
3. Server pipe থেকে output দেখায়।

এতে command antivirus-এ ধরা পড়লে বা crash করলেও Beacon process প্রভাবিত হয় না।

Cobalt Strike user-রা অনেক সময় Named Pipe-এর নাম অন্য program-এর মতো রাখে। যেমন `msagent`-এর বদলে `mojo` ব্যবহার করে Chrome-এর মতো দেখানো। Chrome installed না থাকা computer-এ `mojo` pipe পাওয়া suspicious হতে পারে।

### Named Pipe Permissions

Named Pipe-এর permission দেখতে Accesschk ব্যবহার করা যায়।

- Accesschk দিয়ে DACL (Discretionary Access Control List) দেখা যায়।
- DACL থেকে কে resource read, write, modify বা execute করতে পারবে তা জানা যায়।

Reference: [Accesschk](https://docs.microsoft.com/en-us/sysinternals/downloads/accesschk?utm_source=chatgpt.com)

সব Named Pipe-এর permission দেখতে:

```
.\accesschk.exe /accepteula \pipe\
```

## 5. Named Pipes Attack Example

উদাহরণ: [WindscribeService Named Pipe Privilege Escalation](https://www.exploit-db.com/exploits/48021?utm_source=chatgpt.com)

সব Named Pipe-এ write permission খুঁজতে:

```
accesschk.exe -w \pipe\* -v
```

এতে `WindscribeService` Named Pipe-এ `Everyone` group-এর `READ` ও `WRITE` access পাওয়া যায়।

`Everyone` এখানে সব authenticated user-কে বোঝায়।

### Permission Check

```
accesschk.exe -accepteula -w \pipe\WindscribeService -v
```

Output:

```
Accesschk v6.13 - Reports effective permissions for securable objects
Copyright ⌐ 2006-2020 Mark Russinovich
Sysinternals - www.sysinternals.com

\\.\Pipe\WindscribeService
  Medium Mandatory Level (Default) [No-Write-Up]
  RW Everyone
        FILE_ALL_ACCESS
```

`Everyone` group-এর `FILE_ALL_ACCESS` রয়েছে। এই দুর্বল permission কাজে লাগিয়ে host-এ `SYSTEM` privilege পাওয়া সম্ভব।

মনে রাখবে: Privilege escalation-এর জন্য শুধু user ও group নয়, running process, localhost-only network service এবং Named Pipe-এর permission-ও enumerate করতে হবে।
