# Communication with Processes

## 1. মূল ধারণা

Running process থেকে Privilege Escalation-এর সুযোগ পাওয়া যায়।

উদাহরণ: IIS/XAMPP web server পেলে `aspx/php` shell upload করে web server user হিসেবে shell পাওয়া যায়। এই user admin না হলেও `SeImpersonate` token থাকতে পারে, যা দিয়ে `Rogue/Juicy/Lonely Potato` ব্যবহার করে SYSTEM permission পাওয়া সম্ভব।

## 2. Access Tokens

[Access Tokens](https://docs.microsoft.com/en-us/windows/win32/secauthz/access-tokens?utm_source=chatgpt.com)

- Windows-এ Access Token কোনো process/thread-এর security context নির্ধারণ করে।
- এতে user identity ও privileges থাকে।
- Authentication সফল হলে user-কে token দেওয়া হয়।
- User কোনো process-এর সঙ্গে interact করলে token-এর copy দিয়ে তার privilege level নির্ধারণ করা হয়।

## 3. Enumerating Network Services

Process-এর সঙ্গে যোগাযোগের সাধারণ উপায় হলো network socket (DNS, HTTP, SMB ইত্যাদি)।

[netstat](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/netstat?utm_source=chatgpt.com) দিয়ে active TCP/UDP connection এবং listening port দেখা যায়। Localhost-এ থাকা vulnerable service থেকেও privilege escalation সম্ভব।

## 4. Named Pipes

Process-গুলোর মধ্যে যোগাযোগের আরেকটি উপায় হলো Named Pipes।

- Pipe হলো memory-তে থাকা file; read হওয়ার পর clear হয়ে যায়।
- Cobalt Strike প্রতিটি command-এর জন্য Named Pipe ব্যবহার করে, [BOF](https://www.cobaltstrike.com/help-beacon-object-files?utm_source=chatgpt.com) ছাড়া।

### Cobalt Strike Workflow

1. Beacon `\\.\pipe\msagent_12` নামে pipe তৈরি করে।
2. নতুন process চালু করে এবং command inject করে; output pipe-এ পাঠায়।
3. Server pipe-এর output দেখায়।

Command antivirus-এ detect বা crash হলেও Beacon process প্রভাবিত হয় না।

Cobalt Strike user-রা অন্য program-এর মতো দেখানোর জন্য pipe name পরিবর্তন করে। যেমন `msagent`-এর বদলে `mojo`। একবার Chrome install না থাকা computer-এ `mojo` pipe পাওয়া গিয়েছিল; পরে জানা যায় এটি company-এর internal red team।

### More on Named Pipes

[Named Pipes Documentation](https://docs.microsoft.com/en-us/windows/win32/ipc/named-pipes?utm_source=chatgpt.com)

- Pipe shared memory দিয়ে দুই application/process-এর মধ্যে communication করে।
- দুই ধরনের pipe: Named ও Anonymous।
- উদাহরণ: `\\.\PipeName\\ExampleNamedPipeServer`
- Pipe তৈরি করা process হলো Server, আর connect করা process হলো Client।
- `half-duplex` → একমুখী communication; Client শুধু Server-এ data পাঠাতে পারে।
- `duplex` → দুইমুখী communication; Client ও Server উভয়েই data পাঠাতে পারে।
- একই Named Pipe-এর একাধিক instance থাকতে পারে। প্রতিটি Client connection-এর নিজস্ব independent data buffer থাকে।

### Named Pipe Permissions – Accesschk

[Accesschk](https://docs.microsoft.com/en-us/sysinternals/downloads/accesschk?utm_source=chatgpt.com) দিয়ে Named Pipe-এর permission দেখা যায়।

- DACL (Discretionary Access Control List) দেখায় কারা কোনো resource modify, write, read বা execute করতে পারবে।
- সব Named Pipe-এর DACL দেখতে:

```
 .\accesschk.exe /accepteula \pipe\
```

## 5. Named Pipes Attack Example

[WindscribeService Named Pipe Privilege Escalation](https://www.exploit-db.com/exploits/48021?utm_source=chatgpt.com)

সব writable Named Pipe খুঁজতে:

```
accesschk.exe -w \pipe\* -v
```

এতে `WindscribeService` pipe-এ `Everyone` group-এর `READ` ও `WRITE` access পাওয়া যায়। এখানে Everyone বলতে সব authenticated user বোঝায়।

### Checking WindscribeService Named Pipe Permissions

```
C:\htb> accesschk.exe -accepteula -w \pipe\WindscribeService -v

Accesschk v6.13 - Reports effective permissions for securable objects
Copyright ⌐ 2006-2020 Mark Russinovich
Sysinternals - www.sysinternals.com

\\.\Pipe\WindscribeService
  Medium Mandatory Level (Default) [No-Write-Up]
  RW Everyone
        FILE_ALL_ACCESS
```

`Everyone`-এর `FILE_ALL_ACCESS` আছে, অর্থাৎ pipe-এর সব ধরনের access permission রয়েছে।

এই দুর্বল permission কাজে লাগিয়ে host-এ SYSTEM privilege escalation করা সম্ভব।
