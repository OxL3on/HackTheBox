## **Burp Intruder**

#### Payload Processing

Another option we can apply is `Payload Processing`, which allows us to determine fuzzing rules over the loaded wordlist. 
For example, if we wanted to add an extension after our payload item, or if we wanted to filter the wordlist based on specific criteria, we can do so with payload processing.Let's try adding a rule that skips any lines that start with a `.` (as shown in the wordlist screenshot earlier). We can do that by clicking on the `Add` button and then selecting `Skip if matches regex`, which allows us to provide a regex pattern for items we want to skip. Then, we can provide a regex pattern that matches lines starting with `.`, which is: `^\..*$`:

### Settings

You can customize how Intruder performs the attack.

- **Number of retries on network failure:** Set to `0`
- **Pause before retry:** Set to `0`

### Grep - Match

Used to **flag/highlight responses containing specific text**. For directory fuzzing, we want to find successful pages:

1. Enable **Grep - Match**
2. Click **Clear**
3. Add: `200 OK`
4. Disable **Exclude HTTP Headers** because `200 OK` appears in the HTTP response header.

Now Intruder will mark requests that return **HTTP 200 OK**.

### Grep - Extract

Used when responses are large and you only want to extract/display a specific part of the response. **Not needed here**, because we only care about the HTTP status code.

### Resource Pool

Controls how many network resources/requests Intruder uses. Useful for **large attacks**, but you can usually leave it at the default.
